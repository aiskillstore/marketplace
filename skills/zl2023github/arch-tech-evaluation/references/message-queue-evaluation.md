# 技术选型完整示例：消息队列选型

以下是一个完整的技术选型评估报告示例，展示从需求分析到最终推荐的全流程。

## 业务场景

电商平台需要处理以下异步消息：
1. 订单创建后通知库存、物流、财务等下游系统
2. 用户操作日志收集（日均1亿条）
3. 秒杀/大促场景的流量削峰
4. 订单状态变更的实时推送

## 评估过程

### 1. 需求约束
- 峰值吞吐：10万+ msg/s
- 消息持久化：至少保留7天
- 消费语义：至少一次投递
- 延迟要求：实时场景<100ms，日志场景可容忍秒级
- 团队技术栈：Java为主

### 2. 候选方案
- Apache Kafka
- RabbitMQ
- Apache Pulsar
- Redis Stream

### 3. 多维度对比

| 维度 | Kafka | RabbitMQ | Pulsar | Redis Stream |
|------|-------|----------|--------|-------------|
| 吞吐量 | 100万+/s | 数万/s | 100万+/s | 10万+/s |
| 延迟 | 毫秒级 | 微秒级 | 毫秒级 | 微秒级 |
| 持久化 | 磁盘顺序写 | 磁盘/内存 | 分层存储 | RDB/AOF |
| 消息模型 | 分区+Consumer Group | Exchange+Queue | Topic+Subscription | Stream Group |
| 顺序保证 | 分区内有序 | 单队列有序 | 分片内有序 | 单Stream有序 |
| 运维复杂度 | 中 | 低 | 高 | 极低 |
| 生态成熟度 | 极高 | 高 | 中 | 中 |
| 学习曲线 | 中 | 低 | 高 | 低 |
| 团队经验 | 有经验 | 有经验 | 无经验 | 部分经验 |

### 4. 推荐方案

**推荐：Kafka** — 核心场景（订单事件、流量削峰）
**辅助：Redis Stream** — 低延迟场景（实时推送）

理由：
1. 吞吐量匹配峰值需求（10万+/s）
2. 持久化能力满足7天保留期
3. 生态成熟，周边工具（Kafka Connect/KSQL）丰富
4. 团队已有运维经验

### 5. POC验证要点
- 测试10万/s吞吐下的延迟分布
- 测试broker宕机后的消息恢复时间
- 验证消费端rebalance行为
