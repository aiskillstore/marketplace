# 术语与状态表达示例

本文件提供术语改写、中性标签和状态表达的条件示例。实际任务依次采用用户明确确认的术语、当前项目既有术语和目标领域通用术语；下列示例只在语义及适用条件一致时使用。语义可能变化时先确认实际含义。

## 术语改写示例

| 原表述 | 参考表述 | 适用条件 |
|---|---|---|
| 超长度 | 截断 | 文本或序列因长度限制被裁剪 |
| 超不超长度 | 是否触及长度上限 | 检查输入或输出是否达到上限 |
| Ray 的端口会跟自己撞 | 多个任务的 Ray 抢占同一端口 | 多个任务使用相同 Ray 端口 |
| 臂 | 方案 | 表示实验或对照方案 |
| 只看长度那条线 | 长度启发式基线 | 仅依据长度进行判断的基线 |
| 刷奖励 | 奖励被优化但评测指标未改善 | 奖励上升且目标评测指标没有改善 |
| 存档 | checkpoint | 表示模型训练过程保存的检查点 |
| 血统 | 基座来源 | 表示模型所基于的基础模型来源 |
| 8 个不同血统 | 8 个不同基座的模型 | 表示八个基座来源不同的模型 |
| 把握 | 确认程度 | 表示结论得到确认的程度 |
| 怎么做的 | 实验设置 | 表示实验方法、参数和条件 |
| 还在跑的 | 相关任务仍在执行 | 对象是已经开始且尚未完成的任务；结构化状态字段可使用项目已确认的“进行中”等标签 |
| 赢得很干脆 | 差值为 `{实际差值}` | 写入源材料中的真实差值；实际差值为 `0.030` 时写“差值为 0.030” |
| 测得更准 | 估计精度更高 | 比较估计结果的精度 |
| 测得更糙 | 估计精度更低 | 比较估计结果的精度 |
| 白跑 | 无效运行 | 运行没有产生有效结果 |
| 白占 | 空占 | 资源被占用但没有执行有效任务 |
| 天生需要几百到上千次采样 | 该信号所需的采样量为几百到上千次 | 已确认采样量范围时使用 |

## 中性标签示例

源材料尚未定义固定标签且需要新建字段时，可根据字段实际含义选择以下名称：

- 问题
- 现象
- 影响
- 结果
- 原因
- 范围
- 状态

同一表格或同级章节保持标签形式一致。

## 状态标签示例

以下名称适用于结构化状态字段；项目已有状态名称时沿用项目名称。

| 状态 | 使用条件 |
|---|---|
| 已完成 | 计划内工作已经执行完毕 |
| 已确认 | 结果已经通过证据或验收确认 |
| 进行中 | 工作已经开始且尚未完成 |
| 未达到基线 | 结果低于已定义基线 |
| 结论待定 | 现有信息不足以形成结论 |
| 尚未验证 | 关系、假设或解释尚未得到验证 |
| 原因未查明 | 已确认问题或现象存在，原因仍未确定 |

同一结构中的状态标签保持一致。“做通了”等口语状态应根据实际证据选择对应表达。普通正文直接说明实际对象、动作和过程状态；状态字段使用已经确认的项目标签。
