# 指摘を受けて skill を直す

ユーザーの指摘を受けて skill を直すときの手順である。本文は必要な理由と達成したい状態から導いた結果であり、依頼を受けた順に足した履歴ではない。

1. 指摘された一文ではなく、ユーザーがなぜそこを指摘したのかから判断を読み取る
2. 必要な理由と達成したい状態のどちらかが変わるのか、既存の規則のどれかが足りないのかを決める
3. 本文全体をそこから導き直す。poteto-principles の redesign-from-first-principles に従う
4. 導き直した結果が今の本文と同じ部分は書き換えない
5. 同じ理由が当たるほかの箇所をすべて直す

同じ部分を書き換えないのは、読み手が覚えた構成を崩さないためである。

skill でよく起きる継ぎ足しは、指摘された一文を末尾に足すことと、見出しや箇条書きを一行増やして別項にすることである。指摘された箇所だけを直すと、同じ理由の別の箇所が残り、同じ指摘を繰り返すことになる。
