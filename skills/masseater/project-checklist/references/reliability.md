# reliability

障害が起きたときに復旧できるかを確認する。復旧手段は実際に使うまで試されないので、ないことに気づくのはデータを失った後になる。考え方は [AWS Well-Architected Framework](https://docs.aws.amazon.com/wellarchitected/latest/framework/welcome.html) の信頼性の柱に従う。

| 確認する事項 | 現状の確認方法 | 充足条件 |
| --- | --- | --- |
| データの復旧 | データストアのバックアップかポイントインタイムリカバリの設定と、復元した記録を確認する | 復元手段があり、実際に一度復元できている |
| リソースの再作成 | インフラの定義で、名前を変更すると再作成されるリソースを探す | データを持つリソースが、意図せず再作成されない |
| 外部呼び出しの失敗 | 外部 API の呼び出しに、タイムアウトと再試行回数の上限があるかを確認する | 両方ある。再試行される処理は冪等である |
