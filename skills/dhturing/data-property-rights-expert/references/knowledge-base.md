## 第一部分 · 知识库

### 1.1 一句话定位

数据产权专家负责回答数据领域的**元问题**：数据归谁、谁可以用、谁可以卖。他不出报告、不做评估，但所有后续工作都要站在他给出的权利判断之上。

他的理论基础是「数据二十条」创立的**三权分置**制度——这是中国数据要素市场区别于欧美的核心制度创新。

### 1.3 核心模型：三权分置

这是数据产权专家最核心的知识，必须讲清楚：

| 权利 | 定义 | 谁通常持有 | 能做什么 |
|---|---|---|---|
| **数据资源持有权** | 对合法持有的数据资源享有的持有、管理的权利 | 数据产生者/合法获取者 | 持有、保管、决定是否对外提供 |
| **数据加工使用权** | 对数据进行加工、处理、分析、使用的权利 | 加工者/使用者 | 清洗、建模、分析、内部使用 |
| **数据产品经营权** | 对经加工形成的数据产品进行经营、收益的权利 | 产品开发者 | 销售、许可、收益 |

**核心理解：**
1. 三权**可以分离**——同一份数据，A 持有、B 加工、C 经营，各自合法
2. 三权**不必然同时存在**——可以有持有权但无经营权
3. 三权**不是所有权**——数据产权刻意回避了"所有权"概念，因为数据具有非排他性、可复制性
4. 三权**来源多元**——可以是法定、约定、或者通过加工事实取得

**三权取得方式：**

| 权利 | 取得方式 |
|---|---|
| 持有权 | ① 自行合法产生（如物联网设备采集）② 合法交易/授权取得 ③ 公开合法采集 |
| 加工使用权 | ① 数据持有者自用 ② 持有者授权（合同约定）③ 法律许可（如公共数据开放） |
| 产品经营权 | ① 自主开发形成产品 ② 授权开发 ③ 合作开发（需明确分配） |

### 1.4 核心模型二：数据权属判定的四步法

**第一步：识别数据来源**
```
自有产生 → 权属相对清晰（但需证明采集合法）
授权获取 → 看授权范围（能否转授权？能否商用？）
公开采集 → 看是否违反网站协议、是否涉及个人信息
交易取得 → 看交易合同约定的权利范围
```

**第二步：识别权利负担**
- 是否含个人信息？（个保法约束）
- 是否含重要数据/核心数据？（数安法约束）
- 是否有第三方知识产权？（如地图数据、著作权内容）
- 是否涉及商业秘密？（他人或自己的）
- 是否有合同限制？（如平台协议禁止爬取/转售）

**第三步：确定权利类型与边界**
- 明确持有的是哪几项权利
- 明确权利的地域、时间、用途边界
- 明确是否可转让、可许可

**第四步：形成权利证明文件**
- 权属确认书
- 授权合同（链条要完整）
- 数据来源说明
- 登记凭证

### 1.5 三权分置的实务映射

| 业务场景 | 涉及权利 | 要点 |
|---|---|---|
| 企业自采集数据入表 | 持有权 + 加工使用权 | 证明采集合法（用户同意/合同约定） |
| 数据产品对外销售 | 产品经营权 | 需上游授权允许商用；需完成加工形成"产品" |
| 数据代加工 | 加工使用权 | 合同明确加工范围、成果归属 |
| 公共数据授权运营 | 加工使用权（+有条件经营权） | 依《公共数据资源授权运营实施规范》 |
| 数据资产质押融资 | 需明确质押的权利范围 | 通常质押"经营权"及收益 |
| 数据资产作价出资 | 需可转让的权利 | 三权中可转让部分 |

### 1.6 关键判断口径

- **不承认数据所有权**：不要用"数据所有权"表述，用"持有权/使用权/经营权"
- **个人信息不适用产权**：个人信息受个保法规制，人格权不因加工而转移
- **权利范围以合同为准**：有约定的从约定（不违反法律强制性规定）
- **加工产生新权利**：投入实质性加工可产生新的产品经营权
- **登记是公示非设权**：登记是权利公示与对抗效力，不是权利的来源

### 1.7 常见问题与标准答复

**Q1：我们采集的用户数据，归我们吗？**
A：不归。个人信息的人格权归个人。您取得的通常是"数据处理者"地位，可依个保法在授权范围内处理，但该数据本身不能作为您的资产入表（除非经去标识化/匿名化处理形成新的数据资源，且符合入表条件）。

**Q2：数据所有权到底归谁？**
A："数据二十条"刻意回避所有权，改为三权分置。这是立法智慧——数据可复制、可共享、非排他，套用所有权会产生理论困境。请用三权表述。

**Q3：我们从第三方买了数据，能再卖出去吗？**
A：取决于合同。多数数据采购合同限制转售。必须先看合同，无明确许可的不能转售。

**Q4：三权分置有法律效力吗？**
A：目前"数据二十条"是政策文件，部分已通过地方数据条例、登记规则落地。司法实践中已被广泛参考。属于**政策+地方立法+司法实践**共同构成的行为规范。

### 2.2 标准作业流程 SOP

**S0 委托与范围确认（2~3天）**
1. 明确委托目的（入表/交易/融资/登记/纠纷）
2. 明确分析对象（具体数据资源清单）
3. 输出《委托事项说明书》

**S1 数据来源梳理（1周）**
1. 逐项确认来源类型
2. 收集来源证据（合同、同意记录、采集日志、系统架构图）
3. 输出《数据来源分类表》

**S2 权利负担排查（1~2周，核心）**
逐项排查五类负担：
1. **个人信息**：是否含？是否去标识化？是否有合法处理基础？
2. **重要数据/核心数据**：是否属于？是否履行了相应义务？
3. **第三方知识产权**：是否含受著作权、商标权、专利权保护的内容？
4. **商业秘密**：是否含他人商业秘密？
5. **合同限制**：上游合同是否限制使用/转售/共享？

输出《权利负担清单》（逐项列问题与影响）

**S3 三权界定（1周）**
1. 判断持有的权利类型（可能只有持有权，也可能三权齐全）
2. 明确每项权利的范围（数据范围、用途、地域、时间）
3. 输出《数据产权界定意见》

**S4 权属文件组织（1~2周）**
1. 收集/补充：数据来源说明、权属确认书、授权合同、采集合规证明
2. 检查授权链条完整性（特别是转授权场景）
3. 输出《权属证明文件汇编》

**S5 结论与建议（3~5天）**
1. 给出明确的权利结论（是什么权利、边界在哪）
2. 给出使用建议（可以做什么、不可以做什么）
3. 给出整改建议（如有瑕疵，如何补正）
4. 输出《数据产权分析报告》

**S6 交易结构设计（如涉及，1~2周）**
1. 根据权利状态设计合法流转路径
2. 设计合同条款（权利范围、限制、违约责任）
3. 输出《权利流转方案》与合同草案

**S7 制度设计（可选，1~2周）**
1. 帮企业建立数据权属管理制度
2. 建立权属台账
3. 输出《数据权属管理细则》

### 2.6 关键话术

- "数据不适用『所有权』，用的是『三权分置』——这是中国制度创新。"
- "您手里的数据，先要弄清楚是『只持有』还是『能卖』，这两件事差别巨大。"
- "采集合法是底线。来源说不清的数据，我们不会建议您用它入表或交易。"

**风险提示**：
1. 含个人信息的数据未处理即入表/交易，是最高风险
2. 授权链条断裂（转授权无许可）是常见硬伤
3. 重要数据出境有额外审批要求
4. 权属结论会随政策变化调整，需注明有效期
