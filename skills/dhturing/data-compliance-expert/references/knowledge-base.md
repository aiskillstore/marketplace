# 数据合规专家

> 所属战队：06-合规安全与政策
> 专家编号：34
> 核心使命：确保数据全生命周期的处理活动合法合规，让数据资产「敢用、能用、经得起查」

---

## 第一部分 · 知识库

### 1.1 一句话定位

数据合规专家是**全链路的守法底座**。无论入表、评估、交易、融资，任何环节的合规瑕疵都会让前面的工作作废。他的作用是回答"这件事这么做合法吗"，并给出合规的替代方案。

**与其他专家的边界**：
- 与专家 14（确权法律）的区别：合规专家处理**处理活动**的合法性（怎么做才合规），法律专家处理**权属与合同**（权利归谁、怎么签）
- 与专家 35（数据安全）的区别：合规管"该不该做"，安全管"怎么防风险"
- 与专家 36（个人信息保护）的区别：个人信息保护是合规的一个专项，因其重要性独立成专家

### 1.3 核心模型一：数据合规三法一条例

**这是中国数据合规的核心法律框架，必须完整掌握：**

| 法律 | 定位 | 核心义务 |
|---|---|---|
| **网络安全法** | 基础法 | 等级保护、网络运行安全、监测预警 |
| **数据安全法** | 数据领域基本法 | 分类分级、重要数据目录、安全评估、数据交易中介义务 |
| **个人信息保护法** | 人格权保护 | 告知同意、单独同意、最小必要、去标识化、跨境规则 |
| **网络数据安全管理条例** | 行政法规（2025施行） | 细化上述三法的具体操作要求 |

**《网络数据安全管理条例》的新增重点**（2025-01-01 施行，很重要）：
- 细化重要数据识别与目录管理
- 明确网络数据处理者义务
- 强化个人信息处理规则
- 规范数据跨境流动
- 明确数据交易平台责任
- 加大处罚力度

### 1.4 核心模型二：数据合规的八个专项

数据合规不是一件事，是八个专项：

| 专项 | 核心要求 | 常见问题 |
|---|---|---|
| **1. 分类分级合规** | 按 GB/T 43697 识别核心/重要/一般 | 未识别重要数据 |
| **2. 个人信息合规** | 告知同意、最小必要、单独同意 | 未获取有效同意 |
| **3. 数据来源合规** | 来源合法（自有/授权/公开/交易） | 非法爬取 |
| **4. 数据处理合规** | 处理目的合法、范围适当 | 超范围使用 |
| **5. 数据共享合规** | 共享需有依据、签订协议 | 无授权共享 |
| **6. 数据出境合规** | 评估/备案/认证 | 违规出境（与专家37） |
| **7. 数据交易合规** | 交易标合法、平台审核 | 标的含敏感数据 |
| **8. 数据安全合规** | 等保、安全措施、应急处置 | 未做等保（与专家35） |

### 1.5 核心模型三：合规风险四色分级

本专家自有的风险管理工具：

| 级别 | 情形 | 处理 |
|---|---|---|
| 🔴 **红线** | 违反法律强制性规定（如非法获取数据、未同意处理敏感个人信息） | 立即停止，必须整改 |
| 🟠 **高风险** | 可能引发行政处罚或重大损失（如未识别重要数据、未做安全评估） | 限期整改 |
| 🟡 **中风险** | 制度不完善、流程不规范 | 计划整改 |
| 🟢 **低风险** | 轻微瑕疵、可优化项 | 建议改进 |

**实务应用**：合规审查后出具**四色风险清单**，客户一目了然知道该做什么。

### 1.6 核心模型四：合规体系三支柱

一个完整的数据合规体系由三部分组成：

**支柱一 · 制度**
- 数据分类分级管理办法
- 个人信息保护管理办法
- 数据安全管理办法
- 数据共享与对外提供管理办法
- 数据出境管理办法
- 数据安全事件应急预案
- 合规审计制度

**支柱二 · 组织**
- 数据安全负责人（法定要求）
- 个人信息保护负责人（法定要求）
- 数据合规团队
- 部门数据专员

**支柱三 · 技术**
- 数据分类分级工具
- 权限管理与访问控制
- 数据脱敏/加密
- 日志审计
- 数据泄露防护（DLP）

**实务要点**：制度易写，**落地难**。判断合规体系是否有效，看三点：有没有人负责、有没有工具支撑、有没有留痕。

### 1.7 常见问题与标准答复

**Q1：我们数据不多，需要做合规吗？**
A：需要。合规义务与数据量无关，与"是否处理个人信息/重要数据"有关。只要有用户数据，个保法就适用。

**Q2：合规要花多少钱？**
A：差异极大。基础合规（制度+培训）几万元；完整体系（含等保、审计）几十万到上百万。建议分阶段。

**Q3：数据合规和入表什么关系？**
A：**合规是入表的第一关**。来源不合法、含未处理个人信息的数据，一律不能入表。

**Q4：出问题了怎么办？**
A：① 立即止损；② 评估影响范围；③ 按预案处置；④ 依法报告（重要数据泄露必须报告）；⑤ 整改；⑥ 配合监管。

**Q5：合规审计是强制的吗？**
A：**《个人信息保护合规审计管理办法》**规定，处理个人信息达到一定数量（如超过 100 万人）的处理者，需定期开展合规审计。需关注具体门槛。

### 2.2 标准作业流程 SOP

**S0 合规尽调（2~3周）**
1. 了解业务模式与数据流
2. 收集现有制度、协议、系统信息
3. 访谈关键岗位
4. 输出《合规尽调纪要》

**S1 分类分级（2~4周）**
1. 按 GB/T 43697 识别：
   - 核心数据（关系国家安全、国民经济命脉）
   - 重要数据（特定领域、群体、区域）
   - 一般数据（再分 1~4 级）
2. 特别识别个人信息与敏感个人信息
3. 输出《数据分类分级表》

**S2 合规风险排查（2~4周，核心）**
1. 八个专项逐项排查：
   - 分类分级：是否识别重要数据？
   - 个人信息：是否获取有效同意？是否最小必要？
   - 数据来源：是否合法？授权链条完整？
   - 数据处理：目的是否合法？范围适当？
   - 数据共享：是否有依据？协议是否健全？
   - 数据出境：是否履行手续？
   - 数据交易：标的是否合规？
   - 数据安全：等保是否完成？措施是否到位？
2. 出四色风险清单
3. 输出《合规风险清单》

**S3 合规体系设计（3~4周）**
1. 设计制度体系（九项制度）
2. 设计组织架构（负责人 + 团队）
3. 设计技术措施（工具 + 权限 + 审计）
4. 输出《合规体系建设方案》

**S4 制度建设（4~6周）**
1. 撰写各项管理制度
2. 内部评审
3. 发文实施
4. 输出制度文件

**S5 体系落地（4~8周）**
1. 任命负责人（书面任命，**法定要求**）
2. 部署技术工具
3. 建立流程与留痕机制
4. 培训全员
5. 输出落地证据材料

**S6 合规审计（2~4周）**
1. 设计审计方案与清单
2. 执行审计（查制度、查执行、查留痕）
3. 出具审计报告
4. 制定整改计划
5. 输出《合规审计报告》

**S7 交易合规审核（按需，1~2周）**
1. 审核交易标的：
   - 是否含未脱敏个人信息
   - 是否含重要数据
   - 权属是否清晰
   - 来源是否合法
2. 出具审核意见
3. 输出《交易合规审核意见》

**S8 应急响应（事件发生时）**
1. 立即止损
2. 评估影响范围
3. 按预案处置
4. 依法报告（重要数据泄露需报告监管）
5. 通知受影响个人（如涉及个人信息）
6. 输出处置报告

**S9 监管配合（持续）**
1. 应对监管检查
2. 提交所需材料
3. 落实整改要求
4. 输出应对材料

### 2.6 关键话术

- "合规不是成本，是准入门槛。不合规的数据资产，入表会被退、交易会被拒、融资会被否。"
- "我们用四色清单告诉您：哪些是红线必须马上停，哪些是高风险要限期改，哪些是中低风险可以计划做。"
- "制度容易写，落地难。我们看三个证据：有没有人负责、有没有工具、有没有留痕。"

**风险提示**：
1. **重要数据未识别是最高频的合规风险**
2. **法定负责人（数据安全、个人信息保护）未任命是明确违法**
3. 敏感个人信息需单独同意，多数企业未做到
4. 数据泄露不报告会加重处罚
5. 合规审计有明确门槛要求（如个保处理达一定规模）
6. 行业监管（金融、医疗、汽车）有额外要求，不能只看通用法律
