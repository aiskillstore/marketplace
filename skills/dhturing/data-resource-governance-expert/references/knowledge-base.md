# 数据资源治理专家

> 所属战队：01-资产化流水线
> 专家编号：02
> 核心使命：把散落、混乱的数据，整理成「有目录、有归属、有质量、有分级」的可管理资源

---

## 第一部分 · 知识库

### 1.1 一句话定位

数据资源治理专家解决的是「数据在哪、是什么、谁负责、能不能用」的问题。他是资产化的**地基工程**——没有治理，后面所有环节都建在沙上。

跟「数据治理」这个泛概念相比，本专家的**鲜明特点**是：服务目标是**资产化**，不是为治理而治理。所有治理动作都要能回答一个问题——「这一步对入表/评估/交易有什么用」。

合计 3+3+4+3+3+3+5+5 = 29 项。

**5 级成熟度：**

| 级 | 名称 | 特征 |
|---|---|---|
| 1 | 初始级 | 无制度、靠个人、被动响应 |
| 2 | 受管理级 | 有初步制度、有责任人、局部管理 |
| 3 | 稳健级 | 制度体系化、流程标准化、有平台支撑 |
| 4 | 量化管理级 | 有量化指标、可度量可预测 |
| 5 | 优化级 | 持续优化、数据驱动决策、行业标杆 |

**实务判断**：多数中小企业落在 1~2 级；能支撑入表的底线一般是**在关键数据域达到 3 级**（有目录、有责任人、有质量检查、有分级）。

### 1.4 核心模型二：治理到资产的「四梁八柱」

本专家自有的方法论，把 DCMM 翻译成资产化语言：

**四梁（四个必备成果）**
1. **数据资源目录**——有什么数据（相当于资产的"存货清单"）
2. **数据责任矩阵**——谁负责（相当于资产的"保管人"）
3. **数据标准体系**——什么叫对（相当于资产的"规格书"）
4. **数据质量基线**——好不好（相当于资产的"质检报告"）

**八柱（八个关键动作）**
1. 业务术语标准化（统一口径，消除"同名不同义"）
2. 元数据管理（技术元数据 + 业务元数据）
3. 主数据管理（客户/产品/组织/供应商等核心实体）
4. 数据血缘与影响分析（可追溯，是确权与评估的关键证据）
5. 数据分类分级（核心/重要/一般）
6. 数据生命周期管理（创建→使用→归档→销毁）
7. 数据质量规则与监控
8. 数据安全管理（权限、脱敏、审计）

### 1.5 关键交付逻辑

治理必须**以终为始**：先看下游要什么，再决定治理做什么。

| 下游用途 | 治理必须交付 |
|---|---|
| 入表 | 资源目录 + 权属责任 + 成本可追溯（血缘） |
| 资产评估 | 数据规模、更新频率、应用场景、质量等级 |
| 数据产品上市 | 数据元标准、字段口径、样例数据 |
| 数据交易 | 分级结果（决定能不能交易）、脱敏方案 |
| 融资 | 资产可辨认性证明、权属与质量证据链 |

### 1.6 常见问题与标准答复

**Q1：我们已经在做数据中台了，还需要治理吗？**
A：中台是技术平台，治理是管理体系。上了中台不等于数据可入表——中台解决"通"，治理解决"清、准、责"。两者互补。

**Q2：治理要多久？**
A：聚焦式治理（只治要入表/交易的那部分数据）通常 4~8 周；全企业治理 6~18 个月。**我们主张聚焦式**，不做大而全。

**Q3：治理做完能立刻入表吗？**
A：治理是必要条件不是充分条件。还要过合规门和价值门。

**Q4：DCMM 贯标值得做吗？**
A：如果客户是国央企或有政府项目需求，DCMM 等级是加分项甚至门槛，值得。如果只是数据入表，不必专门贯标，但可参照其框架做事。

### 2.2 标准作业流程 SOP

**S0 目标对齐（1周）**
- 明确：这次治理服务于什么？（入表 / 评估 / 交易 / 融资）
- 确定治理范围边界（不要一开始就全企业）
- 输出《治理目标与范围说明书》

**S1 现状调研（1~2周）**
- 访谈：业务部门、IT 部门、数据团队
- 清点：系统清单、数据库清单、表清单、接口清单
- 问卷：按 DCMM 8 域设计问卷
- 输出《现状调研报告》

**S2 成熟度评估（1周）**
- 按 8 域 29 项逐项打分（1~5 级）
- 绘制雷达图，识别短板
- 输出《数据管理成熟度评估报告》

**S3 数据资源盘点（2~3周）**
- 逐系统、逐库、逐表清点
- 记录：名称、来源、形态、体量、更新频率、责任人、使用场景、对外提供情况
- 对要入表/交易的资源，细化到字段级
- 输出《数据资源盘点清单》

**S4 目录编制（1~2周）**
- 三层目录结构：主题域 → 数据类 → 数据项
- 每项标注：业务含义、技术位置、更新周期、共享属性、分级标签
- 输出《数据资源目录》

**S5 责任体系（1周）**
- 建立数据 owner / steward / custodian 三层责任
- 明确数据产生、加工、使用、对外提供各环节责任人
- 输出《数据责任矩阵》

**S6 标准与元数据（2~4周）**
- 提炼业务术语（消除同名异义、异名同义）
- 建数据元标准（字段定义、类型、取值范围）
- 建指标标准（口径、公式、维度）
- 建立元数据库与血缘图谱
- 输出《数据标准规范》《元数据清单》《血缘图谱》

**S7 分类分级（1~2周）**
- 按 GB/T 43697-2024，识别核心数据、重要数据、一般数据
- 一般数据内部再分 1~4 级
- 输出《数据分类分级表》

**S8 质量与生命周期（2周）**
- 设计六维质量规则
- 设计生命周期各阶段管理策略
- 输出《数据质量规则库》《生命周期管理规范》

**S9 制度建设（1~2周）**
- 撰写管理办法、实施细则
- 输出《数据管理办法》系列文件

**S10 交付与移交（1周）**
- 治理成果移交，培训客户数据团队
- 转下游专家（03/04/05/06）

### 2.4 质量校验清单

- [ ] 盘点覆盖所有要入表/交易的数据，无遗漏
- [ ] 每条资源有明确责任人（不能是"IT 部门"这种集体）
- [ ] 血缘可追溯到原始系统
- [ ] 分类分级结果与安全要求一致
- [ ] 标准中的字段定义与业务实际一致（不是照抄技术字段）
- [ ] 治理成果能支撑下游（目录可用于评估、分级可用于交易）
- [ ] 制度可执行（有责任人、有频率、有考核）

### 2.6 关键话术

- "治理不是给 IT 部门加活，是给企业的数据资产上『产权证』和『说明书』。"
- "我们不做大而全的治理工程，我们只治能变成钱的那部分数据。"
- "数据目录就是您数据的存货清单——没有清单，谈不了资产。"
