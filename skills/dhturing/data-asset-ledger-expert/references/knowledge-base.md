# 数据资产台账管理专家

> 所属战队：01-资产化流水线
> 专家编号：07
> 核心使命：让每一项数据资产在账上有名、有数、有据、有责，形成可持续管理的资产台账

---

## 第一部分 · 知识库

### 1.1 一句话定位

数据资产台账管理专家是流水线的**登记员与档案管理员**。入表完成后，资产不是躺在报表里就完事了——它需要一张「资产卡片」，记录它是谁、从哪来、值多少、谁负责、什么时候摊销、有没有减值。

没有台账，数据资产就是一笔糊涂账；有了台账，它才能被管理、被审计、被融资、被处置。

### 1.3 核心模型一：数据资产卡片

这是台账的基本单元。一张标准的数据资产卡片应包含：

**一、身份信息**
| 字段 | 说明 |
|---|---|
| 资产编号 | 唯一编码（建议沿用数据产权登记编码规则） |
| 资产名称 | 标准化命名 |
| 资产类别 | 按《数据资产分类与代码》归类 |
| 入账科目 | 无形资产 / 存货 / 开发支出 |
| 所属主体 | 持有该资产的法人主体 |

**二、来源与权属**
| 字段 | 说明 |
|---|---|
| 数据来源类型 | 自有产生/授权获取/公开采集/交易取得 |
| 权属类型 | 持有权 / 加工使用权 / 产品经营权（可组合） |
| 权属证明文件 | 编号与存放位置 |
| 是否存在共有 | 是/否，共有人及分配约定 |

**三、规模与技术**
| 字段 | 说明 |
|---|---|
| 数据体量 | 记录数 / 大小（GB） |
| 时间跨度 | 起止时间 |
| 更新频率 | 实时/日/周/月/不定期 |
| 存储位置 | 系统/库/表 |
| 接口情况 | 有无 API，权限要求 |

**四、财务信息**
| 字段 | 说明 |
|---|---|
| 初始入账成本 | 元 |
| 入账日期 | — |
| 摊销年限 | 年（附依据） |
| 摊销方法 | 直线法/其他 |
| 累计摊销 | 元 |
| 账面净值 | 元 |
| 减值准备 | 元 |
| 评估价值 | 元（如评估过） |

**五、质量与安全**
| 字段 | 说明 |
|---|---|
| 质量等级 | A/B/C/D |
| 分类分级 | 核心/重要/一般+级别 |
| 安全等级 | 对应管控要求 |

**六、责任与状态**
| 字段 | 说明 |
|---|---|
| 数据责任人 | 姓名+职务 |
| 管理部门 | — |
| 资产状态 | 在用 / 闲置 / 处置中 / 已处置 |
| 最近盘点日期 | — |

### 1.4 核心模型二：三本账

| 账本 | 内容 | 用途 |
|---|---|---|
| **资产账** | 每项资产卡片全量信息 | 日常管理、盘点 |
| **财务账** | 原值、累计摊销、净值、减值 | 与财务报表勾稽 |
| **权益账** | 权属、登记状态、质押/许可情况 | 融资、交易、纠纷处理 |

三本账必须**互相对得上**。常见问题：资产账有 100 项，财务账只有 80 项（有资产未入账或有资产已处置未销账）。

### 1.5 核心模型三：台账与其他系统的关系

```
数据资源目录（专家02产出的"存量清单"）
        ↓ 经合规、质量、评估、成本
数据资产台账（本专家：入表后的"资产账"）
        ↓
├── 财务系统（总账、无形资产明细账）
├── 数据资产管理系统（香农平台/DAM）
├── 数据产权登记系统（国数局登记）
└── 融资/交易系统（质押登记、交易标的）
```

**关键设计原则**：台账是「一份主数据，多系统引用」，不是各系统各记一套。

### 1.6 关键数据口径

- **资产编号规则**：建议采用「主体码 + 类别码 + 流水号」或沿用数据产权登记的 15 位编码
- **计量单位**：财务口径用元；业务口径用条/GB/次，两个口径都要留
- **摊销起始**：达到预定用途的当月
- **盘点频率**：至少每年一次全面盘点，重要资产每半年
- **减值测试**：至少每年年末一次

### 1.7 常见问题与标准答复

**Q1：台账用 Excel 还是系统？**
A：资产数量 < 50 项，Excel 可支撑；> 50 项建议上系统。本库已有「数据资产管理系统（香农平台）」和「DAM」，可直接部署。

**Q2：台账要不要和财务系统对接？**
A：理想状态要。至少保证台账的财务字段与财务账每月对账一次。

**Q3：数据资产会减值吗？**
A：会。数据时效性衰减、场景消失、被替代都会导致减值。必须建立定期减值测试机制，否则审计会问。

**Q4：入表后不管理有什么后果？**
A：三个后果：审计发现账实不符被调整；减值准备计提不及时被问询；资产无法用于融资/交易（没有可信台账，金融机构和买方都不认）。

### 2.2 标准作业流程 SOP

**S0 需求确认（2~3天）**
1. 确认资产数量级、管理要求
2. 决定 Excel 还是系统
3. 确认与财务系统的对接要求

**S1 体系设计（1周）**
1. 设计三本账结构
2. 设计资产卡片字段（可按行业裁剪）
3. 制定编号规则
4. 输出《数据资产台账体系设计》

**S2 模板制作（3~5天）**
1. 制作 Excel 模板（或配置系统）
2. 制作资产卡片模板
3. 制作盘点表模板
4. 输出模板文件

**S3 台账初始化（1~2周）**
1. 从入表专家处获取入表资产清单
2. 从治理专家处获取数据资源详情
3. 逐项建立资产卡片
4. 输出《数据资产台账》初版（三本账）

**S4 系统实施（2~4周，如需要）**
1. 部署数据资产管理系统（香农平台）
2. 数据迁移与配置
3. 权限设置（财务/数据/业务/管理层）
4. 培训使用
5. 输出系统上线的台账

**S5 财务对账（每季度）**
1. 台账净值合计 vs 财务账无形资产/存货明细
2. 找出差异原因（未入账/未销账/口径不同）
3. 调整至一致
4. 输出《对账记录》

**S6 定期盘点（每半年/每年）**
1. 盘点范围：全部在册资产
2. 盘点内容：账实是否相符、责任人是否变化、数据是否仍存在、场景是否仍有效
3. 处理差异：盘盈、盘亏、状态变更
4. 输出《资产盘点报告》

**S7 减值测试（每年末）**
1. 识别减值迹象（时效衰减、场景消失、技术替代、法律变化）
2. 测算可收回金额
3. 计提减值准备
4. 输出《减值测试报告》

**S8 报表与披露支持（每期末）**
1. 提供附注披露所需数据
2. 配合审计提供台账与凭证

**S9 制度建设（1周）**
1. 撰写《数据资产台账管理办法》
2. 明确归口部门、更新频率、责任人
3. 建立交接机制

### 2.6 关键话术

- "入表只是第一步。台账管得好，这份资产才能一直用下去、一直能融资。"
- "我们给您的不只是一张表，是一套管理办法 + 一个系统。"
- 对客户财务："台账和您的无形资产明细账每月对一次，审计来了随时能对得上。"

**风险提示**：
1. 台账与财务账长期不一致是审计高风险点
2. 不做减值测试可能被审计调整
3. 台账信息含权属与商业信息，需权限管控
4. 系统部署需考虑与现有 IT 架构的兼容
