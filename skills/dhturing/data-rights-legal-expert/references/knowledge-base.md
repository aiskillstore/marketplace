## 第一部分 · 知识库

### 1.1 一句话定位

数据确权法律专家是**持证律师角色**。他与其他确权专家的区别在于：他出具的是**可被登记机构、法院、监管采信的法律意见书**，需要执业资格背书。

在数据产权登记材料清单中，「法律意见书」是必备项（见专家 10）。在数据交易、数据融资尽调中，法律意见书同样常见。

### 1.3 核心法律意见书的结构

一份规范的数据法律意见书，标准结构如下：

```
一、引言
   1.1 委托事项与出具目的
   1.2 出具依据的法律法规
   1.3 声明事项（本意见书的局限、假设、依赖）
   1.4 释义

二、主体资格
   2.1 委托方基本情况
   2.2 主体资格合法性（依法设立、存续）
   2.3 经营范围是否覆盖相关业务

三、数据来源合法性
   3.1 数据来源类型
   3.2 各类来源的合法性论证
       - 自有产生：业务合法性、采集合规
       - 授权获取：授权链条完整性
       - 公开采集：是否违反协议、是否合法
       - 交易取得：交易文件合法性

四、数据权属认定
   4.1 三权分置下的权利类型认定
   4.2 权利边界（范围、用途、地域、期限）
   4.3 是否存在共有人及分配约定

五、合规性审查
   5.1 个人信息保护合规
   5.2 重要数据、核心数据合规
   5.3 知识产权合规
   5.4 合同限制合规
   5.5 行业监管合规

六、数据安全措施
   6.1 制度与组织
   6.2 技术措施
   6.3 应急与审计

七、结论意见
   7.1 逐项明确结论
   7.2 保留事项与风险提示

八、附件
   法律依据清单、核查文件清单、律师执业证复印件
```

### 1.4 核心模型：法律意见的四种结论类型

法律意见不能含糊，必须明确结论。四种标准结论：

| 结论类型 | 表述 | 使用场景 |
|---|---|---|
| **肯定性结论** | "合法/有效/权属清晰" | 无瑕疵 |
| **附条件肯定** | "在满足 X 条件的前提下，合法有效" | 轻微瑕疵可补正 |
| **保留意见** | "除 X 事项外，未发现重大法律障碍" | 存在保留事项 |
| **否定性结论** | "存在重大法律瑕疵，不满足 X 要求" | 硬伤 |

**实务要点**：律师最怕出"肯定性结论"后出问题。所以实务中多用「附条件肯定」或「保留意见」，把假设与依赖事项写清楚（这是自我保护，也是专业要求）。

### 1.5 核心模型：数据交易的合同要点审查

数据流转合同的必备条款：

| 条款 | 要点 | 风险 |
|---|---|---|
| **标的条款** | 数据范围、字段、格式、规模 | 描述模糊导致履行争议 |
| **权利条款** | 授予哪几项权利、是否为独家 | 未明确导致超范围使用 |
| **使用限制** | 禁止用途、禁止转售、禁止再识别 | 缺限制导致风险扩散 |
| **交付与验收** | 方式、时间、验收标准 | 无标准导致扯皮 |
| **价格与支付** | 计价方式、分期、调价 | 定价机制缺失 |
| **质量保证** | 质量标准、误差范围、整改 | 无质量条款 |
| **合规义务** | 双方合规责任、个人信息处理 | 责任不清 |
| **安全义务** | 安全保障措施要求 | 缺安全条款 |
| **知识产权** | 加工成果归属 | 归属不清 |
| **违约与赔偿** | 违约金、赔偿范围、责任限制 | 责任不对等 |
| **争议解决** | 管辖、仲裁/诉讼 | 管辖不利 |
| **合同期限与终止** | 期限、终止条件、终止后处理 | 终止后数据回收 |

### 1.6 关键法律风险清单（尽调必查）

| 风险类别 | 具体风险 | 后果 |
|---|---|---|
| **来源风险** | 非法爬取、超授权采集 | 数据不可用、承担法律责任 |
| **个人信息风险** | 未告知同意、未去标识化 | 行政处罚、民事赔偿、刑事风险 |
| **重要数据风险** | 未识别、未履行义务、违规出境 | 行政处罚、刑事责任 |
| **知识产权风险** | 侵犯他人著作权/商业秘密 | 侵权赔偿、停止使用 |
| **合同风险** | 上游限制转售、限制商用 | 违约、无法交易 |
| **反垄断风险** | 数据封锁、滥用市场支配地位 | 行政处罚 |
| **涉外风险** | 违反境外法律（如 GDPR）、出口管制 | 境外处罚 |

### 1.7 常见问题与标准答复

**Q1：法律意见书必须律师出吗？**
A：数据产权登记的法律意见书通常要求由律师事务所出具，律师签字 + 律所盖章。企业内部法务出具的一般不被采信。

**Q2：法律意见书能保证没问题吗？**
A：不能。法律意见书基于律师的核查与专业判断，有"声明事项"与"假设"限定。它的作用是**专业背书 + 风险揭示**，不是担保。

**Q3：意见书有效期多久？**
A：通常注明有效期（如 6 个月或 1 年），或注明"截至出具日"。重大变化（如政策变动、权属变更）后需重新出具。

**Q4：费用大概多少？**
A：视复杂度，通常数万元。数据产权登记场景的标准化意见书相对便宜；交易、融资的复杂项目更贵。

**Q5：自己写的"权属说明"能代替法律意见书吗？**
A：在登记场景一般不能。在企业内部管理场景可以。

### 2.2 标准作业流程 SOP

**S0 委托承接（3~5天）**
1. 明确委托事项与用途（登记/交易/融资/诉讼）
2. 明确出具范围与时间要求
3. 利益冲突检查
4. 签署委托合同与保密协议
5. 输出《委托事项与工作计划》

**S1 材料收集（1~2周）**
1. 主体材料：营业执照、章程、股东信息
2. 数据材料：数据清单、系统说明、数据字典
3. 来源材料：采集记录、授权合同、交易合同
4. 权属材料：权属确认书、登记凭证
5. 合规材料：个人信息处理记录、安全评估、内部制度
6. 输出《核查文件清单》

**S2 主体资格核查（3~5天）**
1. 核查主体依法设立并存续
2. 核查经营范围覆盖相关业务
3. 核查是否有行政处罚、重大诉讼
4. 输出核查结论

**S3 来源合法性核查（1~2周，核心）**
1. 逐类来源核查：
   - **自有产生**：业务是否合法？采集是否有约定？物联网设备是否合规？
   - **授权获取**：授权链条是否完整（一级到末级）？授权范围是否覆盖本次用途？是否可以转授权？
   - **公开采集**：是否违反 robots 协议/网站条款？是否绕过技术措施？是否涉及个人信息？
   - **交易取得**：交易对手是否有权处分？交易文件是否合法有效？
2. 输出来源合法性论证

**S4 权属认定（1周）**
1. 判定三权类型（引用专家 09 结论或独立判断）
2. 分析权利边界与限制
3. 分析共有与分配
4. 输出权属认定结论

**S5 合规性审查（1~2周）**
1. **个人信息合规**：告知同意、去标识化、最小必要、单独同意（敏感信息）
2. **重要/核心数据**：识别、备案、出境评估
3. **知识产权**：是否侵权、是否有许可
4. **合同限制**：上游限制是否触及
5. **行业监管**：金融、医疗、汽车等特殊行业要求
6. 输出合规审查结论

**S6 安全措施核查（3~5天）**
1. 制度是否健全
2. 技术措施是否到位
3. 应急与审计机制
4. 输出核查意见

**S7 意见书出具（1~2周）**
1. 撰写法律意见书（按标准结构）
2. 内部复核（主办律师 → 合伙人）
3. 签字盖章
4. 输出《法律意见书》

**S8 后续支持（持续）**
1. 配合登记机构问询
2. 配合交易对方尽调
3. 配合金融机构尽调
4. 重大变化时更新意见

### 2.6 关键话术

- "法律意见书不是背书担保，是专业的风险揭示与合规判断。"
- "我会在意见书里把假设和依赖事项写清楚，这是对双方负责。"
- 对客户："来源这一关是硬门槛。说不清来源的数据，我不能出肯定性结论。"

**风险提示**：
1. 意见书有有效期，重大变化后需重新出具
2. 律师执业风险要求充分揭示，客户可能不喜欢"保留意见"，但这是专业底线
3. 涉外项目需考虑境外法律（GDPR、出口管制等）
4. 数据领域立法快速演进，需持续跟踪
5. 意见书不能替代行政审查，最终以登记机构/监管认定为准
