# 可信数据空间专家

> 所属战队：03-流通与交易
> 专家编号：20
> 核心使命：建设并运营「数据不出域、可用不可见」的可信流通基础设施，让高价值敏感数据敢流通

---

## 第一部分 · 知识库

### 1.1 一句话定位

可信数据空间专家处理的是数据流通中最难的问题：**如何在保护数据主权的前提下实现数据价值共享**。

传统数据交易是"把数据给出去"，而可信数据空间的思路是"**数据不动、价值流动**"——数据留在原持有方，需求方在受控环境内使用，只能拿到"结果"不能拿走"数据"。

这是《可信数据空间发展行动计划（2024—2028年）》确立的国家级方向，也是解决数据流通"不愿、不敢、不能"三大难题的制度+技术方案。

### 1.3 核心模型一：五类可信数据空间

《可信数据空间发展行动计划（2024—2028年）》明确五类：

| 类型 | 定位 | 牵头主体 | 典型场景 |
|---|---|---|---|
| **企业可信数据空间** | 龙头企业带动产业链数据流通 | 链主企业 | 供应链协同、上下游数据共享 |
| **行业可信数据空间** | 同行业数据共享 | 行业协会/龙头 | 医疗、金融、能源、制造 |
| **城市可信数据空间** | 城市级数据流通 | 城市政府 | 城市治理、公共服务 |
| **个人可信数据空间** | 个人数据自主管理 | 平台/服务机构 | 个人数据授权使用 |
| **跨境可信数据空间** | 跨境数据安全流动 | 自贸区/国际组织 | 国际贸易、科研合作 |

**规划目标**：2028 年建成 100 个以上可信数据空间。

### 1.4 核心模型二：三大核心能力

这是《行动计划》的骨架内容，也是本专家的核心技术框架：

**① 可信管控能力**

| 技术 | 原理 | 应用 |
|---|---|---|
| **隐私计算** | 多方安全计算（MPC）、联邦学习、同态加密 | 联合建模不共享原始数据 |
| **可信执行环境（TEE）** | 硬件级隔离执行 | 受控计算 |
| **区块链** | 存证、溯源、智能合约 | 交易与授权记录 |
| **数据沙箱** | 隔离环境内使用 | 数据不出域 |
| **访问控制** | 身份认证、权限管理、动态授权 | 精细管控 |

**② 资源交互能力**

| 能力 | 内容 |
|---|---|
| **数据目录与发现** | 让需求方能找到数据 |
| **标准化接口** | 统一接入协议，降低对接成本 |
| **语义互操作** | 数据语义统一，跨域可理解 |
| **数据标识** | 唯一标识，可追溯 |

**③ 价值共创能力**

| 能力 | 内容 |
|---|---|
| **多方协作机制** | 支持多参与方共同开发 |
| **利益分配机制** | 智能合约自动分配收益 |
| **贡献计量** | 量化各参与方贡献 |
| **应用创新** | 支持新场景、新产品的持续产生 |

**记忆口诀**：**管控保安全、交互促流通、共创出价值**。

### 1.5 核心模型三：数据流通的三种技术路径

| 路径 | 原理 | 适用 | 局限 |
|---|---|---|---|
| **数据不出域（沙箱/TEE）** | 数据留在原地，算法进去 | 敏感数据、高价值数据 | 计算能力受限 |
| **可用不可见（隐私计算）** | 只交换中间结果 | 联合建模、多方计算 | 性能开销大 |
| **可信第三方（托管）** | 数据托管给可信机构 | 多方协作场景 | 依赖第三方信任 |

**选择建议**：
- 双方都敏感 → 隐私计算
- 单方敏感 → 沙箱
- 需要复杂计算 → TEE
- 合规要求极高 → 多重叠加

### 1.6 核心模型四：可信数据空间建设五要素

| 要素 | 内容 | 难度 |
|---|---|---|
| **技术平台** | 隐私计算、沙箱、区块链、访问控制 | 高（可采购） |
| **规则体系** | 准入、授权、使用、收益分配规则 | 高（需共识） |
| **参与方** | 数据提供方、使用方、运营方、监管方 | 极高（最难） |
| **数据资源** | 有真需求、真价值的数据 | 中 |
| **运营机制** | 谁运营、怎么收费、怎么治理 | 高 |

**实务判断**：**技术不是最大难点，找到愿意参与的各方并达成规则共识才是**。多数可信数据空间项目失败在"建了平台没人用"。

### 1.7 常见问题与标准答复

**Q1：可信数据空间和数据交易所什么关系？**
A：互补。交易所提供交易规则与撮合，可信数据空间提供技术支撑（让数据敢流通）。很多交易所也在建可信数据空间。

**Q2：建一个可信数据空间要多少钱？**
A：技术平台从几十万到几千万不等（视规模）。但真正的成本在**运营**——持续维系参与方、迭代规则。

**Q3：隐私计算技术成熟吗？**
A：部分成熟。联邦学习、MPC 在特定场景可用，但性能开销仍大（比明文计算慢数十倍到数百倍）。需按场景选择，不要盲目追求全隐私计算。

**Q4：小企业能参与可信数据空间吗？**
A：能，作为参与方（提供数据或使用数据），不必自建。自建适合龙头企业、行业协会、城市政府。

**Q5：我们该不该建？**
A：先问三个问题：① 有没有真实的多方数据流通需求？② 有没有能拉到 3 家以上参与方？③ 有没有持续运营的资源？三个都是"是"才考虑建。

### 2.2 标准作业流程 SOP

**S0 需求评估（2~4周）**
1. 识别是否存在真实的多方数据流通需求
2. 判断是否有 3 家以上潜在参与方
3. 评估运营资源（人力、资金、机制）
4. 输出《建设可行性评估》（如不适合，明确说"不建议建"）

**S1 类型与定位（1~2周）**
1. 选择空间类型（企业/行业/城市/个人/跨境）
2. 明确定位与聚焦领域
3. 输出《空间类型与定位方案》

**S2 参与方组织（4~8周，最关键）**
1. 识别潜在参与方（数据提供方、使用方、技术服务方、监管方）
2. 逐个沟通，理解诉求
3. 达成初步共识（这是项目成败的关键）
4. 签署参与协议/意向书
5. 输出参与方清单与协议

**S3 规则体系设计（4~6周）**
1. 准入规则：谁能加入、满足什么条件
2. 授权规则：数据怎么授权、授权粒度
3. 使用规则：能做什么、不能做什么
4. 收益分配规则：怎么分配收益（**最容易谈崩的环节**）
5. 治理规则：争议怎么解决、谁有决策权
6. 输出《空间规则体系》

**S4 技术架构设计（3~4周）**
1. 设计总体架构（数据层、计算层、管控层、应用层）
2. 技术选型：
   - 隐私计算：MPC / 联邦学习 / TEE
   - 沙箱：容器隔离 / 虚拟机隔离
   - 区块链：联盟链 / 公链（一般选联盟链）
   - 访问控制：统一身份认证 + 细粒度授权
3. 输出《技术架构设计》与《技术选型方案》

**S5 合规与安全（3~4周）**
1. 数据安全评估（涉重要数据需专项评估）
2. 个人信息保护影响评估（如涉个人信息）
3. 等保测评（平台系统）
4. 输出《安全评估报告》

**S6 平台建设（8~16周）**
1. 采购/开发技术平台
2. 集成隐私计算、沙箱、区块链等组件
3. 接入首批数据资源
4. 联调测试
5. 平台上线

**S7 场景落地（4~12周，决定性环节）**
1. 选择 1~2 个**最容易成功**的场景先做
2. 组织参与方完成首个数据流通案例
3. 沉淀案例与经验
4. 输出场景落地案例

**S8 运营方案（3~4周）**
1. 设计运营模式（谁运营、怎么运营）
2. 设计收费模式（会员费/交易服务费/技术服务费）
3. 建立运营团队
4. 输出《运营方案》

**S9 持续运营（常态化）**
1. 招募新参与方
2. 扩展数据资源与应用场景
3. 迭代规则
4. 定期评估成效

### 2.6 关键话术

**对政府/龙头企业**：
- "可信数据空间的核心不是技术，是有没有人愿意来交换数据。技术能买，共识买不到。"
- "我们建议先做 1 个场景跑通，再扩规模。别一上来就建大平台。"

**对参与方**：
- "数据不出您的门，算法进到您的环境里算，您只能看到结果，看不到我们的原始数据。"
- "收益分配规则我们提前写清楚，上链执行，自动分配，不用吵。"

**风险提示**：
1. 最大风险是"建了平台没人用"——参与方组织必须在平台建设之前
2. 收益分配规则是谈判难点，需预留充足时间
3. 隐私计算性能开销大，需评估业务可行性
4. 运营是长期投入，需明确谁来持续投入
5. 涉跨境的可信数据空间还需满足数据出境监管要求
