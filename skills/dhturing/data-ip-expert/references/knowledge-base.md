# 数据知识产权专家

> 所属战队：02-确权与登记
> 专家编号：13
> 核心使命：用知识产权制度保护数据加工成果，并通过存证固化「我确实做过这件事」的时间证据

---

## 第一部分 · 知识库

### 1.1 一句话定位

数据知识产权专家处理的是**数据与知识产权交叉地带**的问题。他的核心工作是两条线：

1. **知识产权线**：数据加工成果能否用著作权、专利、商业秘密保护？怎么保护？
2. **存证线**：如何用技术手段（区块链存证、时间戳）固化数据的存在时间与内容完整性？

这条线看起来"软"，但在数据权属证明、维权、投融资尽调中都极有分量——**没有存证的数据资产，在争议中很难自证**。

### 1.3 核心模型一：数据成果的四种保护路径

| 路径 | 保护什么 | 保护期 | 取得方式 | 数据场景适用性 |
|---|---|---|---|---|
| **著作权** | 具有独创性的数据汇编、数据库 | 作者死后 50 年（法人作品 50 年） | 自动取得（可登记增强） | 数据汇编、可视化、报告 |
| **专利权** | 具有新颖性创造性的算法、模型、系统 | 20 年（发明） | 申请取得 | 数据处理算法、模型架构 |
| **商业秘密** | 不为公众所知、有商业价值、有保密措施的数据 | 无期限（保密状态存续期间） | 自动取得 | 核心数据、客户名单、训练数据 |
| **数据知识产权** | 经实质性加工的数据集合（试点） | 按登记规则 | 登记取得 | 加工后的数据集 |

**选择决策逻辑：**

```
数据成果要不要公开？
├─ 要公开（如对外销售的数据集）→ 著作权 / 数据知识产权登记
│                                  （专利不适合数据集，适合算法）
└─ 不公开（内部核心数据）→ 商业秘密
                          （关键：必须有保密措施）

数据成果是算法/模型吗？
├─ 是 → 评估可专利性 + 商业秘密双轨
└─ 否 → 著作权 + 数据知识产权登记
```

### 1.4 核心模型二：商业秘密三要件

这是数据保护最实用的一条，必须记牢：

| 要件 | 含义 | 数据场景的落地措施 |
|---|---|---|
| **秘密性** | 不为公众所知悉 | 不公开、不发布、访问受限 |
| **价值性** | 具有商业价值 | 能带来竞争优势或收益 |
| **保密性** | 权利人采取了保密措施 | **这是最容易被忽略、也最容易败诉的要件** |

**保密措施清单（缺一不可）：**
1. 制度：保密管理制度、保密协议（员工、合作伙伴）
2. 技术：访问权限控制、加密、水印、审计日志
3. 标识：密级标识、保密提示
4. 物理：机房门禁、设备管控
5. 流程：离职交接、外来人员管理

**实务要点**：很多企业主张商业秘密保护，但拿不出保密措施证据，结果败诉。**保密措施必须留下证据**。

### 1.5 核心模型三：存证体系

存证解决三个问题：**存在性**（某时点已存在）、**完整性**（未被篡改）、**归属**（是谁做的）。

| 存证方式 | 原理 | 效力 | 成本 |
|---|---|---|---|
| **区块链存证** | 哈希上链，时间戳固化 | 司法认可（《在线诉讼规则》） | 低（按次） |
| **可信时间戳** | 国家授时中心时间源 + 哈希 | 司法认可 | 低 |
| **公证存证** | 公证处出具公证书 | 最强证据效力 | 高 |
| **第三方存证平台** | 平台固化 + 出具证明 | 较强（部分司法认可） | 中 |
| **自行存证** | 内部日志、邮件 | 弱（易被质疑） | 极低 |

**存证内容建议：**
- 数据本身：哈希值（不上传原数据，保护隐私）
- 元数据：数据描述、规模、字段、生成时间
- 加工过程：处理步骤、代码、参数
- 归属声明：开发者、权利人

**本库已有实践**：`国数局登记\skillAPI存证证书` —— 这是本库已有的存证产品样例。

### 1.6 核心模型四：数据知识产权登记（试点）

国家知识产权局在多地开展数据知识产权登记试点，特点是：

| 项目 | 内容 |
|---|---|
| 登记对象 | 经实质性加工、具有实用价值的数据集合 |
| 主体 | 数据处理者 |
| 关键要求 | 申请人需对数据有实质性加工投入 |
| 登记效力 | 权利证明（试点阶段效力逐步明确） |
| 与产权登记区别 | 知识产权登记强调"加工创造性"；产权登记强调"权利归属" |

**对比记忆：**

| 维度 | 数据产权登记（专家10） | 数据知识产权登记（本专家） |
|---|---|---|
| 主管 | 数据局/数据交易所 | 知识产权局 |
| 保护对象 | 数据资源 / 产品 | 经加工的数据集合 |
| 理论基础 | 三权分置 | 知识产权 |
| 强调 | 归属与流转 | 加工投入与创造性 |

**建议**：重要数据资产可**两条线都做**——产权登记解决归属与交易，知识产权登记增强保护与维权能力。

### 1.7 常见问题与标准答复

**Q1：数据能申请专利吗？**
A：数据本身不能。但处理数据的**算法、模型、系统**可以申请专利。注意：纯智力活动规则不可专利，需与具体技术手段结合。

**Q2：我们做了数据加工，著作权归我们吗？**
A：如果加工具有独创性（如独特的数据编排、可视化），可能构成汇编作品，著作权归加工者。但要注意：**不能侵犯原始数据权利人的权利**。

**Q3：区块链存证有用吗？**
A：有用，已被司法解释认可。但注意：存证只证明"某时点这个哈希存在"，不证明"内容真实合法"。它是**证据链的一环**，不是万能。

**Q4：数据资产化需要存证吗？**
A：不是法定必需，但强烈建议。理由：① 权属争议时有据可查；② 投融资尽调加分；③ 数据产权登记的技术审查可能需要。

**Q5：商业秘密保护有什么风险？**
A：最大风险是"保密措施举证不能"。第二风险是员工跳槽带走数据。必须签保密与竞业协议、做离职数据审计。

### 2.2 标准作业流程 SOP

**S0 成果梳理（3~5天）**
1. 梳理需保护的数据成果清单
2. 分类：数据集、算法/模型、报告/可视化、核心业务数据
3. 明确保护目标（防抄袭/防泄露/增强融资价值）
4. 输出《数据成果清单》

**S1 保护路径选择（1周）**
1. 按决策逻辑（是否公开/是否算法）选择路径
2. 可多路径叠加
3. 输出《数据成果保护方案》

**S2 商业秘密体系（1~2周，如选择）**
1. 制定保密管理制度
2. 设计技术措施（权限、加密、水印、审计）
3. 签署保密协议（员工/合作方）
4. 建立密级标识
5. 留存措施证据（这是关键）
6. 输出《商业秘密保护方案》与实施证据

**S3 著作权登记（1~2周，如选择）**
1. 判断独创性与作品类型（汇编作品/数据库）
2. 准备登记材料（作品说明书、样本）
3. 提交中国版权保护中心或地方版权局
4. 取得著作权登记证书

**S4 专利申报（2~6周，如选择）**
1. 技术挖掘：识别可专利的算法、模型、系统
2. 专利检索（查新颖性）
3. 撰写技术交底书
4. 委托专利代理机构撰写申请文件
5. 提交 CNIPA
6. 跟踪审查（可长达 1~3 年）
7. 输出专利申请文件与受理通知

**S5 数据知识产权登记（2~4周，如选择）**
1. 确认当地是否有试点（浙江/北京/上海等）
2. 准备材料：数据集合说明、加工投入证明、样本
3. 提交登记
4. 取得登记证明

**S6 存证方案设计与实施（1~2周）**
1. 确定存证对象与频率
2. 选择存证方式（区块链/时间戳/公证）
3. 建立存证流程（生成→哈希→上链→归档）
4. 执行首次存证，形成基线
5. 建立定期存证机制
6. 输出《数据存证方案》与存证证书

**S7 维权准备（持续）**
1. 建立侵权监测机制
2. 收集侵权证据
3. 出具侵权分析
4. 准备维权路径（发函/诉讼/行政投诉）

**S8 协议条款设计（按需）**
1. 数据合作协议中的知识产权条款
2. 员工保密与竞业条款
3. 数据采购合同中的权利条款
4. 输出合同条款模板

### 2.6 关键话术

- "数据不能申请专利，但处理数据的算法可以。"
- "商业秘密保护的关键不是『我说这是秘密』，而是『我确实采取了保密措施，并且有证据』。"
- "存证很便宜，但争议的时候能救命。建议核心数据都做基线存证。"
- "产权登记和知识产权登记不冲突，重要的数据两条线都走，保护更完整。"

**风险提示**：
1. 商业秘密最常见败诉原因是保密措施举证不能
2. 著作权保护不覆盖"事实性数据"（如纯客观统计数据可能无独创性）
3. 专利审查周期长（1~3 年），不适合需要快速保护的场景
4. 数据知识产权登记仍处试点阶段，效力待明确
5. 区块链存证只证明存在性，不证明合法性与真实性
