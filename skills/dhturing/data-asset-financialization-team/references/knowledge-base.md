## 一、团队定位与共同擅长

**共同擅长**：把数据资产变成银行授信、资产证券化产品、信托与保险架构，并用财税口径守住合规与成本底线。

**团队心智模型**：金融化有两条路线、一个底座——
```
             ┌── 质押融资（28，主理人）──── 银行授信
数据资产 ────┤
（已入表）   └── ABS/证券化（29 + 45）──── 资本市场
                    ↑ 增信：信托（43/31）+ 保险（44）
   财税底座（32）：会计处理 / 摊销减值 / 税务测算 ── 贯穿全部路线
```
**先问现金流，再选路径**：没有稳定现金流的资产做不了 ABS，但可能做质押融资；有现金流但权属不清的，先回确权团。

## 三、分阶段 SOP 与预设 Workflow

**SOP 五阶段**：
- **Phase 1 资产与现金流诊断（闸门）**：入表状态、权属清晰度、现金流稳定性与可归集性。
- **Phase 2 路径选择**：质押融资 / ABS / 信托 / 保险（或组合）。
- **Phase 3 结构设计与测算**：交易结构、现金流模型、增信组合、税务测算并行。
- **Phase 4 对接与申报**：金融机构对接、中介组织、申报问询。
- **Phase 5 最终报告**：融资方案 + 结构文件 + 测算报告 + 税务口径 + 放款/发行凭证。

**三个预设 Workflow**：
- **Workflow A 融资路径决策**（最高频）：并行（资产评估 + 现金流判断）→ 串行（ABS 五条件 或 质押方案）→ 并行（税务 + 增信）→ 主理人汇编。
- **Workflow B ABS 全流程**：并行（适格性 + 现金流模型）→ 串行（SPV/增信 → 保险评估 → 税务）→ 主理人汇编申报材料包。
- **Workflow C 信托与保险增信方案**：并行（信托方案 + 险种组合）→ 串行（结构取舍 → 税务测算）→ 主理人汇编。

### 4.3 关键判断规则

- **ABS 五个硬条件**【29】：稳定现金流 / 可归集 / 权属清晰可转让 / 持续性 / 规模足够。
- **现金流可归集性四问**【45】：可计量 / 可持续 / 可归因 / 可验证。
- **增信组合**【29】：内部（优先劣后分层、超额抵押、超额覆盖）+ 外部（差额支付承诺、第三方担保）——数据资产通常需双重增信。
- **信托三模式**【43】：自益（隔离）/ 他益（传承）/ 财产权信托（ABS 载体）；**信托标的必须是数据资产的权利（持有权/经营权/收益权），不是数据本体**。
- **四类保险**【44】：网络安全保险（市场较成熟）/ 数据资产损失保险（新险种）/ 职业责任险 E&O / 知识产权侵权险。

## 六、质量校验清单

- [ ] 增信为双重（内部 + 外部），增信成本已计入融资成本
- [ ] 信托方案明确标的为权利而非数据本体
- [ ] 信托期限与产权登记有效期（≤5 年）已衔接
- [ ] 税务测算覆盖设立与存续环节（视同销售风险已提示）
- [ ] 摊销与减值政策有依据，减值测试安排到每年年末
- [ ] 已如实告知客户：数据资产 ABS 市场案例极少、监管口径仍在明确
- [ ] 未承诺必然授信、必然发行成功、必然通过审查

## 七、风险提示与话术边界

1. **入表 ≠ 能融资**——银行看资产质量与现金流，不看账面数字；必须管理客户预期。
2. **无稳定现金流不做 ABS**——最常见也最昂贵的误判；这类客户应引导走质押融资。
3. **数据资产 ABS 市场案例极少**——属前沿探索，监管口径仍在明确，必须如实告知。
4. **数据资产流动性差**——需较强增信（通常双重），增信成本要计入融资总成本。
5. **信托设立可能视同销售**——产生所得税，必须提前测算（与 32 交叉）。
6. **多数信托公司没有数据资产信托经验**——对接周期长，需耐心沟通。
7. **保险除外责任**——很多数据泄露场景会被除外，条款审查必须逐条做。
8. **存续期风险**——数据资产价值衰减可能触发风险事件，需存续期管理机制。
9. **话术**："入表不等于能融资。银行看的是资产质量与现金流，不是账面数字。"
10. **不越界**：评级报告、法律意见书、审计报告由持牌机构出具；本团不做放款承诺。
