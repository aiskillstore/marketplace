# manuscript 모드 — 완성 원고를 책으로

입력이 이미 쓰인 원고(md/txt/docx)일 때의 절차. 글은 이미 완성됐다고 가정한다 — 이 모드는 내용을 다시 쓰지 않고 구조화·조판만 한다.

## 1. 인제스트

- **md/txt**: 그대로 사용. 여러 파일이면 사용자가 준 순서(파일명 순)를 유지한다.
- **docx**:

```bash
python3 <SKILL>/scripts/ingest_docx.py <원고.docx> <book_dir>
```

Heading 1을 장 경계로 분할해 chapters/와 outline.json 초안을 만든다. python-docx가 없으면 `pip install python-docx` 후 재시도.
- **hwp**: 미지원. 사용자에게 docx/md 변환을 요청한다.

## 2. 정규화

원고를 SKILL.md 콘텐츠 계약 문법으로 맞춘다. 내용은 보존하고 표기만 바꾼다:

- 장 경계: H1이 없으면 장 제목 후보(번호 붙은 대제목, 부/장 표기)를 찾아 `# `로 승격. 한 파일 = 한 장.
- 허용 밖 문법 치환: HTML 태그 제거, 각주는 본문 괄호 병기로, 수평선 제거, 이모지 제거
- 팁·주의·요약 성격의 단락은 ::: tip / ::: warn 콜아웃으로 승격하면 지면이 살아난다 (의미가 확실한 경우만)
- 원고 속 이미지 참조는 실제 파일을 `assets/`에 넣고 경로를 맞춘다. 파일이 없으면 해당 참조를 제거하고 사용자에게 보고.

## 3. outline 보강

- 각 장의 `summary`(도비라 1~2문장)를 원고 내용에서 **추출**해 채운다 — 새로 창작하지 않고 그 장의 핵심 주장을 압축한다.
- 장 수가 2개 이하이거나 한 장이 전체의 60%를 넘으면, 절(##) 경계에서 장을 재분할할지 사용자 의도를 원고 구조에서 판단한다(명백할 때만 분할).

## 4. 분량 정합

원고 총량으로 length를 정한다(사용자 미지정 시): 본문 2.5만 자 미만 = short, 2.5만~8만 = standard, 초과 = long. `book.json`의 length를 실제에 맞게 수정한다 — 게이트 G1이 이 값으로 판정한다.

완료 기준: SKILL.md P1 완료 기준과 동일 + 원고 원문의 문장이 임의로 바뀌지 않았을 것(정규화 diff는 표기 변화만 포함).
