# pagination.md — bookforge 배치(페이지 분할) 규칙서

> 근거: 4관점 조사(전통조판·알고리즘 실측·한국 상업본 PyMuPDF 실측 287유닛·매거진/리포트) + 교차 비판 토론 3라운드의 합의문.
> 표기: [실측]=엔진·상업본에서 측정 확인, [문헌]=공식 문서·실무 문헌, [통념]=근거 약함(보수 운용).
> 핵심 전제: **완성된 글을 잘 나눈다. 채우거나 비우면 이유가 있어야 하고, 그 이유는 기계가 판정한다.**

## 0. 불변식

- **INV-1 목표 쪽수는 조판의 입력이 아니다.** 분량 프리셋(`length_pages`)은 원고 단계에서 총 행수(∑S)로 판정하고, 조판 산출물 쪽수는 **기본 WARN**(qc_gate G1 — 하드 FAIL은 `--strict-pages` 명시 opt-in에서만). 쪽수를 맞추려는 강제 개면·기계 부록·채움 요소는 전부 금지.
- **INV-2 기본값은 꽉 참(flushbottom).** 판면 격자 행수 N에 대해 일반 본문 면은 N행. 미달 면은 사유가 있어야 한다.
- **INV-3 비움은 이름을 가진다.** 미달 면은 ①구조 파생 면제 ②`pageroles.json` 사유 코드 중 하나로만 정당화된다. 둘 다 아니면 FAIL.
- **INV-4 본문 행송은 상수다.** 페이지 단위 행송 조정(feathering) 금지. 세로 여유는 탄성 슬롯(표제 전후·블록 간격)과 문단 단위 미세조정으로만 흡수.
- **INV-5 엔진은 콘텐츠를 생성하지 않는다.** 본문에 없는 인용·수치·캡션·부록을 만들면 HARD FAIL(G10).

## 1. 파이프라인 — 어느 단계에서 무엇을 결정하는가

```
P0 분량 계획   [PLAN 모드만] 절별 목표 행수 = f(면 용량 C, 흡수용량 산식 §5) → 집필 브리프에 기재
               ∑S 대 length preset 판정 (쪽수의 수명은 여기서 끝. 이후 단계로 전달 금지)
P1 계량        C = 마스터별 p90 행수(상수), S = 절의 조판 후 행수 → q = S/C
P2 구조 수술   [PLAN만] q밴드(§8)로 절 병합/분할 확정 — 아직 면 배정 없음(고스트 덱)
P3 리듬 슬롯   전면 이미지는 4슬롯(오프너·서사 전환 H2·연속텍스트 해소·클로저)에만 (magazine/insight/business)
P4 초벌 조판   H1만 개면, H2는 조건부(§3). 레버 전부 기준값
P5 측정        analyze(pdf): 판면 역산·가구 제거 → 면별 reach/ink/lines/gap/imgarea (§7 전처리)
P6 레버 적용   실패 장만 L0→L6 격자 재조판(전수 탐색 후 최소개입 해 선택). 해 없음 → 모드별 분기(§2)
P7 잔여 받치기 면별 잔여 r → 받치기 표(§6)로 요소 라우팅. 재료 실재 검사(G10) 통과분만
P8 게이트      G7~G12 판정 (§7)
P9 되감기      실패 시 P7→P6→P3→(PLAN만)P2 역순. REFIT은 P3에서 멈추고 사람 승인 요청
```

## 2. 모드 이원화 — 재집필 최소주의의 명문화

| | **REFIT** (기존 원고 재배치 / manuscript 모드) | **PLAN** (신규 생산 / topic 모드) |
|---|---|---|
| 분량 결정 | 없음 — 원고 고정 | P0~P2: 절별 목표 행수·q 계량·구조 수술 |
| 허용 조치 | 레버 L0~L6 / 요소 위치 이동 / 문단 1~2개 증감 힌트 / 사유 코드 | 왼쪽 전부 + 절 병합·분할 |
| 금지 | 절 병합·분할, 신규 부록·용어집, 날조 인용·수치, H2 강제 개면 | 날조 인용·수치, H2 강제 개면 |
| 쪽수 프리셋 | 조판 산출물엔 WARN만 | 원고 단계 ∑S로 판정 |
| 흡수용량(§5) 초과 시 | 국소 증감 힌트(대상 문단 ID + ±1줄) → 실패 시 사유 코드 승인 요청 | 원고 반환(분량 재설계) |

## 3. 블록 결속과 개면

**개면**: H1(장)만 `pagebreak`. H2(절)는 앞 면 이어붙임이 기본 — 앞 면 잔여가 `절 제목 + 본문 6줄`을 못 담을 때만 새 면. 새 면으로 갔는데 그 절의 q < 0.55면 결정 철회 후 직전 절과 병합 재판정. 분량 보정 목적의 동적 개면은 어떤 레벨에서도 금지. [문헌+만장일치]

**결속(keep) 계약** — 엔진 실측 기준 [실측]:

| 블록 | 규칙 | Typst | Chromium |
|---|---|---|---|
| 고아/과부 | 문단 앞뒤 최소 **2행** (3행 보장은 양 엔진 모두 불가) | `text(costs:)` 기본이 2행 — **명시 선언으로 계약 고정** | `p,li { orphans:2; widows:2 }` 기본. 3은 꼬리 개선·중간면 하락 트레이드오프 — refit 탐색 후보로만 |
| 제목+본문 | 제목은 뒤 본문 2행과 결속 | heading 기본 sticky(해제 불가) | `h1,h2,h3 { break-after: avoid }` |
| 그림+캡션 | 분리 금지(원자) | 캡션 블록 `block(sticky:true)` 또는 breakable:false 묶음 | `figure { break-inside: avoid }` |
| 표 | **쪽넘김 허용 + 헤더 행 매 쪽 반복**(`table.header`). 판면보다 긴 표를 `breakable:false` 블록에 넣으면 Typst는 넘친 행을 쪽 하단 한 줄에 **0높이로 겹쳐 찍는다** — 넘침이 아니라 데이터가 뭉개진 채 G2·G4류 텍스트 게이트를 통과하는 파괴 모드다(issue #7 [실측], G3-COLLIDE가 검출). | `bf-tbl` 계열 전부 `breakable: true` + md2typ `table.header` | `table { break-inside: avoid }`는 **힌트라 안전** — 한 면을 넘는 표는 브라우저가 무시하고 쪼개며 `<thead>`가 반복된다 |
| 인용·박스·코드 | 1면의 0.7 이하일 때만 통짜 | `block(breakable: false)` | `blockquote, pre { break-inside: avoid }` |
| 본문 문단 | 통짜 금지 | — | **`p`에 break-inside:avoid 절대 금지**(채움 붕괴 1.0→0.7) |

## 4. 장 끝 면(꼬리) 규칙

**판정 밴드** (`reach` = 판면 내 콘텐츠 최하단 도달률, §7):

| 층위 | 값 | 판정 |
|---|---|---|
| 행수 하한 (전 스타일) | `lines < 6` | HARD FAIL — 사유 코드로도 구제 불가 |
| reach HARD 하한 | practical/insight/academic/business **0.45** / essay/magazine **0.35** | FAIL |
| reach WARN 하한 | practical/insight/academic **0.70** / business **0.65** / essay **0.55** / magazine **0.50** | 사유 코드 없으면 FAIL. **essay/magazine/insight는 리포트만**(해당 유형 상용 꼬리 실측 표본 0 — §9 부채. HARD 하한은 그대로 강제) |
| 문서 통계 | practical/insight/academic만: 꼬리 reach 중앙값 ≥ 0.80, p10 ≥ 0.55 | FAIL → 원고 분량 설계 반환 |
| 장 중간 면 | reach < 0.75 HARD / 0.75~0.90(essay 0.88 · insight 0.85 — 130mm 통짜 블록+H2 24mm 이월 물리 [보정]) 사유 코드 필수 | |

근거 [실측]: 상업본 287유닛 중 채움률 0.31 미만 0건, 실용서 p10=0.735. "3~4줄 면"(0.12~0.17)은 상업 단행본에 존재하지 않는 상태다. 에세이는 실측 표본 0 → 비율 임계를 HARD로 쓰지 않는다.

**꼬리 미달 시 대응 순서** — 먼저 흡수예산 판정: `꼬리 행수 ≤ 0.022 × 장 본문 행수`일 때만 당겨오기가 물리적으로 가능하다 [실측: 두 엔진 독립 재현]. ① 예산 안이면 당겨오기(pull-up)로 꼬리 면을 흡수·제거 ② 예산 밖(대략 꼬리 4행 초과)이면 **당겨오기를 시도하지 말고** 밀어내기(push-down)로 6행/하한 이상 확보 ③ 요소 이동(최초 언급 면 ±1) ④ 원고 국소 증감 힌트 ⑤ 전부 실패 → `CH_CLOSE_APPROVED`(사람 승인 필수, 자동 통과 금지).

## 5. 레버 사다리 — 행 흡수의 우선순위와 허용치

적용 전 **흡수용량 산식**부터: `흡수 가능 행수 ≈ 대상 본문 행수 × 0.023` [실측: 행당 회수폭 = 48×Δ자간 + 9×어간×Δ어간비 ≈ 행 길이의 2.3%]. 필요 흡수량이 이걸 넘으면 레버를 시도하지 말고 원고 쪽으로 분기(§2). 4행을 없애려면 앞선 본문 ~170행(7면)이 필요하다 — 장 끝 여백은 대부분 조판이 아니라 분량 설계 문제다.

`typst` = practical/academic/essay/business, `css` = insight/magazine.

**엔진 실측이 확정한 사실 [실측]**: ① 자간(tracking)과 어간(spacing)은 엔진 입장에서 **같은 레버**다 — 페이지별 행수 배열까지 완전 등가(`tracking -0.015em ≡ spacing 80%`, Chromium `letter-spacing -0.035em ≡ word-spacing -0.05em`). 우선순위는 효과가 아니라 시각 비용으로만 갈린다. ② **행간·문단 간격은 미세 레버가 아니라 계단 스위치**다 — 계단을 안 넘으면 조판이 1비트도 안 변하고(leading −3.7% 스윕에도 전 페이지 동일), 넘으면 면 용량 ±1행·판면 깊이 +4.8mm가 튄다. "장 내부만 미세 조정" 절충은 물리적으로 성립하지 않는다. ③ 총행수를 바꾸는 레버는 자간/어간/폰트크기/판면폭뿐이며 앞 둘만 허용된다.

| 단 | 레버 | 허용치 | 단위 | 엔진 |
|---|---|---|---|---|
| L0 | 줄바꿈 재계산 | 무제한(비용 0) | 문단 | 양쪽 |
| L1 | 어간 이동 — Typst `text(spacing:)` (기준폭 평행이동. H&J 3값 지정은 엔진에 없음) | **[80%, 125%]** | 문단 | typst |
| L2 | 자간 — Typst `text(tracking:)` / CSS `letter-spacing` 또는 `word-spacing`(**둘 중 하나만**) | 기본 ±15/1000em, **하드캡 = 폰트 산출**(아래) | 문단 | 양쪽 |
| L3 | 탄성 슬롯 — 표제 전후 공백 | 그리드 ±1, 면당 총 ≤2그리드 | 면 | 양쪽 |
| L4 | 요소 이동 | 도판·풀퀘트를 인접 면으로(최초 언급 면 ±1) | 면 | 양쪽 |
| L5 | orphans/widows 2→3 (CSS 한정) | 꼬리 개선·중간면 하락 트레이드오프 — 탐색 후보 | 요소 | css |
| L6 | 원고 국소 개입 | REFIT 문단 ±1~2개 힌트 / PLAN 재집필 | 절 | — |
| ✕ | **행간(leading/line-height)·문단 간격(par spacing) 미세조정** — refit 탐색 축에서 폐기. 책 단위 1회 캘리브레이션 상수로만 | [실측: 계단·비단조·총행수 불변] | | |
| ✕ | 장평(Typst `text(stretch:)`는 no-op) · 판면 행수·여백(1~2mm 무효) · 폰트 크기 · feathering·`block(spacing:1fr)` 본문 적용 · 빈 줄 삽입 채움 | **전면 금지** | | |

**자간 하드캡은 상수가 아니라 폰트에서 산출한다** [실측]: `cap = −(min(좌 사이드베어링)+min(우 사이드베어링)) + 5/1000em`, 테마가 이미 소비한 letter-spacing을 뺀 잔여로 관리. Noto Serif KR = **−20/1000em**(−25는 잉크 겹침 발생 지점 — 상한이 아니라 사고 지점), Pretendard-Light = −35(insight 테마가 −20을 이미 쓰므로 추가 −15까지). 산출값은 스타일 계약 파일에 기록.

탐색 방법 [실측]: 그리디 조정은 비단조라 실패한다. 실패 장만 **자간/어간 단일 축 ±2% 격자 전수 탐색 + 기준값 대비 편차 최소 해 선택**(typst 0.07s/컴파일, chromium 0.7s/회). 동시 적용 제약: 한 문단에 L1·L2 동시 금지 / 한 면에 자간값 다른 문단 3개 이상 금지 / 한 장 조정 문단 ≤15%. **위계 불변식**: `자간 이송 < 어간 최소 < 행송` — 깨지면 즉시 롤백.

근거 [실측]: 상업본에서 행송은 145면 중 138면 소수점까지 동일(레버 아님), 자간 페이지별 IQR 0(문서 상수), 실제 신축 축은 어간뿐(71~125%) — 그리고 Typst의 justify 어간 신축 대역(82~128%)이 이 상업본 대역과 일치함을 확인. Chromium justify는 **확대만** 한다(100~164%) — HTML 트랙의 어간 축소는 `word-spacing` 음수로만. klreq 4.4.2(당겨오기=낱말 사이 공백 축소)·InDesign 조정 순서와 일치. klreq 4.3.7 금칙 구간(연속 숫자·리더·괄호 앞뒤·구두점 앞뒤)에는 확대 미적용.

## 6. 잔여 받치기 — 뽑는 요소의 정당한 사용

잔여 `r = 1 − D(면 밀도)`. 두 축: r의 크기 × **재료의 본문 실재 여부**(없으면 그 등급은 건너뜀 — 날조 금지).

| r | 조치 | 재료 조건 |
|---|---|---|
| < 0.08 | 아무것도 안 함(여백 유지) | — |
| 0.08–0.18 | 키 스탯 1개 | 절 안에 숫자가 실재 |
| 0.18–0.35 | 풀퀘트 | 인용 가능한 완결 문장 실재 |
| 0.35–0.55 | 사이드바 박스/체크리스트 | 절차·목록·정의 실재 |
| 0.55–0.75 | 시각 요소 승격(도표) | 도식화 가능한 관계 실재 |
| > 0.75 | 요소 추가 금지 → 구조 수술(§2 모드별) | — |

풀퀘트 규율 [문헌]: 한국어 본문 700~1000자당 1개, 절당 ≤2. 원문과 **같은 면**에, 원문 문장과 5줄 이상 이격. 면 정중앙 금지. 전면 이미지는 4슬롯(§1 P3) 밖 삽입 금지, 챕터당 ≤2면·전체 8% 이하.

## 7. 밀도 게이트 — "이유 없는 비움"의 기계 판정

**전처리(공통 1회)**: ① 판면 = tokens.json `body_frame_mm` 정본(테마 값 전사) ② **가구 제거**: 드로잉 rect·이미지 xref 지문이 60% 이상 면에 반복 출현하면 전역 제외(칼럼 가이드·배경) ③ 콘텐츠 = 판면에 **x·y 모두** 걸치는 텍스트 행·이미지·비가구 드로잉 ④ `pitch`=책 전역 행송 중앙값, `N=round(판면높이/pitch)` ⑤ 면별 지표: `reach`(콘텐츠 최하단 도달률), `ink`(행을 pitch 슬롯으로 확장한 합집합 점유율), `gap = reach − ink`(**공기 채움 탐지**), `lines`, `imgarea`.

**구조 파생 면제(선언 불필요)**: 첫 장 이전 전부(표지·목차·판권) / 북마크 장 도비라 / 전면 도판(`imgarea ≥ 0.60`) / float 밀림 면(다음 면 첫 블록 > 이 면 잔여) / 마지막 본문 면.

| 게이트 | 조건 | 판정 |
|---|---|---|
| G1-RENDER | draft/book.pdf 실재 + 판형=tokens `trim_mm` ±0.5mm. 쪽수 범위는 WARN(INV-1, `--strict-pages`만 HARD) | 부재·판형 불일치 HARD |
| G1-SCALE | 본문 최빈 pt(글자 수 가중) = tokens `body_pt` ±0.3pt. **다른 모든 밀도·급수 게이트는 문서 자신을 기준으로 하는 상대 지표라 전역 축소를 원리적으로 못 본다** — Chromium print가 판면 초과 요소를 만나면 문서 전체를 shrink-to-fit으로 줄이고, 그 산출물은 G1(판형만 검사)·G7-FRAME(실측 드리프트 2.7pt < 6pt 임계)·G8·G9를 전부 통과한다(실측: 출하된 예제 1권이 0.804배 축소 상태로 15게이트 통과). `body_pt` 미선언 스타일 팩은 WARN(중단 지점 불변) | HARD — 뮤테이션 스위트 M7로 감도 고정 |
| G2-FONTS | 전 폰트 완전 임베드 + **Type3 글리프 0**. 실측된 Type3 유입 경로는 두 갈래다: ① CFF(.otf) @font-face — Chromium print-to-PDF가 서브셋에 실패해 글리프를 페이지별 벡터로 폴백(→ TTF 교체, `convert_fonts.py`) ② `<img src=*.svg>` 안의 `<text>` — SVG-as-image 모드는 문서 @font-face를 차단해 폴백 폰트로 렌더(→ SVG 인라인 또는 래스터 참조. magazine `$tocmap`이 도해 SVG를 썸네일로 참조하던 경로가 이것) | HARD |
| G3-OVERFLOW | 텍스트·이미지 bbox가 재단 밖(tol 1.5pt) | HARD |
| G3-COLLIDE | **같은 면의 텍스트 라인끼리 교차** — `oy > minH × 0.35` ∧ `ox > 1.5pt`. 임계는 `fo2text.mjs:108`·`:202`의 SVG 라벨 겹침 판정(원본 단위 CSS px, `ox > 2px` → ×0.75 = 1.5pt / `oy`는 비율이라 단위 불변)을 지면으로 이식한 것이다. 세로 박스는 PyMuPDF의 line bbox(=폰트 선언 bbox, 서체에 따라 1.44em까지 부푼다)가 아니라 **베이스라인 기준 [-0.85em, +0.20em] 정규화 박스**를 쓴다 — raw bbox로 재면 임계가 서체 메트릭에 좌우돼 붙지도 않은 인용 2행이 FAIL한다(실측). **다단 스타일은 컬럼 x-밴드로 라인을 먼저 분류하고 같은 밴드 안에서만 비교**한다(magazine `column-count:2`·단간 8mm. 좌우 단은 y가 100% 겹치므로 밴드 없이는 `ox` 임계가 유일한 방어선이다). 밴드 경계는 판면과 단간에서 결정론 도출. **회전 라인**(`line["dir"] != (1,0)`)은 정규화를 쓰지 않고 raw bbox로 판정한다 — 회전 라인의 span origin은 회전 전 기준점이라 세로 정규화가 좌표째 붕괴하고(실측: raw 101.8pt → 정규화 2.8pt), 90°/270° 라벨이 본문 행을 관통해도 교차 0건이 됐다. 면제는 새 집합을 만들지 않고 `imgarea|vecarea ≥ 0.60`(전면 도판)과 `OVERLAP_APPROVED`만 재사용하며, **도비라·앞부속은 어떤 경우에도 면제하지 않는다**(`collide_exempt_pages()` — 목차 넘침 → 도비라 겹침 사고의 발생 지점이자 착지 지점. 앞부속 차감은 `fullbleed` 자동 면제에도 걸린다: 표지는 imgarea 1.0으로 fullbleed에 자동 편입되면서 **G14-C가 원리적으로 스캔하지 않는 유일한 면**이라, 차감하지 않으면 표지 제목 위 겹침이 사람 판단 0·사유 코드 0으로 통과한다) | HARD — 뮤테이션 스위트 M9(도비라)·M9b(본문 면+승인)·M9c(면제 차감 불변식)로 감도 고정 |
| ↳ **검출 하한(명시)** | 이 축이 잡는 것은 "교차 전량"이 아니다. 정규화 박스 높이 `1.05em`과 임계 `0.35 × minH`의 조합이 만드는 산술 하한은 **베이스라인 간격 `0.6825em`**이다 — 같은 급수 두 행이 그보다 벌어져 있으면, 한글 실잉크 대역(≈1.0em)이 실제로 겹쳐도 검출되지 않는다. 즉 **`[0.68em, 1.0em)`는 미검출 대역**이다(실측 스윕 20pt·NotoSerifKR: 0.70em에서 실잉크 949px·게이트 0건 / 0.95em에서 11px·0건). 현행 6스타일의 **본문** 행송은 1.61~1.84em이라 이 대역 밖이고, 의도적으로 조인 디스플레이 행송(magazine `.coverline` 0.92)만 대역에 들어가되 그 교집합은 미미하다. **본문 행송을 0.95em 이하로 잡는 스타일을 새로 만들면 이 축은 그 스타일에서 무력하다** — 상수를 키우면 폰트 선언 bbox(1.44em) 계열 오탐이 즉시 돌아오므로 상수 대신 하한을 명시한다 | 운영 주의 — 게이트 아님 |
| G3-FIT | **앞부속(`range(1, first_ch)`) 텍스트가 선언 프레임 안**. 표지·목차면은 `body_frame_mm`이 아니라 자체 padding·절대배치를 쓰므로 body_frame을 들이대면 전량 FAIL한다 — tokens `front_frame_mm`(리스트 = 앞부속 공통 / 객체 = `cover`는 1면·`toc`는 나머지)이 선언된 스타일에서만 프레임 축을 돌리고, **미선언 스타일은 WARN + 생략**(오탐 0이 합격선). `pagemetrics.analyze`가 이미 드는 면별 프레임과 같은 계열이고 라인은 G3 루프가 모은 것을 재사용하므로 이중 계산이 없다. **양성 조건은 선언 유무와 무관하게 항상 돈다**: 앞부속 면은 `lines ≥ 1` 또는 선언된 역할이 있어야 한다(빈 면이 구조 파생 면제에 삼켜져 전 게이트를 통과하는 구멍). **선언값 자체의 타당성은 G16-SYNC가 렌더 전에 판정한다**(4원소 수치·비음수·프레임<판형·객체형 두 키 필수 — 전부 HARD). 여기서는 그 선언이 이 책에서 실제로 작동했는지만 본다: 선언은 있는데 검사한 면이 0개거나 프레임 면적이 지면의 95% 이상이면 WARN. 검사가 없던 동안 선언값 위조 5종이 참양성 4건을 전부 0건으로 만들었고 **위조가 미선언보다 조용했다**(미선언은 `declared:false` + WARN, 위조는 `declared:true` + WARN 0) | HARD — 뮤테이션 스위트 M11로 감도 고정 |
| ↳ **남는 한계(W4 재판정 R-1, 운영 주의)** | G16-SYNC의 HARD는 물리적 모순만 잡고 WARN은 "프레임 면적 ≥ 95%"만 잡는다. **그 사이가 비어 있다** — 4원소 중 단 하나(예: `toc` 하단 여백)만 조용히 부풀리면 프레임 면적이 그보다 훨씬 낮은 지점(실측: `base-base-mag8`에서 프레임 면적 **77.0%**)에서도 참양성 4건이 FAIL 0·WARN 0으로 전부 사라진다. 95% 문턱은 "선언 자체가 지면 전체나 다름없는" 극단만 잡을 뿐, 이런 **그럴듯한 값으로의 단일 변 조작**은 신호를 전혀 남기지 않는다. 닫으려면 CSS `padding` 실측과의 대조(스타일 팩 CI)가 필요하며 이번 사이클 범위 밖이다 — 운영자는 `front_frame_mm` 변경을 "타당성이 기계로 완전히 검증된다"고 믿지 말 것 | 미해결 — 다음 사이클 |
| G16-LINT | **`contrast_contract` ↔ 실물 대조**(`tests/lint_contrast.py`, html 엔진 한정). `typeset/book-final.html`의 실 텍스트 노드에서 유효 fg/bg/pt/bold를 계산해 계약과 양방향 diff한다. 세 축: ①완전성(CSS↔계약 누락·표기 드리프트) ②pt 정합(계약이 신고한 급수가 theme.css에 실재하는가) ③값 커버리지(theme.css의 모든 `color:`/`background:` 리터럴이 어떤 엔트리엔가 등장하는가). **입력이 렌더 산출물이라 렌더 전 게이트가 될 수 없어** G16-TOKENS(build.py)가 아니라 여기 있다. `book-final.html` 부재(typst 4종)는 명시 skip. **린터 자체가 `SystemExit`을 포함해 죽어도 게이트를 죽이지 않는다** — `g16_lint_check`가 `(Exception, SystemExit)`을 잡아 WARN으로 강등하고(`KeyboardInterrupt`만 예외로 전파), `qc_gate.py:main()`은 진입 시 낡은 `gate-report.json`을 먼저 지우므로 이 경로로 죽어도 디스크에 "직전 실행의 낡은 PASS"가 남지 않는다(W4 재판정 E1 수리) | ②③과 유령 엔트리(GHOST)·계약 부재·stamp 상수 모순은 **HARD**(전부 CSS·파일만으로 증명된다), ①완전성은 **WARN** — 그 축은 이 책의 원고가 그 요소를 밟았는지에 의존하므로 강제력은 전 요소를 밟는 스모크 북에서만 성립한다(extending.md 검증 루프). 뮤테이션 M14로 배선 고정 |
| G4-TOC | PDF 북마크 ↔ 장 시작 면 정합(HTML 트랙은 스탬핑 후 대조). **레벨 2 축 2개**: ㉠수 대조 — 절 북마크 수 == 빌더가 발행한 절 마커 수(`typeset/tocplan.json` `section_markers`). `toc_levels: 1` 스타일은 기대값 0이므로 같은 검사로 "발행하지 않았음"까지 확인된다. ㉡**대상 면 대조** — 각 절 북마크가 가리키는 면에 그 절 제목이 실재하는가(레벨 1엔 원래 있던 대조가 레벨 2엔 없었다). ㉠만으로는 기대값과 실측이 같은 리스트에서 나오는 항등식이라 마커 오배정을 원리적으로 못 본다. html 엔진인데 `tocplan.json`이 없으면 그 자체가 FAIL(구 구현은 WARN 강등이라 HARD 축이 통째로 꺼졌다) | HARD |

**목차 면 회수는 축마다 하지 않는다.** `tocgate.run`이 `find_toc_pages`를 한 번 돌려 A·B·D가 같은 면 집합을 본다. 앞부속 범위(`first_ch` 전달) 안에서는 **장제목 과반 규칙을 쓰지 않는다** — 다면 목차는 면당 장 수가 `24/(1+절수)`로 떨어져 과반이 원리적으로 불가하고(14장×10절이면 면당 2개, need 7), 그 규칙 때문에 A가 "목차 면을 찾지 못함"으로 오탐하고 B·D는 침묵으로 통과했다. 도비라가 범위 밖이므로 "장제목 1개 이상 또는 쪽번호 칼럼(순수 숫자 스팬 3개 이상)"으로 시작 면을 잡고 연속 구간을 확장한다. 목차 면을 못 찾았는데 A가 아무 문제도 내지 않는 조합은 `run()`이 게이트 결함으로 FAIL시킨다.

**순서(qc_gate.py 실물)**: G10 → G0 → G15-PARA(렌더 전) → **G16-LINT** → G1 → G2 → **G3-OVERFLOW**(같은 루프에서 G3-COLLIDE·G3-FIT용 라인 레코드를 함께 수집 — `get_text("dict")` 1회 공유) → G4 → G13 → **G17-FIGFIT** → G14(A~E) → G15-RHYTHM → G11 → **G3-COLLIDE → G3-FIT**(면제가 `fullbleed`·`pageroles`에 의존하므로 그 둘이 확정된 뒤 등록한다) → G7-FRAME → G7-BLANK/G12 → G7-TAIL/MID → G7-DOC → G8 → G9. G3 세 축은 수집 시점이 아니라 **등록 시점**이 순서다.

**중단 지점은 5곳(qc_gate.py 한정)**: G10 실패(`qc_gate.py:655`), G0 실패(`:661`), **G15-PARA 실패(`:667`)**, `draft/book.pdf` 부재(`:686`, G1의 일부), `styles/<style>/tokens.json`에 `body_frame_mm` 없음(`:874`, G7 밀도 전처리 직전) — 이 다섯만 그 자리에서 즉시 `finish()`로 종료하고 뒤 게이트를 아예 실행하지 않는다.

> **재계수 이력(W4 판정 D7 후속)**: 이 문단은 오래 "4곳"이라고 적혀 있었으나 **G15-PARA가 빠진 계수**였고 행 번호도 낡아 있었다(구 표기 326행 = 현 874행). 계수를 늘린 것은 새 게이트가 아니라 **누락의 교정**이다 — 같은 사이클에 배선한 G16-LINT는 중단 지점이 아니다(FAIL을 `fails`에 누적만 한다). 앞의 세 지점(G10·G0·G15-PARA)은 `fails`가 아직 빈 상태에서만 도달하지만, 뒤의 두 지점은 G16-LINT 뒤라 누적분을 함께 실어 종료한다(`finish(..., fails + [...])`).

그 외 모든 게이트(**G16-LINT**·G1 판형·G2~G4·G13·G17-FIGFIT·G14(A~E)·G15-RHYTHM·G11·G3-COLLIDE/FIT·G7-FRAME·G7-BLANK/G12·G7-TAIL/MID·G7-DOC·G8·G9)는 실패해도 `fails` 리스트에 누적만 하고 그대로 다음 게이트를 계속 판정하며, 전 게이트를 다 돈 뒤 `fails`가 하나라도 있으면 그때 일괄 `finish()`로 FAIL 처리한다(중간에 끊기지 않음). G6(시각 판정)은 이 스크립트에 없다 — qc_gate.py의 게이트 집합이 아니다. **이 5곳은 `qc_gate.py`의 실행 흐름만 센 것이다 — 아래 G16-TOKENS는 별개 프로세스(`build.py`)의 유일한 중단 지점이라 이 계수에 들어가지 않는다**(늘지 않는다).

### G16-TOKENS — build.py 소속(이 표·위 중단 지점 계수 밖)

**`qc_gate.py`가 아니라 `build.py`가 렌더 전에 돈다.** 위 G10·G0도 이름은 "렌더 전"이지만 실행 순서가 build → qc_gate라 실제로는 렌더 후에 도는 데 비해, G16은 `build.py:159`(`load()` 직후·`render_diagrams` 앞, `run_g16()`)에서 typst/Chromium 렌더 비용을 지불하기 **전에** 돈다 — 렌더 비용을 아끼는 것이 이 게이트의 존재 이유이므로 `qc_gate.py`에 두면 목적이 무너진다. 리포트 일관성을 위해 `qc_gate.py:634`에서도 같은 순수 함수(`g16_tokens.run`)를 재호출해 결과를 싣지만, 실제 강제(HARD FAIL로 중단)는 `build.py`에서만 일어난다.

**사유 코드 채널**: `<book_dir>/pageroles.json` — 1차 렌더 후 사람/에이전트가 작성. 각 항목 `{page, code, why(필수), anchor(그 면 실재 문자열)}`. **코드 8종**: `PART_DIVIDER`(텍스트 ≤3행) / `FULL_BLEED_PLATE`(imgarea ≥ 0.60) / `EXEC_SUMMARY`(business, ink 0.35~0.70, 폰트·여백 축소 금지) / `ESSAY_BREATH`(essay 꼬리, lines ≥ 6, 장당 1회) / `MAGAZINE_WHITESPACE`(진입점 존재 시) / `TOC_TAIL`(목차 직후 1면) / `CH_CLOSE_APPROVED`(장 끝 면, 레버 소진 후 최종 에스컬레이션 — §4) / `OVERLAP_APPROVED`(G3-COLLIDE 전용 — 선행조건 넷. ㉠**그 면에 실제로 교차 라인이 있어야** 한다 ㉡**도비라·앞부속(표지·목차·판권) 면에는 쓸 수 없다** ㉢**그 면의 모든 교차가 `ox ≤ 3.0pt`**(=검출 임계 1.5pt의 2배)여야 한다 ㉣**그 면의 교차 건수가 5건 이하**여야 한다(W4 재판정 R-2 — 개별 크기가 ㉢ 이내라도 건수가 쌓이면 사유서 1줄이 조판 붕괴 수준의 겹침까지 통째로 면제했다) — 하나라도 어기면 코드 자체가 FAIL). 각 코드는 기계 선행조건 미충족 시 코드 자체가 FAIL(도장 방지).

**`OVERLAP_APPROVED`의 폭발 반경 — 면제는 좌표가 아니라 면 단위다.** 승인은 특정 교차를 지목하지 못한다(`why`·`anchor` 어느 것도 교차의 bbox·건수에 결속되지 않는다). 그래서 사소한 교차 하나로 선행조건을 **제조**한 뒤 같은 면의 중대한 겹침까지 함께 면제하는 경로가 열려 있었다(실측: 장식 불릿 `ox 2.02pt`로 승인을 정당화하고 본문 행 통째 겹침 `ox 38.85pt`를 함께 통과 → `pass` False→True). 위 선행조건 ㉢이 그 반경을 크기로 묶었지만, **크기만으로는 충분하지 않았다** — 개별 교차가 전부 ㉢ 이내(예: ox 2.9pt)라도 건수를 20건까지 쌓으면 사유서 1줄이 전부를 면제했다(W4 재판정 R-2 실측). ㉣(건수 ≤ 5)이 이 갈래를 추가로 묶는다. 이 코드가 존재하는 사유(장식 글리프가 행 끝에 머리카락만큼 물리는 정당한 조판)는 면당 2~3건 안쪽이고, 그보다 크거나 많은 교차는 승인 대상이 아니라 **수리 대상**이다.

**남는 한계(운영자가 알고 써야 하는 것)**: ㉢·㉣ 아래에서도 면제는 여전히 면 단위다. 한 면에 3.0pt 이하 교차가 5건 이내로 있으면 사유서가 그중 하나만 설명해도 전부 함께 열린다. 좌표 단위 승인(교차 bbox를 사유서에 적어 결속)은 이 사이클의 범위 밖이고, 현재 방어선은 ㉢의 크기 상한 + ㉣의 건수 상한 + 예산(`budget = max(3, 0.08·n)`, 28면 책이면 3면)이다. `gate-report.json`의 `G3-COLLIDE.exempt_pages`에 면제된 면이 항상 남으므로 리뷰에서 그 면들을 눈으로 볼 것. **폐기**(단면에서 재현 시 오히려 FAIL): RECTO_ADJUST·SIGNATURE_PAD·ENDPAPER·PART_DIVIDER_VERSO.

**목차 면 수가 바뀌면 재승인한다.** 다면 목차 스타일(insight)은 원고 분량에 따라 목차가 N면으로 늘거나 줄고, 그때 첫 장 이후 **전 페이지가 시프트**된다. 기존 `pageroles.json`의 `page`는 옛 면 번호를 가리키고 `anchor`는 그 면에 더 이상 없으므로 G11이 "anchor 불일치(stale)"를 대량으로 낸다. 이것은 오탐이 아니라 **승인의 근거가 소멸한 상태**다 — 면 번호를 기계적으로 밀지 말고, 새 조판의 콘택트시트를 다시 보고 각 항목의 `page`·`anchor`·`why`를 재작성한다.

## 8. 절 분량 정합 (PLAN 모드 플래너 지표 — PDF 게이트 아님)

`q = S/C` (S=절의 조판 후 행수, C=마스터 면 용량 p90):

| q | 판정 | 조치 |
|---|---|---|
| < 0.35 | 과소 | 인접 절과 병합, 불가면 묶음 면 모듈(짧은 것끼리 묶기 — 낱개 산개 금지) |
| 0.35–0.55 | 미달 | §6 받치기로 q_eff ≥ 0.55, 실패 시 병합 |
| 0.55–1.00 | 적합 | 그대로 |
| 1.00–1.15 | 근소 초과 | 압축(요소 축소·리스트 인라인화). 폰트 축소 금지 |
| > 1.15 | 초과 | 논리 경계에서만 분할, 모든 조각 q ≥ 0.55 |

리포트 "한 면 한 메시지" 성립 = `0.55 ≤ q_eff ≤ 1.00` AND 액션타이틀 1개 AND 진입점 ≥ 1.
