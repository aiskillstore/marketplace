# 오케스트레이션 확장 (Claude Code 전용, 선택)

단일 에이전트 순차 실행으로도 전 파이프라인이 성립한다. 이 문서는 Claude Code에서 대량·병렬 작업을 할 때만 읽는다. Codex CLI 단독 실행이라면 이 문서는 무시한다.

## 장별 집필 병렬화 (codex 스웜)

장 수가 6개 이상이면 `codex exec`를 장당 1개씩 백그라운드 스폰해 나눠 쓴다:

- 태스크: `{id: "ch-NN", prompt: <장 브리프+콘텐츠 계약 전문>, cwd: <book_dir>}` jsonl
- 실행: `codex exec --skip-git-repo-check --ephemeral -s workspace-write -C <book_dir> -o out/ch-NN.md "<prompt>"`를 동시 6~15개
- 프롬프트에는 SKILL.md의 콘텐츠 계약 전문과 저장 경로(chapters/ch-NN.md), 장 제목·요약·구성 규격을 담는다. 워커 간 컨텍스트 공유는 없다 — 파일 계약이 전부다.
- 회수 후 각 파일이 계약을 지켰는지(H1 일치·허용 문법·분량) 검사하고, 위반 장만 재스폰한다.

## 다권 양산 파이프라인

여러 권을 만들 때는 권별로 집필→빌드→게이트가 독립 진행되게 한다(배리어 금지). 권 하나의 게이트 실패가 다른 권을 막지 않는다.

## 스타일 판정 (opus 서브에이전트)

게이트 통과 후, 시각 검수를 별도 판정자에게 맡기면 자기구현 편향을 줄일 수 있다:

- 입력: 해당 스타일의 STYLE.md + contact_sheet PNG (표지·차례·도비라·본문 4면 이상)
- 지시: STYLE.md 규칙 대비 위반 항목을 실물 근거(페이지 번호·좌표)와 함께 열거, A/B/C 등급
- C 등급이면 위반 항목만 수리 후 재판정
