# 标题、封面与开头的写作规则

在方向固定、准备书写任何文字标题、封面标题、新口播或正文修改建议时读取。快捷路径也需要执行。这里负责把既定意思写清楚，不重新开发角度。写后按本文件检查，再交付。

## 适用范围

本文件采用清晰表达原则检查主体、动作、对象、指代和语义，并要求措辞自然、具体，保护用户已经确认的文字。中文属于本地适配，不宣称通过 ASD-STE100 正式符合性检查，不把英文词数规则换成中文字数。

标题和短视频仍可使用具体悬念、反问、修辞强调与作者强句，前提是读者知道在谈什么，正文能兑现。

## 先说清楚，再压缩

1. 用正常中文写出这份内容要表达的完整意思，明确涉及谁、哪件事、什么判断。
2. 从完整意思中选择当前表面需要的信息，再缩短文字；不要直接拼出几行短词。
3. 保留让陌生人识别主题所需的主体、对象和关系。短句可以省略已在同一表面明确交代的成分；不能靠未显示的正文补齐。
4. 先确定自然语句，再分行。每行无需独立成句，但整个封面必须独立可懂。
5. 优先级为：核心含义和独立理解 → 自然措辞 → 具体吸引力与信息分工 → 默认行数。封面每行字数上限（图文封面每行最多 6 个字、极限 7 个字，抖音主页封面每行最多 6 个字）、平台硬限制与用户指定的版式必须遵守；无法容纳时改用更简单而完整的命题，不删除必要对象来硬塞，也不把一行写超上限。

## 陌生人单独看懂

检查时只保留当前成品，暂时遮住原稿、聊天背景、解释段落和另一种标题。

- 文字标题独立显示时，读者能否知道主要对象或主题，以及这句话提出的判断或问题？
- 图文封面整体独立显示时，读者能否说清它在谈什么？“他”“这个”“差一截”“只回一句”若必须回原稿寻找对象，先补主体或直接改写。
- 封面去掉换行、连成一句读时，谁是什么样的人、谁做了什么，是否和原意一致？作者的经历和对别人的判断放在同一张封面上时，最容易把两个主语读成一个人，详见 [封面标题](cover-title.md)「连起来读一遍」；
- 抖音主页封面能否明确标示这条视频讨论的具体主题，并与其他视频区分？“你漏了什么”这类空泛问句不能完成索引。
- 新口播能否让没看标题的人听懂主语、事件和继续听的理由？

悬念可以保留原因、过程或答案；主题和基本关系需要先交代。不能把缺少背景误当成悬念。

标题与封面可以重复必要的主体、主题词和关键名词。先保证各自可懂，再避免整句和全部信息重复。互补不能通过删除语境实现。

## 用目标观众的日常说法

陌生人能看懂主题之后，再检查：目标观众平时会不会这么说话。

- 标题、封面和口播避免使用平台运营、营销和学术的行话，除非作者原文这样说，并且目标观众本身就是同行。例如「订阅逻辑」「分发」「推流」「争点击」「转化」「心智」。改成观众能直接感受到的事：「关注了也刷不到」「发了没人看」「没人点开」。
- 作者原文用了行话、并且这条内容就是讲给同行听的，可以保留原词；面向更广的人群时换成日常说法。
- 检查方法：想象一个不做自媒体的朋友在刷手机时看到这句话，他能不能不停顿就读懂。

## 给用户的说明也用大白话

推荐理由、正文建议、选题菜单、方向说明和提问都会被用户阅读。写这些文字时，按下面的规则检查。

**每句话说清谁、做什么、对什么。**

- 一句话只说一个判断。「人多，很在意；稿子后半段撑得住」这类把几个判断挤在一起的写法，拆成几行，每行写一件事；
- 写出动作和对象。「补一个背书会强很多」改成「补充你做了几年、见过多少人，标题和开头可以写进去，观众更容易相信」；
- 「它」「这个」「这一层」有多个可能对象时，直接写名称。

**不用比喻和内部说法。** Skill 内部的思考用语不出现在用户可见文字里。常见替换：

| 内部说法 | 发给用户时写成 |
| --- | --- |
| 往上拉、拉几层、更好拉 | 讲给更多人、扩大选题 |
| 底子 | 这份稿子主要讲什么 |
| 拉法、挂母题、换说法 | 直接写改了哪个词、加了什么信息 |
| 撑得住、撑不撑得住 | 稿子能讲清楚吗、还要补什么 |
| 锚点 | 稿子里最吸引人的具体细节，并直接写出是哪个细节 |
| 背书 | 能让观众相信你的经历或数字 |
| 回落 | 讲完大问题后，回到稿子原来的内容 |
| 层、层级 | 第几个选题 |

另外不使用：点击型、留存型、注意力推荐、兑现推荐、双重推荐、入口基准、争点、证据边界、抽象层级、四格、F1、L01 和理论名称。

**按事实说，不加评价包装。**

- 推荐理由一句，20 字以内，说观众为什么会点或为什么能看下去，例如「一组数字对比，反差直接」；
- 不解释流程本身，例如「经过内容价值验收」「按两种标准比较」。用户问「为什么」时再解释；
- 判断人群写具体人群，不写「所有人」「大众」；人数多少和关不关心分开写。

交付前把给用户的每一行读一遍：不知道这个 Skill 内部规则的人，能不能直接看懂？看不懂就改。

## 动词要符合日常说法

检查动词与对象的搭配，以及整个句子是否像人在这个场景下会说的话。使用材料中已有的具体动作；不能为了显得短、有力或有方法，临时创造抽象搭配。

尤其避免“你漏了什么”这类把复杂判断压成单一动词、再省略对象的写法。不要只把“漏”换成“遗漏”“补齐”继续保留模糊句式；重新写出具体意思，例如当前内容到底在问是否考虑了获客方式、交付能力，还是在讨论某种创业行为。成品不必全部写进，但必须能判断具体主题。

按语境检查，不机械封禁所有单字动词。原作者明确使用、对象清楚且自然的表达应保留；“漏写一个字”这样的实际动作与空泛钩子分开处理。解释句、推荐理由和改稿建议同样遵守自然措辞要求。

同一对象使用同一名称，准确词语可以重复。避免为换说法增加抽象名词；避免“不是……而是……”及项目禁止的近似句式。引用原文或用户明确要求时遵守原文保护规则。

## 保留力度和原意

- 保留选定方向、原稿强句、事实、条件、否定、因果与承诺强度。清晰表达不能擅自更换立场，也不能把所有观点改成操作说明。
- 对不影响核心理解的概括、强调和次要条件省略，按主 Skill 的表达尺度保留；不用层层限定抵消作者力度。
- 为补全语境，只能使用材料已有的信息；不能编造数字、人物行为、受众心理或效果。
- 原话素材不静默改写。新写口播与已拍原话分开，用户锁定文字优先于默认规则。

## 交付前实际检查

对每个成品分别完成：遮住上下文 → 复述主题和判断 → 检查动作与指代 → 正常读一遍 → 对照原意 → 核对长度和换行。

复述时只能使用当前成品中已有或可直接理解的信息，不能偷偷调用原稿替它解释。若需要附一段说明才能证明这句封面“其实讲得通”，先改成品。字符数合格不能代替理解检查。

同一处理解或用词问题反复出现时，修正写法并保留用户否定过的结果作为回归样本；不能只在分析里承认问题，继续把它放进推荐。检查在内部完成，用户未要求时不附逐项评分表或写作规则讲解。

## 用户否定过的样本

以下成品已被用户否定，不得再以相同或近似写法出现：

| 成品 | 问题 |
| --- | --- |
| 只学直播带货／不看千万粉丝／这生意怎么抄 | 陌生人缺少上下文，不知道在说什么 |
| 创业找对标／你漏了什么 | 单字动词加省略对象，有 AI 味 |
| 粉丝差一大截／他却只回一句／试试才知道 | 人物、比较关系和事件不明确 |
| 小红书订阅逻辑很弱，每条笔记都要靠封面标题重新争点击 | 「订阅逻辑」「争点击」是运营行话，普通人看不懂 |
| 粉丝攒了不少，下一条照样可能没人看（附长篇推荐理由） | 理由和标签太长太专业，用户要读大量文字才能选 |
| 教不会用手机的人用AI／能做到千万播放（抖音主页封面） | 第一行 10 个字，主页封面图很小，字会小到看不清；每行最多 6 个字 |
| 7年没上班／不赚钱的人／都有这个毛病（图文封面） | 三行连起来读，作者被读成「7 年没上班、不赚钱的人」 |
| 大厂都在做AI／我的产品／没开售就排上队了（图文封面） | 第三行 8 个字，超过上限；每行最多 6 个字，极限 7 个字 |

| 材料 | 被否定的菜单 | 问题 |
