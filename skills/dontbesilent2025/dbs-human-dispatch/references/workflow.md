# 使用与任务记录

## 适用入口

- “这件事交给小王，帮我写清楚要求。”
- “看项目里谁适合做，帮我派单。”
- “员工在飞书回填了，帮我答疑／验收。”
- “没有飞书工具，写一段我能直接转发的文字。”
- “配置持续跟进，收到提交后通知我。”

招聘、绩效排名、薪酬处罚与普通写作不属于本 Skill。人员资料不足时只讨论当前任务所需能力，不诊断个人性格。

## 本地运行目录

默认 `~/.dbs/human-dispatch/<项目名与路径摘要>/`。跨 Agent 共享同一目录；跨机器使用同一个服务和存储，不把 SQLite 文件放进云同步目录实现并发。通过 `--state-dir` 明确指定目录。

任务 JSON 字段：

| 字段 | 用途 |
| --- | --- |
| id | 稳定唯一任务 ID，允许英文、数字、下划线和连字符 |
| owner | 老板身份说明；接收人 ID 要实际核实 |
| assignee | 员工身份说明与已核实的飞书 ID |
| goal / deliverables / acceptance | 目标、交付物数组、验收标准数组 |
| due / timezone | 可协商期限与时区；due 可以是“待协商” |
| materials | 员工可访问的资料链接或摘要数组 |
| feedback | 回填渠道、完成标记与求助方式 |
| authorization | 自动派单、答疑、调整和通知的明确授权范围 |
| doc_token / doc_url | 已核实文档 token 或 URL；纯文字任务可省略 |
| mode | text / on_demand / automatic |
| state | 初始只能是 draft；送达与验收由证据推动状态转换 |

`register` 创建后不覆盖任务。修改内容使用 `revise --task-file`，保留修订历史；不得改任务 ID、原负责人或文档绑定，转交应另建任务。范围或授权修订先经老板确认。

每次 `transition` 需要 evidence，历史记录保存时间、来源状态、目标状态与证据。任务状态与队列状态分开：事件处理成功不会自动验收任务。

## 老板汇报示例结构

任务 ID／负责人；当前状态；已核实成果；待补证据或阻塞；下一步；老板是否需要决定。自动通知内容只使用本任务必要资料，不附员工全部档案。

## 验收边界

链接打不开时不能通过；文稿符合原要求但老板提出新方向时另建任务；员工只说明“已经完成”时请其提供成果；生产上线、付款、对客户承诺需单独核实授权。通知工具成功后才记“已发送”，送达与已读仍需额外证据。
