# 简历事实守卫 resume-claim-guard

从岗位 JD 出发，写一份面试官一对一追问时你都答得上来的简历。

AI 很会把简历往 JD 上靠，但它不知道你真正做过什么。于是“参与”被写成“主导”、原型被写成“上线”、随手编一个“转化率提升 35%”。简历是好看了，面试官问一句“这个数字怎么来的”，你就答不上来。

这个 Skill 把顺序反过来：**先问你做过什么，再写简历**。

```
贴 JD → 拆出岗位要求 → 反问你有没有对应经历 → 只用你确认过的事实写定向简历 → 逐句体检 + 预演面试追问
```

## 最快的用法：复制一句话

在豆包、Kimi、DeepSeek、ChatGPT 里任选一个，复制下面这句话，后面接上岗位 JD 和你的旧简历，发送：

```text
帮我按下面的 JD 改简历。规矩：先别写；你每条回复只问一段经历、最多 3 个问题，问完就停下等我答，问清我本人做了哪部分、做到哪一步（计划/原型/上线）、数字从哪来；我回复“确认”事实清单前不许写简历；只用我确认过的事，不许把参与写成主导、原型写成上线、编数字；最后告诉我面试官会怎么追问、我该怎么答。
```

它会先问你经历，你确认之后才写。想要更严格的完整版（逐句体检、投递建议、面试统一口径），用 [PROMPT.md](PROMPT.md)。

## 它和普通 AI 改简历有什么不同

- **先反问，后动笔**：按 JD 每条职责问你“做过相关的事吗、你本人做了哪部分、做到哪一步、数字从哪来”，整理成事实清单，你确认后才写。
- **动词有上限**：个人角色（参与 → 负责 → 主导）和交付阶段（计划 → 原型 → 上线 → 有结果）分两条轴，都不能超过事实。JD 写“主导”，你只负责一部分，就写“负责”。
- **缺口不硬塞**：JD 要求但你没做过的，不写进简历，而是告诉你面试被问到时怎么诚实回应。
- **每句话都预演一遍面试**：面试官最可能的追问、只用事实写的回答要点、绝对不能说的话。
- **不打分**：只给“建议投递 / 补充材料后投递 / 谨慎投递 / 暂不建议投递”和一句理由，不编“匹配度 85%”。

## 一分钟开始

**第一步：你用的是什么？**

| 你用的工具 | 怎么接入 |
|---|---|
| ChatGPT | 也可以做成 GPT，配置见 [platforms/chatgpt-gpt.md](platforms/chatgpt-gpt.md)（豆包、千问的自建智能体已于 2026-07-15 下线，国内聊天工具直接用上面的一句话版） |
| 豆包、ChatGPT、Kimi、DeepSeek 等网页聊天 | 打开 [PROMPT.md](PROMPT.md)，复制整段粘贴进对话框，再贴上 JD。不用安装任何东西 |
| Claude Code | 对它说：`把 https://github.com/korey2028-prog/resume-claim-guard 克隆到 ~/.claude/skills/resume-claim-guard` |
| Codex | 对它说：`把 https://github.com/korey2028-prog/resume-claim-guard 克隆到 ~/.codex/skills/resume-claim-guard` |
| WorkBuddy | 对它说：`把 https://github.com/korey2028-prog/resume-claim-guard 克隆到 ~/.workbuddy/skills/resume-claim-guard` |
| 其他支持 SKILL.md 的 Agent | 把仓库放进它的 skills 目录 |

**第二步：你手里有什么？**

| 你有 | 它会怎么做 |
|---|---|
| 一个岗位 JD（最推荐，有没有旧简历都行） | 完整五步：拆 JD → 反问经历 → 匹配 → 写定向简历 → 体检和面试预演 |
| 只有一份简历 | 逐条追问“这句里你本人做了什么、上线了吗、数字从哪来”，再体检和预演面试 |
| 原版简历 + AI 改过的版本 | 揪出 AI 加进去的动词、数字和结果，只追问这些 |
| 投给不同公司的几个版本 | 列出同一段经历在各版本里的不同写法，已投出去的给面试统一口径 |
| 简历定稿，马上面试 | 只做面试追问预演 |

JD 和简历可以是 PDF、Word、HTML、Markdown 或直接粘贴的文字。

**第三步：说一句话**

```text
用 resume-claim-guard 帮我准备这个岗位。不要替我编任何经历。
```

## 你会得到

1. JD 拆解：硬性条件、核心职责、能力要求、加分项
2. 事实清单：从你的回答整理，等你确认
3. 要求—证据匹配表和投递建议
4. 定向简历草稿：只用你确认过的事实
5. 逐句体检表：每句标 `confirmed` / `supported` / `needs-source` / `inference` / `rejected`
6. 面试追问预演：每段经历 2–3 个追问、回答要点、不能说的话、被问到缺口时怎么答
7. 需要你确认的清单
8. 未决项和真实缺口

## 人工边界

事实、动词上限和最终文本都由你确认。它不会投递简历、发送消息、登录招聘账号，也不会把 JD、模型建议或推断写进你的事实清单。

## 示例

全部是虚构候选人：

- [jd-to-interview](examples/jd-to-interview/)：完整五步，从一份 JD 和一份注水旧简历，到定向简历和面试预演；
- [single-html](examples/single-html/)：只体检一份 HTML 简历，展示动词越级和编号泄露；
- [multi-version](examples/multi-version/)：两份定向版简历，展示底稿自相矛盾、过期数字和跨版本不一致。
