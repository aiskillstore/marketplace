# 面试追问预演

简历上的每一句，面试官都可以一对一追问。体检通过之后，为每段经历做一次预演。

## 每段经历输出以下几项

| 项 | 写法 |
|---|---|
| 最可能的追问（2–3 个） | 按面试官的习惯问：你本人做了什么？为什么这么做？数字怎么来的？遇到什么问题、怎么解决？结果怎么验证？优先问简历里最强的动词和每个数字 |
| 回答要点 | 只用事实底稿里的内容，按“背景—你做了什么—结果—你学到什么”写成 3–5 个要点，不写成背诵稿。每个要点后标事实编号 |
| 不能说的话 | 列出会越级的说法，例如“我主导了整个项目”“上线后用户涨了”，并写出事实边界 |
| 被问到旧版写法时 | 已投出去的旧版里有 `rejected` 或 `needs-source` 的主张，每条给一句统一口径：直接承认写得不准、以新版为准，再转回真实做过的事。不辩解，不临时补编数字 |
| 被问到缺口时 | 对 JD 的真实缺口，给一个诚实回应的结构：承认没做过 → 说最接近的真实经历 → 说准备怎么补。不编、不含糊带过 |

## 追问的来源

- 简历里每个数字：怎么统计的、什么时间、和什么比；
- 每个“负责”“主导”：团队几个人、你的边界在哪、谁做决定；
- 每个“上线”“落地”：用户是谁、多少、现在还在用吗；
- 每处 AI 辅助：AI 做了什么、你怎么检查的、错过什么；
- JD 核心职责里候选人是 `表达缺口` 或 `证据不足` 的部分：面试官最可能在这里深挖。

## 高风险标记

以下情况在预演里标“高风险”，放在最前面：

- 主张状态是 `supported` 但还没确认；
- 数字只有一个来源且没有记录日期；
- 同一经历在不同版本简历里写法不同，且其中一版已经投出去（统一口径写进回答要点）。

多段经历都是高风险时，按风险从高到低排：已外发版本里有 `rejected` 的 > 已外发版本里有 `needs-source` 的 > 未确认的 `supported` > 单一来源的数字；同级按 JD 职责优先级排。

预演不判断候选人能否通过面试，也不打分。候选人练习后的作答由候选人自己判断；预演结果不回写事实底稿。
