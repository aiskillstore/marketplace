# 拆 JD 与匹配

## 拆解

保留 JD 原句，按四类列表，每条一行：

| 类别 | 判定方式 |
|---|---|
| 硬性条件 | 学历、届别、专业、地点、到岗天数与时长、语言证书。逐条对照候选人情况，写 `符合` / `不符合` / `待确认` |
| 核心职责 | JD 里“负责……”“参与……”的句子。这是反问经历的主线 |
| 能力要求 | “熟悉……”“具备……”。区分可以用经历证明的（做过数据分析）和只能自述的（沟通能力） |
| 加分项 | “优先”“加分”。缺了不影响投递建议，只列出 |

记录 JD 来源（链接或“用户粘贴”）和日期。JD 不完整或只有标题时，告诉用户缺什么，按现有内容继续，结论标 `待核验`。

一份 JD 里同一要求换了说法出现多次，合并成一条，保留最具体的原句。职责超过 8 条时，按 JD 中出现的顺序和篇幅挑出最重要的 5 条作为主线，其余并入能力要求。

## 匹配状态

| 状态 | 含义 | 去向 |
|---|---|---|
| `已匹配` | 有确认过的事实直接对应 | 写进简历，排在前面 |
| `表达缺口` | 做过，但旧简历没写或写偏了 | 第 4 步重写 |
| `证据不足` | 可能做过，但缺来源或候选人记不清 | 问一次能否补来源；补不上就不写确定事实 |
| `真实缺口` | 没做过 | 不写进简历；写进面试预演的“诚实回应” |
| `待确认` | 等候选人回答 | 回答前不进入简历 |

一条职责只成立一半时（JD 写“策划、执行并复盘”，候选人只做过执行），拆成两行分别标状态。只能自述、无法用作品证明的能力（沟通、抗压）标 `证据不足`，不写成简历要点，面试时用一段具体经历举例。

一条要求可以对应多条事实；一条事实也可以支撑多条要求，但在简历里只用一次，不同段落不重复堆同一件事。

## 投递建议

只用四档，并写一句理由：

- `建议投递`：硬性条件全部符合，核心职责多数 `已匹配` 或 `表达缺口`；
- `补充材料后投递`：硬性条件符合，但关键职责 `证据不足`，补一份作品、截图或链接就能改善；
- `谨慎投递`：核心职责一半以上是 `真实缺口`，或有一条硬性条件 `待确认`；
- `暂不建议投递`：有硬性条件 `不符合`。

不输出百分比、分数或“匹配度 80%”这类伪精确数字。最终投不投由候选人决定。
