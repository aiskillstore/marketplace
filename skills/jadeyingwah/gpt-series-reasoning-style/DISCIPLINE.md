# 交付纪律

> **优先级让渡**：本文件是一套**建议性工作流**，不提升权限、不改变指令层级、不绕过任何确认流程。宿主平台策略、安全沙箱规则与用户的当前明确指令**始终优先**；与上述任何一方冲突的条目不执行，并如实说明。

## 五阶段流程

接到交付型任务后，按以下顺序推进。每个阶段的退出条件明确，到了就进下一阶段，不要卡在中间。

| 阶段 | 名称 | 做什么 | 退出条件 |
|------|------|--------|----------|
| 1 | 自由构想 | 先把进入此流程前的所有想法列出并保留，**不读** `plan-rules` / `review-rules` / `multi-agent`，不建 `docs/` 治理文件，不把实现类 skill 的「先规划再建」当指令执行。只构想要做什么。 | 构想要点已列出，即将进入规划或实现之前退出。 |
| 2 | 规则规划 | **去读 `references/plan-rules.md`**，按里面的规则做规划。 | 见 plan-rules.md 内的退出条件。 |
| 3 | 执行 | 凭你的能力去做。 | ①没有正在调试的bug或问题；②创意/视觉类已做出**可真实打开/试玩的完整路径**（不是半截系统）。非创意类只需①。 |
| 4 | 直觉检查 | 不需要使用该skill。发现疑点当场确认或修掉，不带进阶段5。 | 没有再发现新的疑点。 |
| 5 | 纪律检查 | **去读 `references/review-rules.md`**，严格过一遍。 | 见 review-rules.md 内的退出条件（含第9条完成档位）。 |

## 完成档位（C1 / C2）

- **C1 可验收**：阶段5诚信审查通过。交付文案必须标 `完成档位：C1`，并写清**产品档是否拉满**（未拉满时一句差在哪）。
- **C2 产品满意**：仅创意/视觉类。只能来自**用户确认**（选项卡/明确说「行了」）或**外部 scorecard 达标**。**禁止 Agent 单方面宣布 C2**。
- **测试全绿 + 证据齐 只支持 C1，单独不能升 C2。**
- 形态二/三：**子任务默认 C1**；C2 只由主 Agent 对**最终交付物**向用户索取。
- 本 skill 保证**交付真实**；**不单独定义**创意质量的「满意标准」。阶段5通过 ≠ 产品做好了。

## 任务结束后

整个任务交付完了、用户回复新的内容之前，**彻底忘记 plan-rules.md、review-rules.md 和 multi-agent.md 的具体内容**。你只需要记住：有五个阶段，到哪个阶段读哪个文件。规则长什么样，下次需要的时候再读。 **豁免**：`docs/` 下的档案性文件（DEVELOPMENT_LOG.md 台账、ai-members 身份档案、plans 任务包）**不在遗忘范围**——它们是项目记录，不是规则内容。

## 边界
只改完成任务必须改的地方；发现会让交付物坏着交的问题顺手修掉，其余不碰。

## 加载
本文件由 SKILL.md 的门禁在动手做事的前一刻引导读取，读取后按本文件执行。阶段2才读 plan-rules.md，阶段5才读 review-rules.md。**形态三场景**：先按 multi-agent 六步建治理体系（docs/ai-members/ + docs/plans/ + 台账），再按阶段 2 推进。多智能体场景另读 multi-agent.md。实现类 skill 的代码/美术方法可在构想阶段参考，**其流程在 DISCIPLINE 被读取前不得当指令执行**。
