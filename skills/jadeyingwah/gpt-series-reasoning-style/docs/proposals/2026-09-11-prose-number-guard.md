## 1. 问题（Problem）

仓库里有一类数字：**它们由某个来源派生，却被手抄进多处散文/HTML/YAML 表面，且没有任何检查把它与来源对齐。**

- SB4 数**文件**（identities == 21）、SB5 数**文件**（references == 13）——只管文件数，不管散文里写的数。
- SB19 只管**身份计数的散文**（"22 个身份"）。

结果：**检查项数 / `SKILL.md` 行数 / 自测条数 / references 份数**这四类"散文里的派生计数"全部**无人守卫**。改一处、漏一处，字面层就与真实值不一致，而 `selfcheck` 依旧是绿的。

## 3. 设计（SB21 = 散文计数匹配其来源）

一条登记表驱动的静态检查：**（活表面，逐行正则，期望值元组，标签）**。
来源真值在检查内**现算**，不落常量：

| 族 | 来源真值 | 覆盖表面 |
| --- | --- | --- |
| 检查项数 | `selfcheck.py` 内 `c = new(` 的出现次数 | README 徽章 / 树 / 表 / CI 行 / 复杂度预算行 / 发布前清单、`site/index.html` 表、workflow 步骤名、以及两处的「新增第 N 项」次序数（= 项数 + 1） |
| `SKILL.md` 行数 | `len(SKILL.md.splitlines())` | README 仓库树「≈N 行」、复杂度预算「当前约 N 行」 |
| 自测条数 | 解析出的 Test 条数 | README 徽章 / 树 ×2 / 表 ×2 / CI 行、`site/index.html`、`references/self-test.md`「冻结于 77」 |
| references 份数 | `references/*.md` 计数 | README「13 份 references」、「13 份按需规则文档」 |

**刻意做的取舍**：

- **只覆盖有唯一来源、且出现在活表面的计数**。四族之外的新散文数字（无论哪类）**不在守卫范围**——必须显式登记才会被管。这是"窄而可信"对"宽而误报"的取舍。
- **排除有日期的记录面**（`CHANGELOG.md` / `INTERNAL-HISTORY.md` / `docs/reviews/` / `docs/field-tests/`）——**过去某天写的计数对那天是正确的**，与 SB19 同一理由。
- **不引入容差**。"≈/约" 不豁免：这些数字是每批手工递增的锚点，**要求精确相等**正是设计意图（`83ed1ec` 的 +1 漂移因此可被抓住）。

## 5. 已知盲区（诚实边界）

- **仅四族**。新出现的散文计数（如未来加"探针条数""安装平台数"散文）不会自动被管，须登记进 `fam` 表。
- **逐行正则**。跨行书写的计数不会被看到（当前无此形态）。
- **只查"字面一致"**。一个被写成 21 却**语义上就是错**的数字（例如把别的数硬凑成 21）不在守卫内——SB21 验的是"散文数字 == 来源真值"，不是"来源真值本身对不对"（来源正确性由被指向的检查负责）。
- **与 SB19 的边界**：身份计数的散文仍归 SB19；SB21 不重复覆盖身份族。
