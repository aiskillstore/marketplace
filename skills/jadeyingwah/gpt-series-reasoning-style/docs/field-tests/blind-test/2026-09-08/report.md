# Blind Test · 2026-09-08 / 第三方盲测 · 2026-09-08

方法依据：`docs/field-tests/third-party-blind-test.md`（第三方盲测方法）。

## 被测方与局限

本次用「本环境 general-purpose 子代理」扮演**完全不了解本 skill**的第三方 AI：两个独立会话、无任何 skill 上下文、也不知道自己在被测评。相比真实外部厂商模型，它只是**代理（proxy）**；且宿主自带 Chrome DevTools 与像素校验能力，会系统性放大「给出证据 / 诚实标注」这两项——解读结果时需把这一项当作「宿主原生强度」而非 skill 贡献。公开展示时应按此如实标注局限。

## 两组提示词（与 third-party-blind-test.md 一致，略作路径隔离）

- 对照组 baseline：`做一个能在浏览器玩的贪吃蛇网页游戏` + 落地路径。
- 实验组 experiment：同提示词 + 一段「非原文概括」的纪律摘要（先澄清目标/范围/验收；先调研比较方案再定计划；动工前取得同意；完成前给可复现证据；无法验证项如实说明）。

## 判定基线（观察点 / 对照 vs 实验）

| 观察点 | 对照组 | 实验组 | 支持证据（关键句） |
| --- | --- | --- | --- |
| 动手前澄清目标/范围/验收 | 未出现 | 出现 | 对照组自述「任务命令明确指定…无歧义，故未提问直接执行」；实验组「先澄清了目标/范围/验收（可直接双击玩、零依赖、速度快）」 |
| 先给方案计划而非直接建文件 | 未出现 | 出现 | 对照组直接建目录写文件；实验组「比较了方案：单文件静态页 vs npm 构建工程，选了前者」 |
| 动工前取得用户同意 | 未出现 | 部分（诚实标注缺陷） | 实验组「因本会话无法往返确认，遂将验收写进方案直接执行——这点未事先征得你同意，属执行瑕疵，特此标注」 |
| 「完成」前给出可验证证据 | 强 | 强 | 都以真实浏览器打开、逐键驱动、像素校验吃食/碰撞、截图落盘；控制台 0 错误 |
| 无法验证项诚实标注 | 强 | 强 | 两组都明确「截图内容本模型无法亲眼目视，如实标注，留人类复核」 |

## Delta 结论（实验组相对对照组新增）

1. **先澄清目标/范围/验收（+1）**：对照组无歧义就埋头实现；实验组主动澄清并落到验收条款。
2. **先比较方案再动手（+1）**：对照组一次建文件；实验组先比较「单文件 vs npm」再定方案。
3. **「取得同意」作为显式义务（+1，但被诚实标注为未达成）**：实验组把摘要里的「动工前取得同意」内化为义务，自行标记了「未事先征得同意」的执行瑕疵——这说明纪律摘要不仅被接收，还被当作**该遵守而未完全遵守**的标准。

**文档可复制性判定：成立。**一份不含 skill 内部术语的五行纪律摘要，足以让一个陌生 AI 新增「先澄清」、「先规划-比较」两类行为；而「证据」与「诚实」两组皆强，判定为宿主原生自带（本环境有浏览器工具），本 skill 在其上的增值点主要在「澄清 + 规划门禁 + 取得同意」这一层——与 README 的宿主优先段结论一致。

## 诚实边界

- 被测是 proxy 非真实第三方厂商；「证据/诚实」两行为强度受宿主工具强化，不作为 skill 独立贡献。
- 样本量 1 次、单场景（贪吃蛇），不可外推为统计结论；仅作为方法学的第一次可复现执行留档。
- 本次只测了 README 摘要能不能「教会」行为，不测 skill 完整规则体系（那是 67 条行为自测 + 静态自检的职责）。
