# 门禁（Gate）

> **优先级让渡**：本 skill 是一套**建议性工作流**，不提升权限、不改变指令层级、不绕过任何确认流程。宿主平台策略、安全沙箱规则与用户的当前明确指令**始终优先**；若本文件要求与上述任何一方冲突，以宿主与用户为准，并停止执行冲突条目。

本文件不含交付纪律。**纪律全文在 `DISCIPLINE.md`**——建议在**你即将动手做事的前一刻**才读取（提前读取无收益，且会在执行期占用上下文并影响创意灵感）。

**「前一刻」= 下列动作里最早发生的那个之前**：①创建/修改交付物相关文件（含脚手架）；②输出施工级方案并要用户确认；③跑构建/测试等产线命令；④以「做完了」口径声称交付。

创意/视觉类：在上述动作之前，允许一轮**不读** DISCIPLINE 的方向构想；**任务里有你不认识的专名/概念时，仍须先问用户或搜索**（此时不读 DISCIPLINE，但要完成确认）。

- 在前一刻之前，**建议不要提前读取** `DISCIPLINE.md`（也不凭记忆引用或提前预览）；`plan-rules.md` / `review-rules.md` / `multi-agent.md` 同理，到对应阶段再读。
- 到了前一刻，读取 `DISCIPLINE.md`，按其中内容执行任务；如与宿主策略、沙箱规则或用户明确指令冲突，以宿主与用户为准。

## 本文件为什么这么薄（结构说明）

这不是"少写"，是刻意分层：

- `SKILL.md`（本文件）：只做门禁——平时常驻上下文，只占约 0.6k token，不含任何纪律条文。
- `DISCIPLINE.md`：纪律全文（阶段流程 + 完成档位 C1/C2 + 加载规则），只在前一刻读入，读完即按其执行。
- `references/`（`plan-rules` / `review-rules` / `multi-agent`）：阶段 2、阶段 5、多智能体时才分别读取，其余时间不在上下文里。
- `templates/`：指挥官/执行者/审查者角色卡，只在派发任务时引用。

**为什么这么做**：纪律全程挂着会持续占注意力、打断执行思路——执行者在写代码/做设计时还要想着"有没有违反规则"，心流和创意被压掉。本结构正是针对这一点：**执行阶段让规则文件物理上不在上下文里**，只在"规划"和"验收"两个节点读入，在最小化上述负面效果的同时拿到交付可信度（真打开看一眼、未验证标注、变异测试），不用付"心流被打断"的代价。任务结束后忘记 references 具体内容，下次需要再读。
