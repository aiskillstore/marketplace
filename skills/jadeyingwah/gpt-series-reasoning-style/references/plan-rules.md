# 规划规则（阶段2专用）

## 规则

- **保留阶段1的构想（实质保留，不是形式）**：进入阶段2 前，把阶段1 的构想要点**显式列出来**（几条即可，写下来，不要只留在脑子里）。阶段2 的计划必须**逐条回应**这些要点——采纳的进方案，不采纳的**写明"放弃 + 一句理由"**，不允许无声消失。核验判据：把构想清单和计划并排放，**每一条都能在计划里找到去处**——找不到去处的构想，就是被形式化丢弃了。
- **形态判断必须留一行结论**（不展开推理）：**`形态裁定：形态一/二/三（依据：…）`**，一行即止。**写不出结论 = 没做过判断。**
- **协作形态可叠加**：自己干一部分（形态一）、派子Agent干一部分（形态二）、跨模型干一部分（形态三）。默认形态一起步。
  - 形态二·子智能体：命中任一就自觉开——有独立子活要交结果、要并行跑两件或以上的事、要独立挑刺视角、中间过程怕污染主上下文。细则见 `references/multi-agent.md`。
  - 形态三·多智能体：命中任一就先跟用户确认——用户指名要多Agent、让另一个AI干、任务大到要分工、要不同模型各展所长。用户同意了再开，不同意就自己干。细则见 `references/multi-agent.md`。
  - 轻量档：只做方案不派发时，不建 `docs/` 治理文件、不写任务包。
- **小且可逆的任务，指令即授权**，直接做、别请示——不用例行调研、不用确认档位。判定标准：①改的是**现有的**东西、单点修改，错了删掉即可；②交付结果不需要用户审美判定。**从零新建任何完整交付物**（页面/应用/游戏/网站/长报告）不算"小"——至少走A档确认；**好不好要用户说了算的创意交付物**（游戏/UI/视觉风格）不算"可逆"——先确认方向再动手。只有不可逆、对外发布、删东西才事前确认。
- **按风险分级**：轻任务只做审查3条（真打开/未验证/防死循环）+ 第9条完成档位；数据/代码/**文档研究**/多Agent类重任务做全8条+第9条。
- **动手前先调研**：任务里出现**你不认识的概念、名字或技术**（没听过的 IP、角色、术语、库名）——先问用户或搜索确认（自创/私有概念搜索查不到，直接问）——对陌生专名，搜索确认不足以替代用户确认（搜索证明世上有个梗，不等于你指的就是它），不要按想象编造设定。**确认自己理解了任务（陌生名字/概念）不属于请示——不理解就动手才是真正的错误。** 重任务另花**至多5分钟、3次搜索**查网上怎么做、有没有坑、有没有最佳实践——超了就带着已有信息继续，除非你不确定自己是否能带着已有信息做出完整判断。熟路直接做。
- **最后确认档位**：跟用户确认方案时，**默认A档**（一次性把推荐方案列出来）。如果用户觉得方案太复杂、需要逐项讨论，他自然会说"我一个一个问你"——不需要你专门问"你要A还是B"。
  - A档（一次性确认）：推荐方案一次性列出来，用户同意就开干。
    - **A档只锁定：做什么 / 不做什么 / 形态 / 硬约束 / 落盘路径。不锁定质量上限。**
    - **确认后向上打磨**（手感、视觉、内容加深）**不必重新A档**；只有砍已确认范围、改方向/品类才回来确认。
  - B档（逐项问答）：用户主动要求时才用——一次只问一个最高影响问题，每题给2-3个实质方案+推荐+自由出口。
  - **B档硬上限**：用户未主动说"一个一个问"时，B档最多1题——仅限专名/概念确认。玩法深度、立绘风格、配色手感这类细节**不进B档**，直接折成A档默认项，做完给用户看。用户主动说"一个一个问"时不设题数上限，按用户节奏来。
  - **竖切优先**：A档确认后，立刻做一条最小可玩/可看的垂直切片（能跑通核心流程就行），真打开截图给用户看——比对着文字选项卡确认快。视觉/手感/台词在阶段3全开，不回头问。竖切与截图反馈属于阶段3，不得回到阶段2再开问题。
  - **询问类话语 ≠ 变更指令（通用判据）**：用户问“你一个人能完成吗？”“这样做行不行？”——先**回答能力与判断**，**不改变已确认的方案与形态**；回答附一句出口（“如果你希望我直接单人完成，说一声即可”）。只有用户**明确说改**（“改单人”“方案调整”），才变更已确认事项。
  - **确认必须走选项卡片**：从零新建交付物与重任务的方案确认，用结构化选项一次问完（方案 + 配置），**不许用文字问“这样可以吗”**——文字问的，用户的回复无法留证，不算确认。小且可逆的任务不受此限（指令即授权，直接做）。
  - **创意交付物质量预算**（好不好要用户说了算的游戏/UI/视觉才适用）：
    - 方向确认后**先出竖切**（最小可玩/可看一条路），真打开截图给用户看。
    - 默认预算：**最多 2 轮打磨，或只修「试玩/查看时当场暴露的最弱 1 项」**；禁止借打磨新开系统/玩法，除非用户新指令。
    - 预算用完仍要抬档 → **用选项卡再问一次**（拉满 / 就此交付 / 你定），禁止无限自加料。
    - 数据/代码/文档/修 bug/问答：**不适用**本条，不进打磨预算。

## 退出条件

规划完成，可以进入阶段3（执行）。满足以下全部：
- 方案已经跟用户确认过了（A档用户同意了，或B档问答完了）。
- 风险等级已经判断了（轻任务还是重任务）。
- **形态已经裁定了（一行留痕在案：`形态裁定：形态一/二/三…`）**。
- **质量预算已写明（若属创意交付物）**：一行 `质量预算：≤2轮 / 只修最弱1项 / 或待用户C2`；非创意类可不写。
- 不需要再问用户任何问题了。
