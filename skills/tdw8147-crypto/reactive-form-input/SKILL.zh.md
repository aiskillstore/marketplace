# 响应式表单输入核对

当应用还没接受输入时，不再把“字段填上了”当成成功。

## 什么时候用

- 受控字段显示预期文字，联动状态却没变。
- 页面同时有可见联系字段、隐藏副本和名称相近的搜索框。
- 值看起来合法，但校验还在转圈、报错，或关联控件仍禁用。
- 测试期间发生前端导航，字段被替换了。
- 没有浏览器，用户仍需要根据已有页面记录交付核对结果。

## 什么时候不用

- 用户要正式提交申请或完成付款。
- 提交已经超时，现在要确认是否送达。
- 输入发生在本地编辑器，不是有应用状态的表单。
- 任务是实现校验逻辑，而非观察字段。
- 用户只问该填什么格式，不问应用是否接受。

## 核心规则

1. **在所属表单中识别可见、可编辑的控件。** 隐藏副本和同名搜索框可能给出很像真的、却与目标无关的结果。
2. **优先正常填充或键盘输入；替换前说明怎么清空。** 正常交互走的是应用预期路径，同时保留用户要求的格式和单位。
3. **仅改 DOM 属性不算成功。** 显示出字符串不能证明应用已接受；保留控件限制，走正常校验流程。
4. **显示与应用接受分开记录。** 值看对了、校验没同步，不能算生效。
5. **有界等待业务状态。** 页面加载结束不等于异步校验结束；正在校验时不判最终失败。
6. **只有正常流程需要时才失焦。** 点击最终提交或随意拼事件，会改变测试对象而不是观察输入。
7. **导航后重新定位，保留拒绝提示。** 旧句柄或偷偷换值都会让观察偏离原本要测的输入。
8. **没有页面权限也交记录。** 区分已有资料、缺失观察和建议动作，未验证的记录也能接着用。
9. **不为补证据而提交。** 如果此前提交结果未知，只查原请求，绝不重放。

## 工作流程

### 1. 定位目标字段

- 记录页面版本、所属表单、标签或可访问名称，以及预期格式或单位。
- 排除隐藏副本和无关同名控件。
- 检查可见、可编辑；如知道遮挡或禁用原因，原样记录。
- 导航后先确认新页面上下文，再重新定位控件。

### 2. 记录操作与显示结果

- 在已授权的实际操作中，使用正常填充或键盘输入。
- 替换旧值前说明怎么清空，避免误追加。
- 格式被拒时，不擅自换成另一个业务值。
- 记录输入方式、观察时点、显示值是否匹配；敏感值脱敏。
- 仅交文档时，注明哪些动作来自资料，哪些只是建议。

### 3. 找能归到该字段的应用信号

- 记录校验提示、关联按钮或派生值，并注明证据位置。
- 变化必须能归到目标字段和当前页面，而不是上一次渲染。
- 按钮若依赖多个字段，不能只凭禁用就认定本字段失败。
- 正常操作需要离开字段时，走正常失焦路径，不用提交来失焦。

### 4. 给出证据支持的状态

- `已生效`：显示匹配，且相关应用信号证明接受。
- `未生效`：校验已明确拒绝，或观察到应用状态确实没有同步。
- `校验中`：能确认异步检查仍在运行；写出等待的信号。
- `未验证`：资料或权限不足以证明应用状态；写清缺了哪层。
- 同时写支持结论的证据和仍未知的部分。

### 5. 给一个下一步，或停止

- 写一个正常交互或观察，附上限和完成信号。
- 等指定的应用状态，不只等页面加载。
- 已生效就停；如果非提交不可继续观察，说明限制并停止。
- 有草稿与提交工具时，读必要资料，写完整记录，再同轮顺序提交。

## 输出模板

```markdown
# 输入生效核对｜[字段]
页面／表单：[版本或视图]／[所属表单]
目标：[标签或可访问名称]｜[可见／可编辑／阻碍]
期望格式／单位：[格式或未提供]

## 操作与显示
- [方式和清空行为]｜[观察时点]｜[显示是否匹配，已脱敏]
- 来源：[实际观察／资料记载／仅建议]

## 应用信号
- [校验提示／关联控件／派生字段]｜[证据位置]
- 归属：[为什么适用于该字段和当前页面]

## 结论
- [已生效／未生效／校验中／未验证]，依据：[证据]
- 缺口：[缺失信号或无]
- 下一步：[一个正常动作、上限、完成信号／停止]
- 最终提交：未执行
```

## 完整示例

### 示例一｜联系邮箱显示正确，应用模型却是空的

**输入。** 账户页 r8 的联系邮箱在个人资料表单里，不是页头搜索框；另有同内部名称的隐藏字段。
先前脚本设置了可见字段的 DOM 值。给定的 r8 检查显示目标字段模型为空，且没有校验正在运行。
保存按钮禁用，但它还依赖其他字段。本次不能保存。

**反例**

> 地址已经显示，强行启用保存点一下就能验证。

**正例**

> 目标：r8 个人资料 → 联系邮箱，可见控件，邮箱格式；排除隐藏副本与页头搜索框。
> 显示：DOM 赋值后匹配，值已脱敏；来源为给定的 r8 检查记录。
> 应用信号：同一记录显示字段模型为空，且无校验在运行；保存按钮禁用不是该字段独有的信号。
> 结论：该次观察中未生效。建议下一步：用正常键盘交互清空并替换一次，在现有测试窗口内观察字段被接受或出现最终校验提示。
> 本记录未实际操作页面，未执行最终提交。

### 示例二｜应用还在查工作区标识是否可用

**输入。** 新建工作区 r12 表单的可见标识字段已有旧草稿。测试者全选后输入指定的小写标识。
页面显示正确的值与“正在检查可用性…”。测试从观察时点起最多等五秒。
应用验收信号为同一标识显示“可用”；本次不创建工作区。

**反例**

> 继续按钮还不可用，换个标识，点创建看看。

**正例**

> 目标：r12 新建工作区 → 标识，可见、可编辑，小写标识格式。
> 操作：键盘全选替换；输入后观察到显示值匹配。
> 应用信号：该字段旁显示“正在检查可用性…”，未出现接受信号。
> 结论：校验中，不是已拒绝。下一步：观察同一字段最多五秒，看到“可用”、最终拒绝或到期即停；到期时报告最后状态。
> 保留原标识，未执行最终提交。

## 常见错误与警讯

| 警讯 | 应该怎么写 |
|---|---|
| “选择器找到一个元素” | 写明可见可编辑的控件、所属表单和页面。 |
| “看起来正确，所以成功” | 单独记录应用信号。 |
| “按钮禁用就是本字段不合法” | 查明实际依赖；不知道就保留不确定。 |
| “还在校验，所以被拒绝” | 标为校验中，在上限内观察。 |
| “导航后沿用旧元素” | 在新页面上下文重新定位。 |
| “点提交试试看” | 写明观察限制，停止，不提交。 |

## 交付前自检

- [ ] 已排除隐藏副本及无关表单。
- [ ] 格式、单位和清空方式没有改变用户指定的值。
- [ ] 显示与应用证据分列，敏感值已脱敏。
- [ ] 信号属于当前页面和目标字段。
- [ ] 异步校验没有被写成最终拒绝。
- [ ] 实际观察、资料记载、建议动作三者分开。
- [ ] 只有一个有界观察动作，或明确停止。
- [ ] 没有最终提交，也没有重放请求。

## 交付即止

要交的是记录，不是提交后的表单。输入生效不证明业务已提交。
如果下一条证据只能靠最终提交获得，写明限制并停在这里。
