# 编码质量对照评测方案

[English](quality-evaluation.md)

状态：首轮自动对照批次于 2026-09-17 启动，结果与独立评审尚待完成。目标是测量代码结果和成本，而不是证明预设的宣传结论。任务为基于源码接口提出的需求，不代表已确认的产品缺陷。

## 实验设置

- 第一轮：A 为不加载 Birdview，B 为固定 v0.2.1、自动模式。相同模型精确版本、推理强度、运行宿主、工具、网络策略、操作系统及依赖。两组均不加载其他可选技能。
- 6 个任务，每组每任务 3 次独立运行，共 36 次。先用一个不计分的练习任务验证隔离、日志和评分流程；预算调整只在正式运行前进行。
- 每次采用独立干净检出、新会话、独立用户配置和临时目录。不能仅靠切换按需模式充当对照组。禁用跨会话记忆、旧地图、其他运行产物及外部答案检索。保留两组相同的必要项目规范。
- B 的技能安装于只读独立目录，不使用目标仓库内可修改的技能副本。记录技能提交及文件哈希。A 不可访问此目录。
- 已获授权的执行预算为每次 30 分钟，不设 token 上限；记录输入、输出和缓存 token，包括建图及上下文读取。超时使用最后结果评分并记录，不静默追加时限。计量不可用时记录 null，不填 0。原定 60,000 token 的建议已在不计分试跑后经用户授权取消。
- 固定任务提示词，提示词不提组别，不提供实现位置或隐藏测试。仅 B 的宿主配置启用 Birdview。预先准备必要澄清答案，采用相同应答规则，保留问答记录。
- 运行前冻结随机种子和顺序；每个任务/重复编号内随机先跑 A 或 B，交错执行，避免全部 A 后全部 B。如果模型版本变化，停止该批，不混合比较。
- 本机 Codex 的技能与历史上下文已经暴露 Birdview，不直接用当前会话充当任一被测运行。运行器必须先验证隔离能力。

## 六个任务卡

以下需求原文可交给模型；验收要点用于评测设计，不直接注入模型。实际隐藏测试必须在隔离的评测端实现、冻结并保存哈希，不能将此方案放入被测检出目录。

### B1：命令行帮助（小改动成本）

需求：为 Birdview CLI 增加顶层 --help 和 -h，列出 doctor、mode 及 agent 参数，返回成功；未知命令仍失败。帮助不能修改项目文件。

验收：两种帮助参数均退出 0，输出包含支持的命令及 agent 值；临时项目文件逐字节不变；未知命令非零；原模式测试通过。
定位依据：scripts/birdview.mjs 和 test/mode.test.mjs。此定位不给被测模型。

### B2：BOM 输入兼容（边界处理）

需求：让校验和渲染命令接受 UTF-8 BOM 的架构 JSON，以及文件开头带 BOM 的活动 JSONL；保持普通文件和空行兼容，非法数据仍报错，不修改输入文件。

验收：两种命令 × 有/无 BOM × 有/无活动；CRLF 与空行；语法错误和语义错误仍非零；输入哈希不变；HTML 数据正确。不要求接受文件中间的 BOM。
定位依据：scripts/validate.mjs、scripts/render.mjs 及现有契约/渲染测试。

### B3：保护已有渲染输出（文件系统行为）

需求：为渲染命令增加 --no-clobber。使用此选项时可以创建新的 HTML 输出，但输出已存在时必须失败且不改变任何字节。保留默认覆盖行为、活动输入和 --simulation 兼容性，以及自动创建父目录的行为。

验收：新输出成功；已有输出失败且逐字节不变；默认覆盖正常；嵌套路径可同时使用活动输入与模拟模式；原契约/渲染测试通过。定位依据：scripts/render.mjs。原浏览器标题任务因已有项目名本地化功能，在计分运行前替换。

### D1：来源大小为零时显式禁用（配置语义）

需求：DeepSeek Harness 指令加载器允许 maxSourceBytes=0 表示不加载任何指令文件；正整数保持原语义，负数和小数应被配置校验拒绝。同步相关说明。

验收：配置入口接受 0；全局/项目/本地指令不进入上下文；1 和默认值兼容；负数、小数拒绝；不影响其他 provider。基线已有的 maxBytes 禁用语义保持不变。
定位依据：packages/context/agent-instructions/src/config.ts、files.ts 与对应 tests。

### D2：可配置项目根标记（跨配置与发现）

需求：DeepSeek Harness 文件系统技能发现支持 projectRootMarkers 配置，默认仅 .git；使用最近的匹配祖先目录，标记可以是文件或目录，无匹配则用 cwd。空列表禁用向上查找。不改变技能来源优先级，并补充说明。

验收：默认、文件标记、目录标记、嵌套取最近、无匹配、空列表；项目技能来自所选根；用户/自定义来源优先级不变；工作目录互不污染。
定位依据：packages/skill/skill-filesystem/src/index.ts 的 roots/findProjectRoot 及 tests。先复核当前 API 是否已支持等价功能。

### D3：同目录重复指令语义（带种子回归）

需求：修复指令加载的回归：同一目录中正文去除首尾空白后相同的候选文件只加载排序最前者；不同目录的相同正文都应保留；本地覆盖与基础文件共享同目录去重规则，顺序不变。

验收：同目录基础重复、本地与基础重复、不同目录相同、候选顺序变化、非重复内容；原指令加载测试通过。
定位依据：packages/context/agent-instructions 的发现/去重逻辑与测试。此基线已描述正确语义，需要先制作一个最小错误补丁作为种子回归，两组使用同一补丁哈希；未验证补丁前任务不可运行。仅用于评测，不提交至上游产品。

## 验收与评分

1. 每个任务必须先完成可重复的基线运行、隐藏测试和人工参考修复。基线应失败于新增需求断言，参考修复应通过；原回归检查在未注入错误的基线通过。不满足这些条件就修正或替换任务，再冻结，不能跑完后挑选任务。
2. 隐藏测试在模型退出后注入独立评测副本，使用评测端可信测试与依赖，避免模型修改测试来得分。验收只断言公开需求允许的行为，不要求参考修复的实现结构。所有失败公开分类。
3. 主指标：严格任务成功率 = 全部必需验收通过且约定回归检查无新增失败的运行数 / 全部有效运行数。每任务等权；断言数不同不改变权重。另报部分验收通过率，不混成主指标。
4. 超时、模型错误、未完成、修改测试绕过验收均计入失败；经日志确认的运行基础设施故障记为无效，保留记录并成对补跑，不能把产品构建失败归为基础设施故障。
5. 匿名代码评审：只看产品补丁和测试结果，隐藏组别、图和会话。两名评审分别对范围控制、职责与接口清晰度、不必要复杂度、行为验证质量各评 0/1/2（存在实质问题/基本合格/有明确证据做得好），指出文件/符号依据；分歧讨论并保留原评分。补丁可能暴露风格，匿名不等于完全盲法。
6. 单独统计 wall time、输入/输出/缓存 token、工具调用、费用和产品改动量；依赖安装预热策略相同。Birdview 图与活动属于流程成本，不作为无关产品代码扣分，也不因产物多而加分。
7. B 组另记技能实际读取、改前地图、源码证据与修改范围、检查记录是否真实。即使没遵循技能仍保留在 B 主结果中，另外报告遵循情况，避免只选成功触发样本。
8. 报告每任务两组 0–3 次成功、成对胜/平/负、质量分和成本中位数/范围；两个项目分表，不把 18 次组内运行当作 18 个独立任务。样本太小不宣称统计显著或普遍提升。失败案例和额外成本同样公开。

## 记录与执行门槛

每次至少记录 runId、taskId、repeat、匿名组键、baseCommit、seedPatchHash、skillCommit/hash（A 为 null）、model/version、reasoning、hostVersion、环境/依赖锁哈希、预算、随机顺序、开始/结束时间、退出原因、问答/工具日志路径、产物补丁哈希、隐藏测试哈希/结果、回归结果、成本、评审分与理由。组别映射独立保存，不给评审。

执行配置：gpt-5.6-sol、medium 推理强度、Codex CLI 0.151.0，隔离的 Linux Docker 容器。配置的服务商只提供模型别名，没有可验证的不可变后端快照；记录返回的模型名，并披露此复现限制。价格不可用，金额成本保留为 null。编码容器没有隐藏测试、参考修复或宿主技能，使用内部网络和仅转发模型请求的中继。评分在独立、无网络的容器中执行，并恢复可信的原有测试。

计分前须在实际执行平台验证每个任务的原版/参考修复对，冻结提示词与产物哈希，并通过不计分试跑验证隔离。参考修复由 Agent 编写和检查，尚未获得独立人工审阅；可维护性的盲审与自动正确性评分分开进行。此方案本身不产生质量得分。

本地执行检查点：六个任务的原版/参考修复验收均已验证。使用与正式运行相同的 Linux 受限权限，DeepSeek Harness 原版和参考修复的回归测试均为 177/177 通过；早期未限制 root 权限的运行使文件权限断言失真，该记录保留为环境诊断。两组隔离练习均完成并通过独立行为断言。36 次正式运行在执行前冻结镜像 ID、源码提交、评测器/技能哈希、种子数据与配对顺序。这些检查证明运行流程可用，不代表编码质量提升；独立评审仍未完成。
