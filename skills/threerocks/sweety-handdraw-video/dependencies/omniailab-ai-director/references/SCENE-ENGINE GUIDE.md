# 剧本引擎（五要素 · 压力测试 · 三层修法）

**给剧本做结构体检。** 在 AI 影视里，一场戏不成立是要花真金白银才发现的——你只有生成了才知道它不行。所以**在生成任何一个镜头之前**，先让每一场戏过一遍这台引擎。

> **与电影艺术知识层的关系**：本层是**审计工具**（五要素逐项判定 → 唯一最弱点 → 三层修法），只诊断、不改戏。**读本的方法与判准**（spine／戏剧块／叙述拍／支点／三幕功能／铺垫与回收／对抗的双向预判）来自 `FILM-ART GUIDE.md`，逐条依据见 `film-art/01-story-and-script.md`。两者同时命中时：**结构要素的判定口径以本层为准，导演化的读本解读以电影艺术层为准**；**两层都不改戏**——改写一律由创作者拍板。

## 在本流水线中的定位与边界

- **本层位于流水线的最前端（P0 之前 / P0A 之中）**，只处理**剧本结构**；它不管镜头、不管资产、不管提示词。
- **默认只做诊断**。本 skill 的主流程只处理**已定稿剧情**（不改戏、不加角色、不加台词、不改结局）。因此本层在流水线内的用法是 **AUDIT（审计）**：逐要素判定 + 指出**唯一最弱点** + 给修法建议，**由创作者拍板**，代理不得自行改戏。
- **WRITE / 共写模式属于流水线之外**：仅当创作者明确说"帮我写这场戏/给我几个方案"时才启用。此时剧本尚未定稿，仍走本层，产出交给创作者定稿后再进 P0。
- **不单独计为一个子技能**，是剧本层的规范。

## 何时调用 · 怎么调用

| 时机 | 怎么用 |
|---|---|
| **用户丢来一个剧本／大纲／一场戏，问"这行不行""哪里弱"** | 走 AUDIT：逐要素判定，输出唯一最弱点与三层修法。**不改戏**，只给建议 |
| **P0A 剧本解析时** | 用本层给每场戏标注结构判定（尤其"反转是否惰性"），**作为解析结果的一部分呈现**；创作者要改则回到剧本层处理，改完重新从 P0 开始 |
| **用户要写新场次／要几个方案** | 走 WRITE / CO-WRITE（流水线之外）。多个方案必须在**战术与／或反转**上不同，而不是只换语气 |
| **整本剧本问结构** | 先按"危机开启→危机解决"**切分序列**，再逐序列审计 |

## 一、五要素引擎（定义是精确的，不得用教科书版本替换）

### 1. 目标（Goal）

主角为之搏斗的**那唯一一件、从头到尾不变的事**：修正**已经建立**的问题，并尽可能快地达到解决它的结果。

- "已经建立"指的是**此前被铺下的一切**——可以是深背景、可以是几场之前、也可以是**一分钟之前**（上一场留下的烂摊子，就是这一场要修的"过去"）。
- **主要目标永不改变**，主角在目标上**永远不会判断错**。
- **每一场戏的目标都必须是通往故事目标的因果链上的一环。** 检验法：**把这场戏整段删掉，通往故事目标的链条依然成立 → 这场戏不通过"目标"检验。** 不允许孤儿场次。
- 主角**可以**错——但只能错在**战术**上，绝不能错在目标上。
- **"他本该怎么做"不是一个独立的检验项。** 正确动作由**障碍＋代价**共同决定，是环境让正确动作变成非选不可（他不能一身臭汗去提案——保安直接拦）。若代价不同（生死关头），同一个障碍（脏）就不成立了。所以"正确的战术"就是**障碍与代价逼出来的那个**。若主角采取了一个**代价不足以为其辩护**的战术，就要标出来，并说明这是败笔还是刻意自毁。

### 2. 障碍（Obstacle）

**一个强悍的情境，它使"路径上的某一环"或"整个目标"陷入危险。** 它是**威胁**，不只是**代价**——它让某一环（或整个目标）**有失败的可能**。

- 它可以是一片**需要搜索的分叉空间**（要翻的很多文件夹、时间、耐心、专注、没人来打扰），也可以是一堵**单点硬墙**（电池没电——没法在一台死机器上搜索）。**单点硬墙通常会催生一个新的子目标**，并带出它自己的一片地形（找充电器 → 家里没有 → 去买/去借）。
- 障碍有**两个尺度**：**局部**（威胁当前这一环）或**全局**（威胁整个目标）。**每一次都要指明是哪一个。**
- 障碍是**逼主角做出选择或改变战术的那个东西**。没有危险 → 不需要战术 → 没有戏。
- 审计检验：**说出被置于危险的是什么、在哪个尺度上。** 如果没有任何东西真的处于危险中，这个障碍是假的，这场戏会松掉。

### 3. 战术（Tactic）

**威胁逼出来的那一步**——基于主角**当前（通常是不完整的）认知**做出的**合理猜测**。这是**不确定条件下的搜索**，不是"因为蠢而犯错"。

- 一个"错"的战术不是笨。它是对一片他看不全的空间所做的**合理试探**（去"图片/家庭"文件夹找那张照片——不在；而现在他**知道**它不在那儿了）。主角**误读了障碍、输入输出、或情势**；他看不到真相会揭示的东西。引擎的本质是**一处认知/真相的落差**：他所相信的，与真实情况之间的距离。
- **每一次失败的战术都必须交回信息**，收窄搜索范围，并重塑下一步。戏剧性来自**收窄**，不是惩罚。
- 审计检验：
  - 好：战术是他根据现有信息做出的合理下注，**且它的失败告诉了他（和我们）新东西**。
  - 弱：他根本没有理由去试的战术；**或一次零信息的失败**（他什么都没学到、搜索没有收窄——原地打转、重复翻同一个文件夹）。
- 失败的战术**只有在"失败什么也没教会"时才算弱点**。

### 4. 反转（Reversal）

**一次与预期相反的转折。** 形态有三种：

1. **我自己的动作反过来咬我**——我为了某事做的动作，开始反对那件事（我为了提案去洗澡 → 洗澡让我迟到，错过了提案）。
2. **隐藏的能动性被揭示**——我以为我在作用的那件事/那个人（或是看起来中立的那个），其实一直在**作用于我**，或帮我、或害我（买家一直在促成我的失败／暗中力挺我）。这是惊悚片的招式，常在**真相落差闭合**的那一刻点火。
3. **一般情形**：局势转向了与战术意图相反的方向。

**配额规则**：

- **每一个序列至少一次反转**，可以更多。单场戏可以纯粹是升级；但一个**已经解决的序列若零反转，即为不合格**。
- **序列** = 从某个特定危机（威胁某一环/子目标的障碍）**开启**，到它**解决**（被克服，或它击败了主角、逼他改道）为止的那一串场次。路径上的一环 = 一个子目标，由威胁它的那个障碍来定义。
- **序列会嵌套**（电池没电催生"去买充电器"，那是一个自己的小序列）。**每一个解决单元都需要它自己的反转**，并要标注尺度：完整子目标序列 vs. 其内部子序列。

### 5. 价值转变（Value Shift）

**由反转触发、发生在观众心里的那次"对这个人的重新判断"。** 这是拱心石，也是最容易被误解的一环。它**不发生在剧本页面上，发生在观众脑里**。

- 每一次反转都强迫观众**重新评判**这个角色。例如同一个主角跨多次反转的判断轨迹：*人不错 → 是老手 → 有点狡诈 → 不对，他是走投无路 → 是孝顺儿子 → 他其实是个孩子 → 这才是真正的男人该有的样子 → 一个男人*。
- 核心规则：**没有价值转变的反转是惰性的（inert）。** 一次结构转折**只有**在它推动了观众对**这个人**的判断时，才算反转。如果你说不出观众的**"前判断"和"后判断"**，这个反转就是死重，无论情节翻了多少。
- 一次序列上的价值转变应当构成**一条被设计过的、不断加深的弧线**，而不是随机来回翻。审计要看**轨迹**：这些重判是在搭建一个令人意外、不断加深的人物肖像，还是只是在摇摆？

## 二、完整因果链（一切以此为主干）

```text
目标（固定引擎；每一场戏都是通往它的因果链一环）
→ 障碍（强悍情境，使某一环或整个目标陷入危险；指明被危及的是什么 + 尺度）
→ 战术（威胁逼出来的那一步；基于当前认知的合理猜测；其结果必须交回信息并重塑下一步）
→ 反转（与预期相反的转折：我的动作反过来咬我，或隐藏的能动性被揭示；每个序列至少一次）
→ 价值转变（反转迫使观众重新评判这个角色；没有价值转变 → 反转无用）
```

## 三、三种模式

- **审计（AUDIT）**：创作者给出已有的场次／序列／大纲／整本剧本，要测试与诊断。
- **写作（WRITE）**：创作者要求写一场戏、出一个方案。
- **共写（CO-WRITE）**：来回迭代——他写，你给方案和修法，如此往复；过程中持续跑审计逻辑。

## 四、审计流程

按顺序走完链条（反转与价值转变要放到**所属序列**的范围里看）：

1. **目标**：用一句话说出这场戏的目标。它是通往故事目标的因果链一环吗？跑**删除检验**。不知道故事目标 → 先问，否则无法完整审计目标。
2. **障碍**：说出那个强悍情境、**它危及的到底是什么**、在**哪个尺度**（某一环／整个目标）。没有任何东西真的处于危险 → 标为松弛。
3. **战术**：找出战术。它是基于现有认知的合理猜测吗？是被危险**逼出来**的吗？结果**交回了信息**吗？标出零信息失败与无动机战术。
4. **反转**：在序列里定位反转。是哪一种形态？确认**每个已解决的序列至少一次**。零次 → 不合格。
5. **价值转变**：对**每一次**反转，说出观众对该角色的**前判断 → 后判断**。说不出 → 该反转为**惰性**（标为优先修复项）。再评估整条**轨迹**：是加深的设计，还是随机摇摆。

### 输出结构

```text
场次/序列：<一行定位>

链条检查
• 目标 —— <判定 + 一句话>
• 障碍 —— <被危及的是什么 + 尺度 + 判定>
• 战术 —— <是否被逼出？是否合理猜测？是否交回信息？判定>
• 反转 —— <形态 + 是否存在？序列内是否有至少一次？判定>
• 价值转变 —— <每次反转的前判断 → 后判断；若说不出则写「惰性」；并给轨迹评语>

唯一最弱点：<修好它，收益最大的那一个要素>

如果……会怎样
1.（最小改动）<保留创作者版本，只改那一个最弱点，其余照旧成立>
2.（干净修法）<一个完整成立的版本，即便离原作更远>
3.（可选）<只有确实必要／确实加分时才给>
```

## 五、五条纪律

1. **定义是精确的，不是教科书的。** 判断或动笔前，重读相关要素的定义。
2. **反转配额是硬的**：每个已解决的序列 ≥1 次。
3. **先切序列，再审计**。整本剧本要先切分，再逐序列走链条。
4. **最常见的真实失败：翻了情节、却没动观众判断的"惰性反转"。** 永远优先把它揪出来。
5. **多个方案必须在战术与／或反转上不同**（这样价值转变才不同），不能只是换语气。

## 六、交付前质检

- [ ] 每一场戏都通过**删除检验**（删掉它，通往故事目标的链条就断）？
- [ ] 每个障碍都指明了**被危及的是什么**与**尺度**？
- [ ] 每个失败的战术都**交回了新信息**、收窄了搜索？
- [ ] 每个已解决的序列都有**至少一次反转**，且形态明确？
- [ ] 每一次反转都说得出观众的**前判断 → 后判断**（没有惰性反转）？
- [ ] 价值转变在序列层面构成**加深的弧线**，而非随机摇摆？
- [ ] 全流程**只诊断、不改戏**；任何改写都由创作者拍板？
