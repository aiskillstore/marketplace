# BLOCKING — 站位与场面调度层（跨镜站位锁定）

把「人物站在哪、朝哪、怎么动」从散文描述升级为**可复用、可核查的坐标数据**，让同一场景的站位在全部镜头之间保持一致，消除「上一镜还在原位、下一镜就漂了」的问题。

---

> **与电影艺术知识层的关系**：本层管**坐标与跨镜一致**（人在哪、朝哪、怎么动，可核查、可继承）。**为什么这么走**——走位必须有动机、纵深与层次、群戏以组为单位、距离与无用空间——来自 `FILM-ART GUIDE.md`，见 `film-art/05-staging-and-camera.md`；**关系线与越轴判断**见 `film-art/04-visual-language.md`。**坐标与协议以本层为准，调度设计与越轴判断以电影艺术层为准**——先有调度设计，再用本层把它锁成坐标；反过来做（用机位补走位）戏不会变好。

## 一、在本流水线中的定位与边界

本文件是 OmniAiLab AI导演 skill 的**站位／场面调度层**，挂在 CINEDANCE（视频提示词）体系下，与 ACTING（表演）、EMOTION（情绪）、LIRA（图像）、STYLE（画风）、COMBAT（打斗）并列协作，**不单独计为一个子技能**。

它只负责「人和物在空间里到底站在哪、朝哪、怎么动、怎么跨镜不变」——坐标、朝向、姿势、走位路径、机位坐标、间距与穿模、跨镜连续性。

七条边界规则（重要，优先于本文件内部的默认值）：

1. **只管空间，不写文案。** 本层产出「站位摘要 + 站位数据 + 场景数据」，**不产出图像或视频提示词正文**。提示词由 LIRA（图像）与 CINEDANCE（视频）按本层数据编写。
2. **镜头口径从属主流程。** 站位数据描述「摄影机在哪、朝哪」，但景别、运镜方式、切镜结构一律服从 P4 已确认的分镜设计与 P1 摄影基准；本层不改变已确认的镜头设计。
3. **姿势口径从属 ACTING／EMOTION。** 本层只给**身体的空间姿态**（站／坐／卧／跪／格斗…）与关节角度；角色为什么摆这个姿势（目标、障碍、策略、节拍、情绪命题）由 `ACTING GUIDE.md` 与 `EMOTION GUIDE.md` 决定。本层不写表演动机。
4. **打斗口径从属 COMBAT。** 含近身对抗时，动作内容（动作脊柱、动作链、镜头契约、观察轴）由 `COMBAT GUIDE.md` 编排；本层只负责把 COMBAT 的动作**落到坐标与姿势上**，并统一武器 ID 口径。
5. **参数不进提示词正文。** 本层数据中的 `aspectRatio`、`fov`、时长等是**导演台与平台的结构化字段**，只允许出现在场景数据文件或平台 UI 中，**不得写进图像／视频提示词正文**（正文里用"宽幅横幅画面""本镜实际时长"这类语境描述）。
6. **工具口径。** 场景数据是 **OmniAiLab 导演台** 的结构化输入。字段名以 OmniAiLab 导演台实际上架字段为准；若实际字段与本文件 schema 的命名不一致，按**语义等价**映射（位置→坐标、朝向→角度、姿势→预设…），不得删改语义。
7. **只处理已定稿剧情。** 不借本层新增角色、改变人物关系或增减场景物件。

平台口径：本层只使用 **OmniAiLab**（https://www.omniailabx.com/）的导演台与画布能力。署名统一为 `OmniAiLab`。

## 二、根因与解药

### 漂移的根因

每个镜头都用**文字重新描述一遍空间**。AI 读到的是"女主在教室中央、几个男生倒地"这类**每次措辞都不同、且没有坐标系**的句子，于是每一镜都独立重新推断布局 → 位置、朝向、左右关系、距离全部重新掷一次骰子。

散文锚点（"1 米以内""背靠墙壁"）解决了**单镜内**的准确性，但解决不了**跨镜**的一致性：下一镜重写时，这些锚点会重新组合。

### 解药：一场景一份站位基线，全片共用

- 一个场景（空间）只有**一份**「站位基线」：所有在场角色的坐标、朝向、姿势、所持武器、道具位置与机位基准，写死在数据结构里。
- **每个镜头从基线取数**，只改本镜真正发生变化的字段（谁移动了、谁转身了、谁倒下了）。
- **不需要变化的角色一律冻结**（`locked`），镜头数据里保留基线值，不重写、不重新描述。
- 换镜时必须显式写明「谁、从哪、到哪、经过什么、耗时多久」；**没写的人 = 没动**。

> 核心纪律：**没有坐标变化证据，就不许改站位。**

## 三、工作流

1. 从剧本／分镜提取：场景、人物与关系、关键动作、武器、道具、视角、光线、剧情重点。
2. **先定人物位置与朝向 → 再定支撑物与环境道具 → 最后定镜头、光线与连续性。** 顺序不可颠倒。
3. 为每个角色选择 `posePreset`；只有预设无法覆盖的精确动作才补 `poseControls`（逐关节角度）。
4. 依动作语义从武器库选唯一稳定的 `weapon` ID（见 `blocking-weapon-library.md`）。用户明确指定时以用户指定为准；**无武器语义时省略 `weapon`**，不给日常人物或未成年人自动配武器。
5. 校验：落地／坐姿支撑、穿模、遮挡、人物间距、行动通道、武器握持、画幅安全区。
6. 按固定四段格式输出，并逐镜完成跨镜连续性自检。

---

## 四、空间与朝向规则

- 地面为 `y=0`，`+Y` 向上；主要行动区靠近 `[0,0,0]`。
- 人物正面朝向目标点 `[tx,tz]` 时，朝向角 `facing = atan2(-(tx-x), -(tz-z))`。
- 朝向角约定：

| `facing` | 正面朝向 |
|---|---|
| `0` | 朝 `-Z` |
| `1.5708` | 朝 `-X` |
| `-1.5708` | 朝 `+X` |
| `3.1416` | 朝 `+Z` |

- 单位一律为**米**；坐标为场景世界坐标，同一场内跨镜**不得换算、不得更换原点**。

---

## 五、姿势预设与关节控制

支持的 `posePreset`（21 项）：

`stand`、`t-pose`、`walk`、`run`、`sit`、`lie`、`crouch`、`kneel-one`、`kneel-two`、`hands-on-hips`、`lean`、`bow`、`think`、`fight`、`kick`、`throw`、`push`、`wave`、`reach`、`cross-arms`、`phone`

- **坐姿**必须匹配椅子或长凳的实际位置与高度；**倒地**人物贴近地面；**站立与奔跑**至少有一只脚可靠接地。
- 预设表达不了的精确动作，用 `poseControls` 覆盖：身体、躯干、头、肩、肘、手、髋、膝、脚的角度。
- 优先用预设；关节控制只补真正需要的自由度，不要用关节角度重写整个姿势。
- 同一角色跨镜保持同一姿势语义时，**沿用同一预设并冻结**，不要换一个近义预设重新描述（那是漂移的常见入口）。

---

## 六、多人间距、通道与遮挡

- 人物与实体道具之间通常保留至少 **0.35 m** 间隙。
- **动作通道**（走位路线、挥击弧线、刺击方向）不得穿过墙体或主要道具。
- 遮挡要有意为之：前景遮挡必须写明「谁遮谁、遮住多少」，不许出现偶然穿模。
- 画幅安全区：处于画面边缘的角色，其动作幅度要保证不因运镜跑出画外。

## 七、高度与支撑校验

- 每个角色都必须有明确的**支撑**：地面、椅面、墙、台面、或另一个角色。
- 悬空状态（跳、飞、被击飞）必须写明**起跳点、最高点、落点**以及落点支撑物。
- 同一场内不许无理由改变支撑状态；换场景时重新建立基线。

---

## 八、镜头与路径（坐标层）

- 机位与人物在**同一个坐标系**里算关系：`camera.position`、`camera.target`、`camera.fov`。机位侧（谁在摄影机左／右）由坐标自行推导，不靠形容词。
- 人物位移使用 `movementPath`（至少两个 `[x,y,z]` 点），顶层用 `characterPathDuration` 指定时长。
- 连续运镜使用 `camera.keyframes` 与 `camera.pathDuration`；路径应避开墙体与演员动作区。
- 第一视角 `bodyView` 仅使用 `hands` 或 `none`；`handView` 可为 `left`、`right`、`both`。
- 画幅候选值与全部字段定义见 `blocking-stage-schema.md`。**这些值只进导演台字段，不进提示词正文。**

---

## 九、跨镜连续性协议（本层核心）

### 9.1 建立基线

场景首次进入时建立该场景的「站位基线」，包含：全部在场角色的 `id`／`name`／`color`／`position`／`facing`／`posePreset`／`poseControls`／`bodyType`／`scale`／`weapon`，以及场景道具与机位基准。

**基线一旦确认，即为该场景全片的唯一真相。** 后续任何镜头都不得凭印象重写。

### 9.2 逐镜取数

- 每个镜头只写**本镜发生变化**的角色字段；未变化角色继承基线并保留 `locked`。
- **发生位移**的角色：写 `movementPath`，或写「起止坐标 + 耗时」，二者必居其一；不许只写"走过去"。
- **发生转向**的角色：写新的 `facing` 值与转向原因（被叫住／转身取物／回身应对）。
- **武器状态变化**（拔出／放下／脱手／换手）必须显式写出，并在后续镜头继承新状态。
- **新入场／离场**必须写明入场点坐标或离场方向，禁止凭空出现或凭空消失。

### 9.3 换镜必须继承的十二项

1. 当前在场角色名单（不多不少）
2. 地点地理布局与坐标原点
3. 画面左右关系与轴侧（除非本镜有意越轴；越轴须按分镜规则与 `COMBAT GUIDE.md` 的「观察轴与越轴重建」处理）
4. 视线目标
5. 光照方向
6. 服装与配饰
7. 伤口与污渍
8. 手持道具与武器
9. 手部状态（握什么、空不空）
10. 血、雪、灰、汗、水、火、烟等附着连续性
11. 物体状态（门开合、灯明灭、椅子倒没倒）
12. 情绪发展（承接上一镜，不归零）

切镜后**不得重置动作**、**不得让人物瞬移**、**不得在无时间与位移支持时改变与地标的距离**、**不得引入新道具或新角色**。

### 9.4 漂移排查顺序（发现站位漂时按此顺序查）

1. 该场景**有没有**建立基线？没有基线 → 先补基线，这是首要原因。
2. 本镜是否**重写了未变化角色**的坐标／朝向／姿势？重写 → 改回继承 + `locked`。
3. 位移角色是否只有"走到"而没有坐标或路径？补 `movementPath` 或起止坐标 + 耗时。
4. 机位是否与人物在同一坐标系？机位另算一套 → 把机位拉回同一坐标系。
5. 是否换了近义姿势预设／近义道具名？统一为基线里的同一取值。
6. 十二项继承项逐条对照，找出第一条不一致的项。

## 十、与主管线的对接

| 本流程阶段 | 站位层做什么 |
|---|---|
| P1 创作基准 | 只读、不介入：画幅与镜头家族以 P1 为准，本层的 `aspectRatio`／`fov` 必须服从 P1 锁定 |
| P2 角色母板／设定板 | 角色一致性锚点（脸型／发型／服装／工牌）在本层以 `id`／`name`／`color` 绑定，便于跨镜点名 |
| P2 关键道具 ／ P3 场景资产 | 道具与场景作为**空间锚点**进入站位数据：道具用 `kind`／`size`，建筑构件用 `box.semanticType` |
| **P4 分镜与首帧** | **主战场。** 先出全片站位基线与逐镜站位表，再生成首帧；首帧提示词里的空间描述必须由站位数据翻译而来，不得另行措辞 |
| **P5 视频提示词** | CINEDANCE 从站位数据取：首帧状态、空间调度、视线与身体朝向、地标邻近性、移动方向与路径 |
| P6 生成／剪辑 | 质检时按「换镜必须继承的十二项」逐镜核对 |

## 十一、输出格式

严格依次输出：

1. **【站位摘要】**：主体、景别层次、行动关系与镜头重点（给人看的一句话级说明）。
2. **【站位数据】**：人物表（编号／名称／颜色／坐标／朝向／姿势／武器／身体类型）＋ 道具与支撑表 ＋ 机位参数 ＋ 连续性继承项。
3. **【假设与风险】**：关键假设，以及遮挡、碰撞、支撑、出画风险。
4. **【场景数据】**：`SCENE_JSON`，无注释的有效 JSON（字段定义见 `blocking-stage-schema.md`）。

> 站位数据与场景数据是**内部中间产物与可选交付物**，不是提示词。若作者使用 OmniAiLab 导演台，可将 `SCENE_JSON` 作为导演台输入；即便不使用导演台，**【站位摘要】与【站位数据】仍必须产出**——它们是跨镜一致性的唯一依据。

## 十二、交付检查

- 场景数据包含 `scene`、`characters`、`props`、`camera`、`lighting`、`continuity` 六个顶层键。
- 只生成当前版本支持的姿势、武器与第一视角字段。
- 人物落地或坐稳；武器与动作匹配且不穿模；间距 ≥ 0.35 m；动作通道未被墙体或道具堵死。
- **逐镜核对十二项继承项**；未写明的角色一律保持基线位置与朝向。
- 站位摘要、站位数据、风险说明与场景数据**四者互相一致**（附录 B 为逐项清单）。

## 附录 A：站位示例（五则）

用于说明如何把一句粗略构想翻译成坐标化站位。示例沿用源素材的五个典型多人场面，已按本流水线口径（真人实拍、坐标化、【参数不进正文】）改写。

### A1 · 教室群战（一人 vs 多人倒地）

- **输入构想**：日本教室；女主（JK 制服少女）摆格斗姿势，多名反派被击倒、姿势各异，教室一片混乱；真人实拍。
- **站位要点**：
  - 女主 `char_heroine` 立于原点附近 `[0,0,0]`，`facing` 面向最近倒地者，`posePreset: fight`。
  - 倒地反派 4–5 名，围绕女主呈扇形散布，距女主 1.0–2.2 m，`posePreset: lie`，各自 `facing` 取不同值以形成"姿势各异"。
  - 支撑与环境：翻倒课桌用 `box.semanticType: step` 作前景遮挡块；散落纸张作为地面层，不计入人物间距。
  - 机位：略高于人群的俯角中景，`camera.position` 同时覆盖女主与最近两名倒地者。
- **关键约束**：女主与每个倒地者间距 ≥ 0.35 m；倒地者全部贴地且互不重叠；前景课桌不得遮住女主面孔。

### A2 · 第一人称视角（主体在镜头外）

- **输入构想**：第一人称；日本教室；主角是普通男生（镜头外、看不到脸），看到女主被围住，紧张握拳、想上前救援。
- **站位要点**：
  - `bodyView: hands`，`handView: both`；主角本体不入画，仅通过手部与视点存在。
  - 女主与围困者位于主角正前方 3–5 m，形成纵深分层：女主处于中景，围困者环绕其外圈。
  - 机位 = 主角视点坐标，其 `facing` 与主角朝向一致。
- **关键约束**：第一人称下需防手部比例失真；围困者不得遮住女主面部；主角本体不得意外入画。

### A3 · 街道对峙（俯拍、持械）

- **输入构想**：日本街道；男女主着学生制服摆战斗姿势，反派体型各异、持不同武器；机位为反派背后上方俯拍。
- **站位要点**：
  - 男主女主并肩或背靠背居中，离地支撑为街面。
  - 反派 3–4 名在外圈形成包围，包围圈留出**唯一缺口**（即主角的突围方向）。
  - 武器按 `blocking-weapon-library.md` 选稳定 ID（如 `baseball-bat`／`knife`／`parang`）。
  - 机位置于反派背后上方，其 `facing` 与包围缺口方向呈明确定角。
- **关键约束**：进 `fight` 编排前先定 A／B 画面位置与包围缺口方向（动作编排交 COMBAT）；兵器挥击侧各留 ≥ 0.8 m 空间。

### A4 · 空中追击（悬空支撑）

- **输入构想**：中景；超能力少女（JK 制服）以超人姿态飞行逃离包围，后方反派变异人在空中发射能量波攻击；写实风格。
- **站位要点**：
  - 女主位于高空 `y≈2.5`，`facing` 朝逃离方向；反派在后方呈扇形，`y≈1.8–2.2`。
  - 飞行 = **悬空支撑**，必须写明起跳点、最高点与落点（本场次落点待后镜给出）。
  - 能量波方向与各反派 `facing` 一致，不得朝向自相矛盾。
- **关键约束**：空中角色间距 ≥ 0.35 m 且拍点／翼面不得重叠；**高度值必须显式写出**，不得只写"在空中"。

### A5 · 城市街道战斗破坏（人群逃散）

- **输入构想**：日本秋叶原；环境遭战斗破坏；主角为人形怪物、抬腿攻击，人群四散逃跑；写实电影。
- **站位要点**：
  - 怪物居中偏前景，`posePreset: kick`，`bodyType: giant`。
  - 逃跑人群在后景分层散开，`facing` 一律背离怪物；各人之间保留 ≥ 0.35 m。
  - 建筑构件（招牌、围栏、车辆）以 `box.semanticType` 标为 `wall`／`vehicle` 等，作为空间锚点固定街道走向。
- **关键约束**：逃跑人群不得逆流；破坏构件不得落在任何角色的动作通道内；怪物动作幅度与画幅安全区需匹配。

## 附录 C：站位示意图法（`@staging_` —— 用一张图直接控制站位）

本文件正文的**坐标基线**解决的是内部一致性：谁在哪、跨镜有没有漂。当一个镜头需要**人物精确的多点站位**（谁在画面哪个位置、什么姿势、朝哪边），而文字怎么写都说不清时，用示意图法——把站位**画出来**交给模型。

### C.1 原理

让模型把这张图当作**一套空间数据系统**（线、颜色、位置、方向）来读，**而不是一张要照着抄的画**。（对外称呼时**刻意避开"图片""参考图"这两个词**，就叫它"位置图／示意图"。）

### C.2 三层反渗色架构（必须同时成立）

示意图的画风一旦渗进成片就是灾难。渗色有三个入口，全部要堵：

1. **图像层**：人物只是**细线轮廓、不填色**。线条读作"图纸"，大块平涂读作"美学"。网格线保持极淡——它是给创作者用的，不是给模型的信号。
2. **文本层**：连接器块**只用正向表述**。模型对否定很弱，「不要扁平插画／不要矢量图形／不要网格」会把 *扁平／矢量／网格* 这几个词注进视频提示词，反而点燃你要禁掉的那种画风。所以连接器**绝不描述示意图的图形风格**，只声明风格来自哪里。图形词汇只允许出现在**示意图的生成提示词**里——那里永远不进入视频上下文。
3. **结构层**：示意图**最后附**，排在场景与角色参考之后，让实拍参考主导风格投票。

### C.3 两步流程（严格按序）

**第一步：交付示意图的生成提示词。**

- 把目标画面作为**构图专用参考**：只取它的取景、机位、裁切、每个人的位置姿势与比例；**摄影质感一概不取**。
- 明确两条护栏：**不得添加画面里没有的任何东西**；**被画框切掉的身体不许补全**。
- 同时给出命名：结果图命名 `@staging_代号_场次_版本`；源帧命名 `@loc_代号_场景名_场次_版本`（见 `ASSET-SYSTEM GUIDE.md`）。
- 再给一句**颜色说明**：每个颜色在源帧里对应谁。
- **这一步只交付「生成提示词 + 命名 + 颜色说明」。**

**第二步：被要求时，交付连接器块**（粘进视频提示词参考区）。

```text
@staging_[代号]_[场次]_[版本] —— 仅作位置参考
本参考只用来读取每个图形在 @loc_[代号]_[场景名]_[场次]_[版本] 里的位置、姿势与朝向。
本镜的一切视觉品质——风格、光线、调色、脸、服装、环境、道具——
全部且仅来自 @loc_[代号]_[场景名]_[场次]_[版本] 与角色参考。本镜是完全写实的真人实拍画面。

字母对照（字母只存在于本段文字中，不出现于参考图上）
@A = 图上【蓝色】图形 = [角色资产标签] → [位置：站位、姿势、朝向]
@B = 图上【橙色】图形 = [角色资产标签] → [位置]
（每个图形一行）

渲染规则：把真实的、写实的角色（用他们各自的参考）放进场景
@loc_[代号]_[场景名]_[场次]_[版本] 中由本参考定义的位置，除此之外不取本参考的任何东西。

锁定：所有风格、光线、质感仅来自 @loc_[...] 与角色参考；
@staging_[...] 只定义位置。图上的颜色仅用于在本图内标识谁是谁，
服装与调色来自角色与场景参考。所有人保持被锁定的站位，直到剧本规定的动作发生。
```

**附着顺序：场景参考与角色参考在前，示意图在最后。**

### C.4 日常用法：有了示意图，覆盖镜头就变成对话

一场戏有了站位示意图之后，取下一个镜头不必重写全部空间描述——直接说 **"给蓝色那位一个中近景"**、**"现在给绿色那位的视角"**，就能拿到**为新景别或新机位重新排布的示意图**。同一套约定可以延伸到：

- **轨迹**：一条彩色虚线表示抛掷物或人物的横移（写明起点、路径、终点、以及触发它的那个节拍）。
- **摄影机运动**：用箭头表示推轨／摇镜方向，并在传说里声明"箭头只表示摄影机路径"。

### C.5 修改示意图的两条纪律

1. **每个元素都用它被分配的颜色来命名，绝不用物件或人名**："把**蓝色**那位移到沙发的左边缘"，而不是"把某人移过去"。颜色是示意图的语言，人名属于视频提示词。
2. **重画修正版时，永远喂给图像模型"当初那张原帧"，绝不喂上一版示意图**。示意图永远从真实镜头画出来；把一张画喂进模型，它就开始复制那张画的缺陷，而不是复制帧里的几何。

### C.6 规则

- **字母活在提示词空间，颜色活在图像空间。** 图上不出现任何字母与文字（渲染出来的字母会渗进成片）。
- **一人一色、低饱和、色相尽量分开**；颜色只表示身份，**绝不表示服装**；只描边，不填色。
- **用摄影机这一侧的正面视角**（变体见下），绝不用俯视平面图——视频模型按画面思考，不按建筑图纸思考。
- **姿势是几何**，**裁切也是几何**（被画框切掉的图形就画成被切掉的）。
- **网格是给创作者的，不是给模型的**，保持极淡；绝不在连接器里提网格。
- **绝不为了"藏干净"而牺牲信号**：要降的是**风格当量**（轮廓、低饱和、淡网格），不是**信号对比**。
- **与坐标基线的关系**：示意图法解决"这一镜的站位怎么让模型看懂"，坐标基线解决"跨镜站位不漂"。两者**同时成立**：先用正文建立基线并逐镜取数，再把本镜站位画成示意图；图中位置必须**取自基线坐标**。

**变体（几何／机位锁定型）**：当示意图**只用来锁构图与机位**、风格全部来自场景参考时，也可以用**俯视平面图**、并在图上**用字母代替人物**——但这会同时抬高渗色与字母渲染的风险，只在"确有必要且场景参考足够强"时使用。

### C.7 已知故障与修法

| 故障 | 成因 | 修法 |
|---|---|---|
| 渗色（图的画风进入成片） | 图里有填色／视频提示词里有图形词汇（**含以否定形式出现**）／图先于或替代了实拍参考 | 三层同时修：图上继续减风格当量；把图形词从视频提示词里全部删掉；重排附着顺序、示意图最后附；仍渗色则把该镜的运动语言写得朴素物理，最后一招是从该镜撤掉示意图 |
| 颜色渗进服装（蓝图形 → 蓝外衣） | 填色，且颜色语义没被路由走 | 只描边不填色；颜色只绑身份；锁定行明确把服装路由到角色参考 |
| 模型补出画面里没有的东西（补全被裁的人体、给无头躯干加头盔、凭空加家具） | 没给护栏 | 加"不得添加画面里没有的东西""不许补全被切掉的身体"两条护栏；逐图形写明裁切；失败过的元素进正向锁定 |
| 道具高度不对（刀从喉咙漂到胸口） | 位置没锚在解剖上 | 用**正向 + 对照**的说法锚定："贴着**喉咙**、下巴下方——不是胸口" |
| 站位鬼影 | 一场景多版示意图但引用了旧版 | 每镜只引用当前有效版本，重拍递增 `_v2`／`_v3` |

### C.8 质检清单

**生成的示意图（打标签之前）**：只有细轮廓、无填色无阴影；图上无任何字母文字；被裁的身体保持被裁（没有凭空补出的人头／头盔／家具／额外人物）；道具高度与源帧完全一致；姿势（头部角度、视线方向、嘴部、异常姿态）与源帧一致；取景与画幅与源帧一致。

**用了连接器之后**：成片完全写实、无任何扁平／图纸感；无白底或网格残影、无画线边缘；服装／护甲／调色里没有示意图的颜色；画面内无字母或排版文字；每个角色在其被锁定的位置、朝被锁定的方向，直到剧本规定的动作发生。任一不通过 → 回到"喂进它的那一层"去修（图像层→继续减当量；文本层→从视频提示词里删掉图形词；结构层→把示意图重排到最后），并递增版本号。

## 附录 D：首帧占用 · 弱词禁令 · 格式模式与剪辑类型

### D.1 首帧占用锁

如果这一镜必须以"人物已在画面里"开始，就直说：

```text
第一个可见帧里已经包含全部必需角色，且都在正确位置。
没有空的建立帧。不延迟角色出场。开画不缺任何必需主体。
空间关系在第一帧就立刻可读。
```

只有创作者明确要求时，才允许空的开画。要求闪切或极短建立镜头时，它**仍然必须立刻包含必需的被摄主体或地点信息**——不许空的闪切、不许抽象填充、不许随机风景插入。

### D.2 站位用可测量的物理语言，不用弱词

**弱词一律替换掉**：近处 · 附近 · 旁边 · 某一带 · 那一区域 · 周遭。

换成可测量的说法：**一米以内 · 正在触碰 · 双脚在根圆内 · 手放在把手上 · 正站在牌下 · 背贴着墙 · 在后排车门前面 · 在南侧路缘边缘**。

每个重要对象都要交代：**画面位置 · 世界位置 · 与地标或与其他角色的距离 · 身体朝向 · 视线方向 · 移动方向 · 前中后景**。

```text
@角色甲 站在那辆车残骸一米以内，一只手搭在烧焦的引擎盖上。
@角色乙 与 @角色丙 并排在前景，朝向 @角色甲。
乙在两人中的画面右侧，丙在画面左侧。两人身体都朝向 @角色甲。
两条视线都锁在 @角色甲 身上。@角色甲 从车那边正面朝向他们。
```

**地标锚定**：弱写法是"在树附近""在出租车旁""在那个地点一带"；强写法是"@角色甲 站在那辆车残骸一米以内，一只手按在烧焦的引擎盖上"。

### D.3 身体朝向与视线是两件事，都要写

`躯干朝向 X` · `眼睛始终锁在 X` · `头转向 X` · `背对镜头` · `侧脸朝画面左` · `视线越过镜头看向 X` · `除非明确说明，角色不移开视线`。

对话戏另加：**说话角色的嘴唇只为剧本台词而动**；其他角色除非明确说话，否则**安静地听**；没有明确指定的画外音一律不要。

### D.4 格式模式决策：单镜连续 vs 受控多镜

先在内部选定一个：

- **默认是「单镜连续」。**
- 只有以下情况才用「受控多镜」：创作者明确要求切镜／闪切／蒙太奇／插入／反打／硬切；动作无法在一个机位清晰调度；某个关键细节需要插入特写；两个同时发生的情绪反应需要从不同角度给；这一场需要"地理＋反应＋细节"；创作者要求预告片式、碎裂、记忆、梦境、混乱、冲击或 MV 式剪辑。

**选了多镜，就必须把每一次切镜都写清楚**：A 镜时长 · 摄影机 · 首帧可见主体 · 空间站位 · 动作 → 切镜类型 → B 镜同样。**绝不让模型自行发明未指定的切镜，绝不接受随机蒙太奇，绝不切到本镜不活跃的角色／物件／资产标签。** 每一次内切都要延续空间连续、画面方向、视线、光线方向与角色位置。

### D.5 剪辑类型白名单

只使用被命名的剪辑类型：**硬切 · 猛切 · 匹配剪辑 · 插入剪辑 · 反打剪辑 · 甩镜剪辑**。

不用淡入淡出、叠化、转场特效。除非创作者明确要求：

```text
不用淡黑。不用叠化。不用溶接。不用转场特效。只用硬切。
```

### D.6 机位与构图写成"操作员行为"

定义：镜头性格 · 机位高度 · 摄影机距离 · 机位角度 · 机位在哪一侧 · 主体大小 · 画面位置 · 摄影机运动 · 焦点行为 · 景深 · 手持质感 · 框架优先项。

偏好措辞：`摄影机固定在 X` · `摄影机从 X 移动到 Y` · `镜头在胯高` · `镜头在雪面高度` · `操作员站在阴影侧` · `主体占画面左三分之一` · `地标占住左侧三分之一` · `画面右侧留负空间` · `优先侧脸` · `优先三四分之三角度` · `只在情绪必要时正面`。

若允许构图自由，仍须保持：主体位置 · 视线 · 地标临近关系 · 光线方向 · 启用参考 · 动作时序 · 镜头性格。

### D.7 手持规则

要求手持时，**用物理语言描述**：操作员的呼吸 · 微小的自我稳定 · 重心移动 · 有机的不完美修正 · 肩托的重量 · 细微的脉动 · 人的修正。避免：数字抖动 · 随机晃动 · 除非要求否则不要云台般的丝滑 · 除非要求否则不要漂浮的无人机感 · 除非要求否则不要机械轨道感。
