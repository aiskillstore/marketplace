# 音乐场景与唇形同步（让模型演唱一首已经做完的歌）

**核心结论：视频模型不会表演你的歌。** 你让它说唱，它给你一张对着空气动的嘴；你让它生成音乐，它要么拒绝，要么给你一段剪辑会打架的东西。所以**音乐永远不从模型来**——**歌先写完录完，然后让模型去"演"它。**

## 在本流水线中的定位与边界

- **只管音乐场景的生成与对位**：歌→块→黑画面视频→提示词→唇形锁。曲风、编曲、混音属于音乐制作，不在本层。
- **与主流程的关系**：音乐段落仍然走完整流水线（P1 风格锁定、P4 分镜、P5 提示词、P6 生成剪辑）；本层是它的**专项加法**。所有镜头级规范（块序、十一条铁律、资产、站位）**照常适用**。
- **不单独计为一个子技能**。

## 何时调用 · 怎么调用

| 时机 | 怎么用 |
|---|---|
| **P4 分镜时** | 先确认**歌已经终混**（不是 demo、不是待替换的版本）；按第二节切块并规划每块对应的镜头 |
| **P5 写提示词时** | 对每个音乐块，用第三节的两条附加指令叠加在常规块序之上 |
| **P6 生成时** | **在设置里关掉生成的音频**（关键一步）；按块逐个生成 |
| **P6 剪辑时** | 把歌铺回静音画面之下；块与块在**气口**上对接 |

## 一、为什么必须"先歌后演"

- **嘴是被波形锁住的**：模型是**从波形构建口型**的，所以驱动它的必须是**最终那一条人声**。**一个你打算之后替换的 demo 不行**——口型会锁在一个不存在的声音上。
- **生成不出音乐**：让模型生成音乐，结果要么是拒绝，要么是编辑阶段必须对抗的东西。
- **版权检查**：如果让模型自己产声音，版权检查就有东西可抓、可能直接拦掉这一条。**把生成音频关掉，就什么都不会被拦。**

## 二、管线（六步，严格按序）

1. **歌做完**：完整主歌、真人声、终混。
2. **切成约 12 秒的块**——这是模型可靠处理的镜头长度。**切点落在人声的气口上，绝不切在词中间。**
3. **每块做成一个黑画面的视频文件**：视频轨是**占位**，音轨是**歌的那一块**。
4. **生成时把音频关掉**：人声仍然驱动唇形（嘴由波形构建），但片段回来是**静音**的。**版权检查没有东西可抓，无法拦这一条。**
5. **逐块生成**——一次一块，不要一条提示词里塞两块。
6. **剪辑**：把歌铺回静音画面之下，**块与块在气口上对接**，接缝自然落在呼吸处。

## 三、两条附加指令（叠加在常规块序之上）

### 3.1 附加指令一：这个文件就是这首歌，他正在唱它

**不要说"这是一个参考""这是口型指南""我们的工作流是……"**——模型对工作流毫无兴趣，**元叙述会把模型搞糊涂**。只声明事实。

```text
@[视频1](video_1) —— 他们正在演唱的那首歌（本文件载有【角色名】这一段的 12 秒块）。
本文件的音频就是这次现场演唱。他唱出这一段的每一个音节——
说唱几乎是连续的，所以他的嘴只在本文件自己的气口处休息。
（本文件自带的画面是黑场填充——画面绝不来自视频1，只有音轨来自它。）
```

### 3.2 附加指令二：这一块的歌词 ＋ 硬唇形锁 ＋ 嘴的所有权

**把歌词写出来有助于口型**——模型会读语音、预先塑形元音。**但文字与音频在边缘处不会对齐，那里必须以文件为准。**

```text
本块歌词（以视频1 中听到的为准——【文件是唯一真相】：
如果这一块是从半句开始或半句结束的，嘴跟着【文件】走，不跟这段文字）：
"[把这一块里能听到的歌词逐字写在这里]"

唇形锁（硬）——【角色名】的嘴属于视频1 的人声，不属于任何别的东西。
逐帧精确：每一个音节都按它听起来的样子塑形；不许延迟、不许漂移、不许空着不动——
嘴如果错过了某一拍的时值，这一条就作废。

嘴的所有权——每一个可听清的字都属于【角色名】。
其他人的嘴是【活的】——张嘴大笑、喝彩、无声的"嘿"——
但它们绝不模仿、不回响、不做歌词的口型。
```

## 四、已知故障与修法

| 故障 | 成因 | 修法 |
|---|---|---|
| 嘴对着空气动 | 没有给出驱动波形，或驱动的是 demo | 用**终混**切块；附加指令一原样写上 |
| 口型与歌词在块的首尾错位 | 文字与音频边缘不对齐 | 明写"**文件是唯一真相**，半句时跟着文件走" |
| 其他角色跟着做歌词口型 | 没有"嘴的所有权"这条 | 加上"嘴的所有权"段：其他人的嘴是活的，但不做歌词口型 |
| 一条里塞两块，节奏打乱 | 块太长或提示词里塞了两块 | 一次一块；**12 秒是可靠长度** |
| 接缝处有一声卡顿 | 切点没落在气口上 | 切点只落在**人声气口**，绝不切在词中间 |
| 版权检查拦掉生成 | 让模型产了声音 | **在设置里关掉生成音频** |
| 块与块之间情绪断裂 | 每块单独起手 | 参照主流程的跨缝两招：把上一块结尾那句的尾巴喂进本块开头 |

## 五、交付前质检

- [ ] 驱动用的是**终混人声**，不是 demo？
- [ ] 每块约 **12 秒**，且切点落在**气口**上？
- [ ] 每块都做成了**黑画面视频文件**（视频轨是占位、音轨是歌的块）？
- [ ] 生成设置里**音频已关闭**？
- [ ] 附加指令一用了"**这就是那首歌，他正在唱它**"的写法，**没有**任何工作流叙述？
- [ ] 歌词块写了"**文件是唯一真相**"的边缘规则？
- [ ] 有**硬唇形锁**与**嘴的所有权**两条？
- [ ] 剪辑里歌铺回静音画面之下，接缝落在气口上？
