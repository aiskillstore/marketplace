# H3 字体包装生成指令执行语法

本文件只规定 MiniMax H3 能直接执行的可见、可听、可计时语言。风格知识从对应风格 Reference 读取，字体骨架和组合从 `typography-system-library.md` 读取。

## 1. 输入与输出边界

- 时长：4–15 秒整数。
- 画幅：16:9 / 4:3 / 1:1 / 3:4 / 9:16 / 21:9，由用户确认。
- 分辨率：默认 2K；只有用户明确要求且当前能力摘要提供可用档位时才改。
- 参考视频：单段 2–15 秒，最多 3 段，总计不超过 15 秒。
- 参考图：最多 9 张；参考音频最多 3 段且不能单独输入；混合素材最多 12 个。
- 素材按上传顺序写 `@图片1`、`@视频2`、`@音频3`，不写本地路径。
- 生成指令 Prompt 使用 `working_language` 的自然语言；非口播 `agent_curated` 先按用户确认的 `text_language` 执行，选择 `agent_recommended` 时必须先说明推荐理由。`exact_user_text` 只使用用户原文，语言选择只能决定排版角色，不能翻译、补写或替换；口播字幕保持准确台词，编辑标题和标签仍按用户设置混排。
- 目标 5600–6200 字符，硬上限 7000。长度按最终字符串逐字符计数，包含空格、标点、换行和素材标记；超过 7000 或无法可靠计数时禁止展示和生成指令。先删重复形容词，再合并重复身份/负面边界和相邻状态同义句；不压缩准确文字、文案角色、素材用途、画幅、时间点、主体身份、字体角色、构图状态或原片锁定项。

Prompt length gate: count the final string once. If it exceeds 7000 characters or cannot be counted, stop before display or execution. If it exceeds 6200, apply the defined deterministic compression order, recount once, and continue only when the result is within range.

### 口播包装工具边界

- `talking_head`、口播精剪、口播字幕包装和带动效的字幕包装，最终视觉结果必须由视频生成并锁定 MiniMax H3。
- 转写只提供准确台词、意群、重音和时间点；不得把转写后的 SRT/ASS 或烧录字幕当作包装结果。
- 字幕处理不参与视觉包装。媒体合成仅可在 H3 结果之后恢复/混合原对白、精确裁切或封装，不得在 H3 之前或替代 H3 绘制字幕、卡片与字体动画。
- 口播默认让 H3 生成少量触感音效并保持原对白优先；用户明确不要新增音效时才关闭。需要恢复准确源音轨时，在 H3 结果之后处理。
- 口播 13–15 秒必须把 `SPEECH_BEAT_MAP` 落成可见版式：单句字幕底座（单次只显示一个完整意群/一句话，长句可折成 1–2 行）→至少两次 Keyword Hero 关键词包装动画→至少一次来源明确的素材弹窗/原片 crop/PiP 证据卡→一次说话人缩到左上/右上角的小头窗→人物/字体终态；Prompt 必须写出素材来源、卡片证明的台词、停留/退出方式、mini-head 位置和两次 2%–3% 合成层微运动。

## 2. 最终 Prompt 结构

按下列顺序输出；没有素材时删除 `【参考素材说明】`：

```text
【项目设置】
【参考素材说明】（按需）
【核心创意】
【主体与空间】
【字体、色彩与版式系统】
【音乐与声音】
【文案系统与白名单】
【构图状态与画面过程】
【全局连续性与交付】
```

`【项目设置】` 必须写明：模型、时长、画幅、主体类型、主体模式、`画面处理=保留原环境/架空重建/局部混合`、文字语言和音乐模式。主体类型不决定是否换景。

字符分配：

| 区域 | 建议字符 | 内容 |
|---|---:|---|
| 项目与素材 | 300–500 | 时长、画幅、模式、素材用途 |
| 核心创意、主体与空间 | 700–1000 | 身份、舞台、镜头、光线 |
| 字体、色彩与版式 | 900–1300 | TYPE CAST、COLOR SCRIPT、GRAPHIC KIT、SPACE BINDING、COMPOSITION SCORE |
| 音乐 | 350–550 | 风格配乐/原声和 cue |
| 构图状态与时间轴 | 2600–3400 | 3–5 个可见状态 |
| 连续性与边界 | 250–450 | 统一性和少量必要边界 |

`【文案系统与白名单】` 使用固定结构。把 `SCENE_PACKAGING_COPY` 当作音乐 skill 的歌词底稿：先形成连续语义，再从同一底稿拆出不同字体层级的文字，不能先列关键词再硬拼成介绍：

```text
COPY_MODE: user_supplied | grounded_editorial | concept_fiction。
FACTS_FOR_COPY: [已从素材/用户描述确认的主体类别、可见形态、材质、动作、场景和用途；未知项写 unknown。]
SCENE_PACKAGING_COPY: [40–120 字的一段完整产品/场景介绍词，像旁白或歌词一样有明确对象、具体特征、关系和观看重点。先写 FACTS_FOR_COPY，再允许加入与主体一致的概念化想象、感官隐喻或视觉世界；不写制作指令。可按“它是什么 → 哪些具体特征/关系值得看 → 这段包装想象它如何被看见”连成 2–4 句。]
COPY_BRIEF: core_subject=[主体]；content_angle=[从 SCENE_PACKAGING_COPY 提炼的统一内容角度]；concrete_cues=[3–6 个线索]；tone=[文案语气]；language_mix=[agent_recommended / Chinese / English / Mixed]；recommendation_reason=[选择 Agent 推荐时的一句人话理由]；truth_boundary=[不可虚构项]；creative_boundary=[哪些是概念发散，哪些是已确认事实]。
COPY_DECK:
- id=[T1...] | text="[从介绍词中抽取或紧贴原句改写的准确屏幕文字]" | source_span=[介绍词中的连续短语/句子] | language=[中文/English] | role=[master / secondary / editorial_label] | semantic_job=[定题/展开/转折/收束/具体锚点] | basis=[介绍词/用户意图/台词/可见事实]。
COPY_TRACE: T1→[介绍词第几句/哪一短语]；T2→[...]；每个 id 必须能回指 SCENE_PACKAGING_COPY 的事实锚点或概念发散段落，不能从字体动作、包装材质或泛化风格词临时造词。
TEXT_WHITELIST: [逐项列出 COPY_DECK 的全部准确文字]。不同 id 使用不同文字和不同语义；同一文字只能在自己的角色内做尺度、材质或裁切变化，不能用同义拼词、逐字互译或制作过程词凑层级。
```

`SCENE_PACKAGING_COPY` 先回答“观众正在看什么、它有哪些具体特征/关系、这段包装想象什么”，至少有一个自然主句和一个清晰对象关系。没有产品资料时可以自由发散，但要把它写成概念叙事或感官隐喻，而不是伪装成真实规格、测量数据、用户见证或功能承诺；禁止虚构数字、型号、品牌、奖项、测试结果和可验证性能。仍然禁止“名词＋空泛动词”、抽象概念堆叠和随机风格词。`COPY_DECK` 中的每条文字都要通过静态海报阅读测试，并能由 `COPY_TRACE` 回指介绍词的事实锚点或概念发散；脱离动画仍是面向观众的标题、观察、感受、态度或具体标签。镜头、舞台、字体、版式、画面、转场、下一拍、进入、落位和回收属于执行指令，不得伪装成屏幕文案。

唯一 Prompt 按以下骨架展开，字段细节使用本文件后续章节和已读 Reference，不得另做摘要版：

```text
【项目设置】
MiniMax H3｜分辨率=2K｜[时长]｜[画幅]｜[主体类型]｜[主体模式]｜画面处理=[保留原环境/架空重建/局部混合]｜[文字语言]｜[音乐模式]
【参考素材说明】[逐项写 @图片/@视频/@音频的单一用途、保持项和允许变化项；无素材删除]
【核心创意】[主体＋统一世界＋视觉事件＋状态数量＋镜头/剪辑逻辑＋主风格]
【主体与空间】
IDENTITY LOCK: [真实身份特征]。
[产品按需] PRODUCT PROTECTED LAYER（内部检查，不是画面主题或可读文案）: [保持源中可辨识的轮廓、关键组件关系、材质与 Logo；包装特效与本体分层]。
STAGE/WORLD: [地面、后墙、消失方向、主体锚点、前中后景、转场表面]。
CAMERA/LIGHT: [相机起点→路径→终点]；[主光/轮廓光/移动高光→主体→字体]。
【字体、色彩与版式系统】[完整 TYPE CAST / COLOR SCRIPT / GRAPHIC KIT / SPACE BINDING / COMPOSITION SCORE]
【音乐与声音】[Mode / Profile / cue map / Mix]
【文案系统与白名单】[完整 COPY_BRIEF / COPY_DECK / TEXT_WHITELIST]
【构图状态与画面过程】[逐项展开 COMPOSITION STATE]
【全局连续性与交付】[主体、空间、字体、颜色、声音和转场连续性；仅保留本项目必要边界]
```

## 3. 素材角色

### 视频二创

```text
@视频1：主体、关键动作、语义和声音节奏参考。保持[身份/动作/内容锚点]；允许重建[空间/局部构图/景别/镜头表现]以承载字体和图形包装。原片已有 Logo、字幕和商业结构不自动复制为新增包装层。
```

### 锁定原片

```text
@视频1：原片编辑主体。保持主体、场景、构图、景别、运镜、剪辑、动作时序、速度、色彩、光线、声音和已有画内文字；只增加字体、图形载体、遮挡关系和局部响应，不新增或改写原片 Shot。
```

### 主体图片

```text
@图片1：主体与空间参考。锁定[产品轮廓/结构/材质/颜色/真实标识，或人物脸/发型/服装/体态，或 Logo 字形/比例/颜色/字距，或场景骨架/消失方向/关键物件]。若画面处理=保留原环境，保持原图构图、空间骨架、关键物件、透视和光线，只新增包装层；若画面处理=架空重建，普通源背景不作为最终舞台；若画面处理=局部混合，明确保留区与允许重建的局部表面。
```

### 字体/风格图片

```text
@图片2：字体和版式参考。只读取字形骨架、角色对比、尺度层级、颜色角色、图形载体、空间关系与运动气质；不复制其中品牌、人物、文案或水印。
```

多素材逐项给一个主要用途；不要写“参考全部内容”。

## 4. 核心创意与主体空间

核心创意用 1–2 句写清：

```text
[时长]，[画幅]。[主体]在[保留的真实环境/局部混合空间/重建舞台]完成[明确事件]；使用[主体模式]、[画面处理]与[主风格]，形成[3–5]个相互继承的动态海报/空间构图状态；架空重建时相机以[明确起点→路径→终点]串联全貌、多角度和细节，保留原环境时改为[原相机锚点＋字体层运动路径]；字体、图形、光线与音乐由同一动作/cue 触发；内容包装而非卖点广告。
```

`【主体与空间】` 必须写：

```text
IDENTITY LOCK: [真实可见身份特征]。
STAGE/WORLD: floor=[材料/颜色]；back_plane=[材料/颜色]；depth_layers=[前/中/后景]；vanishing_direction=[方向]；subject_anchor=[位置/轴]；transition_surface=[边缘/墙面/纸面/玻璃/阴影/字腔]。
CAMERA: [镜头/焦段感/景别起点] → [truck/orbit/push/rise/pass-through] → [终点]；每次改变角度展示新的真实结构或空间关系。
LIGHT: key=[方向/软硬]；rim=[方向/颜色]；moving_highlight=[来源→经过部位→停止点]；type_response=[哪一层字体响应]。
```

保留原环境不重建 STAGE/WORLD：视频写 `PRESERVE_ORIGINAL_FOOTAGE`，图片写 `PRESERVE_SOURCE_FRAME`。两者都要补原环境中的地面/墙面/玻璃/货架/阴影/消失方向、字体层景深、安全区和可用遮挡边；这些是包装锚点，不是环境改造。

## 5. 字体、色彩与版式系统

最终 Prompt 必须展开下列块，不能只写“高级字体设计”：

```text
TYPE CAST:
- Display A: [语言/准确文字角色]；[字形骨架]；[字宽/字重/端点/字腔或笔画性格]；[实心/描边/纸面等材质]；[主颜色]；[全屏/后景/空间标题用途]。
- Display B: [与 A 的可见对比]；[语义不同的次级文案/英文编辑标题/状态转换句]；[颜色和尺度]；不得复用 Display A 的文字。
- Utility: [稳定中小字号骨架]；[与 A/B 不同的真实标签、短句、部件名或字幕用途]。
- Marks: [只由白名单字符形成的重复/轮廓/裁切纹理，或无文字的边框/箭头/圆点/网点/短线/涂鸦]。

COLOR SCRIPT:
- state 1: [背景/Display A/Display B/专色/主体色关系]。
- state 2: [哪两个颜色换位、反白或由专色接管]。
- final: [如何回到统一终态]。

GRAPHIC KIT:
- [2–4 个组件]：[形状/尺寸/颜色/起点/承载哪层文字/回收方式]。

SPACE BINDING:
- relation 1: [文字贴附墙/地/玻璃/纸面/画框，匹配一个消失方向]。
- relation 2: [主体与文字谁在前、谁遮挡谁、遮挡多久、何时恢复完整可读]。
- relation 3（按需）: [字腔/边框/色块成为镜头入口或转场表面]。
- relation 4（炫酷艺术/空间字体优先）: [至少一次让同一主字跨地面→后墙或玻璃→前景板共享消失点；相机沿字面/字腔穿行，文字成为空间平面，不把每个词贴在主体旁边]。

COMPOSITION SCORE:
- [3–5 个状态]；每个状态写主焦点、三档尺度、图形载体、景深、颜色状态和继承到下一状态的元素。
```

15 秒通常使用 2–4 个协调字体角色，并为大/中/小层级分配不同文字。13–15 秒非口播 `agent_curated` 的 `COPY_DECK` 使用 1 条主标题、2–4 条次级文案和 3–6 条编辑标签；同一文字只可在自己的角色内做字阵、描边和裁切重复，不能跨 Display A/B/Utility 复用。`exact_user_text` 以用户提供的文字数量为准。

## 6. 构图状态语法

13–15 秒非口播使用 3–5 个状态；9–12 秒使用 3–4 个；6–8 秒使用 2–3 个；4–5 秒使用 1–2 个。

```text
COMPOSITION STATE N｜[start–end]
Frame/subject: [主体姿态、空间、镜头起点→过程→终点；产品补真实角度/结构]。
Type stack: Display A=[master id/准确文字/尺度/位置/景深/颜色]；Display B=[不同 secondary id/准确文字/尺度/位置]；Utility=[不同 editorial_label id/准确文字/稳定区]；Marks=[图案或同角色白名单纹理]。
Graphic carrier: [边框/分栏/纸条/色块/圆环/网点/透明板]从[来源]进入，承载[文字层]，停在[位置]。
Space binding: [贴附表面与消失方向]；[主体/文字/载体遮挡关系]；[相机视差或镜头穿越]。
Motion cue: [音乐/动作/切镜]触发整组进入；主 Hero 在[时间]完整可读；最强运动只作用[一个焦点]，其他层同步落位或稳定。
Effect chain: [真实来源] → [路径] → [与主体] → [与字体/载体] → [回收到来源/成为下一状态]。
Resolve/transition: [哪些层退出]；[哪个字、框、色块、轮廓或光带保留为下一状态的墙/地/遮挡边/镜头入口]。
```

一个状态可同时包含 3–6 个协同层，但只有一个最强运动焦点。不要把“一段只做一个主动作”理解成“一段只能出现一个元素”。

### 15 秒最低可见交付

- 1 次全屏或近全屏 Hero（约 75%–130% 画面宽度）；`preserved_architecture_scene` 覆盖为一次 55%–85% 空间 Hero，不使用屏幕级字幕板。
- 大/中/小三档文字尺度。
- 2 个以上字形角色在不同状态中形成对比。
- 1 次主体前景/文字后景到文字前景/主体中景的层级交换。
- 1 个边框、分栏、纸条、色块或图案阵列系统。
- 1 次字体成为墙面、地面、画框、空间入口或镜头穿越对象。
- 1 次专色反转、底色切换或黑白关系翻转；`preserved_architecture_scene` 不强制反转，只从真实空间取一个专色并保持环境连续。
- 1 次 Hero 完整稳定停留 0.55–1.0 秒；中文长短按可读性延长。

## 7. 主体与空间最低交付

本文件不重复主体规则。先从 `subject-packaging-system.md` 选择空间策略与主体分支，并把其中的身份锁、相机权限、空间边界和专属检查逐项写入最终 Prompt；再使用本文件第 5–6 节补齐字体系统和构图状态。主体规则与当前风格冲突时，以更严格的身份保护和原片权限为准。

## 8. 字体与特效事件

单个文字层：

```text
TRIGGER → ENTER → FULLY_READABLE → REACT → DEPTH_OR_LAYOUT_CHANGE → EXIT_OR_SETTLE
```

组合状态：

```text
CUE → CARRIER ENTERS → DISPLAY A/B LOCK TO GRID → UTILITY/MARKS SETTLE → HERO READABLE → ONE FOCAL RESPONSE → ELEMENT BECOMES NEXT STATE
```

小特效：

```text
SOURCE → PATH → CONTACT/RESULT → DESTINATION
```

来源可为主体边缘、真实高光、手势、切镜边、纸缝、字形基线、音频重拍；归宿为同一来源、文字边缘、舞台表面或下一状态的图形组件。不要用 `or NO EXTRA EFFECT` 给模型省略包装；选择风格后至少写一条具体 effect chain。

## 9. 语言执行

先建立同一个 `content_angle`：先完成 `FACTS_FOR_COPY → SCENE_PACKAGING_COPY → COPY_TRACE`，再让主标题定题，次级文案分别展开动作/关系、具体观察、转折或收束，标签锚定真实物件、部件、材质、地点、声音或状态。13–15 秒非口播使用 1 条主标题（中文通常 6–14 字，英文 3–8 词）、2–4 条次级文案（中文通常 8–22 字，英文 4–10 词）和最多 3 条编辑标签；9–12 秒使用 5–8 条不同文字，4–8 秒使用 3–6 条。不同层不得同义改写、逐字互译或只换一个形容词。

每条文案执行 `HUMAN_SPEECH_CHECK + POSTER_READ_TEST`：有明确对象与关系，脱离动画仍像真实标题、观察、感受、态度或标签；不得虚构身份、数据、功能、价格、奖项、产地、经历或具体事件。`静物有光 / 轻轻靠近 / 结构启动 / 低音上线 / 风感在线` 这类无完整关系的伪诗意/伪产品词，以及 `GALLERY / ROOM / FUTURE SPACE / FLOW / GRID / LINK` 这类无上下文英文填空必须重写，不能只替换一个字继续套句式。保护规则词（如“结构完整、组件关系、透明度保持”）只能留在内部检查，不能进入 `SCENE_PACKAGING_COPY`、`COPY_DECK` 或 `TEXT_WHITELIST`。

- 全英文不得用 `FUTURE MATTER / ENTER THE UNKNOWN / QUANTUM GALLERY / PARTICLE FIELD 01 / REALITY RECONSTRUCTED / THE FUTURE IS HERE` 一类无展项支撑的万能未来套话；英文编辑层也必须在 `COPY_TRACE` 中说明对应的中文事实/关系或已确认英文名称，不能只因为看起来像设计词就加入。
- 空间序列文案使用“一个主标题定题 → 不同句子说明空间关系与观看路径 → 中英文标签锚定真实物件/材质/区域/光线”，不为每个空间各编一条无关系诗句。
- `exact_user_text` 逐字保留；可在自己的角色内重复、描边、裁切或作纹理，但关键可读状态必须完整，不为凑数量或混排增加文字。

### English

默认混排中的英文必须是一条自然 editorial phrase、动作句或具体标签，并为整套文案增加中文层没有的新信息；不把中文逐字翻译一遍，不使用孤立名词堆或伪 UI 栏目。全英文模式至少有两条正常完整 phrase，单词标签不超过一半；删掉主体后可套到任意科技视频的 stock futurism、虚构展区名/编号/坐标/系统状态均视为失败。写清大小写、字宽、字重、端点、字腔和字距；完整拼写后可裁切、拉伸、描边或在自己的角色内重复。

### Chinese

中文主标题和次级文案要像真实的人会说或编辑会写：有明确对象、动作、关系或观察，不写“名词 + 空泛动词”的 AI 诗句。写清方黑、圆黑、粗宋、现代宋、人文黑、手写/书写骨架等可见结构；保持偏旁、笔画交叉和方形重心。可用横排、竖排、错位行、单字全屏和粗细对比，不套用极端英文窄体压缩。

### Mixed

非口播默认使用。指定中文主内容与英文编辑层，或按用户要求反转主次；两种语言由不同 Display/Utility 角色承担，分开基线、字号和阅读顺序。两种语言围绕同一 `content_angle`，但必须表达不同信息，不做逐条双语翻译。

## 10. 音乐与 cue

音乐模式、风格配方和 cue 数量以 `music-direction-library.md` 为唯一来源。本文件只规定最终输出块：

```text
MUSIC / AUDIO:
Mode: [preserve_original_audio / style_generated_instrumental / use_uploaded_audio_as_rhythm_reference / no_music].
Profile: [BPM、拍号、声音材料、能量曲线、无歌词]。
Cue map: [4–6 个准确时间点] → [相机/主体/Carrier/Display A/B/回收]。
Mix: [对白/环境声/产品细节优先级]。
Talking-head only: `SFX MAP` = [准确时间] → [Keyword Hero / Evidence Card / punch-in / layout swap] → [一个短触感音效] → [对白压低/恢复]；至少 3–5 个 cue，其中两个对应不同 Keyword Hero、一个对应 Evidence Card。
```

图片或纯文字生成不写 `Audio: N/A`。每个构图状态绑定一个主 cue；不要每个字逐个踩点。

## 11. 连续性与交付

`【全局连续性与交付】` 先写正向连续性：

```text
主体身份在所有角度一致；舞台材料和消失方向连续；Display A/B/Utility 的字形角色不互换；颜色角色按 COLOR SCRIPT 切换；每个 Carrier/光效有来源和归宿；前一状态至少一个元素进入下一状态。
```

再写本项目真正需要的少量边界：不虚构卖点/价格/CTA、不出现白名单外可读文字、不破坏主体身份；锁定原片时不改变原片内容。不要重复几十条同义负面句。

## 12. 生成指令前检查

- 设置是否全部来自用户确认，参考比例是否只作信息；未明确改档时分辨率是否为 `2K`。
- 最终是否使用中文、是否已逐字符计数且 `<=7000`；目标是否落在 5600–6200，超过硬上限是否已阻止生成指令。
- 是否具有 TYPE CAST、COLOR SCRIPT、GRAPHIC KIT、SPACE BINDING、COMPOSITION SCORE。
- 13–15 秒非口播是否有 3–5 个 `COMPOSITION STATE` 和 2–4 个字体角色。
- 是否包含大中小尺度、全屏 Hero、前后景交换、图形载体、空间化字体和颜色状态变化。
- 是否先写 `FACTS_FOR_COPY`，再写自然连贯的 `SCENE_PACKAGING_COPY`；未知产品特性是否保持 unknown，没有擅自补成功能或感受卖点。
- `COPY_DECK` 每个 id 是否都有 `source_span` 和 `COPY_TRACE`，可回指介绍词的事实锚点或概念发散段落；无法回指、只是风格词或制作词时是否已阻止生成指令。
- `COPY_BRIEF` 是否锁定同一内容角度、具体线索、语言推荐理由与事实边界；13–15 秒非口播是否有 1 条足够完整的主标题、2–4 条次级文案和最多 3 条编辑标签，短时长是否按比例缩减。
- Display A/B/Utility 是否使用不同文字并承担不同语义；中文是否自然完整，英文是否为自然搭配；默认是否形成中英文混排且没有逐条互译、孤立名词堆、伪诗意或伪 UI 填空。
- 全英文模式是否至少有两条完整 phrase、单词标签不过半，并通过主体具体性检查；是否删除万能未来套话以及虚构的展区、编号、坐标和系统状态。
- 每条文字脱离动画后是否仍像真实海报文案成立；是否把任何制作过程词误写进 `COPY_DECK`。
- 每个状态是否有多层组合、一个最强运动焦点、完整可读时刻和向下一状态的继承。
- 每个 effect chain 是否有来源、路径、结果和归宿，没有 `NO EXTRA EFFECT` 逃生口。
- 图片/纯文字/架空生成是否具有风格音乐和 cue；锁定原片/口播是否保留原声。
- 口播包装是否启动 H3 生成最终视觉；转写是否只提供台词和时间点；媒体编辑器是否仅在 H3 成片之后恢复音轨、裁切或封装。
- 口播基础字幕是否一次只显示一个完整意群/一句话，避免多句同时上屏和固定底部圆角框；是否有两次以上 Keyword Hero、一次来源明确素材弹窗/crop/PiP 证据卡、一次说话人左上/右上角 mini-head 小窗、两次合成层微运动，以及逐事件的 `SFX MAP`。
- 所有可读文字是否逐字来自白名单。
- 是否逐项通过 `subject-packaging-system.md` 的本次主体检查与当前风格 Reference 的专属检查。
