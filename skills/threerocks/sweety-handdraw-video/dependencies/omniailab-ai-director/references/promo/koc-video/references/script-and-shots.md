# 口播、分镜与视频 Prompt

> **触发**：人物锚确认后，编写口播、分镜和最终视频 prompt。

先确定整条内容如何推进，再完成一条连续表达，最后决定镜头如何承载它。不要先画时间格，再把广告句分别填进去。

## 0. 确定内容推进与 speech plan

在写逐字口播前，先用内部短句想清楚：开场让观众进入什么；后续通过什么动作、观察、观点或回答继续；结尾抵达什么新的理解、状态或选择。它不必是固定三幕式，也不要求每个开场问题在某一镜机械作答，但每一段都要继承前一段并增加新内容。

多 clip 时为每段记录“上一段留下的状态”和“这一段新增的内容”。如果交换两个片段的顺序仍完全没有影响，说明它们可能只是并列卖点，还没有形成叙事推进。

在写台词前，同时建立一份全片唯一的 **speech plan**。它是声音归属的真相源：每段人声写清 `speaker`（谁在说）、`source`（镜头内说话 / 画外旁白）和 `voice_identity`（是否与其它 clip 是同一声音）；没有台词的片段明确标记为 `no speech`。

- `镜头内说话`：可见的对应人物正在说话，并按需要口型同步。
- `画外旁白`：叙述者不在画面中；画面人物不应被写成正在说这段台词或对口型。
- 同一 `voice_identity` 出现在两个及以上 clip 时，在第一段建立一个完整的 `voice_signature`，并逐字复制到每个相关 video prompt。它至少包含语言/口音、年龄感、音高区间、音色明暗、共鸣、亲密度、咬字和语速基线；本段的情绪、力度、停顿或相对语速可以变化，但不能改写这份锁定。
- 多人对话按每一句的 `speaker` 与先后顺序记录；不同说话人需要有可听见的身份区分，不用预设固定的性别、年龄或声线模板。

speech plan 是内部制作合同，不额外塞进用户确认问题。用户版分镜只呈现最终可听见的关系和听感。

## 1. 写连续口播

围绕已确认的开场和核心信息，先写一段同一个人能够自然连续说完的话：

- 一段主要推进一个感受、判断或使用过程；同义评价只留最具体的一句。
- 用正在发生的动作和具体观察承接判断，不连续堆抽象形容词。
- 每句口播都对应当前动作、观察或即时判断，并推动下一步动作或态度；不要先写一段脱离镜头的广告词再贴到画面上。
- 允许短句、停顿和不对称表达，不把每句写成结构整齐的广告金句。
- 不强制口播承担 Hook；画面、对话或声音已经完成开场时，主口播可以稍后进入。
- 第一人称可以演绎可信的使用处境，但不能新增硬性能事实或冒充第三方证言。
- CTA 与前文语气和真实购买路径一致；没有明确入口就自然收住。

避免连续使用同一种语言模板，例如反复的“不是……而是……”“我最喜欢的是……”“属于……那种”。重点不是替换禁词，而是把整段读一遍：如果像四句互不相连的广告标题，重新写成一条生活线。

中文 15 秒通常约 40–55 字，英文约 32–40 words，并为动作和自然停顿留时间。超出时先删重复评价、次要卖点和形容词，不要求人物加速说完。

对谈、采访和 podcast 通常在 30 秒以上更容易建立话题、人物观点和自然的产品承接，但不设最低时长。较短时把它写成一段值得单独观看的切片：围绕一个具体问题和有内容的回答展开，不强求同时完成产品介绍、卖点和 CTA；所有说话人的台词共同占用时长预算。暂时遮住产品后，对话本身仍应值得听。若主持人必须从第一问开始递产品卖点，优先改成朋友问答、街访或普通双人对话。

逐字台词与整个模型生成 prompt 使用 `deliverable_language`：北美/海外受众默认英文，国内受众默认中文，用户明确指定优先。用户确认版分镜使用 `working_language`，其中逐字台词保持 `deliverable_language` 原文，不翻译。用户提供的准确台词始终保持原文。用户对话语言、受众成片语言与模型 prompt 语言是三个明确区分的层次。

## 2. 从表达和动作设计镜头

先画出完整的真实使用动作链：人物从什么状态开始，如何拿取、打开、使用、穿戴或收起产品，最后停在哪里。拿起、打开、装入、拉好、背上、调整和转身展示可以共同构成一条完整生活逻辑，不因动作多就删掉必要步骤。

再决定每个动作由什么画面承载：

- **A-roll** 承载人物持续表达、反应和主要叙事。
- **B-roll / coverage** 单独拍产品特写、操作步骤、上身关系、使用结果或生活瞬间，再按口播和信息需要穿插。
- 能在同一机位自然完成的动作保持连续；产品与身体关系、遮挡或结构状态变化复杂时，可以切到动作已经完成后的稳定状态。切点省略的是模型不必计算的中间形变，不省略观众理解使用过程所需的信息。
- 丰富感来自有意义的动作、人物反应、视点和 coverage，不要求一次生成或一个连续镜头承担整条复杂物理链。

只有以下变化值得切镜：

- 动作进入了一个无法在当前机位清楚呈现的新阶段。
- 信息重点或观察对象发生变化。
- 需要新的视点来展示产品与人体、环境或结果的关系。
- 场景或时间确实改变。

同一个简单转身、拿取、打开、使用产品或说完一句话的过程，可以保持连续。切镜边界落在完整台词和完整动作之后，不在一句话或一个动作尚未完成时切换片段或重置状态。时间段是内容节奏标记，不自动代表剪辑点。若同一镜头跨多个时间段，在 prompt 中明确 `continuous handheld take`、`the camera continues following` 或同等自然语言；只有确实要切时才写 `cut to` 并说明切换理由。

每个 15 秒 clip 至少形成两次可感知的视觉推进。推进可以来自人物状态或反应变化、产品与人物或环境的关系变化、相机随动作自然改变距离与观察对象，或在完整台词和动作之后切入有信息价值的 reaction、POV 或 product coverage。视觉推进不等于固定切两次镜，也不要求轮换景别；连续跟拍可以通过人物移动、重新取景和动作结果形成变化。画面长期停留在同一构图、同一姿势和同一产品关系，即使人物持续口播，也不算推进。

切镜由动作、反应或信息变化触发。不得在一句话中间或动作状态不稳定时，单纯为了增加镜头数量而切换。

不要把动作丰富误写成一次生成中的连续物理负担。动作、道具或身体关系复杂时，把动作链拆成几个可独立获得的 coverage；每个画面有清楚的起点、主要动作和结果，并用有意切镜进入下一稳定状态。镜头数量由观看节奏和信息需要决定，不靠删动作换稳定，也不为覆盖动作清单机械切镜。

镜头少不等于画面停滞。整段需要持续出现与内容有关的视觉进展，可以来自人物动作、产品状态、构图调整、环境反应或有理由的切镜；如果一段画面长时间没有新信息，就增加推进，而不是单纯延长静止口播。

## 3. 用户确认版分镜

画布分镜只呈现用户需要判断的内容：

```markdown
# {时长} KOC / UGC 视频分镜

- 创意：{开场实际发生什么，后续如何顺着展开}
- 人物：{谁在什么情境表达}
- 声音：{谁在镜头内说话、谁是画外旁白、每位声音最终听起来怎样，以及同一声音跨片段如何保持连续}

| 时间 | 镜头 | 画面 | 逐字口播 | 声音 |
```

镜头列需要说明是“连续跟拍”“同一机位继续”还是“切到近景”，不能只写一串不同景别，让用户和模型猜哪里发生剪辑。产品限制、refs、模型参数、混音参数和内部禁令不进入用户版分镜。

分镜与逐字口播用 writing to canvas 落画布，再用 confirmation card 确认。用户通过输入框反馈时更新节点并重新确认；用户直接编辑节点后，生成前用 latest canvas version 重读最终版本。

## 4. 多 clip 边界

先读取 capability 的合法 duration，再安排 clip。边界必须落在完整动作和完整句子之后：

- 一句台词只进入一个 clip，不拆半句，也不在相邻 clip 重复。
- 新 clip 可以继承上一段的末态，但从新增动作和新增台词开始。
- 边界无法对齐时，先缩短台词、调整动作时长或保留无口播动作，再更新分镜并重新确认。
- 每个 clip prompt 的时间从 `0s` 起算；画布分镜使用全局时间轴。

生成前按顺序合并所有 clip 的逐字台词，与确认版分镜逐句核对：不得新增、遗漏、改写、重复或跨边界。

## 5. 编译视频 Prompt

Prompt 只写当前 clip 真正需要的信息，并按自然因果顺序组织：

1. 每张 reference 先写清在本 clip 的职责与适用范围：角色资产的身份锚承接对应身份、稳定造型和内容气质；产品原图承接产品事实；交互锚承接已确认的上身、手持或尺度关系。再独立写出本 clip 的开场状态、动作和构图。只有图片本身就是本 clip 起始画面时才作为首帧输入；其它按普通 reference 传入，并按传入顺序写明对应角色资产 id 与职责。
2. 平台、画幅、拍摄者与相机关系，以及场景中必要的空间信息。
3. 当前 clip 承担的 A-roll 或 coverage、动作的起点与结果，以及时间段是否在同一镜头内继续。
4. speech plan 中的逐字台词、说话人、镜头内/外来源和它发生在动作的哪个位置；画外旁白明确叙述者不出镜，画面人物不说这段台词或对口型。
5. 同一 `voice_identity` 的完整 `voice_signature`（逐字复制，不同 clip 不自行改写）；只有本段表演变化另写情绪、力度、停顿或相对语速。
6. 环境声和已确认的音乐听感。

英文人物默认使用 `the creator`，不从样板或人设名称自行补 `he / she`；用户明确指定代词时才固定使用，并在所有 clip 保持一致。

含真人画面要有与内容相关的持续状态和小动作，而不是静止脸加产品。具体表现由当前动作和拍摄关系决定，不给每个 prompt 复制同一套眨眼、碎发、晃动或皮肤描述。人物和产品外观已由锚传递时，不重复转述完整外观。

手持不是问题，缺少拍摄逻辑才是问题。UGC 临时记录、自拍视频和朋友跟拍可以保留轻微晃动与取景修正；固定教程或稳定产品演示则使用相符的机位。相机变化应帮助观众看清动作、关系或信息。

## 完成条件

- 整段口播读起来是一条连续表达，不是广告句拼接。
- 开场完整继承用户确认的方案，后续兑现同一内容线。
- 每一段都承接前一段并增加动作、信息、观点或结果；片段不是可以任意调换的并列展示。
- 每次切镜都有动作、信息、视点或场景理由；时间码本身不是理由。
- 即使采用单镜或少镜，画面仍持续推进，没有长时间维持同一状态。
- 完整使用动作链没有因求稳而缺步骤；复杂身体或产品关系按可独立生成的 coverage 和稳定状态组织。
- Prompt 语言与目标市场一致；人物指代、逐字台词和 refs 职责前后一致；每个角色资产、身份锚和 reference 映射前后一致。
- 每段人声与 speech plan 的 `speaker`、`source` 和 `voice_identity` 一致；跨 clip 的同一声音逐字沿用同一份 Voice Lock。
