# 通道选择层（先选对产出通道，再谈怎么做）

**同一支片子，可能有两种完全不同的造法。** 选错不是"差一点"，而是**整支白做**——生成通道造不出"分毫不差的产品界面"，代码渲染造不出"真实的人与自然场景"。

本层只做一件事：**在正确的时机，用一句话给出判断与理由，让创作者选对通道**。它不改主干、不改任何一层的做法；判定完成后立即把上下文交给 `PROMO GUIDE.md`（生成通道）或 `MOTION-STUDIO GUIDE.md`（代码渲染通道）。

## 一、两条通道是什么

| | **生成通道** | **代码渲染通道** |
|---|---|---|
| 入口层 | `PROMO GUIDE.md`（14 个商业短片方向） | `MOTION-STUDIO GUIDE.md` |
| 画面从哪来 | 模型按提示词生成 | **真实页面截图／录屏** ＋ 代码逐帧渲染 |
| 在哪出片 | **OmniAiLab 画布**，选 **MiniMax H3** | 逐帧渲染（工程化），可导出剪映工程回交 |
| 强项 | 真实的人、实景、氛围、材质与光、想象力画面 | 精确还原界面与排版、真实数据、逐帧可控的运镜与卡点 |
| 弱项 | 画面内文字与数字不稳定，精确版式做不到 | 造不出真人实景；没有真实界面素材就无从下手 |
| 迭代方式 | 改提示词重生成（带随机性） | 改代码重渲染（确定性、可复现） |
| 成本形态 | 按生成次数计 | 建设期投入高、**改版便宜** |
| 许可注意 | — | 渲染引擎**个人与小团队免费、公司使用可能需付费** |
| 典型交付 | 15 秒–数分钟成片 | 15–90 秒短片 ＋ **可编辑工程** |

两条通道**不是替代关系，是并列关系**，而且可以**接力**（见第六节）。

## 二、五个判据（按顺序看，第一个能分开就停）

### 判据 1｜画面里的主角是什么？（最关键，一条就能分开大半）

- **真人、实景、自然、动物、情绪与氛围** → **生成通道**
- **产品界面、数据、文字排版、几何图形、Logo 演绎** → **代码渲染通道**

### 判据 2｜要不要"分毫不差"？

- 要：界面像素级还原、文字逐字精准、数字必须是真的、版式要严格对齐 → **代码渲染**
- 不要：氛围对、感觉对就行 → **生成**

### 判据 3｜手里有没有真实界面素材？

- **有**（网页／App／后台／小程序／桌面端，可截图或可录屏）→ 代码渲染**可行**
- **没有**（产品还没做出来，只有一个概念）→ **代码渲染直接不成立**，退回生成通道

### 判据 4｜要不要精确到帧的运镜与卡点？

- 要（卡拍、hold、变速、多元素同步入场、转场钉帧）→ **代码渲染**
- 不要（自然运动、随机感反而更好看）→ **生成**

### 判据 5｜时长与投放？

- **15–90 秒**、官网／应用商店／发布会／大屏／社媒信息流 → 代码渲染的主场
- **15 秒–数分钟**、电视／影院／社媒品牌投放 → 生成的主场
- **超 3 分钟或系列长内容** → 逐帧成本随长度线性上涨，**以生成为主**

> **判定顺序**：判据 1 能分开就停。判据 2–5 用来**确认与修正**；一旦**判据 3 不成立**（没有真实界面素材），代码渲染立即出局，无论其余判据多像。

## 三、什么时候提醒（三个节点，其余时候不提）

| 节点 | 什么时候 | 做什么 | 强度 |
|---|---|---|---|
| **A 定形态** | 用户说出"宣传片／产品片／发布视频／功能演示／广告／电视片"时（`ONBOARDING GUIDE.md` 分流、`GUIDE.md` 第 0 步） | **一句话报倾向 ＋ 一句理由**；不展开、不摆对比表 | 轻 |
| **B 素材核验后** | 素材与文字核验完成、**进入 P4 出首帧之前** | 用五判据正式确认一次，**此处锁定通道** | **必做** |
| **C 用户改口** | 任何时候用户说"这个字改不了""能不能换真人""能不能精确点""能不能省点钱" | 立即重判，并说明换通道的代价 | 随时 |

**不要提醒的时候**（避免噪音）：

- 用户**已经明确说了**走哪条 → 直接走，不问；
- 片子**明显只有一条路**（纯剧情片、纯实拍纪实、纯二维动画）→ 本层不出现；
- **已过 P4 且用户没提出异议** → 不主动翻案。

> **为什么不在节点 A 就把话说死**：定形态时通常还不知道"有没有真实界面素材、文字要不要逐字精准"，问了也是白问。**A 只报倾向，B 才定案。**

## 四、怎么问（话术，照抄）

**节点 A｜报倾向（这是判断，不是提问）**

```text
先给你一个路线判断（不对就纠正我）：

这条片子我倾向走「<通道名>」——因为 <一句理由>。
另一条路的差别是：<一句话说清它擅长什么>。

先把规格定下来；等素材核完、进分镜之前，我们再最终敲定走哪条。
```

**节点 B｜决定性确认（唯一一次正式问）**

```text
素材核完了，进分镜之前把通道定下来（定了就不再改）：

① 生成通道（OmniAiLab 画布 · MiniMax H3）
   画面由模型生成：适合真实的人、实景、氛围与材质。
   代价：画面里的文字与数字不稳定，精确版式做不到。

② 代码渲染通道
   画面来自产品真实界面截图，代码逐帧渲染：界面能分毫不差地还原，
   文字与数据精准，运镜与卡点可控，还能回交可编辑工程。
   代价：需要你提供能截图的真实界面；渲染引擎公司使用可能需付费。

按你这支片子，我建议 ①/② —— <理由>。

确认走哪条？也可以说"两条都要"：概念镜头走生成、界面镜头走代码渲染，
最后合成在同一条时间线上。
```

**节点 C｜改口时**

```text
你提的这一点，正好是两条通道的分界线。

<现象>（例如"这几个字老是变""界面还原不了"）在生成通道里做不到——
要精确，就得换成代码渲染通道：用真实界面截图、代码逐帧渲染。
代价是 <代价>（要提供可截图的真实界面／建设期更长／渲染引擎许可）。

换不换？还是先把当前这条做完？
```

**用户说"你决定"时**：按五判据定，然后**把理由说出来**，不要沉默执行。

## 五、应用场景全表（别漏）

按**画面主角**分四类。看到自己的场景，就按那一类的倾向走。

| 场景 | 常见叫法 |

| 剧情化广告 | 电视广告、剧情广告、品牌大片、系列 Campaign |
| 达人／种草／口播 | KOC、测评、开箱、用户证言、专家分享、手部实测 |
| 公益／城市／文旅 | 公益广告、城市宣传片、旅游宣传片、政务片 |
| 招聘／雇主品牌 | 招聘片、雇主品牌片、员工故事 |
| 节目／剧集预告 | 节目宣传片、剧集预告、真人秀片头 |

| 新品发布主片 | 发布会主视觉片、新品片 |

### C 类｜屏为主体（界面、数据、文字、图形）→ 代码渲染通道

| 场景 | 常见叫法 |
|---|---|
| 软件／SaaS 发布 | App 发布、小程序发布、产品发布视频、官网首屏片 |
| 功能演示／操作教程 | 功能演示、操作流程、上手教程、SaaS 界面动画 |

| 电商图文 | 主图视频、详情页视频、商品卖点卡 |

### D 类｜混合（人 ＋ 屏）→ 接力（见第六节）

| 场景 | 分工 |
|---|---|
| 招商／加盟 | 品牌与门店氛围 → 生成；数据与政策页 → 代码渲染 |
| 产品发布会开场 | 品牌情绪铺垫 → 生成；产品与功能段 → 代码渲染 |

| 教育／课程 | 讲师与实景 → 生成；知识点动画／讲题板书 → 代码渲染 |

### 电视宣传片单独说

**"电视宣传片"不是一个通道，是一堆片型的统称**——先分清是哪一种，再选：

| 电视上是哪一种 | 倾向通道 |
|---|---|
| 频道 ID／台标演绎、栏目包装、片头字幕 | **代码渲染**（字体与版式要准） |
| 节目预告／剧集宣传片／晚会宣传片 | **生成**（真人、节目画面） |
| 电视广告 TVC | **生成** |
| 公益广告／城市形象片 | **生成** |
| 大屏／LED 视觉、展会循环片 | **代码渲染** |
| 晚会／大赛视觉包装 | **混合**（情绪段生成、版式段代码渲染） |

## 六、混合与接力（最常被漏掉、也常常才是对的答案）

**"两条都要"往往才是最优解**，但要说清怎么分工，否则会变成两套风格硬拼。

**分工边界（一句话记法）**：**会动的真人实物走生成，屏幕上的一切走代码渲染。**

- **生成段**：概念镜头、人物镜头、实景与氛围镜头 → `PROMO GUIDE.md`
- **代码渲染段**：产品界面、数据图表、文字版式、Logo 演绎、转场包装 → `MOTION-STUDIO GUIDE.md`
- **必须统一的三件事**：同一条时间线合成、同一套卡点、同一套音效语气
- **视觉必须同源**：代码渲染段的配色与字体**从品牌自身设计系统取**（见 `MOTION-STUDIO GUIDE.md` 第四节）；生成段写进提示词的也用**同一套颜色宪法句**（见 `PROMPT-DOCTRINE GUIDE.md`）

**先做哪一条**：先定**生成段的风格锁定（P1）**，代码渲染段从同一套 tokens 出发。**顺序反了，会让代码段"另起一套皮肤"**——这是混合片最常见的翻车点。

## 七、效率与人性化原则（硬规则）

1. **先给判断，再给选项**——不要甩一张对比表让创作者自己选；先说倾向哪条、为什么。
2. **同一节点只问一次**——用户答了就往下走，不反复确认；重复问会让整条流程卡顿。
3. **说清代价**——每条路都有自己的代价（生成通道改不了字、代码渲染要真实素材且公司许可可能付费），报判断时一并说。
4. **不等用户懂**——创作者不知道有两条路，是我们的责任讲清楚；**他不需要先学会，才能得到对的答案**。
5. **信息不足只问必需的**——只问"有没有真实可截图的界面""画面里的文字要不要逐字精准"两件，其余按判据自己判。
6. **选定即锁**——过了 P4 出首帧后不再主动翻案；要换必须由创作者提出，并说清返工范围。
7. **改口即重判**——创作者说"改不了""不对""能不能换个做法"时，**立刻重判通道**，不要硬撑。
8. **不因为模板现成就推荐它**——代码渲染有现成工程可用，但片型不对就该明确说不。

## 八、交付前自查

- [ ] 通道判定**有依据**（能说出命中哪条判据），不是凭感觉；
- [ ] 判定发生在**素材核验后、P4 之前**，且**真实停顿过**一次；
- [ ] 报判断时**说清了理由与代价**，不是只给结论；
- [ ] 走**混合**的片子，分工边界**写进了分镜**（哪一镜走哪条通道）；
- [ ] 代码渲染段**没有另造"宣传片皮肤"**，配色与字体来自品牌设计系统；
- [ ] 若中途换过通道，**返工范围已说明**；
- [ ] 未向创作者隐瞒关于渲染引擎许可的注意（公司使用可能需付费）。
