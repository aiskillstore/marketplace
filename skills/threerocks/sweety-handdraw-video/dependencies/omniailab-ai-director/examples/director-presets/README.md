# 导演预设库（20 位 · 选择 · 推荐 · 混合）

**怎么用（三步）**：

```text
① 定导演：用户点名 → 直接加载对应文件；没说清 → 从下面的「按类型推荐」给 2–3 个候选
② 读一位：只打开 examples/director-presets/<NN>_<中文名>.md 这一个文件，不要一次读多个
③ 出声明：按 references/DIRECTOR-VISION GUIDE.md 第四节产出「导演风格声明」，写进「全片风格锁定」
```

> **一次只展开一位主导演。** 多位导演走"主 ＋ 借用维度"，规则见 `references/DIRECTOR-VISION GUIDE.md` 第五节。
> 全部中文重写、去硬件厂商与型号；**参数只用于选型，写进提示词的一律是可观察结果**。

## 三、按情绪／场景推荐（第二入口）

| 你要的感觉 | 首选 | 理由（一句话） |
|---|---|---|
| 让观众揪心但不混乱 | 斯皮尔伯格 | 单一空间内障碍逐级升级，观众永远知道危险与出口在哪 |
| 让观众替角色紧张 | 希区柯克 | 先把秘密给观众，等待被撑满 20–60 秒 |
| 让观众保持判断距离 | 库布里克 | 高照度、无处可藏，看清一切却依然不安 |
| 让观众仰视而不是共情 | 维伦纽瓦 | 人缩到画幅高度 5%，给二十秒不解释 |
| 让观众和角色一起被困 | 伯格曼 | 正面凝视、不切、长镜内部必须有心理变化点 |
| 让时间自己说话 | 塔可夫斯基 | 镜头不动，水与火替人物表演 |
| 让距离感成为主角 | 迈克尔曼 | 人永远隔 2–4 米、一层玻璃或一整座城市 |
| 让孤独变成建筑的形状 | 侯孝贤 | 机位退到 6–12 米外，任何象征元素不许进来 |
| 让一场群戏有了可读的阵型 | 黑泽明 | 长焦把队列压成横向的带，运动方向全段一致 |
| 让颜色替你说话 | 张艺谋 | 主色占画幅 60–80%，换色是情节点不是装饰 |
| 让城市替你抒情 | 王家卫 | 前景永远有东西挡住，正脸是舍不得给的东西 |
| 让规则本身成为悬念 | 诺兰 | 规则在前 90 秒交代完，悬念只是时间够不够 |

## 四、混合速查（多选时先看这张表）

**可以混（机制互补，互不为反例）**：

| 组合 | 怎么混 |
|---|---|
| 芬奇（主）＋ 王家卫 | 借王家卫的**前景遮挡**与**霓虹污染**；芬奇的通透可读保持不变——**这两条要写清程度**，否则会互相抵消 |
| 诺兰（主）＋ 库布里克 | 借库布里克的**高照度恐惧**只用在室内段落（诺兰本身禁止霓虹与全息 UI，正好相容） |
| 斯皮尔伯格（主）＋ 黑泽明 | 借黑泽明的**天气作用在身体上**（风雨尘泥）用于高潮段；空间可读性保持斯氏规则 |
| 维伦纽瓦（主）＋ 塔可夫斯基 | 借塔氏的**水与反光面**放进前景；尺度与雾的纵深梯度仍归维氏 |
| 张艺谋（主）＋ 黑泽明 | 分段主导演更稳：**仪式段给张**、**冲突段给黑泽** |
| 侯孝贤（主）＋ 王家卫 | 借王氏的**时间标记**（日期、编号、次数）写进台词与道具；机位纪律仍归侯氏 |
| 迈克尔曼（主）＋ 芬奇 | 借芬奇的**信息流动表**（谁在第几分钟知道什么）；「拍谁会干什么」仍归曼 |
| 科恩兄弟（主）＋ 库布里克 | 借库氏的**正面死中构图**做个别镜头；切点晚一秒的机制保持科恩 |

**不可混（互为反例，混用会同时废掉两边）**：

| 组合 | 为什么 |
|---|---|
| 库布里克 ＋ 芬奇（同一镜） | 一个用广角单点透视把人压进建筑、背景必须完整清晰；一个用长焦把人切成样本、背景必须压扁成失焦色块——**背景的处理要求正好相反** |
| 雷弗恩 ＋ 王家卫（同一镜） | 一个锁死机位、绝对正面对称、画面无遮挡；一个小幅手持、偏心构图、前景必须有遮挡 |
| 张艺谋 ＋ 朴赞郁（同一镜） | 一个填**一种颜色**（60–80%）＋ 等距同动作的 30–200 个单元 ＋ 只用眼平/顶俯两档；一个填**三种以上图案** ＋ 一两个人 ＋ 每场必做一次穿过中间高度的不可能运动——**张的参数明文禁止朴的运动** |
| 塔可夫斯基 ＋ 马力克（同一镜） | 一个机位钉死 30–90 秒、让自然元素运动；一个以步速持续漂移、单镜 2–5 秒 |
| 伯格曼 ＋ 王家卫（同一镜） | 一个要**正面全脸**且整张脸落在景深里；一个拍侧脸、后颈、被遮住的半张脸 |

> **分段主导演是更安全的混法**：把不同幕交给不同导演，各段内部不混（例：第一幕维伦纽瓦／第二幕雷弗恩／第三幕芬奇）。

## 六、每位预设文件的统一结构（也是新增导演的模板）

```markdown
# <中文名>｜<英文名>
> **一句话**：…（≤30 字，必须是一个机制，不是形容词）
> **触发词**：…

## 一、适用与不适用（含"改用谁"）
## 二、反例：最容易混的相邻导演（机制差异）      ← 必须有，否则不合格
## 三、六维推理机制（叙事／空间与机位／光学／光影／时间与剪辑／声音与表演）
## 四、风格参数（选型台 · 机器可读 YAML）
## 五、可执行清单（6–8 条，每条都是动作）
## 六、与其它层的对接（哪些维度接管、哪些保持全片默认）
```

**六条写作纪律**：

1. **一句话里必须能读出机制**（"让建筑比人更有权力"可以；"冷峻高级"不行）；
2. **反例节必须给出"同一批手段、不同目的"的差别**，并点名替代对象；
3. **凡给数字，都要说明它换来什么可见结果**（例：长焦在 3 米处给胸口以上画幅，机位不必逼近）；
4. **参数块只做选型**，正文写结果语言；
5. **不做"情绪形容词堆砌"**：每一条要么是取舍，要么是禁令；
6. **不与既有层重复**：视场角锚点归 OPTICS、五维档位归 CAMERA-LIGHT、块序归 PROMPT-DOCTRINE。

## 七、扩容：新增一位导演

1. 在本目录新建 `NN_<中文名>.md`（两位数序号控制排序），按上面第六节的**统一结构**写；
2. 在本 README 的**总表**（第一节）与**按类型推荐**（第二节）各加一行；如适用，在**混合速查**里补一句；
3. 若该导演与某条专线（纪实／动画／宣传片）相关，在对应线的文件里加一句入口；
4. 升版（`references/` 与 `examples/` 下全部 .md 的 frontmatter 版本号要脚本批量同步）→ 同步飞书操作手册 → 提交推送（钩子自动）。
