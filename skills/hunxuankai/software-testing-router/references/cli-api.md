# 函数、命令行与接口

当断言是计算结果、导出内容、协议或服务业务行为时，这些入口通常成本较低。先检查项目已有的测试命令、CLI `--help`、API 文档和测试环境，不凭空发明接口。

## 可执行方式

CLI 用参数数组启动进程，明确工作目录、编码、输出目录与超时。PowerShell 参数、Python 字符串和 JSON 分属不同转义层；JSON 序列化不等于 shell 转义。路径含空格、中文和符号时，优先 `subprocess.run([...], shell=False)`。

应同时检查：

- 退出码、必要 stderr/stdout；工具有 JSON 业务码时按其真实协议判断。
- 输出是本次生成：使用空目录、唯一 ID 或本次任务元数据。
- 重新打开文件核对内容、数量、尺寸或结构，不能仅检查“文件存在”。

HTTP 除状态码外，检查响应结构、业务码及业务副作用。`HTTP 200` 可以携带业务失败。本包故意包含此场景，不能把某个服务的 `code == 0` 当作所有 API 的标准。

涉及重试时区分可重试读取和可能重复提交的写入。超时可能意味着“已经执行但响应丢失”；先查询任务状态或按接口的幂等契约处理。

## 可复现样例

从技能根目录运行：

```powershell
.venv/Scripts/python.exe -m pytest tests/test_cli_api.py -q
```

这里实际启动 CLI 子进程以及仅监听 `127.0.0.1` 的 HTTP 服务，验证中文参数、JSON 产物、无效输入、非零退出码和 HTTP 200 下的业务失败。测试使用显式期望 `{name: "中文 样例", quantity: 3, total: 21}`，不再次调用被测导出函数来生成期望。

## 边界

接口可用于准备或清理测试数据。任务若是“按钮能否触发提交”，必须保留真实按钮事件及其可观察结果；直接请求接口生成成功记录只能说明接口可用。Mock 通过只证明被隔离部分，不等于真实服务集成通过。
