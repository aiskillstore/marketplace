# 增加语言、框架和平台

按“平台 + 框架 + 被验证的行为 + 实际入口”扩展。语言只是其中一个字段：Java HTTP 服务可能直接复用接口路线，JavaFX 窗口则需要在对应环境验证界面入口。

## 一条扩展应交付什么

| 字段 | 记录内容 |
|---|---|
| 对象 | 语言、框架、版本、操作系统；源码、EXE、URL 中实际具备哪些 |
| 断言 | 要证明的具体行为，以及由哪个可观察结果判断 |
| 入口与探测 | 实际发现的 CLI/API/DOM/UIA/AX/框架测试能力，选择理由 |
| 工具与依赖 | 现有工具可否复用，真正需要安装的依赖及版本 |
| 运行方式 | 可复制的命令、必要环境变量、测试数据与输出目录 |
| 验证证据 | 成功流程及相关失败场景的真实结果、日志、环境和日期 |
| 边界与恢复 | 缺少入口、超时、状态未知时怎样停止或换方法；哪些行为尚未验证 |
| 状态 | `verified`、`partial` 或 `unverified`，必须与证据一致 |

`verified` 只针对记录里的环境、版本和行为，不等于该语言的所有应用均受支持。`partial` 应点明未完成的断言；资料研究或模拟结果使用 `unverified`，不能包装成实机通过。

## 在现有结构中落地

以下开发步骤仅在维护仓库进行：运行包源码在 `skills/software-testing-router/`，新增参考页/驱动写入该子树；测试、fixtures、依赖和完整复现文档留在仓库外层。安装副本不包含开发测试，不在其中修改源码或执行仓库复现命令。

1. 先在现有路线运行一个小流程，确认缺口。仅更换语言而接口契约相同，优先复用已有方法。
2. 将该框架独有的信息放到一份 `references/` 文档；通用规则留在 `SKILL.md`。只有反复需要的操作才新增 `scripts/`，避免每个语言复制一个相同驱动。
3. 给新增能力添加可运行样例和有针对性的断言。例如改控件定位，就检验重名、错误作用域和实际触发对象，而非检查文档里有没有某个词。
4. 保存真实执行证据和明确的复现命令，再更新主入口/验证范围。新平台暂时无法运行时保留未验证状态，继续完成其他已授权内容。
5. 修改通用驱动时，重跑受影响的既有路线。依赖、测试数量、耗时都依据实际输出更新，保留旧证据供对照。

## 已完成记录的例子

- 对象：C# / .NET Framework WinForms，Windows 10 x64，编译后的独立 EXE。
- 入口：只读窗口探测与 UIA Value/Invoke Pattern。
- 断言：在指定父区域点击唯一按钮；跨独立窗口确认；核对新产生的 JSON 文件。
- 依赖：驱动使用 Python 标准库、PowerShell 7 和系统 UIA；测试样例由系统 .NET Framework 编译器构建。
- 相关失败：重名、错误区域、错误 EXE、未出现的状态、动作阻塞、记录被截断。
- 命令（维护仓库根目录，已准备测试依赖）：`python -m pytest tests/test_uia.py tests/test_uia_optimization.py tests/test_uia_journal.py -q`。
- 边界：不等于键盘快捷键、拖拽、其他 Windows 版本或所有自绘组件已验证。

当前证据统一从 [验证记录](validation.md) 进入。扩展时补充有用信息即可，不需要引入插件注册系统、强制审查轮次或覆盖所有平台的大套测试。

## Mac 新路线的状态

1.1.0 的 [macOS 原生路线](macos-accessibility.md) 将平台入口、有限步骤引擎与 AX 原生封装分离，复用现有 JSONL 恢复协议；旧 Windows 驱动保持可用。Mac 以真实程序路径、PID 与秒/微秒启动时刻绑定目标，使用原始 AX selector 和唯一祖先范围，不添加坐标或键鼠回退。Linux 暂不增加原生 GUI 驱动。

当前 Mac 状态为 `unverified`：实现、替身测试和 opt-in 验收用例不等于实机通过。具备 Mac 后按版本、CPU 架构、Python、权限归属与实际控件记录结果；原生验收串行运行，独立读新产物。测试样例可依赖 Swift/AppKit 编译器，运行包仍只用 Python 标准库与系统框架。不替用户改 TCC，不增大超时掩盖失败，不以 CLI/DOM 成功冒充原生按钮成功。
