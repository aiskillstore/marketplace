# 快剪后接点闪跳：定位、修复、验收

本页只处理本轮删气口、删冗余动作后新增的视频接点，不改变剧情取舍、BGM 选择或草稿事务规则。先保留已压紧的实声，再修画面覆盖；确实没有可用画面时，少恢复几帧有效动作也比增加装饰转场可靠。

## 每个新接点都进入联系表

在 `apply` 后、提交前执行下面命令。`baseline` 是本轮输入，`input` 和 `edit-report` 必须来自同一次 apply；最终回读则配同次 readback 重绑的 report。不要把 BGM-only 的零新接点报告套给上一轮精剪接点。

```powershell
python "<skill>/scripts/seam_review.py" scan --baseline "<baseline.json>" --input "<edited/draft_content.json>" --edit-report "<edited/report.json>" --copy-root "<副本根目录>" --preview "<本版本preview目录>" --ffmpeg "<ffmpeg>" --ffprobe "<ffprobe>" --output "<新的接点审阅目录>"
```

输出 `review.html`、`seam_review.json`、逐接点 PNG 和 `decisions.template.json`。扫描包含 `report.seams_us` 以及与 baseline 不同的源范围/静态画面边界，既查整段删时形成的接点，也查补画面、翻转、重新取景产生的边界。`--all-boundaries` 用于用户要求整集回看或无历史剪辑报告时复核当前全部视频边界；它不把所有旧边界判成错误。

- 每组取接点前 `5、2、1` 帧与后 `0、1、3、8` 帧，按目标帧显示时间映射源时码。源帧使用 ffprobe 解出的真实 PTS，报告源 FPS、帧数、尺寸、哈希；不把源 24 fps 误当目标 60 fps。微秒剪口可在目标帧之间。
- 源联系表不含剪映的缩放、位移、滤镜和字幕；绑定 preview 后同时输出实际渲染联系表，以后者判断成片。源表用于追溯残帧和动作来源。
- `same_media_same_transform_skipped_source` 表示同一媒体跳过源时间且画面参数相同，优先查同人同景别的姿势突变；不是人脸识别。缩略图差值仅定位，不能判人物、景别、因果或是否通过。
- 每项先看联系表，再正常速度看接点前后至少一组完整问答或动作。记录人物是否相同、景别是否相同、手位/头位/视线/关键道具是否跳变，以及为什么保留或如何修。

## 修复次序与可执行方法

### 1. 在真实动作或换镜点接

源连续时直接回到连续有效画面；同源同参数的连续子段交给 `merge_contiguous` 合并。源时间已跳过时，寻找动作方向一致的切点：例如抬头开始接抬头进行中，不把低头定住直接接头已抬高。可先在删口左右各试移 `1–3` 个真实源帧；每次同时复核实声，不能为了对齐画面截掉辅音。实际改回输入 `cuts` 边界，再 apply。

如果需要恢复 `2–6` 个目标帧的有效动作，必须重新量实声和字幕边界；不要恢复原来的整段无信息等待。没有自然动作接点，进入下一项。

### 2. 用同场的有效反应、手部或道具做画面桥

用现有 `bridges` 替换接点附近的画面，原对白、字幕和环境声不动。初试保留 `0.25–0.60 s` 的一个有效动作或反应；以观众能看清道具、交接、握紧或态度变化为结束依据。必要识别可延长到 `0.8 s`，不能只插 `1–3` 帧形成新的闪帧。

桥的窗口通常跨过问题接点，例如接点在 `12.57 s`，尝试 `12.40–12.85 s`。供体必须来自本集同场的已静音/已分离声音视频，源时段确实存在该动作；不要拿另一场手部特写掩盖时间关系。原对话明确显示说话嘴型时，桥到听者或手部也须确认语义可成立。两端都查手位、视线、轴线和道具状态。

```json
{"bridges":[{"start_us":12400000,"end_us":12850000,"donor_segment_id":"本轮baseline供体段ID","source_start_us":18000000}]}
```

此 JSON 中的时间仍是本轮输入时轴，删后由后端映射。供体源长度等于删后桥的实际保留长度，不按输入窗长度盲算。

### 3. 局部大特写 / 静态 punch-in 改变景别

没有合适异角度，但原镜有足够清晰度和画面空间时，让接点右侧稳定切到更紧景别。先试 `1.15–1.30` 倍；清晰度、额头/下巴、手和关键道具都允许时再到 `1.40`。数字是试剪范围，不是每次都放大的固定配方。

源尺寸和实际输出尺寸写入接点记录。以源宽/最终输出宽估计可用分辨率：例如 `1088 px` 宽源输出 `1080 px`，即使 1.15 倍也已插值，应在 1080 成片尺寸看眼睛、发丝和字幕附近；不能因 540 预览看着清楚就宣称无损。4K 源输出1080通常余量更大。不得通过降输出规格让裁切“通过”。

新接口使用静态值，仍由 `apply` 的哈希、普通正向1倍速和引用校验保护：

```json
{"bridges":[{"start_us":12400000,"end_us":12850000,"donor_segment_id":"供体ID","source_start_us":18000000,"reframe":{"scale_multiplier":1.22,"offset_x":0.0,"offset_y":-0.03}}],
 "reframes":[{"start_us":12566666,"end_us":16000000,"track_id":"主视频轨ID","reframe":{"scale_multiplier":1.22,"offset_x":0.0,"offset_y":-0.03},"rationale":"切到更紧的有效反应；头位和眼线已逐帧核对"}]}
```

`scale_multiplier` 乘供体/原片段已有静态 scale；`offset_x/y` 加到已有归一化画布位移，正负方向以渲染实图核对。后端允许倍率 `1.05–1.50`、位移增量 `[-0.25,0.25]`，执行默认用更小试剪值；这不是自动安全裁切保证。禁止动画关键帧、旋转或复杂变形直接套该接口。

重构图从接点右侧保持到下一次真实换镜/有用反应结束，初试至少 `0.4 s`，通常 `0.6–1.2 s`。如果同一长镜中途回原景别会新增跳点，可保持到原镜结束。不要 1–3 帧放大再缩回，不要在每个删口交替推拉。局部眼睛/手部大特写必须有可辨的剧情作用、原素材清晰度和完整动作，不做自动人脸裁切。

### 4. 声画分开处理的实际边界

现有 `bridges` 可保持原实声，把画面先切到听者/道具，这是当前后端可以落实的声画分离。`audio_edge_fades_us` 的 10–40 ms 淡化可减轻音频接点爆音，不能修人物画面跳变。

真正 J/L cut 或 `2–6` 帧音频交叠需要独立音频重定位、可用源余量和相应原生/后端实现；当前 `bridges/reframes` 不能完成它。不得只写“做 J-cut”或添加淡化字段就报告已实现。确需此法，使用明确支持的原生操作并单独回读验证，不改变其余轨道时序。

### 不用这些方式敷衍通过

- 同人同景别硬跳不要默认加叠化：双脸重影通常更明显。叠化仅适用实际时间流逝/回忆等语义明确场合。
- 滤镜、亮度/色温匹配只修两边色差，不能修头位、手位和道具跳变。只在两边确有可见色差时小幅统一，保留原调色基线。
- 动画、抖动、模糊、炫光、旋转、变形和闪白转场不作为常规遮掩；它们会制造新的视觉事件。快动作的 motion cut 可用，但必须源画面里已有真实运动，不能靠滤镜伪装。
- 翻转只修有证据的左右关系/反字，不能为让脸的位置相近而翻转。翻后检查文字、手、衣服不对称和镜头轴线。

## 验收与提交

### 补画面内部也可能有闪现

源文件可能已经烘焙叠化。只取剪口前后几帧会漏掉桥中部或桥尾的旧姿势短暂回现。对改过的 bridge/reframe，从完整动作的入口看到出口；用本版本原生 preview 检查全部目标显示帧。`run` 会从当前 edit report 自动枚举每个补镜/重构图操作并生成待审的 `picture-ranges/<range_id>/`，但不会自动审阅通过。单独执行时把 `--range-id`、输入/输出时间和轨道与同一份 edit report 对齐：

```powershell
python "<skill>/scripts/fine_cut.py" seam-review inspect-range --input "<edited/draft_content.json>" --edit-report "<edited/report.json>" --copy-root "<副本根>" --preview "<本版preview>" --range-id bridge-0001 --start-us 33050000 --end-us 37116666 --handles-ms 300 --primary-video-track-id "<主视频轨ID>" --ffmpeg "<ffmpeg>" --ffprobe "<ffprobe>" --output "<新的整段检查目录>"
```

`--range-id` 只能引用当前 report 的操作，不允许输入手工指定、互不对应的另一组时间。输出源/渲染逐帧页、完整目标帧号及其实际源 PTS、正常速度视频入口、默认 pending 的区间记录；最多 900 显示帧，较长窗口拆成有重叠的短范围。取帧包含入口前和出口后余量，未自动识别叠化。`validate-range --scan <range_review.json> --decisions <填写后的记录>` 检查入口/内部/出口、正常速度记录及哈希。

quality review 的 `picture_ranges` 必须逐项引用本版本的 `range_review.json` 和已完成 decisions。原接点 `seam_decisions` 仍要审，不能用区间记录替代。只有无需补镜/重构图的旧任务不新增此项。

如果已离门人物在旧场尾叠回坐姿：先找到叠化前最后连续有效源帧，再检查下一场开头是否有可用真实画面。可把桥分两段：旧场连续动作结束 → 下一场开头 → 下一场原有源入点。下一场供体末尾应在源 PTS 上接回原片段；保持原对白/字幕/总时长，复核场次因果、嘴型、手位与两端。例：下一场基线从 source 1 秒起，可用其真实 source 0–1 秒提前覆盖旧叠化；只有该段实际存在且内容可用才这样接，不能复制任意一秒广角。

源 24 fps、目标 60 fps 时，微秒边界未必落在显示帧上。出口查 `ceil(end_us×fps/1e6)` 的首个出口显示帧及前一帧；不能凭四舍五入多保留一帧放大。tight/original 对照无收益或用户明确选原景别，就恢复该范围，保留其他认可修复。连续源画面可解的问题优先用连续源，不机械叠加 punch-in。

修复后重跑 apply、preview、seam scan；修复两端的新边界也必须复核。只看无声联系表不能把 `normal_speed_review` 写为 true。每项 `reason` 写可复核观察，例如“右手仍握杯，抬眼方向相同；用听者0.42秒反应跨过源跳时2.4秒”。不写“优化自然”之类空话。

把模板另存为 `decisions.json` 后填写，运行：

```powershell
python "<skill>/scripts/seam_review.py" validate-review --scan "<接点目录/seam_review.json>" --decisions "<decisions.json>"
```

只有每项 `decision=pass`、`pose_and_prop_checked/frame_review/normal_speed_review=true`、人物/景别观察为布尔值、具体说明非空且输入/素材/preview 哈希仍一致才返回 `passed`。自动检测或模型仅看帧时诚实保持 pending；此工具不自行写 true。零新接点的音频任务可返回0项通过，不需伪造画面审批。

接入 `run --review` 或 `review-check --seam-scan` 时，quality review 的 `seam_scan` 必须与传入的扫描文件路径相同，扫描中的输入 JSON 和 edit report 哈希必须与本轮一致；`required_review_count=0` 时 `seam_decisions` 可保持 `null`，大于0时引用已完成的 decisions 文件。

回写仍按原 `commit → verify → readback → 最终 preview → 最终 qc`。最终报告分别记录帧核验、正常速度观看、实际监听与原生播放范围；接点报告不是试听证明。
