# 时间线编辑、回写与边界

优先通过 [fine_cut.py](../scripts/fine_cut.py) 调用随附脚本。路径来自机器配置，不依赖旧项目工作目录。工作顺序见 [本地执行与恢复](jianying-workflow.md)。

## 四个执行层

1. [run_workflow.py](../scripts/run_workflow.py)：通过 `fine_cut.py run` 编排完整流程，保存阶段输入签名、脚本/配置版本和产物哈希，支持候选待审、提交前待确认及断点续跑。没有批准计划不删减；初始 clone 只创建独立副本，没有显式 `--commit` 不把精剪时间线写回副本。
2. [draft_workspace.py](../scripts/draft_workspace.py)：精确定位、完整独立副本、本轮快照、编解码回环、事务回写/恢复及保存回读。支持已识别的 `Timelines/project.json` 多时间线布局，包含主线根级活动镜像；未知布局报具体文件/身份缺口。
3. [timeline_ops.py](../scripts/timeline_ops.py)：从本轮明文和 [哈希绑定计划](plan-schema.md) 隔离生成统一删时、多语言字幕、桥接/翻转、连续音乐、增益自动化及独立音效。它不判断剧情、不写真实草稿。
4. [analyze_draft.py](../scripts/analyze_draft.py)、[transcribe.py](../scripts/transcribe.py)、[plan_candidates.py](../scripts/plan_candidates.py)、[preview_draft.py](../scripts/preview_draft.py)、[media_qc.py](../scripts/media_qc.py)：资源/内嵌及分离人声候选分析、可选词级转写、两阶段候选计划、版本绑定渲染、媒体检查与接点图。各自留证，不能相互冒充；候选计划只有显式批准后才进入 `timeline_ops.py`。

## 副本、镜像和新保存

`clone` 完整备份/校验项目内资源与清单，复制后建立不同草稿/项目身份、重定位内部路径并登记。外部视频/BGM默认保留可读原始引用；确需完全携带时显式 `--collect-external-media`，不默认复制整个外部库。`--destination` 可指定独立目标。

镜像按内容识别：每集正式文件/活动 `template-2.tmp`、主线根 `draft_content.json/template-2.tmp` 应对应当前主线；历史 `draft_content.json.bak` 可以较旧，不能硬当活动镜像。项目 `.bak` 和元数据也绑定本轮。工具核对ID/布局，备份历史内容并按角色更新，不把所有 `.tmp/.bak` 一律覆盖。

剪映可能自动发现新副本并分配登记ID。精确同路径、唯一且与源独立时协调身份；同名其他路径或新保存冲突保留现场，不盲加第二条或覆盖。每轮从当前保存版继续，包括用户手调的曲目、增益和字幕。

写入前检查锁与原始哈希，先编码全部改动并解码验证，再更新所选集、有效镜像和清单。同副本串行写。失败恢复只覆盖能证明仍是本轮写入的文件；保留外部改动。快照/journal是恢复入口，旧已提交快照不能覆盖后续保存。

## 编辑计划与声音

快节奏任务在整句删口后继续做源画面重选。长原镜可以拆成多个短的 source/target 子段，分别承载进入、动作、反应和结果。视频子段可以与对白、环境声和字幕采用不同边界，但每个边界都要以真实音节、手位、视线、道具和动作状态复核。

配乐计划在画面重排后重新评分，不按轨道名称判断角色。读取素材实际类型和内容，优先保留前奏短、起拍快、瞬态清楚、能推动当前节拍的段落。旧配乐只有在仍然推动当前冲突或情绪时保留。相邻场景能量变化时，优先重做短衔接或换拍，避免慢前奏和多层同质 BGM 长时间叠放。

时间用整数微秒的左闭右开区间，按实际源/目标范围映射，近既有边界才吸附。不要先把所有源切点取整到目标60fps，24fps源切点可能在两帧之间。字幕仅定位；气口查实声/动作。部分截字、截字幕或未知时间效果应拒绝，整句删除需显式列语音和各语言字幕ID。

普通正向1倍速支持细剪；未受影响原段保留、整段删除不必重采样。需要部分裁剪的复杂变速、复合、反放或未知动画给出具体段ID和缺口，不能丢效果。先做其他支持的操作，必要原生步骤才用界面。

补画面通常只动视频，记录供体/源入点/目标范围，保护原对白和字幕。镜像有明确依据才设最终方向，复核道具/文字。可安全合并时，将同素材、同参数、源/目标连续片段合一，避免独立seek产生 A→B→A 单帧回退；普通重复采样帧不等于倒退，先比较真实源帧。

BGM 按材料和段 ID 分类，包含未命名轨。高能场景至少比较 3 个候选，30 至 60 秒集默认拆 2 至 3 个能量区并完成一次升能、换拍或撤拍。跨画面删口保持音乐源连续，在尾部缩短并映射原音量事件。新 BGM 计划记录 `mix_role=bgm`、`fader_db=-9~-5`、源峰值和计算后的 `target_peak_dbfs`。按剧情换曲时核准源入点、段落增强和尾音，给台词和情绪提示留空。交叠使用等功率自动化时撤相应旧淡出/淡入，保留外侧首尾和已有效的音量曲线。新增 duck 采用上限，避免已有低量再次相乘，渲染检查交接和对白。`music.ducks` 只作用于 baseline 已有音乐段。新增 BGM 需要用分段或局部 fader 实现对白让位。

剪映片段推子是相对增益，`volume` 使用线性倍率，换算为 `10^(推子 dB/20)`。素材经过推子、自动化和叠加后的峰值以 dBFS 检查。独立声源的预计峰值可由实测选段峰值加推子 dB 得出，实际混音用渲染验证。计划中 `target_peak_dbfs` 是选段加增益后的目标峰值字段，不能直接填剪映推子读数。

用户手调过的音量和气口以当前保存版为基线。若增益后预估接近或超过满幅，先定位高峰及叠加声源。以实际渲染查是否发生削顶或余量不足，优先用短局部关键帧、窄范围增益修整或可验证的峰值保护，并在邻句恢复原有效增益。只有明确测得某段普遍偏高或用户要求时才扩大处理范围。声音入点、相邻音节、推子参考和原来的配乐层次都要复核。

音效按事件决定保原声、加强、新增或留白，不以固定数量/泛低音覆盖所有镜头。30 至 60 秒集默认至少 3 个独立可感知事件，冲突加反转的集数通常需要 4 至 8 个。每个事件核拟用段起音、主attack、尾音、峰值/RMS 和 `fader_db=-5~-2`。短击打不能把密集长声压住后一句。可在隔离目录用FFmpeg裁短、EQ和淡尾，不覆盖用户库。`timeline_ops.py` 会用 `fader_db` 与实测源峰值换算 `target_peak_dbfs`，并在计划中回报两者。

快剪同源同景别跳时接点按 [闪跳修复](seam-repair.md) 全量采样与逐项正常速度回看。后端新增 `bridges.reframe` 和 `reframes` 静态倍率/位移操作；仅画面变化，普通旧计划兼容。不得把未支持的动画、滤镜、复杂变形或 J/L 音频交叠写成已执行功能。

## 验收证据

最终预览与当前输出JSON哈希绑定，依赖/设置不变且证据完整才 `preview --reuse`；新增修改只重做受影响集。`qc` 技术通过只证明解码、时间/帧率和电平等检测，不证明情绪/听感。新接点、全局短镜候选看实际帧，主要音效attack对动作，关键台词与BGM接点核实声。

`commit` 后 `verify` 回读正式文件、活动镜像、项目/元数据及独立身份，再用 `readback` 导出最终 JSON；仅在非路径结构一致时重绑编辑报告，最终预览/QC 使用该回读版本。原生重新保存后用 `verify --native-saved` 核播放字段并解释规范化差异，不拿旧哈希覆盖新保存，也不把精确提交模式的 `readback` 报告强行套用到规范化版本。原生播放、实际试听与本地渲染分别如实报告。
