# 激活后的开发规范

[English](development.md)

仅在 Birdview 已激活且用户授权编码时适用。实施前遵循 [SKILL.zh.md](../SKILL.zh.md) 的已展示方案确认步骤；单纯建图或最初的编码请求不代表方案批准。沿用已有地图和变更流程；这些规则不会开启持续生效行为，也不覆盖项目指令。

## 选择相关规范

阅读相关实现、调用方和适用的设计决策。先从源码解决疑问，仅询问仍未明确且实质影响任务的选择。编辑前明确预期可观察行为及适度的验证方法。必要时组合以下规范，例如修复按钮失效时结合故障诊断与界面检查，不对每个任务执行所有章节。

### 修复问题

建立复现，或检查与用户所述现象相符的具体失败证据。使用最小有效测试、命令、请求或界面操作。间歇性故障记录复现条件和频率。无法复现时说明尝试过什么、缺少什么证据，区分暂定修复和已验证修复。

选择修复方案前，用证据检验可能原因。疑难故障可对比多个假设，简单问题不强制假设数量。调查时一次改变一个相关变量。性能问题须在可比较条件下测量受影响场景的修改前后表现。

修复后重新运行原始场景。回归测试能覆盖真实失败路径且有长期价值时再添加；可行时观察其修复前失败、修复后通过。说明缺失的覆盖。清理本任务引入的临时诊断内容，不删除他人的工作。

### 功能与行为变更

明确可观察的验收行为和重要失败路径，按小块行为逐步实现与验证。测试应通过稳定接口覆盖真实路径，不照抄内部实现，也不因模拟内部协作者而虚假通过。用户要求或确有收益时采用测试先行；不强制每次修改都使用，也不为无明显风险的简单可逆编辑堆测试。

### 重构与架构变更

检查受影响的调用方、兼容要求和已有决策。说明具体收益，例如消除重复业务规则或减少调用方必须了解的细节。未获授权改变的行为应保持，并验证受影响的接口和路径。不添加推测性抽象，不扩大到无关清理。普通编辑不启动架构评审；仅在技能触发规则允许且用户提出要求时使用独立评审流程。

### 界面变更

在相关视口尺寸检查渲染结果和受影响交互。涉及加载态、空态、错误态时检查这些状态，并检查相关键盘操作、焦点和可访问标签。按改动规模选择检查，文案修改无需全站审计。无法进行视觉或交互验证时说明限制，不宣称已验收。

## 记录与完成

沿用[变更流程](show-changes.zh.md)：在 `planned` 的原因中记录预期行为和验证方法，在 `checks` 中记录实际命令、退出码和观察结果，在 `constraintReviews` 中复核适用的已记录约束。不编造字段或通过结果。人工检查只支持已检查范围，活动结束不证明正确性。

区分未执行检查、环境阻塞和实际失败。自主继续常规检查和有理由的重试，仅为实质未决选择或必要访问条件提问。相关检查通过后，只因范围改变或剩余风险扩大测试。重新核对原始需求；职责、归属或关系变化时更新地图；交付改动、实际验证和剩余限制。这些是 Agent 指令，校验器检查记录，不证明 Agent 确实遵循了流程。
