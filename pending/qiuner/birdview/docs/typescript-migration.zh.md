## 目标与范围

将 TypeScript 作为第一方可执行代码的维护语言，覆盖 Node 命令、校验、渲染、浏览器交互、仓库工具与测试。CSS、HTML、Markdown 和 JSON/JSONL 数据保留适合的格式。分发的 JavaScript 是生成产物，不是另一套手写实现。

迁移旨在改善数据契约、状态建模和修改安全性，不是框架重写、性能承诺或 AI 编码效果提升的证据。保留冻结评测产物和正在执行的基准测试。

## 目标结构与技术决策

```text
src/
  contracts/         运行时定义及推导的领域类型
  core/              语义校验与纯布局、状态逻辑
  node/              CLI、渲染、Git 检查和仓库工具
  viewer/            浏览器入口、交互、状态和 DOM 代码
test/                 TypeScript 单元、集成和浏览器测试
scripts/*.mjs         分发的 Node 入口和配套产物
assets/viewer.js      内嵌到独立 HTML 的浏览器构建产物
schemas/*.json        如消费者仍需要，保留生成的交换契约
```

仅在输出映射就绪后将现有 CLI 移入目标结构，全程保持公开路径可用。Node ESM 与浏览器 DOM 使用独立 TypeScript 配置；通过显式导入共享领域类型，不使用隐式全局变量。

以 TypeScript 运行时 Schema 定义作为结构契约的唯一来源。阶段 1 选择 TypeBox 0.34.41 配合现有 Ajv 8.20.0，替代最初的 Zod 候选：它能直接表示现有 `uniqueItems`、`dependentRequired`、模式属性及严格对象规则。从定义推导类型，对外 JSON Schema 由它生成，不手写维护平行定义。JSON/JSONL 仍是面向 AI 的交换格式。字面量联合导出为 `anyOf` 而非 `enum`；通过旧 Schema 对照接受范围，Ajv 详细错误文字和条数可能不同。已有公开 Schema ID 和定义锚点保留，日期时间仅作注解的现有策略不变。

跨记录与仓库检查保留为显式语义校验：地图版本绑定、文件归属、事件顺序、约束引用及 Git 比较，不会因为对象具有 TS 类型就自动成立。外部输入先作为 `unknown`，通过验证后再收窄类型。交换数据、界面状态和布局计算结果分开建模。

使用 `tsc` 做严格检查和 Node 编译。使用轻量浏览器打包器，优先在兼容性验证后选择 esbuild，将显式导入构建为单个自包含脚本并内嵌 HTML。通过 `file://` 打开不应需要服务器、CDN 或运行时模块请求，不为迁移单独引入 UI 框架。

## 阶段与验收

### 0. 固定迁移基线

- 清点受维护脚本、浏览器入口、测试、模板与网站内联脚本及发布资源。实验预览单独分类，仅在被确认为正式维护代码后迁移。
- 记录 CLI 退出行为、导出函数、合法与非法测试数据、多语言视图及独立 HTML 行为。
- 与进行中的工作明确共享文件归属，单独记录原有失败。

验收：有限定范围的文件清单、基线结果和明确的首批目标；迁移提交不包含无关工作。

### 1. 建立唯一契约定义

- 在 `src/contracts/` 定义架构、活动、约束、证据、翻译与校验结果，并推导类型。
- 保留缺失与 null 的区别、旧格式可选字段、未知字段拒绝、字符串与路径限制、跨 Schema 引用及校验选项。不静默转换值或删除非法字段。
- 用同一批正反例对照新旧校验结果，解释每个接受范围差异；已有消费者使用的错误代码和位置应保持。
- 单独测试 JSON Schema 导出：自定义校验未必能完整表示，应说明结构与语义边界，不能宣称导出 Schema 覆盖全部要求。

验收：测试数据结果一致、校验后有效收窄类型、Schema 导出可复现。确需破坏数据格式时提供版本化迁移和测试数据，不能在语言迁移中意外改变。

### 2. 迁移 Node 核心

- 按依赖顺序迁移 `validate.mjs`、`render.mjs` 和已接纳的约束检查功能，以真正的类型化实现替换 `src/render.d.mts`。
- 为选项、结果、诊断及文件系统和进程边界定义类型。保留安全路径检查、输出替换行为及 CLI 退出码。
- 同步迁移仓库构建、文档工具，必要时用生成入口保持命令路径稳定。

验收：针对编译 JS 的 CLI、契约和 Git 测试通过；仓库外执行 `doctor` 正常；安装包无需调用 TS 编译器即可运行。

### 3. 迁移浏览器实现

- 先迁移路由布局和翻译逻辑，再迁移活动状态、约束、指引和主视图。
- 用显式导入和小型类型化视图状态替代脚本文本插入及隐式共享变量。不要把全局变量换成无类型的大上下文对象，也不引入庞大状态机框架。
- 用联合类型表示视图模式和事件阶段，明确处理不存在的模块、事件及 DOM 节点，不用批量断言或非空断言掩盖问题。
- 将执行源代码字符串的测试改为直接模块测试，同时保留针对生成页面的真实浏览器测试。

验收：中英文、架构／更改／对照、选择、悬停、缩放、指引、约束详情和窄屏布局行为保持。检查空数据、旧数据、转义与浏览器错误，页面继续离线自包含。

### 4. 完成工具、测试与分发

- 迁移剩余受维护工具、浏览器测试及网站、模板中的执行逻辑，不重写第三方代码。编译后的测试放在 Git 忽略的目录中，浏览器测试使用构建产物。
- 编译器与打包器保持开发依赖。发布安装检查包括必需 JS、运行时依赖、资源、生成 Schema 和许可证声明。
- 扩展 `check:build` 覆盖全部生成产物，包括新增和删除的输出。维护明确输出清单，不能清理任意路径，也不能将生成物清理与源码删除混在一起。
- 避免循环启动依赖：npm 命令须能先构建 TS 版本的构建检查工具，或随包提供并验证它生成的 JS。

验收：干净源码压缩包能按文档安装运行；Windows/Linux 和支持的 Node 版本生成结果可复现，不受 CRLF/LF 检出影响。

### 5. 清理过渡路径并发布

- 证明结果一致后，再删除临时声明和重复手写 JS。Ajv 是 TypeBox 契约选定的校验器，不是迁移遗留；更新锁文件、第三方声明、技能指令及双语安装、贡献文档。
- 除非明确提供迁移说明，否则保持外部命令和数据兼容。保存基线结果，列出已验证平台、跳过的浏览器检查和剩余缺口。
- 获得授权后才发布，不替换进行中评测的冻结技能快照。

验收：所有受维护的第一方执行源码和测试为 TS；剩余 JS 明确属于生成产物或第三方代码；没有未解释的临时绕过。

## 质量门槛与执行规则

- 要求 `strict`、`noUncheckedIndexedAccess`、`noEmitOnError`；新契约启用更严格的可选属性检查。不用大范围 `any`、`@ts-nocheck` 或未经检查的双重断言伪装迁移完成。
- 每批执行类型检查、构建及产物一致性、相关行为测试和差异审阅。浏览器行为或构建改变时执行浏览器检查；集成节点运行完整平台矩阵。
- CI 最终覆盖 Windows/Linux、支持的 Node 版本、语义与契约数据、生成物一致性、文档和浏览器冒烟测试。已有浏览器测试不等于已被 CI 执行。
- Schema 或类型检查通过不证明架构真实或产品正确，报告实际结果与限制。
- 每个提交只包含一个连贯阶段或模块，独立产品改动单独处理。失败批次连同生成物和依赖改动一起回滚；安装与浏览器门槛通过前保留旧发布版。
