# Inverted index for text search

## Scenario

A policy archive has thousands of documents. A query should find records containing both words without reading all document bodies.

## Failure modes

Singular/plural normalization changes meaning in some domains. Newly updated records can lag the primary store, and query syntax must be compiled safely.

## Explain it simply

Store a list of document IDs for each word so a search can combine just the lists it needs.

## Implementation guidance

Specify how the analyzer handles case, accents, stop words and product codes before exposing search. For AND matching, tokenize the query and intersect the postings for its terms. Keep syntax generated by the application separate from user text. Store a reference to authoritative records rather than treating search results as permissions. Test inflections, punctuation-heavy codes and authorization changes alongside recall and response time as the corpus grows.

## Decision rules

- **General term search needs ranking and tokenization** Use a text index with documented analyzers, postings intersections and scoring. Index size and update lag must be monitored.
- **Only exact small identifier lookups are required** Use a keyed index or simple prefix lookup matching the stated contract. This preserves exact semantics but provides no relevance ranking.

## Verification

- Test phrase, spelling and multi-term fixtures with known correct results.
- Update and delete source records, then verify search freshness and rebuild semantics.
