# Engineering documentation

Write down how a user starts, how data moves through the entry point, and which invariants are important to its callers. Examples should link to a runnable implementation, test, fixture, or clearly labeled simulation.

Keep stable contracts, setup requirements, and schema or API changes near the relevant owner. Generate repetitive rendered views from their source where practical. Cite the environment, scope, and evidence behind compatibility or performance claims.

For an operational change, document prerequisites, normal operation, likely failures, and recovery. Update setup or examples as part of a contract change to avoid mismatched guidance.
