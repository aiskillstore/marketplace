# One Pass: checklists by deliverable

Read only the section for what you are making. Each section lists the checks that most often cause a rejection, so you catch them before handing over.

## Code change

- [ ] The change does what the request says, and nothing else (no unrelated refactors).
- [ ] The relevant test passes. If there is no test and the change is risky, add one small test first.
- [ ] Ran the build or linter the project uses, if it is cheap.
- [ ] No secrets, debug prints or leftover temp files in the diff.
- [ ] Error paths behave (empty input, missing file, network failure), if the change touches them.

## Image, post, banner or slide

- [ ] Exact size and format required (e.g. 1080×1350, 1080×1920, PNG or JPG).
- [ ] Every number, price, phone, address and name matches the source, character by character.
- [ ] Spelling checked; no text cut off, overlapped or outside the safe area.
- [ ] Brand rules: logo, colors and fonts as the brand file says.
- [ ] Photos look real and clean: no strange hands, faces, melted objects, invented letters, or other brands' logos.
- [ ] One look at a zoomed crop of the busiest area.

## Video

- [ ] Size, duration and frame rate as required.
- [ ] The first frame is not empty and shows the hook.
- [ ] Text and buttons inside the platform's safe zone for the whole video.
- [ ] Loudness within the project's target; no clipping.
- [ ] Music licensed for the use; never a track with unclear rights.
- [ ] Check a frame strip (one image with frames every 1-2 s) rather than playing it several times.

## Copy or text

- [ ] Says what the brief asked, to the right audience, in the right language and tone.
- [ ] Facts (prices, dates, offers, claims) come from a source, not from memory.
- [ ] No banned claims for the channel (e.g. health promises or misleading before-and-after in ads).
- [ ] The project's duplicate or style checker passes, if there is one.
- [ ] One call to action, with the right contact.

## Data, settings or records

- [ ] Wrote only the fields the request covers.
- [ ] Read back each written field from the system itself, not from your own notes.
- [ ] Nothing deleted or overwritten without the user's approval.

## Report or analysis

- [ ] Every number has a source (file, query, page) and a date.
- [ ] Separates what was verified from what is an estimate.
- [ ] Answers the question asked first, in the first lines.

## Brief for another agent or chat

- [ ] Goal in one sentence.
- [ ] Exact inputs: full paths, IDs, links.
- [ ] The acceptance list the work will be judged by.
- [ ] What to avoid (past rejections, banned items).
- [ ] What done looks like, and how and where to report (with evidence).
- [ ] All of it in one message.
