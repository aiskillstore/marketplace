# 多智能体协作细则（形态二三）

本文件仅在叠加形态二三时按需加载，平时不读。

## 形态二·子智能体

**命中任一就开：**
- 有一段完全独立的子活干完交结果即可
- 要并行跑两件或以上的事
- 要一个独立挑刺视角
- 这段活会产出大量中间过程怕污染主上下文

**派发规范：**
用 `create_agent` 派，给清三样：
1. 目标——要干什么
2. 完成标准——怎么算做完了
3. 交回给谁——结果交回主Agent验收

**纪律：**
- 子智能体交回后，主Agent仍是DRI，必须自己验收（不因子智能体说做完了就直接交付）
- 子智能体不直接对用户
- 一个人连贯干完的事不开二

## 形态三·多智能体

**命中任一就考虑：**
- 用户指名要多Agent / 指挥官
- 让另一个AI干
- 任务大到要分工（有人写、有人审、有人管进度）
- 要不同模型各展所长

**先跟用户确认再动手：**
形态三要建 `_agents/` 文件夹、写任务包、填模板——有外部副作用。命中后先跟用户说"这个任务适合多智能体分工，要不要开？"，用户同意了再往下做。用户说不用就自己干。

**六步操作：**
1. 确认叠加形态三，指挥官身份声明一句（「我是指挥官」）。
2. 在当前项目根目录下建 `_agents/` 文件夹，从 skill 的 `templates/` 复制三份模板填好：commander / executor / reviewer。
3. 把要跨模型的部分拆成子任务，每个写一份七要素任务包（背景 / 已定决策 / 未定缺口 / 完成标准 / 允许与禁止范围 / 唯一 DRI / 交回给谁）。
4. 任务包交给你转述给执行者（跨模型只能靠你转述，create_agent 是形态二的事）。你说「已转述」才算派发。
5. 执行者交回后：指挥官**先对照原始目标**检查有没有跑偏（做的是不是用户要的、有没有漏项、有没有擅自加东西），再交给审查者挑刺；审查意见回指挥官，决定改还是收。
6. 指挥官独立核验后，给用户最终汇报（做了什么 / 怎么验的 / 没验什么）。

**红线：**
- 执行者说「我做完了」不算验收
- 审查者不亲自改
- 不向用户绕开指挥官直接汇报
