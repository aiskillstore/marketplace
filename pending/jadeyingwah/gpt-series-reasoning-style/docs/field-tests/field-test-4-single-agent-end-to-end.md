# Field Test 4 — Single-Agent Backbone, End-to-End / 实测四：单 Agent 主干端到端

- 日期：2026-09-09
- 被测版本：v1.1.0（本地含 3 个未推送提交，`56a338a`）
- 形态：**单 Agent 主干**（AI 自选，非用户指名）
- 补齐的空白：此前 `field-test-1` 是指挥官形态端到端、`field-test-2` 是对抗探针、`blind-test` 是第三方盲测 —— **主干形态此前没有专项端到端报告**
- 被测项目：一个从零构建的命令行待办工具（Python stdlib，零依赖），在独立工作区内，**未纳入本仓库**

## 为什么选这个场景

刻意选"从零新建产物"以命中轻通道**排除项①**，强制走全流程而不是绕过门禁。它同时具备：真实持久化（文件 IO）、有状态 CRUD、可枚举边界（空输入、无效 ID、损坏数据、Unicode、flag-like 参数、ID 复用）—— 给 bug sweep 提供攻击面。规模小（~350 行）但完整（模型 / 存储 / CLI / 测试 / 文档 / 证据）。

## 本次实测抓到的问题

### 抓到被测项目的缺陷（证明机制有效）

| 缺陷 | 说明 |
|---|---|
| `clear()` 语义错误 | 无参数应全清，实际保留已完成任务，且返回计数错误。**关键：38/38 测试全绿时它仍然存在** —— 唯一的 clear 测试用例里两个任务恰好都是未完成态，掩盖了分支 |
| 列表输出乱序 | ID 复用后新任务插到末尾，显示 #2 在 #1 之前 |
| 空路径错误信息误导 | 空参数被解析成当前目录，报 `Permission denied`，与真实原因无关 |
| 类 flag 参数被吞 | 以 `--` 开头的标题被参数解析器吃掉，报误导性"缺少参数" |

四个全部修复 + 补回归测试 + 复验（64/64 测试、18 条命令复跑全绿）。

### 反哺本 skill 的发现

1. **测试全绿 ≠ 功能正确**（最重）。已据此在 `references/common-failures.md` 的 Claims 表补"功能正确"一行，并在 `series-reasoning-lessons.md` 强化对应的失败模式条目。
2. **实操闭环对非 GUI 产物缺分档**。原闭环只有"按钮/手势/截图"与"无 GUI 就标 UNVERIFIED"两条路，导致 CLI 类产物被迫降格标注。已在 `series-reasoning-workflow.md` 补「Non-GUI artifacts」分档（CLI/库/API/文档各自的证据形态），并澄清"产物类型无 GUI" ≠ "环境无能力"。
3. **资源盘点缺"已被本 skill 覆盖"这一档**，容易重复加载同义 skill 白烧 token。已在 `workflow.md` 补为第四档结论。
4. **门禁「最高影响问题」与「需要你确认」易重叠**。已在 `SKILL.md` 与 `workflow.md` 两处模板同步加区分说明。

另有一条**撤回**：实测初稿曾建议"给 bug sweep 加固定攻击面清单"，核对后发现 `Generative Divergence Protocol` 明确写了"固定分类清单只是冷启动辅助，不是发散本身"—— 这是刻意的设计选择，不是缺失，故撤回该建议。
