# 视觉证据与未覆盖平台

“不要默认 Computer Use”不等于“禁止截图”。颜色、裁切、字体、透明度需要图像证据；截图可用于最终观察或差异定位，而不必驱动每一步操作。

## 视觉要求

固定版本、字体、窗口/画布尺寸、缩放、背景和色彩条件。优先保存原始截图或无损导出图，比较相关区域。透明图片至少考虑合适的合成背景；仅看 alpha 通道或透明区域的隐藏 RGB 值可能误判。

精确像素、阈值差异、感知指标各有用途，均不自动等同于“视觉正确”。参考图不可信、字体替换或环境变化时，解释限制，不把一张自己生成的图当成独立设计基准。

本包只校验透明像素在黑白背景下的合成比较和差异检测，不声称已完成人类审美检查、真实字体裁切回归或视觉点击识别性能比较。相关小型验证位于维护仓库 `tests/test_visual.py`，执行范围见本包 [验证摘要](validation.md)；安装副本不包含测试样例。

## 自绘画布与无结构化入口

DOM 存在不代表画布内部对象可定位；UIA 有外壳也不代表画布暴露控件。先检查应用已有测试接口、对象模型或可访问性支持。如果验收要求真实拖拽，直接修改内部坐标只能验证模型状态，不能代替拖拽链路。

需要视觉操作时按当前环境可用工具和用户约束选择。把一次观察得到的可靠定位尽量复用，动作后验证语义结果，避免重复的整屏截图猜测。用户禁止这条路线时，明确报告受阻范围和需要的能力。

## 未实测的路线

移动端、macOS 原生应用、Linux 桌面、C++ Qt、真实 Electron/WebView2 和 Windows 的其他封装库，没有在本包获得执行验证。它们可能有对应平台测试工具，但应先在实际目标做可观察能力探测，再写具体建议；不能将本包 Windows/Chromium 结果外推为已通过。

没有适合当前断言的入口时，保留证据并清楚报告未验证内容。不要把“执行不了”改称“测试通过”，也不要为了覆盖更多平台而无条件安装大量依赖。
