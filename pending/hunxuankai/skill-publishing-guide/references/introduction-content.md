# 介绍内容的准备、同步与验收

发布包和页面介绍可能走不同的保存、审核、翻译或展示链路。上传 ZIP、更新版本、导入 GitHub 或推送仓库，只能证明相应操作；不能默认全部展示内容随之同步。

## 先识别内容层与来源

| 内容层 | 应确认的来源与用途 | 不能默认推出什么 |
| --- | --- | --- |
| 发布包内容 | 本次归档或上传的文件字节、版本和来源提交，包括 SKILL.md 正文与运行依赖 | 包正确不代表页面介绍已更新 |
| SKILL.md 的 `description` | YAML 中用于技能发现/触发的描述；部分平台会将其作为简介建议 | 它不是长篇概述，不为了平台文案静默改写触发条件 |
| GitHub README | 明确是仓库根还是 skill 子目录、哪个 ref/版本；通常服务于仓库读者 | 仓库 README 不等于包内 README，也不保证平台拉取或重新生成 |
| 平台简介/摘要 | 列表卡片或详情页顶部短文；核对实际表单值、抓取来源及公开字段 | 简介包含新功能不代表概述正文也包含 |
| 详情页概述正文 | 实际渲染的长文；可能来自包内文件，也可能是单独保存的自定义 Markdown | 不能只凭标题或版本推定其来源，更不能默认 ZIP 覆盖自定义文案 |
| 平台翻译 | 平台实际展示的语言版本、原文来源及版本对应关系 | 字段带语言后缀不证明生成方式、重建触发或已与原文同步 |
| 缓存与展示副本 | 当前 URL、语言、所选版本、页面/API/下载各自的观测时间 | 内容不同不等于已经确认是缓存；没有依据不承诺刷新时间 |

先从当前官方说明、实际表单/预览及必要的只读内容入口定位来源；记录证据等级和日期。找不到来源或编辑入口时写明待核验，继续完成不依赖该事实的文案准备。只处理用户选定的渠道与语言；没有某种展示面的平台写“不适用”及依据。

## 发布前准备可直接使用的文案

以本次选定来源和验证记录为准，准备平台简介及概述全文，必要时同步选定的 README。文案应写清：

- 新版具体增加、修正或移除的功能，保留仍适用的已有能力。
- 系统支持与限制：原生实现、可移植入口、仅有指导和没有支持分别表述。
- 运行依赖、权限或工具前提；维护/测试环境的依赖不能冒充运行依赖。
- 真实执行过的验证及环境，未实测、失败、跳过和未知部分。新增 macOS 指导或实现不能写成 macOS 已实机通过；Windows 上的检查也不代表其他系统已通过。

为每层指定来源文件/ref、源版本、拟更新全文和目标入口。默认读取文件的概述要检查该文件正文；已有自定义概述要逐项比较并准备新版正文，不能只更新摘要或变更说明。平台字数/格式限制按当前规则适配，不靠删掉依赖或未验证说明来制造完整支持的印象。

## 提交时确认实际接收内容

查看本次表单、导入清单、预览或正式客户端的提交材料，确认简介和概述实际采用哪份内容。自动抓取的建议尚未采用、编辑器仅保存到草稿、未填写独立概述、写请求结果未知，分别记录。若入口没有概述字段，核对实际文件来源和官方更新机制，不臆造字段或接口。

提交后用与本次身份/版本关联的记录确认接收与审核状态；没有介绍字段回显时，保留已提交材料及“服务端保存内容待核验”。留空、清空、复用旧文案和复制文件正文可能有不同语义，不能以一个客户端的省略字段推定服务端会删除旧介绍。

## 发布后的四项验收

逐项注明身份、目标版本、URL/入口、时间、所见内容及与拟更新文案的比较结果：

| 验收对象 | 实际核对 | 结果独立记录 |
| --- | --- | --- |
| 版本 | 正确 namespace/slug 的公共作者版本或平台修订 | 目标版本可见、仍旧或未知 |
| 下载包 | 从实际渠道取得的包、文件清单及内容/哈希与选定来源一致 | 包一致、缺文件、仍旧或未核验；本地包不能替代 |
| 简介 | 实际列表/详情顶部文案；区分 API 原文和网页语言字段 | 对应新版、仍旧、不一致或未核验 |
| 概述 | 详情页实际正文、语言及所选版本；逐项检查功能、系统、依赖与验证范围 | 对应新版、仍旧、局部缺项或未核验 |

仅“版本公开”不能写成发布整体完成；待审核、目标版本公开和网页介绍更新可以处于不同状态。翻译或不同展示副本有差异时保留各自观测，原因与刷新时限未经证实就继续标为待核验，不自动升版、重传或重建条目。状态与恢复见 [核验说明](verification-and-recovery.md)。

## 需要用户手动操作时

先完成独立可做的包校验和文案。按照 [发布记录模板](submission-record.md) 交付“平台简介全文”和“详情页概述 Markdown 全文”，分别放入可复制文本块或准备好的文案文件；交付时必须已填好实际内容，不能留给用户自行补写。

同时给出已核实的入口、身份/版本、实际字段、保存与提交步骤，以及完成后应查看的四项证据。概述入口尚未确认时，完整文案照常准备，明确下一步只是定位来源/编辑能力，不能将猜测写成填写步骤。沿用会话通知规则请求必要介入，等待实际回复；不把手动上传 ZIP、填写版本号当作概述已经提交。

## 发布交付清单

- [ ] 来源、目标版本、发布文件和许可已确认。
- [ ] 各层介绍来源、语言、拟更新范围及默认/自定义模式已记录，未知项有原因。
- [ ] 简介与概述全文和新版功能、系统支持、运行依赖、真实验证范围一致。
- [ ] 实际接收的文件和介绍内容已核对，草稿与提交状态分开。
- [ ] 回执、审核状态与本次身份/版本关联，未用旧版公开替代新版待审。
- [ ] 版本、下载包、简介、概述的公开核验分别有结果、时间和证据。
- [ ] 未完成项、所需用户操作及完整文案已交付，没有未经证实的同步或刷新承诺。

只咨询或准备时，尚未授权/执行的提交和公开验收写“未执行”；这不阻止本地准备交付，也不能改写成已发布。
