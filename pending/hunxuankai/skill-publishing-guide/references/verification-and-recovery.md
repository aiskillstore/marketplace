# 发布状态核验与中断恢复

## 先确认发布路线到了哪一步

受限或新渠道的核验分层记录，每层注明日期、官方来源及实际检查：

| 核验层次 | 可以依据什么确认 | 仍不能推出什么 |
| --- | --- | --- |
| 正式入口已恢复 | 正常 TLS 的实际官方页面、可打开的投稿模板，或可获取且来源明确的官方 CLI | 主页返回 200 不代表上传、投稿或审核可执行 |
| 发布流程已核对 | 当前官方文档/界面/CLI 明确接收物、字段、权限、条款及核验入口；本地材料满足已知要求 | 文档与客户端观察不能当作服务端上传实测 |
| 本次发布已验证 | 已授权的真实提交关联到本次身份/版本，随后取得相应审核与公开内容证据 | 一次成功回执不能代替目标版本的公开核验 |

仅咨询或准备时可完成前两层，不要求真实提交测试；已有发布授权才执行相应外部写操作。入口仍失败时记录具体阻塞，沿用有效授权继续其他独立工作，不使用相似域名或非官方 CLI 猜测恢复。各版本的实际状态按下表报告。

## 先把几个事实分开

| 可以报告的状态 | 所需证据 | 不足以支持它的信号 |
| --- | --- | --- |
| 本地准备完成 | 选定来源、材料及检查结果 | 尚未创建的包或预期命令 |
| 已接收/处理中 | 与本次身份/版本关联的回执或任务 | 只有 HTTP 2xx，没有业务状态 |
| 待审核 | 对应版本的审核状态或未合并审核 PR | 老版本已经公开 |
| 目标版本号已公开 | 正确身份和作者版本/平台修订的公共页面或 API | 不能代替下载包或网页介绍核验 |
| 发布包已核验 | 从实际公开渠道取得的文件/包与选定来源一致 | 本地已有副本、只有公开版本号 |
| 网页介绍已更新 | 实际简介与概述分别符合新版文案，并记录语言与核验时间 | 摘要包含新功能、ZIP 更新、源 README push |
| 目录已收录 | 目录默认分支的实际条目及正确链接 | 创建 PR、后台私有条目、源仓库 push |
| 失败/被拒绝 | 明确的失败或审核结果 | 超时、匿名 404、无搜索结果 |
| 未知/受阻 | 缺少关键证据、入口或权限 | 不应改写成成功或不存在 |

保留平台原始状态词及核验时间。平台 HTTP/业务码各不相同，不套用另一个服务的成功码。公开版本、作者版本、平台修订和 manifest 协议版本也可能是不同字段。

## 每站核对这条链

`来源提交/目录及介绍文案 → 本次文件或包/表单内容 → 提交身份/版本 → 回执/审核 → 公开版本、包与网页介绍`

查看最能证明当前目标的入口：有权限的发布记录用于定位提交，公开页面/manifest/下载用于证明对外可获得。只有旧版可见时，同时记录旧版和本次新版状态。对目录 PR 还需检查目标分支里的实际链接。

按 [介绍内容的四项验收](introduction-content.md) 分别记录版本、下载包、简介和概述，逐项比较新版功能、系统支持、依赖和真实验证范围。简介已更新但概述仍旧时，明确记录两者，不合并为“页面已同步”；版本已公开但包/文案未核验时，也不报告发布整体完成。待审核、版本公开和网页展示更新分别保留原始状态与时间。

声明“安装到本次内容”时，从真实渠道入口取得文件，核对来源/版本及必要哈希；本地已有副本不能替代该证据。安装核验可能有本地写入或遥测，应在任务范围内使用隔离目录，不覆盖用户正在用的版本。

包内文件、独立介绍、翻译、网页展示副本、安装来源及后台记录可能不同步。先定位实际来源和语言/所选版本，再分别记录观测；不能仅因内容过时就断言是缓存，不编造刷新 SLA。匿名查询 404 可能只是待审/私有过滤，也可能是账号或 namespace 错误；无法进一步核实时保持未知。

## 超时、重复版本及重试

写请求开始后超时，先保存时间、目标、来源哈希及可用请求/任务 ID，标为结果未知。随后做只读状态查询，将已有条目与该请求关联。

`VERSION_EXISTS`/409 或同名冲突只能说明某个身份已有记录；比较 owner/namespace、slug、作者版本、来源与内容，确认它是相同发布、不同内容还是待审条目。不可仅为绕过冲突自动改名、bump、删除或重发。

当官方定义了幂等键/恢复协议时按原请求身份操作；没有依据时不假定 POST 可重复执行。缺少下一步必要权限或选择时，先交付已完成部分与可核对的待办，再按会话规则请求用户介入。

需要回退本地安装或处理已公开版本时，先检查平台能力和备份，不假定撤回可以消除既有下载，也不覆盖已发布标签/附件来伪装同一版本。

报告使用 [模板](submission-record.md)，真实 ID、账号配置和日志存于被发布项目的维护记录。
