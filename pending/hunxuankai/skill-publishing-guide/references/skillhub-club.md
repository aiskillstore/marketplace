# SkillHub.club：网页导入与官方 CLI 发布

资料核验分两部分：2026-11-07 的官方 CLI 文档、链接的官方仓库及 npm `@skill-hub/cli` **0.1.9** 代码；2026-11-08 的官网“发布”入口、已登录的 `/app/skills` 表单及文件选择器属性。

CLI 0.1.9 的启动、帮助、SKILL.md 校验、普通本地 init 和受控文件扫描已在隔离用户/staging 中实测；未登录的 push/publish 认证守卫按预期失败。网页本轮只核对表单，没有输入字段、上传文件、创建条目或公开；服务端接收、详情页资源上传及实际发布结果仍未验证。本平台是 `skillhub.club`，不能使用腾讯 `skillhub.cn` 的账号、接口或 ZIP 规则。

## 选择本次输入

- **网页导入**：官网“发布”链接进入 `/app/skills`，提供创建表单与 ZIP/Markdown/文本文件导入控件，不要求先创建 GitHub 仓库。实际解析、完整文件接收及公开状态分别核验。
- **CLI 托管发布**：从本地单个 skill 的工作目录上传文本文件，再把远程条目公开。不需要先创建 GitHub 仓库，也不是上传整个仓库 ZIP。
- **已有公开 GitHub 来源**：官网 FAQ 宣传 SKILL.md 来源会自动索引。源码已公开、网站已收录和本次内容已刷新分别核验；没有确认任意 repo/tree URL 的手动导入接口或固定收录时限。用户未授权 GitHub 发布时，不能为了该路线自动建仓或公开源码。

只要求准备时，生成独立 staging 目录、预期文件清单、来源提交/作者版本及 SHA-256；没有登录也能完成。staging 根是选定 skill 的 SKILL.md 与其依赖，不能带入兄弟 skill 或整个维护仓库。

## 网页创建与文件导入

正式入口为 [Skills 管理页](https://www.skillhub.club/app/skills)。已有有效浏览器会话直接复用；只有实际登录受阻时才请求用户完成登录。不要从浏览器提取凭据给 CLI 使用，两种会话分别处理。

当前“创建新技能”表单提供名称、描述、分类和逗号分隔的标签；名称旁提示仅小写字母、数字、连字符，最多 64 字符。这是界面说明，本轮未通过创建请求测试服务端校验，也未替用户选择分类或标签。

“上传 ZIP / SKILL.md”区域提示：拖入下载的技能 ZIP 或包含 SKILL.md 的文件，会自动创建技能并生成首版。页面文字列出 `.zip`、`.md`、`.txt`；文件选择器实际 `accept` 还包含 `.markdown`，并允许多选。选择器属性只证明可选择的文件范围，不证明任意 Markdown/文本都能被识别为合法 skill，或多份 SKILL.md 会怎样导入。

选择或拖入文件属于上传及创建远端记录，不是离线预检。仅核对表单时读取说明与属性；真实导入在本次授权内使用已固定的单个 skill 及完整文件清单。

当前页面提示二进制资源可在详情页补充。本轮没有已有测试条目，也没有为核验新建条目，因此未核对详情页的资源类型、大小、路径保持及公开操作。网页 ZIP 的根层级、文件数量/大小上限和新条目的默认可见性仍未确认；不能套用腾讯 SkillHub、Agensi 或下文 CLI 的限制，也不能把 `.skillhub.json` 的 private 默认值当作网页默认状态。

准备 ZIP 时固定所选发布单元和实际归档结构。若包含必要图片、PDF 或其他资源，上传后要核对服务端完整文件集合；不能仅凭 ZIP 控件存在或“首版已创建”宣称完整产物已公开。

## CLI 发布路线

执行前从官方来源核对实际 CLI 版本及所用子命令的 `--help`。0.1.9 的普通 `init` 只在当前目录生成本地 `.skillhub.json`，已有 SKILL.md 会保留；`init --link <skill-id>` 则要求登录并查询远程条目。初始化在独立 staging 中进行，保留来源目录及已有配置；更新时核对实际绑定的 skill ID，不捏造或重建远程身份。

需要真实发布且已有相应授权后，缺少登录时使用官方 `login`；已有有效会话直接复用。当前命令路线如下，每步检查实际结果后再继续：

```powershell
npx @skill-hub/cli init
npx @skill-hub/cli push
npx @skill-hub/cli publish
```

`push` 上传文件，可创建远程条目并返回 skill ID、slug、平台修订和文件统计；`publish` 处理远程公开状态。初始化配置默认是 private，但不能把本地默认值当作服务端状态证据。上传和公开分别属于外部写操作，沿用本次任务的授权范围。

名称、描述、分类与标签按用户材料和当前客户端可用字段确定，不默认采用网页示例中的分类值。凭据由正式客户端管理，不打印、复制进发布包或改为第三方镜像认证。

## 上传前核对完整文件集合

0.1.9 的扫描器只接收允许扩展名的文本文件；允许 `.md`、`.py`、`.sh`、`.js`、`.ts`、`.json`、`.yaml`、`.yml`、`.toml`、`.txt`、`.mjs`、`.cjs`。默认忽略点文件、`.skillhub.json`、Git/依赖目录、dist/build、日志、环境配置和锁文件。SVG、图片、PDF 和归档不在该允许列表。

该版本 `push` 根据账号 tier 使用单文件 100 KiB 或 Pro 的 1 MiB 检查；超限文件会警告并跳过。配置中的 ignore 与默认规则合并，实际扫描仍受扩展名、点文件和大小检查限制。这是客户端代码观察，不是完整服务端契约，也不构成升级付费账号的要求。

该版本 `status` 的本地扫描仍使用默认 100 KiB，可能漏列 Pro `push` 能上传的较大文件。不要把 status 的本地文件统计当作 Pro 上传集合的完整证据；以实际待上传清单和服务端文件记录核对。

本次受控扫描实测了 100 KiB/1 MiB 参数下的不同文件集合、默认排除的 JSON 被 ignore 否定规则恢复、以及 SVG 仍被扩展名过滤。1 MiB 是扫描参数测试，不是实际 Pro 账号或服务端额度测试。

比较预期清单与实际待上传清单，连同许可文件、脚本及引用资源核对。若必需资源被过滤或跳过，当前上传集合不完整；保留源码，查证其他官方入口/新客户端能否完整接收，或交付具体阻塞及适配选项。不能静默删依赖、仅凭成功退出码或使用 force 参数宣称包完整。

## 更新、版本与公开核验

0.1.9 的 `publish` 遇到远程 `status=published` 会直接返回 `already published` 和已有 URL，不扫描或上传本地文件。更新必须先比较绑定条目的文件并 `push` 本次内容，再按实际远程状态处理公开；只重新运行 `publish` 不能证明新版已更新。

`push` 的返回 `version`、`status` 的 `current_version` 和 `versions` 的版本历史是平台修订记录，不能直接当作 SKILL.md 中的作者版本。保存实际 ID/slug、来源、作者版本、平台修订、完整文件清单及内容哈希。

用官方 `status`、`versions` 或有权限的管理页关联本次上传，再从实际 `public_url` 核对公开身份、版本及可获取内容。网站评分、自动索引、公开详情、可下载和安装成功分别记录；公开页存在或 CLI 成功提示不能证明本次完整产物可获取。需要报告完整安装时，从真实公开入口取得内容，在隔离目录与来源逐文件比较。

超时、同名冲突或公开页仍旧时按 [核验与恢复](verification-and-recovery.md)查询，不自动改名、重建条目或重复上传。真实回执写入被发布项目的 [发布记录](submission-record.md)。
