# 动效工作室（代码渲染通道）

本层是**代码渲染**这条产出通道的唯一入口：把产品界面做成电影感短片，用**真实页面截图 + 2.5D 运镜 + 节奏卡点 + 电影级音效**，逐帧渲染出片。它自带 **157 张动效镜头配方卡**（每张含意图、动效核心、参数表、已知坑与参考实现）、七份规则文档、可跑的工程模板与 154 份音效素材。

> **两部分分开放**：**规则文档**在本目录 `references/motion/`（七份）；**可照抄的资产**在 `examples/motion/`（镜头卡、桥段模板、工程模板、参考实现、组件、素材、脚本、剪映工程）——它们全部与 Remotion 绑定，换渲染引擎就不适用，所以归**成品资产层**，不与规范混放。

**它与「宣传片线」是并列的两条通道，不是同一件事**：

| | 本层（代码渲染） | `PROMO GUIDE.md`（生成通道） |
|---|---|---|
| 画面从哪来 | **产品真实界面**（截图 / 录屏 / 真实 UI 状态） | 生成模型按提示词产出画面 |
| 强项 | 像素级还原产品视觉、精确的功能演示、逐帧可控的运镜与卡点 | 概念画面、写实人物、自然场景、想象力驱动 |
| 典型片型 | 产品宣传片、发布视频、功能演示、官网首屏片 | 品牌概念片、TVC、形象片、包装片 |
| 不可替代处 | 观众要"看清楚这个产品到底怎么用" | 观众要"感受一种氛围与调性" |

**两条通道可以接力**：概念镜头走生成通道，产品界面镜头走本层，最后在同一时间线里合成。

## 一、触发判定：先判断这条通道对不对

**不是所有片子都适合代码渲染。** 判定错方向会让整支片子白做——所以**在选模式、采素材、写代码之前，必须先过这一关**。

### 强信号（命中两条以上，基本确定走本层）

- 手里有**真实的 web / 桌面 / 移动端产品界面**要展示，不是只有一个概念；
- 要求**精确还原**产品视觉：字体、配色、圆角、间距、真实文案与真实数据状态要对得上；
- 要做**功能演示**：展示交互流程、状态变化、多页面串联，而不是"感觉一下"；
- 需要**逐帧可控**的运镜与节奏（卡点、hold、变速），不接受生成模型的随机性；
- 成片时长在 **15–90 秒**，投放渠道是官网／应用商店／发布会／社媒信息流／销售私发。

### 反向信号（命中任一条，**明确说不**，并给替代路线）

| 需求 | 说法 | 替代路线 |
|---|---|---|
| 真人出镜、实拍剧情、生活场景 | "要有人、有故事、真实场景" | 主干 `P0→P6`；需要生成画面时并用 `PROMO GUIDE.md` |
| 只有一句创意、没有可展示的产品界面 | "帮我做个概念片，还没做产品" | `PROMO GUIDE.md` 生成通道（概念画面是它的强项） |
| 写实人物、自然风光、想象力画面为主 | "要大片感的自然场景" | 生成通道；本层只承担其中的界面镜头 |
| 超长片（>3 分钟）、系列长内容 | "做一集 10 分钟的" | 主干 + 剪辑；代码渲染逐帧成本随长度线性上涨 |
| 剧情片／纪录片／MV 主体 | — | `references/FEATURE-PRODUCTION GUIDE.md`／`DOCUMENTARY GUIDE.md`／`MUSIC-SCENE GUIDE.md` |

**判定话术**（照这个说，别含糊）：

```text
先判断一下这条路线对不对，再说怎么做。

你这支片子我看了下：有真实的网页界面要展示、要精确还原产品视觉、
时长也在 60 秒内 —— 这正好是「代码渲染」通道最擅长的情况：
用产品真实截图 + 2.5D 运镜 + 卡点，逐帧渲染，画面 100% 可控。

反过来，如果是要拍真人、讲故事的剧情片，这条通道就不合适，
那种我们走主干的全流程。

要不要按代码渲染这条路走？
```

**不要**在没看清素材时就默认用模板，也不要因为模板现成就推荐它。

### 该说不的时候，把话说完整

判定为反向信号时，**不要只说"这条通道不合适"**——要把创作者送回正确的那条路，并说清代价：

```text
这条通道我建议不走——它会卡在 <具体原因>。
按你说的需求，应该走 <生成通道 / 主干全流程 / 纪实线>：<一句话理由>。
如果只是其中几段需要展示真实界面，也可以两条接力——
真人实景走生成、界面与数据走代码渲染，最后合成在一条时间线上。
```

**完整的两通道判据、提醒时机、场景全表、混合分工与话术见 `references/CHANNEL-SELECT GUIDE.md`**；本层第一节只回答"本路通不通"，**通道的最终选择与锁定由该层统一裁决**。

## 二、先问用途：用途决定形态

同样的产品，投放在官网首屏和发在社媒信息流，片子长得完全不一样。**明确用途之前不要进分镜。**

| 用途 | 形态要点 | 常用镜头卡 |
|---|---|---|
| 官网／落地页首屏 | 无解说、自动静音可看、首屏 3 秒内出产品 | 墨线准星开场 / 聚光锁定卡片 / 发牌飞入 |
| 应用商店预览 | 前 5 秒必须展示核心操作，竖屏优先 | 打字筛选穿页 / 详情卡逐字段自建 |
| 发布会／大会 | 大屏可读，节奏可以慢，允许留白与呼吸 | 升降臂拉升揭示 / 全员合影发布 |
| 社媒信息流 | 前 1.5 秒抓人，强卡点，字幕通栏 | 硬切节拍 / 三行霓虹跑马 / 预埋彩蛋 |
| 销售私发／招商 | 功能要讲透，可带字幕与配音，时长放宽到 90 秒 | 活体图表 / 环形图解标注 / 文档自写 |

**用途说不清时，只问三个问题收敛**：

1. 这个片子**给谁看**（客户／投资人／用户／招聘）；
2. 播在**哪里**（官网／商店／大屏／朋友圈）；
3. 看完希望对方**做什么**（去注册／下单／记住品牌／理解一个复杂功能）。

三个答完，形态基本就定了。

## 三、四种用法

判定通过、用途明确之后，再选制作方式。**四种互不合并**，用户已明确选择时直接执行，不重复询问：

1. **模板复现** —— 想要与模板片高度相似的效果：读 `examples/motion/工程/说明.md`，按既有镜头结构替换目标产品的截图、文案与品牌信息。用户点名"用那支纸墨晨读风模板"时视为已选定。
2. **自主创作** —— 要新风格并授权自主决定：读 `motion/工作流.md`，从产品理解连续推进到终检，中途不逐阶段等确认。
3. **共同创作** —— 要参与关键决策：读 `motion/协作引导.md`，依次确认产品简报、需求决策、视觉方向、镜头映射与最终分镜，放行后再进流水线。
4. **单镜头／单动效** —— 只要一个效果：从 `examples/motion/镜头卡/` 选卡（按类别目录或 `examples/motion/镜头卡/索引.json` 检索），读卡全文，按"参考实现"定位对应源码。

**用户说"你全权决定"或"跳过确认"时**，切到自主创作并记录这一选择；不要一边说自主推进、一边继续逐阶段要确认。

## 四、核心理念

1. **复刻真实页面必须用真实截图**；手搓 UI 只限非复刻场景，且"达不到出版级质感"或"观众看不懂它在表达什么"就是不合格，要退回截图路线。页面数据按风险分级：公开数据在产品简报确认后才可用，客户／个人／内部／密钥／实时数据**一律用虚构或脱敏内容，并在采集前冻结**。
2. **视觉语言必须从产品自身生长**，不能另造一套"宣传片皮肤"。做 styleframe 前先从设计系统、源码或 computed styles 提取设计 spec（字体与字重、字号层级、行高字距、栅格间距圆角、背景／表面／正文／强调／状态色），片中所有标题、字幕、数字、版式、转场、粒子与光效配色都复用或克制扩展这套 tokens。
3. **电影感来自运镜、光影、节奏与声音的配合**，不来自炫技动画。被反复认可的是：单主角完整动作弧、物理隐喻驱动的加速度、侧斜机位环绕特写、`riser→impact→sparkle` 的声音句式。批量元素入场靠运动本身，不靠逐个发光——装饰性泛光群发即廉价，单点高质量光效可做。
4. **每个镜头只讲一个动效；关键信息落定后必须呼吸。** 一种手法全片只当一次主角，重复镜头与重复 tagline 一律删。节奏偏好是单向的：反馈全部指向"放慢／停留"，从未出现"太慢了"——品牌字标落定 hold ≥1s、批量动效收尾留 0.5s 静止、开场主体动作给足 3s。
5. **强节奏 BGM 的片子，所有转场与动效必须卡在拍上。** 开工前先做节奏分析（BPM 与相位网格拟合 + 鼓点定位），网格按瞬态覆盖率验收通过后才分镜；时间线用拍号写，重音钉真实瞬态而非网格插值点，渲后回测切点误差。卡拍管的是时机不是幅度——作用于整画面／相机层的节拍冲击全片 ≤3 处。
6. **用镜头卡必须读准确的参考实现。** 卡片给的是语义与参数表，调校过的参数真相在实现代码里（缓动、时值配比、摘罩时机、已知坑的规避写法）。允许适配性改动，但卡上"已知坑／命门"标注的参数**不得降档**——质量标准只升不降。凭理解新写＝放弃全部调校积累。
7. **方向未定不进逐镜头实现。** 产品简报 → 需求到执行决策表 → 文字方向 → styleframe → 镜头映射 → 分镜，这个顺序不变；共同创作逐级交用户确认，自主创作由 Agent 选定并连续推进。
8. **验收贯穿全程 + 交付前独立审查。** 每个镜头出静帧自检，每轮修改后整片渲染抽帧回看；交付前派一个干净上下文的 subagent 按 `motion/终检清单.md` 独立终检，逐条出带帧号证据的报告。**制作者对自己的产出有确认偏差，首检永远不能交给用户。**
9. **确定性渲染**：禁 `Date.now()`／`Math.random()`，一切伪随机固定种子，逐帧可复现。

## 五、与主干的关系（边界）

**本层只改"产出通道"，不改主干方法论。** 具体：

- **仍适用**：资产的成对与命名、表演与情绪的写法、16 段固定块序与十一条铁律（写提示词时）、光学与布光的可观察结果口径、交付前的质检纪律。
- **本层新增**：真实页面截图采集、代码化的运镜与动效实现、逐帧时间线与卡点、音效钉帧、工程化渲染与独立终检。
- **冲突时以主干为准**：本层的默认值（如某些镜头卡的固定机位、无 BGM 版交付）只在自身描述范围内成立；全片口径一律以 P1／P4／P5／P6 为准。
- **参数只进数据文件与工程配置，不进提示词正文**——与本仓一贯口径一致。

## 六、阶段对接

| 主干阶段 | 本层落点 |
|---|---|
| 判定形态 | 用第一节的强／反向信号判定是否走本层，并说清替代路线；**通道的正式确认与锁定在素材核验后、P4 之前**（见 `references/CHANNEL-SELECT GUIDE.md`） |
| P0 项目接收 | 产品简报（只读检查）：定位、受众、可用页面与状态、数据风险分级 |
| P1 创作基准 | 从产品设计系统提取视觉 tokens，产出 styleframe 与设计 spec |
| P2–P3 资产 | 真实页面截图采集（整页 2x 纹理 + 元素级抠图 + 坐标表） |
| P4 分镜 | 功能到镜头映射 → 完整分镜（镜头顺序、时长、页面状态、字幕、转场、SFX） |
| P5 逐镜头 | 按镜头卡 + 参考实现实现，逐镜头静帧自检 |
| P6 声音与交付 | 音效钉帧、卡点回测、整片渲染、剪映工程导出、独立终检 |
