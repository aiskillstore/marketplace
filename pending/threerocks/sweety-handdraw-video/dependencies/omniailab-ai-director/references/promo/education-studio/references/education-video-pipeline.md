# 教育视频生产管道

## Canvas delivery contract

全部阶段产物必须物化到 OmniAiLab 画布 画布。初始规划使用一个“完整 Brief”可编辑 text node，统一承载教学 brief、视觉方向、完整逐字旁白、完整视频脚本、路线建议和产物清单；用户完成风格与路线选择、进入正式分镜阶段后，再创建分镜 text node。图片、视频、VO、音乐和音效使用生成工具返回的画布节点；剪辑使用已打开的视频编辑器插件及其 Agent 能力。阶段完成以有效节点 id 为依据，聊天 Markdown 用于说明画布交付位置与用途。

后续 Stage 消费文本产物前必须调用 latest canvas version 重读最新内容。分镜阶段读取完整 Brief；媒体生成阶段读取完整 Brief 和正式分镜。用户在画布上的修改优先于会话中的旧副本；用户在聊天中的修改先用 canvas locating 定位并通过 anchored text edit 回写画布，再继续执行。不要仅凭文件名、旧 node identifier 或聊天中的脚本判断文档存在。

## 教育视频创作合同

教育视频提示词使用统一风格锚点与逐镜教学字段；旁白直接进入视频片段提示词，与画面事件、动作、文字动效和转场共同生成；视频确认后按需要生成独立正式 VO 作为替换或精修层。风格选择、分镜图生成、H3 生成、画布和视频编辑器按照当前 OmniAiLab 画布 工作流执行。

## 教育视频创作合同

### 风格锚点

风格使用可观察的完整视觉锚点表达。通过 confirmation card 展示 3–5 个完整风格方向，用户选择后收敛为一段统一锚点：

- 视觉媒介；
- 构图语言和主体—背景关系；
- 线条、材质与画面质感；
- 色彩、光影与信息层级；
- 时间线、地图、公式、角色关系等教学信息的呈现方式；
- 镜头运动与动效节奏；
- 与主题一致的聚焦原则。
- 负向提示词：画面瑕疵、风格偏移、角色漂移、错误文字、错误动作及该主题需要排除的元素。

风格锚点原文贯穿脚本、分镜、分镜图、关键帧和所有视频提示词，各镜直接继承同一锚点。

### 逐镜教学合同

逐镜合同完成后建立项目生成输入合同：

| 层 | 内容 | 消费位置 |
|---|---|---|
| 项目级信息 | 项目名、画幅、分辨率、文件命名、全片时间与片段顺序 | 画布与视频编辑器 |
| 共享资产 | 人物、音色、场景、风格、用户素材及各自适用片段 | 各片段的素材装配 |
| 当前片段内容 | 当前片段可见画面、动作、局部时间轴、逐字旁白、屏幕文字、声音事件 | 模型 prompt |
| 执行设置 | 经能力摘要核准的模型路线、画幅、分辨率、时长和命名 | 生成阶段 |

从完整脚本提取跨片段共享实体并先完成资产化。同一人物跨两个及以上片段出现，或讲师/主持人持续出镜时，为其建立稳定身份记录和人物资产图；已有合格用户参考图则直接登记，否则用 image-generation model 生成干净背景资产图，固定脸部、发型、年龄感、体型、服装、配色和标志性配件。每个共享资产记录路径、用途、适用片段集合和确认状态。用户确认后，片段装配器按适用集合附加人物、音色、场景、分镜和其它素材，并保持各自引用职责。直接文字生视频与分镜图路线共用同一份共享资产表。

正式分镜中的每个镜头必须包含下列字段：

| 字段 | 必须回答的问题 |
|---|---|
| 片段编号、全片时间段、计划生成时长、提交 duration | 这段旁白在全片什么位置，实际执行模型生成多少秒？ |
| 画面内容 | 观众实际看见哪些具体对象和变化？ |
| 景别、机位、运镜、转场 | 信息如何被揭示，为什么在这里切换？ |
| 主体、角色、道具 | 谁做什么，哪些对象必须保持一致？ |
| 对应逐字旁白 | 哪句话落在这一镜的哪个动作窗口？ |
| 承担知识点、教学功能 | 这一镜讲什么，帮助学生完成什么认知动作？ |
| 视觉证据/视觉比喻 | 什么可见变化直接证明旁白含义？ |
| 学生观察任务/理解目标 | 学生此时应该看哪里、发现什么？ |
| 学科准确性/教师复核点 | 哪个事实、动作、公式、结构或单位需要精确呈现？ |
| 负向提示词 | 这一镜需要排除哪些画面瑕疵、风格偏移、错误文字、错误动作或多余元素？ |
| 屏幕文字 | 必须逐字出现什么，外观与出现时机是什么？ |
| 声音 | 台词、环境声、动作音效和音乐如何配合？ |
| 关键帧描述 | 哪个稳定状态需要先锁定，哪些运动留给 H3？ |
| 参考素材来源 | 使用哪个画布节点或用户素材，承担什么参考角色？ |

技能演示类额外包含动作要点、正确动作对照和安全点；概念解释类额外包含视觉比喻；微课类额外包含教学功能与学科复核点。字段齐备后进入视频生成。

## 中间产物

复杂任务使用结构化中间产物，名称可以按宿主系统调整，但字段语义保持稳定：

| 阶段 | 最小产物 |
|---|---|
| brief | 受众、目标、时长、格式、假设、素材 |
| research | 事实、术语、公式、来源和待核验项 |
| script | 段落目的、旁白、屏幕文字、练习点 |
| shot plan | 时间码、镜头目的、画面描述、转场 |
| scenes | 场景类型、组件、内容字段、资产 |
| editing_project | 起止时间、音画层、字幕和重点出现时间 |
| review | 教学问题、事实问题、排版问题、修改建议 |

局部修改优先：修改脚本段落时只重算相关字幕、镜头和后期编排；修改组件样式时复用内容数据。每次局部修改都记录最新 `content version marker`，以精确锚点提交文本编辑；若修改目标、事实、时长预算或声音拓扑，则回到 Brief 重新确认并重建受影响的后续规划，未受影响的镜头和资产继续复用。

## 前置规划包

### 视频脚本内的声音规划

教育视频先建立 `Brief.md`，再建立 `视频脚本与提示词.md`。后者是声音和时长的唯一真相源，必须先标记声音拓扑：`纯旁白`、`出镜口播`、`角色对话` 或 `无人声演示`。每个生成片段写明逐字旁白/台词、有效字数、全片基准语速、采用语速、朗读/停顿估时、声音起止时间、`voice_required_seconds`、1–2 秒画面缓冲、`target_seconds`、计划生成时长、提交 duration、回算语速、语速负载状态、全片时间码、音色锚点、音色参考选择和声音事件。声音规划未完成前，不进入任何生成调用。

用户未指定精确总时长时，先在 `Brief.md` 写出内容完整的逐字旁白初稿，再按有效字数、受众基准语速、标点/呼吸停顿和必要画面缓冲计算自然总时长。计算后使用真实 confirmation card 询问：`按照当前脚本和自然语速，预计成片约为 X 秒。这个时长可以接受吗？`，选项固定为：`接受 X 秒（推荐）`、`更多的秒数`、`更少的秒数`。后两项分别注明需要增加脚本字数与教学内容、减少脚本字数并精简内容。选择更多或更少时，先修改逐字旁白，再重算并重新确认；不得只拉长或压缩视频 duration，也不得用改变语速代替脚本调整。确认后才建立正式逐片段声音规划。

用户明确给出具体总时长时，将其作为脚本规划的硬约束：先锁定 `target_duration_seconds`，结合受众语速、标点/呼吸停顿和必要画面缓冲反推 `voice_budget_seconds`，再组织旁白和镜头，不先写一份超出预算的长稿后强行压缩到视频里。旁白初稿完成后必须计算 `voice_required_seconds` 与 `target_seconds`，并按模型合法 duration 校准片段边界；超出预算时优先删减重复信息、合并相邻语义或拆分为系列，不能靠提高语速、删停顿或只修改视频 duration 兜底。

在任何图片、音频或视频生成前，先将完整制作规划物化为一个“完整 Brief”文本节点：

```text
brief
→ Brief.md
→ visual direction
→ 视频脚本与提示词.md（含声音规划）
→ 完整 video script / shot plan
→ 路线建议
→ 产物清单
```

规划包必须能让用户在生成前看到整片将如何被理解和呈现：

- VO 是包含全部逐字文案的完整可执行文本；
- visual direction 包含媒介、色彩、材质、构图、景别、镜头节奏、动效和转场；
- video script 逐段对应旁白内容、教学目的、画面事件、屏幕文字、声音和时间；
- 路线建议说明为何选择直接根据逐镜教学记录生成视频，或先生成分镜图再作为 H3 图片参考；
- 产物清单说明将生成哪些图片、音频、视频、字幕、可编辑视频项目和最终文件。

规划阶段先用独立 confirmation card 确认成片怎么讲，再询问视觉风格和生成路线。从剧情叙事、讲师讲解、角色问答、板书推演、图解海报、实验实操、案例观察、沉浸探索和混合讲解中，选择最适合当前主题、受众和时长的 3–5 项。每张卡使用“分类名称：一句直白解释”，并补充对当前主题的效果或取舍；同一组卡片必须在叙事主体、知识载体或镜头结构上存在明显差异。完整 VO 和长脚本保存在同一个完整 Brief 节点。用户选择后回填该节点，再进入下一 Stage。

初始规划阶段的画布文本节点数量固定为一个。完整旁白、视频脚本和规划信息使用 Brief 内的章节组织。正式分镜文本节点在用户完成风格与路线选择后按阶段创建。

### 脚本修改闭环

用户提出脚本修改时：先读取最新画布版本，定位段落/镜号并读取必要上下文，再提交带精确锚点的最小修改；只有整篇重写才替换全文。修改后必须重新读取最新文本，重新计算旁白容量、片段边界、提示词、字幕、VO 和局部后期时间，并重新通过时长硬门，不能只在聊天里展示修改稿。

规划包写入画布后必须设置五个前置决策门：

- **成片讲法**：从教育视频叙事形态库中选出的 3–5 个差异明确的分类，每项附一句直白解释；
- **视觉风格**：3–5 个完整风格方向卡片，每张卡片呈现完整可观察基准；
- **画面路线**：直接根据逐镜教学记录生成视频 / image-generation model 分镜图后作为 H3 图片参考 / 两者结合；
- **性别**：女声 / 男声；
- **讲述风格**：清晰亲和的教师讲解 / 活泼有感染力的少儿讲解 / 稳重专业的纪录片讲解 / 用户提供参考音色；
- **音色参考**：`生成音色参考` / `只用文字在提示词里控制`。前者用 voice-reference generator 生成 3–15 秒可试听样本，音色与语气更稳，后续视频更容易保持一致；后者更省积分、链路更快，但音色一致性更多依赖提示词，波动会更大；

六项 question 结果齐备后进入关键帧和视频生成。选择结果写回规划节点，并成为后续 Stage 的 execution lock；后续阶段直接继承已确认值。声音生产由逐镜旁白同时驱动画面和视频原生声音，独立正式音频在视频确认后按需生成。

## 丰富度与音画对位

教育视频的丰富度由“视觉证据链”建立，转场用于衔接信息变化：

```text
知识点/旁白
→ 学习者需要看到的证据
→ 可见动作或图形变化
→ 镜头目的与构图变化
→ 视频生成 / 后期文字层
```

每段旁白必须绑定至少一个视觉功能：提出问题、展示现象、建立空间、拆分结构、表现因果、对比两种方案、演示正确步骤、揭示结果、提出练习或回收结论。相邻旁白通过不同主体、空间、尺度、构图或动作提供持续推进的视觉证据。

完整规划包还应包含：

- 开头钩子：在前 3–8 秒提出问题、异常现象或可观察挑战；
- 学生观察任务：让观众知道这一镜要看什么；
- 视觉比喻：说明抽象概念映射到什么动作、空间或材质；
- 视觉 progression：主体、空间、尺度、构图、色彩或运动节奏随知识推进发生变化；
- 风格锚点：媒介、质感、色彩、光影、构图、镜头和信息呈现方式；
- 结尾回收：总结、关键辨析点、练习或迁移问题。

### 生成前：按声音容量计算 duration

以下“旁白反推时长”规则只适用于 `纯旁白` 模式。纯旁白片段以旁白语义单元划分，不以统一镜头长度划分；设计画面前先逐段估算旁白承载时间，并为每段选择当前 H3 支持的最短合法 duration。视频 duration 是声音容量计算的结果，不是预先分配的容器；禁止先定 8 秒、11 秒或 15 秒视频，再把不同字数的旁白塞进去。任何估时超过单片段上限的旁白，必须先按自然语义边界拆分，再分别计算：

1. 每个项目先确定一个全片基准语速：默认中文教育语速约 3.0 字/秒（约 180 字/分钟）；低年级 2.5–2.8 字/秒，高年级 2.8–3.2 字/秒，中学及成人 3.0–3.4 字/秒；
2. 数字、英文、公式和专业术语按实际朗读音节折算，不按书写字符机械计数；
3. 基础时长使用“有效朗读字符数 ÷ 基准语速”；
4. 追加标点停顿：逗号 0.2–0.35 秒，句号、问号和感叹号 0.4–0.7 秒，段落切换 0.8–1.2 秒；
5. 用 `voice_required_seconds = 有效朗读字符数 ÷ 采用语速 + 标点/呼吸停顿` 计算声音容量，再加 1–2 秒画面缓冲得到 `target_seconds`；非语音动作或观察时间不得继续把短旁白片段向外撑长；
6. 将 `target_seconds` 向上匹配当前 H3 支持的最短合法 duration。若离散时长会留下超过约 2 秒的无旁白头尾，先合并相邻连续语义或重切片段；确有独立无旁白演示时改用对应声音拓扑。`target_seconds` 超过模型上限时必须按自然语义边界拆分并分别重算，短于模型下限时优先与相邻连续语义合并。

纯旁白片段记录旁白字数、全片基准语速、采用语速、朗读估时、停顿估时、旁白起止时间、`voice_required_seconds`、1–2 秒画面缓冲、`target_seconds`、计划生成时长、提交 duration、回算语速、语速负载状态和拆分依据。出镜口播、角色对话和无人声演示改为记录台词、口型、人物反应或动作完成所需时间。所有模式都要求 `提交 duration = 计划生成时长`，但只有纯旁白模式受无旁白头尾限制。

语速负载状态是生成前硬门：`ok` = 回算语速不超过全片基准语速 + 0.3 且不超过 3.4 字/秒；`warn` = 3.4–3.6 字/秒，只允许短句、复述口诀或紧急指令，并必须保留停顿；`blocked` = 超过 3.6 字/秒、VO 实测时长长于视频、或为了对齐视频删掉停顿。`blocked` 片段必须先改写、拆分或延长到合法 duration；不得派发 H3，也不得先生成短视频再在后期强贴长 VO。

### 生成前预算预检

生成前必须统计旁白总字数、全片基准语速、预计总时长、逐片段 `voice_required_seconds`、逐片段 duration、回算语速分布、H3 片段数、必要分镜图数、是否生成 voice-reference generator 音色参考，以及是否需要独立音效资产，并把预计生成生成次数写入规划节点。禁止批量为所有片段复用同一个 duration。花字、贴纸、重点条和轻提示音默认写进视频提示词，不单独生成。没有明确构图变化时，不按每个内部画面事件重复生成分镜图。预算未闭合、生成次数异常或存在 `blocked` 语速负载时，先调整方案并向用户说明，不得直接批量启动生成。

### 生成后：按真实 timing 校准

教育讲解执行声音融入视频链路：先完成旁白脚本并拆入分镜；每个视频片段保留该段逐字旁白、讲述语气、起止窗口、关键词画面事件和同步动作，并默认开启原生声音生成。使用参考音频时，音色锚点统一写为“@音频N 锁定……女声/男声口播旁白”。若需要 voice-reference generator 音色参考，把音色锚点与逐字试听台词合并写入 `texts`，例如“成年女历史老师，活泼但不夸张，用中文说：‘……’”，不要加入未定义的额外字段。音色参考进入画布后，登记到共享音色记录，记录音色锚点、适用说话人和适用片段集合，再用确认卡让用户确认或重新生成。片段装配器为所有适用片段保留该音色路径；音频引用独立成立，不以同时存在图片或视频引用为前提。人物、分镜和其它视觉参考按各自适用集合另行附加。仅当最新能力摘要明确不支持音频引用时，才把对应片段改为独立旁白替换计划并显式记录原因。视频片段确认后，按需生成正式旁白与音乐；读取音频 timing 后，通过视频编辑器替换或叠加正式 VO。

正式对齐以局部语义为单位，而不是只对齐总时长：

1. 原生旁白或独立 VO 绑定唯一的视频片段或明确的时间区间；
2. 每个关键词绑定分镜中承担该知识点的可见动作、文字或图形变化；
3. 原生旁白与画面已对位时优先保留同步关系；
4. 独立 VO 长于画面时调整该镜节奏、延长有意义的观察状态或重生成该镜视频；
5. 若某段实际 VO 长于已生成视频，或为了放进视频需要把 VO 变速到超过语速上限，必须回到对应片段重算并重生成，不允许用剪辑强行压缩；
6. 使用视频编辑器项目保留视频、VO、字幕、音乐和音效的独立轨道与可编辑关系。

一条跨多镜长 VO 直接覆盖拼接视频、在尾部统一补静音、仅依赖 `-shortest` 截断或只比较总时长，都不构成音画对齐。

## 声音生产流程

默认执行顺序：

```text
完整 Brief 中的逐字旁白章节
→ 分镜逐镜绑定旁白、视觉证据、动作结果和计划时间窗口
→ 将逐字旁白、讲述语气、时间窗口和同步动作写入视频提示词
→ 开启原生声音生成并确认视频片段
→ 按需生成独立正式 VO 与音乐节点
→ 依据实际声音 timing 建立可编辑视频项目
→ 保留或替换原生旁白，叠加正式 VO、字幕、动作音效和音乐
→ 试听检查后渲染
```

视频提示词中的旁白默认采用清晰、亲和、专业的教育口吻，并使用 `working_language`；视频生成阶段开启原生声音。只有在用户需要稳定音色、重新录制或替换原生人声时，才使用独立语音工具；用户只选择可感知的音色或讲述风格。音乐根据主题选择，教学类视频保持旁白优先并在人声区间降低音量；校园宣传可加强情绪推动。

音画对位遵循：

1. 旁白关键词落在对应视觉证据开始出现之后，结论落在动作结果可见时；
2. 新概念出现前保留短预备时间，解释结束后保留阅读或观察时间；
3. 原生旁白与画面已对位时优先保留同步关系；
4. 独立 VO 比画面长时优先延长可观察动作、停顿或片段，保持语义完整；
5. 字幕按 VO 实际 timing 切分，术语、数字、单位和公式逐字一致；
6. 背景音乐在人声区间自动降低音量，动作音效与关键词错峰呈现；
7. 修改某段旁白时更新对应视频片段的提示词和声音层，再更新音频、字幕和局部后期编排，其余已确认素材继续复用。

## 双链路选择

视频模型默认使用 `MiniMax H3`。没有参考素材时直接使用统一风格锚点与完整逐镜教学记录；存在分镜图、用户图片、参考视频或参考音频时，统一使用 H3 全能参考模式。image-generation model 生成的分镜图作为图片参考，为 H3 提供主体、场景、构图、材质、色彩和文字版式依据。

链路仍需用户选择时，必须使用 confirmation card 可点击选项：

- `直接文字生视频（推荐）`：生成更快，尤其适合台词和画面对齐要求高的内容，允许 H3 自主完成构图和动态设计；
- `先生成分镜图再生视频`：先检查文字、公式、版式和构图，再由 H3 生成视频，适合更强调静态可控性的内容。

默认始终推荐直接使用 H3 生视频，并在 confirmation card 中固定为第一项。文字、公式、UI、品牌版式、连续性或静态可控性只用于说明分镜图备选的取舍，不得据此把分镜图改成推荐项；只有用户主动选择分镜图路线时才进入该链路。

### 链路 A：直接文字生视频

```text
教学 brief → 统一风格锚点与逐镜教学记录 → H3 生成 → 检查
```

适用条件：

- 快速出样或创意验证；
- 画面允许 H3 自主完成构图；
- 文字、公式和图形需要准确，静态位置由 H3 在生成时完成设计；
- 角色状态、镜头起落和品牌版式由逐镜教学记录明确。

### 链路 B：分镜图作为全能参考后生视频

```text
教学 brief → 脚本/镜头节拍
→ image-generation model 生成独立分镜图
→ 检查文字、公式、构图和视觉一致性
→ H3 全能参考模式使用图片参考与完整逐镜教学记录
→ 检查
```

适用条件：

- 文字、公式、UI 或版式是画面核心；
- 开场构图、答案落点或转场视觉需要提前明确；
- 同系列需要稳定的角色、场景、排版或视觉身份；
- 用户希望先看静态画面再生成视频；
- 直接生成时某个稳定状态反复漂移。

分镜图模型固定使用 image-generation model。每个下游参考是一张干净的独立图片，完整呈现主体、场景和稳定构图。为每张图片明确主体、场景、风格、材质、构图或文字版式参考作用。运动过程、动作发展、事件顺序、变形、切镜、转场和声音由完整逐镜教学记录描述。

## 选择型交互

以下决策统一使用 confirmation card：

- 教学产物：讲解视频 / 教案 / 课件 / 题组；
- 视频链路：直接文字生视频 / 分镜图作为全能参考；
- 分镜策略：直接进入视频生成 / 生成推荐分镜图；
- 画幅：16:9 / 9:16 / 1:1 / 其它当前合法比例；
- 总时长：旁白初稿完成后展示按当前脚本推导的预计秒数，并提供接受、增加脚本字数做更长版本、减少脚本字数做更短版本；
- 音色或讲述风格：清晰亲和的教师讲解 / 活泼有感染力的少儿讲解 / 稳重专业的纪录片讲解 / 用户提供的参考音色；
- 音色参考：`生成音色参考` / `只用文字在提示词里控制`。前者多一步确认和生成，音色与语气更稳，后续视频更容易保持一致；后者更省积分、链路更快，但音色一致性更多依赖提示词，波动会更大；
- 字幕与配乐：添加 / 保持纯净画面与原声；
- 交付：打开可编辑视频项目 / 最终渲染导出。

用户已经明确的选择直接继承。多个互相独立且选项已知的决策可以合并在一次 confirmation card 中。

## 提示词写法

### 1. 固定统一风格提示词

用户先通过 confirmation card 选择具体成片方案，用它规划整片结构和逐镜内容。随后选择视觉风格，将视觉方向收敛成一段可直接用于分镜生成的提示词，并把原文写入可编辑分镜脚本。统一风格提示词依次包含：

1. **视觉媒介**：明确画面所属媒介类型和影像质感；
2. **构图语言**：镜头景别、画面层次、主体与背景关系；
3. **线条与材质**：明确线条特征、表面材质和纹理表现；
4. **色彩与光影**：明确色彩结构、明暗关系和信息层级；
5. **信息表达方式**：时间线、知识点、地图、公式、建筑细节或人物关系如何可视化；
6. **负向提示词**：与教育主题冲突的风格、画面瑕疵、角色漂移、文字错误和多余元素。

成片讲法落实在逐镜内容中。统一风格锚点原文贯穿分镜、分镜图、关键帧和后续视频生成；同一项目逐字复用。

计划生成时长：
提交 duration：
画面内容：
景别与运镜：
入镜状态：
出镜状态：

对应旁白：

学科准确性注意事项：
关键帧描述：
转场设计（每对相邻镜头逐条填写）：
```text
前镜编号 → 切换时间点 → 前镜出镜动作 → 转场方式 → 转场持续时间 → 承接的知识关系 → 后镜编号及入镜构图/动作
```
参考素材来源：
```

教育主题需要文字、公式、UI、动效、剪辑和声音时，直接补充在该镜的“画面内容”“转场设计”和“对应旁白”中：逐字写出屏幕文字，说明出现、强调、变形和退场；写清主体动作、运镜、环境声和动作音效。

每次画面切换都写清：切换时间点 → 上一画面的出镜动作 → 转场方式 → 下一画面的入镜构图 → 持续时间 → 所承接的知识关系。动作匹配、形状匹配、颜色承接、空间推进、遮挡切换、文字/图形变形、声音桥和直接切换按内容关系选用。片段内部转场进入视频提示词；相邻视频片段之间的转场同时进入两侧镜头记录和视频编辑计划。

镜头衔接硬性要求：每次画面切换都记录前镜出镜动作、转场类型、转场开始时间、转场持续时间、所承接的知识关系、后镜入镜构图与动作。不得用“自然衔接”替代具体转场字段；这些信息必须进入视频提示词和视频编辑计划。

### 3. 按确认后的分镜生成

选择分镜图参考链路时，直接使用统一风格锚点和对应分镜生成独立分镜图；用户在画布确认后进入视频生成。H3 使用全能参考模式，视频提示词直接使用：

```text
统一风格锚点原文
+ segment_content：可见画面、人物动作、局部时间轴、逐字旁白、屏幕文字、声音事件
```

项目生成输入合同编译为两份输出：模型 prompt 读取统一风格锚点和当前片段内容；执行说明读取项目级信息、执行设置与当前片段匹配的共享资产。模型 prompt 以可见主体、场景和动作开头，随后组织局部时间轴、逐字旁白/台词、已确认屏幕文字、环境声与动作音效。人物、音色、分镜图和其它参考素材按用途附加。项目名、片段编号、镜号、全片绝对时间和拆分关系用于画布与视频编辑器，每类信息只有一个消费位置。

执行包按以下顺序装配：统一风格锚点与当前片段内容组成模型 prompt；本片段人物、分镜、场景和用户图片按职责附加；说话人的已确认音色单独注明；片段编号、绝对时间和拆分关系保留在编辑计划中。模型路线、画幅、分辨率、时长和命名只从执行设置读取，不在 prompt 中重复成传输字段。

视频提示词中的旁白文案、局部旁白窗口、关键词画面事件、文字、动作、事件顺序、运镜、转场、剪辑和声音均直接来自对应分镜记录。提交前确认逐字旁白与局部时间窗口齐备，并为每份参考素材明确主体、场景、风格、材质、构图、动作或声音参考作用。每个视频片段生成后进入画布并按镜确认。

### 4. 区分全片时间与片段局部时间

在 Brief、分镜表和编辑项目元数据中维护全片绝对时间，用于确定片段顺序、总时长和后期落点。在每次视频生成提示词中建立独立局部时间轴：起点固定为 0 秒，终点等于本片段独立计算的提交 duration；将声音窗口、关键词画面事件、文字动效和必要转场全部换算为局部时间。仅在纯旁白模式中，旁白结束至片段结束的无声区间超过 1 秒时必须写明阅读、观察或动作完成任务；其它模式按人物表演和可见动作节奏执行。

镜号、全片绝对时间、子片段编号和拆分关系写入生成任务元数据。视频提示词直接描述当前片段可见的入镜状态、动作进展、出镜状态与局部时间窗口。镜头因时长上限拆分后，每个子片段拥有完整可执行的局部描述，并通过出镜状态、入镜状态和编辑项目元数据维持连续性。

## 教育文字、公式与图形

教育组件直接写入视频提示词：

- 定义/术语：标题、关键词高亮、术语卡片、例句卡片；
- 公式/推导：公式分步显示、变形箭头、已知条件卡片、答案揭晓；
- 流程/机制：流程图、因果连线、分层结构、时间轴；
- 比较/数据：对比卡片、表格、柱状图、数轴和关键数据标注；
- 练习/反馈：题目卡片、选择项、答案反馈、关键辨析点；
- 课程切片：章节页、进度条、统一片头片尾、系列编号。

写法顺序：

1. 逐字锁定必须出现的文案、公式、数字、单位和符号；
2. 说明字体气质、字号层级、颜色、位置、卡片或图形外观；
3. 说明出现方式、路径、缩放、描边、高亮、变形和退场；
4. 说明与旁白、动作、音效及切镜的同步点；
5. 提交前逐字核对文字，并逐项核对 UI/图形结构。

需要完全准确、可编辑或批量替换时，同时保留确定性叠加路径。

## 视觉与音频节奏

先确定旁白节奏和信息层级，再决定动画时长。每引入一个新概念，至少留出“出现—解释—回收”的时间；公式、代码和复杂图表分层出现。字幕与旁白保持语义同步，重点词采用短时高亮，整句保持稳定可读。

多版本输出时复用同一内容模型，调整画布比例、字号、字幕安全区和片头片尾，并保持知识结论一致。

## 质量闸门

进入下一阶段前必须满足：

1. brief：目标可观察且受众明确；
2. script：每段对应一个教学目的；
3. shot plan：画面能表达关键关系；
4. editing_project：旁白、字幕和画面时间相互对齐；
5. review：列出事实、教学、音画、排版四类问题及处理状态。
