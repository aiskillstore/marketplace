# 差分法手册（通用兜底通道）

当存档是私有二进制、看不出结构时，用「对比两个状态的存档」来定位 CG 解锁位。
这个方法与具体游戏/引擎无关，适用性最广，但成败取决于**采样质量**。

## 为什么差分有用

游戏把「某张 CG 已解锁」写进存档时，本质上只是把某处若干字节从 A 值改成 B 值。
同一款游戏的相邻两个存档，95% 以上的字节完全相同，剩下的差值就是这次操作改变的状态。
只要操作时只做一件事（解锁一张 CG），差值就高度可信。

## 采样流程（关键，别偷步）

```
1. 进游戏 → 存到槽位 A                 （此时 CG 未解锁）
2. 退出/存档后，把整个存档文件复制出来命名为 A
3. 进游戏 → 只做一件事：解锁 CG #1 → 立刻存到槽位 B
4. 复制存档文件命名为 B
5. 再解锁 CG #2 → 存槽位 C → 复制为 C   （强烈建议，用于拟合步长）
```

铁律：

- **一次只改一件事**。顺手买了瓶药、走了两步路，都会引入额外差值。
- **立刻存档**，不要在游戏里继续做别的事。
- **退出游戏再复制文件**。很多游戏在退出时才把内存状态刷写到磁盘，边开着边复制会拿到旧内容。
- 若游戏 save 时会重排/压缩整个文件导致全文件变化，差分法失效。

## 执行差分

```bash
python scripts/save_diff.py A B --gap 8 --json ab.diff.json
python scripts/save_diff.py B C --gap 8 --json bc.diff.json
```

参数含义：

| 参数 | 作用 |
|---|---|
| `--gap N` | 相距 N 字节以内的变化合并为一个区间。默认 8，适合"字段紧挨着"的情况 |
| `--max-run N` | 长度超过 N 字节的区间视为结构性变化并剔除。默认 64 |
| `--ignore offs` | 排除已知噪声偏移，如 `0x00-0x20`（时间戳/种子） |

## 怎么读结果

```
@0x316 (1B)  46 -> 54        ← 单字节翻转，典型的布尔标志（F -> T）
@0x1204 (4B) 01 00 00 00 -> 20 00 00 00   ← 计数/索引类字段变化
@0x9100 (16B) ...            ← 长度较大的变化，可能是 CG 名字/ID 列表加入新项
```

优先关注**单字节变化** —— CG 解锁标志几乎都是布尔或小枚举。
理想结果：解锁 1 张 CG 后只有 1~3 处单字节变化。

## 从差分到"全解锁"

一次差分只知道"这两个字节跟解锁有关"。要解锁**全部**，需要推断它们属于一个更大的阵列：

```bash
python scripts/infer_plan.py ab.diff.json bc.diff.json \
    --target A --auto-extend --out plan.json
```

推断逻辑：

1. 汇总所有单字节变化偏移
2. 对它们拟合等差数列：**`start` + `k × stride`**（用相邻差的最大公约数）
3. 拟合成功 → 说明找到了 CG 标志数组；拟合失败 → 只修补已观测到的偏移
4. 统计出 off 值（未解锁）与 on 值（已解锁）的众数
5. 按 `--count`（已知 CG 总数，最可靠）或 `--auto-extend`（向前扫描）外扩出全部槽位

### 提高成功率

- 多解锁几张 CG，每次存一份 —— 采样点越多，拟合越可靠
- 若已知游戏总共有多少张 CG，直接 `--count N`，跳过猜测
- `--on-hex` / `--off-hex` 可强制指定目标值（例如确定是 `'T'`/`'F'` 时）
- 卸载不干净（例如存档同时写了计数 + 列表）时，把明显无关的区间用 `--ignore` 排除后再跑一次

## 什么时候差分法会失败

| 现象 | 原因 | 对策 |
|---|---|---|
| 全文件每个字节都变 | 整体压缩 / 流式加密 | 先解决压缩与加密，否则无法差分 |
| 变化区间上百处 | 存档含时间戳、随机种子、加密 nonce | `--ignore` 排除；或让两次采样间隔极短 |
| 两次采样变化位置完全不同 | 字段在文件中位置不固定（可能是哈希顺序） | 换用引擎语义解析 |
| 改完游戏读档报错 | 存档有校验和 / 签名 | 需要另行修正校验和字段，否则放弃 |
