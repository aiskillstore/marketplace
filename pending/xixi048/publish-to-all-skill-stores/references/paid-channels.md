# 付费渠道与定价

**默认立场：能收费的渠道就收费。** 免费渠道留引流版，付费渠道挂完整版或 Pro 版；
同一个技能在不同渠道是不同 SKU，不必同价。

## 一、哪些渠道真能收到钱

## 零、最要紧的一条：能不能收费取决于「形态」，不取决于「渠道」

2026-10 实测国内两家：

- **腾讯 SkillHub / SkillPay**：平台**暂不收取技术服务费**（0 抽成），按次计费、单价自定，
  支付宝 / 微信实时结算到绑定账户。**但它只认 Pay Skill**——安全设计上要求
  「源文件依赖后端服务，脱离后端无法独立使用」，并按「确认支付 → 返回支付触发标识 → 任务内继续执行」
  改造调用链。**纯本地脚本型技能（改本地文件的、跑本地构建的）无法直接变成 Pay Skill。**
  入驻本身很快：实名认证 + 绑定支付宝即可（`/dashboard/merchant` 会显示「已绑定」）。
- **阿里云百炼 Agent Store**：Agent 变现体系（AI 打赏 + Agent Commerce Suite 统一分账 + 支付宝收付），
  本质是「服务商 / ISV 侧的分账」，同样要求交付的是**可调用的服务**，而不是一个 SKILL.md 文件夹。

结论：**"能收费"通常等于"你有后端"。** 一个纯 Agent Skill 想收钱，只有两条路：
① 找到接受「打包文件 + 价格字段」的市场（skillbay.sh 是这种）；
② 把技能升级成带后端调用的服务（腾讯 Pay Skill / 百炼 Agent），这时才轮到 0 抽成或 70% 分账。

| 渠道 | 收费方式 | 分成（开发者拿） | 准入门槛 | 能不能脚本设价 |
|---|---|---|---|---|
| **WorkBuddy 开放平台** | 一次性买断 / 按月订阅 | **99%（内测期平台服务费 1%）** | 开发者认证（个人需人脸）+ 微信签约；**须先有 1 个过审资产才能开收款** | ❌ 定价在后台付费设置里 |
| **skillbay.sh** | 一次性 / 订阅 | **100%（平台 0 抽成）** | 邀请制：先提交 → 人工审 → 发邀请 → Stripe 结算 | ❌ 需 seller 账号 + Stripe onboarding |
| **腾讯 SkillPay** | 按次，单价自定（支付宝/微信） | **100%（平台暂不收技术服务费）** | 实名+绑定支付宝/微信商户号；**技能须改成依赖后端的 Pay Skill** | ❌ 需平台侧改造 |
| **扣子 Coze** | 按次（可低至 ¥0.5/次）/ 月订阅 | 约 **70%** | 需入驻商户 `code.coze.cn/merchant-management` | ❌ 需平台侧操作 |
| **阿里云百炼 Agent Store** | AI 打赏 + Agent Commerce 统一分账 + 支付宝收付 | 按 ISV 分账协议 | 需服务商/ISV 身份，交付可调用服务 | ❌ |
| **GPT Store** | 订阅分成 | 开发者 **85%**（平台抽 15%） | 需 ChatGPT Plus + Builder Profile | ❌ |
| **Windows Agent Store** | 应用内购买 | 开发者 **85%** | 需微软开发者账号 | ❌ |
| **Dify 市场** | 自接支付 | 私有部署 **0%** | 自部署 | ✅（自己写支付） |

**共同点：定价动作全部发生在"账号/商户"层，不在"提交"层。**
匿名提交接口（skillstore / skillsmd / skillbay quick）**都设不了价**——
skillstore 与 skillsmd 干脆只做免费收录。

所以正确做法是：**先用匿名 API 抢免费的曝光位，同时把付费 listing 的字段全部填好，
等账号/邀请到位后一次粘贴。**

## 一·五、WorkBuddy 开放平台（国内抽成最低的一家）

`open.workbuddy.cn`。内测期平台服务费约 1%（另有 0.6% 的口径，以后台实时显示为准），
买断与月订都由创作者自定，微信签约后可直接提现。买家居中是客户端存量用户，
所以「被发现」不靠目录 SEO，靠客户端里的技能市场搜索。

**三条顺序铁律，倒一条就白做：**

1. **先有 1 个「审核通过」的免费技能，才能开收款账户。** 开通收款的前提有三项：
   完成开发者认证、账号无违规记录、**已有 ≥1 个过审的技能或专家**。
   免费资产不支持事后转付费，所以是「先发免费版过审 → 开收款 → 再单独发付费版」。
2. **观察期只能发布 1 个付费资产**，首次产生订单后才能继续发第 2 个。
3. **付费方式（一次性买断 / 按月订阅）审核通过后不可更改。** 界面原话是为了不影响已安装用户。

**规格上限（超了直接传不上去）：**

| 项 | 要求 |
|---|---|
| 格式 | 仅 `.zip` |
| 体积 | **≤ 3 MB**（专家包 ≤ 20 MB） |
| 目录层级 | **最多两层**（根 + 二级文件夹 + 文件） |
| SKILL.md | 必须在**包根** |
| 头像 | 512×512 px，≤500 KB，仅 JPG/PNG |
| 审核时长 | 官方 7 个工作日，实测常见 1–2 天 |

**最容易漏的一条：frontmatter 要 8 个必填字段。**

通用 Skill 规范只要 `name` + `description`，开放平台额外要
`display_name` · `display_name_en` · `description_zh` · `description_en` · `version` · `author`。
缺一个就解析失败。**不要为了这个去改源 SKILL.md**——那会污染其他商店的物料。
正确做法是单独出一个构建步骤，在打包时注入：

```python
# 只改 zip 里的那份，源文件不动
fm.insert(idx_of_license, 'display_name: "..."\nversion: "1.0.2"\nauthor: "xixi048"')
```

打包前自检三件事：`name` 是 hyphen-case、frontmatter 里**没有尖括号**、体积 ≤3 MB。

**发布链路：**

```
注册 → 开发者认证（个人：手机+邮箱+人脸）→ 发布管理 → 技能 → 创建
→ 上传 zip → 选市场分类 + 服务类目 → 提交审核
→ 过审 → 收入变现 → 开通收款账户（填资料 → 审核 → 微信扫码签约）
→ 回到技能 → 编辑 → 付费设置 → 选买断/月订 → 填价 → 勾原创声明 → 发布
```

付费设置藏在**「配置」这一步里，默认是免费**，要手动切。定价建议首版 5–10 元试水，
官方示例是 79 元买断，但市场里跑通的真实订单多在 19–29 元。

## 二、skillbay.sh 的定价字段（照抄即可）

上架 listing 走 `POST /api/v1/sellers/{org}/listings`（multipart，需 session 或 bearer）。
`SkillForm` 关键字段：

| 字段 | 约束 | 建议值（本技能实测） |
|---|---|---|
| `title` | 3–80 字符 | `create-all-cg-save` |
| `summary` | ≤140 字符 | 一句话说清"给谁、解决什么" |
| `description` | 20–20000 字符 | 用 STORE-LISTING 里的长描述 |
| `category` | 枚举 slug | `coding & dev tools` / `games` |
| `price` | **整数美元**，0=免费，上限 10000 | **5**（≈¥35） |
| `examples` | JSON 数组，1–5 条，每条 `{prompt, without, with, notes?, model?}` | **必填项**，没有 example 不能提交审核 |
| `file` | zip，SKILL.md 在**单一顶层文件夹**根部，≤25 MB | `dist/<name>-skillroot.zip` |

定价经验值：

- 低于 **$3** 会被默认当成"自用玩具"，反而不如免费
- **$5** 是"有人真会买"的最低舒适区
- 拆 SKU 比抬价有效：核心免费引流 → Pro 适配器包 **$6.9** → 数据集/ID 库 **$5.9**

## 四、合规红线（写进 listing 的 Scope Guard）

- 不承诺破解、不绕过 DRM、不涉及联机/排行榜/反作弊
- 明确"只处理用户自己合法拥有的副本"
- 含脚本的技能主动披露：零依赖、无网络、无动态执行、写入前强制备份
- 审核索要补充材料时，**加说明而不是删功能**——安全能力就是卖点
