# 可续办交接

把散落的进度记录整理成断点单，让接手者不用翻完整段对话就能继续做。

## 什么时候用

- PDF 已生成，但还没打开成品验收。
- 换班时，一件事已经可以做，另一件在等具体事件。
- 新版只改了一处，旧版检查仍能覆盖未改的部分。
- 中断的请求可能已经生效，下一班不能重复执行。
- 工作已经验收，需要在交接时明确结案。

## 什么时候不用

- 用户要你现在完成修复，而不是写交接。
- 要交的是发布公告，不涉及后续接手。
- 眼下要核对回执，不是转交工作。
- 同一经办人只想知道当前进度。
- 项目还没开始，没有执行状态可交接。

## 核心规则

1. **有多少资料就先交多少。** 明确写出的缺口，比一直扣着不交的断点单更有用。
2. **新消息只覆盖对应的旧事实。** 版本更新不等于其他已定事项都得重问。
3. **给证据标清版本和范围。** 旧检查能支持未改的内容，但不能证明新版已预览。
4. **区分暂停、取消、结果未知。** 三者分别意味着等触发、移出队列、核对已有尝试。
5. **副作用未知时保留原请求身份。** 已有的标识、目标、时间和提交指纹能让接手者查原单，不用重放。
6. **有实际备份就写位置，没有就写“无”。** 触发恢复时，猜出来的地址不顶用；资料没提就写“未提供”。
7. **达到验收就结案。** 可选优化不是交接待办。

## 工作流程

### 1. 开头先写目标和状态

- 写清做到什么才算验收，不只写项目名。
- 状态用已完成、未完成、暂停、取消或结果未知。
- 子项状态不同时，在总状态下分开标记。
- 验收标准没给就写“未提供”，不要自定。

### 2. 写清已完成证据的适用范围

- 找出最新明确更新替代的是哪条旧说法。
- 保留无关事实，不重问已确定事项。
- 逐项写结果、证据位置、版本和覆盖范围。
- 对未改部分沿用适用的历史证据，不写成重新验证过。
- 没做检查与检查不通过分开写。

### 3. 只排必要动作

- 不用等别人就能做的事放前面。
- 有依赖的先写前置，再写后续检查。
- 暂停项附上明确恢复条件。
- 旧清单里的取消项不再排入待办。
- 恢复只写在条件分支，不排成必做项。

### 4. 给出第一动作

- 写成**动词＋对象＋完成信号**。
- 路径和入口只写资料明确提供的。
- 没有能做的事时，说清正在等哪个事件。
- 副作用未知时，保留原请求信息，建议只读查询原请求或有界等待，绝不重发。
- 已验收就写**已完成，无下一动作**。

### 5. 写下恢复信息并交付

- 交代改了什么、实际备份在哪、什么情况下恢复。
- 确知无备份就写“无”；不清楚就写“未提供”。
- 不执行恢复，也不代做剩余动作。
- 如有草稿和提交工具，读取所需资料，写完整断点单，再同轮顺序提交。

## 输出模板

```markdown
# 交接｜[交付物]
目标／验收：[结果与可观察信号]
总体状态：[已完成／未完成／暂停／取消／结果未知]

## 已完成及证据
- [结果]｜[证据位置]｜[版本]｜[覆盖范围]

## 剩余事项（按顺序）
1. [可做的前置动作 → 预期结果]
2. [依赖项或等待项 → 明确条件]

## 续办断点
- 第一动作：[动词＋对象＋完成信号]
- 无可做事项时：[具体等待事件／已完成，无下一动作]
- 结果未知的原请求：[标识／目标／提交时间／提交指纹]
- 只查原请求或有界等待：[入口／上限／结束条件]

## 变更与恢复
- 变更：[对象]｜备份：[实际位置／无／未提供]
- 仅在以下条件恢复：[已提供的触发条件]
- 缺口：[未提供的事实或未执行的检查]
```

可选段落只在不适用时略去；不能因为有关键缺口就整段不写。

## 完整示例

### 示例一｜导出后只改了封面

**输入。** `review/body.md` 记录 `guide-r6.pdf` 的正文检查通过。
r7 只换封面，已有 `exports/guide-r7.pdf`，但没人打开过。
验收要求渲染后的标题不被裁切；封面备份是 `backup/cover-r6.svg`。
已有明确恢复条件：新版预览发现标题裁切。

**反例**

> r7 已完成，检查通过。想稳妥的话发布前再全查一遍。

**正例**

> 目标：r7 正常渲染、标题未裁切。状态：未完成，待预览。
> 已完成：`review/body.md` 覆盖 r6 的正文，r7 正文未变；该记录不覆盖 r7 封面的渲染。
> 第一动作：打开 `exports/guide-r7.pdf`；看到封面且能判断标题是否被裁切即完成该动作。
> 剩余：记录预览结果。只有标题被裁切才恢复封面，并复查受影响的渲染。
> 变更：仅封面。备份：`backup/cover-r6.svg`。恢复条件：r7 预览中标题被裁切。

**为什么能用。** 接手人拿到了文件、视觉验收信号和受影响范围，不用重查无关部分。

### 示例二｜索引可更新，导入仍暂停

**输入。** r3 报表总计已通过检查，见 `checks/totals.txt`。
暂存环境的索引可独立更新。导入 `im-42` 在 14:10 UTC 超时，提交校验和是 `f7a`。
经办人暂停导入，等窗口重开，并取消了重复导出。交接时没有改动。

**反例**

> 导入失败。你接班后再发一次，然后重新导出副本，重查总计。

**正例**

> 目标：更新暂存索引并核对已有导入。状态：未完成。
> 已完成：r3 报表总计通过，见 `checks/totals.txt`。
> 第一动作：更新暂存索引，看到 r3 列在索引中即完成；不依赖导入。
> 导入：暂停至窗口重开，结果未知。原请求：`im-42`，暂存环境，14:10 UTC 超时，校验和 `f7a`；提交时间未提供。
> 窗口重开后：在原状态页查一次 `im-42`；若不可查，保留未知。不重发。
> 重复导出：已取消，不排队。交接期间无变更，无需恢复。

**为什么能用。** 能做的先推进，不把超时写成可以重做副作用的理由。

## 常见错误与警讯

| 看到什么 | 断点单怎么写 |
|---|---|
| “全部通过”却链接到旧版本 | 写明版本以及它支持的未变范围。 |
| “准备好就继续” | 指出解除暂停的事件或产物。 |
| “超时了再试一次” | 保留原身份，写一次查询或有界等待。 |
| “备份应该在归档” | 写实际位置、“无”或“未提供”。 |
| 已取消事项重新出现在待办 | 移出队列，只有确实有用才保留取消说明。 |
| 已验收还排着复核 | 写“已完成，无下一动作”。 |

## 交付前自检

- [ ] 开头有目标和当前状态。
- [ ] 更新只替换对应事实。
- [ ] 已完成证据标明位置、版本及范围，或写清缺口。
- [ ] 可做项在等待项前，前置项在依赖项前。
- [ ] 第一动作有对象和完成信号，或有确切等待事件。
- [ ] 未知尝试保留原请求身份，没有安排重放。
- [ ] 有变更就标备份状态和恢复触发条件，缺什么写什么。
- [ ] 已验收不排下一步，已取消不留在队列。

## 交付即止

接手人知道怎么继续、等什么，或者知道已无待办，断点单就可以交。
提交交接不等于完成业务。不要代做剩余动作，也不要为修饰清单推迟交付。
