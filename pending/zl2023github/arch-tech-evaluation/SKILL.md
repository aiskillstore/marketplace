# 技术选型评估

## 概述

系统化的技术选型评估流程，从功能、性能、成本、社区、学习曲线、生态兼容性等多维度对比技术方案，输出结构化评估报告。

## 触发条件

当用户需要：
- "比较A和B"
- "技术选型"
- "选哪个框架/数据库/中间件"
- "评估XX技术"
- "A和B哪个更好"
- 任何需要技术对比和决策的场景

## 评估维度

| 维度 | 权重 | 评估内容 |
|------|------|----------|
| **功能匹配度** | ★★★★★ | 是否满足核心功能需求 |
| **性能** | ★★★★☆ | 吞吐量、延迟、并发能力 |
| **可扩展性** | ★★★★☆ | 水平/垂直扩展能力 |
| **可靠性** | ★★★★★ | 稳定性、容错、数据一致性 |
| **运维复杂度** | ★★★☆☆ | 部署、监控、运维成本 |
| **社区活跃度** | ★★★☆☆ | GitHub Stars、贡献者、更新频率 |
| **学习曲线** | ★★★☆☆ | 团队上手成本 |
| **生态兼容性** | ★★★★☆ | 与现有技术栈的集成度 |
| **成本** | ★★★★☆ | 许可费、基础设施、人力成本 |
| **安全性** | ★★★★☆ | 安全特性、漏洞历史 |

## 工作流

```
用户提出技术选型需求
  │
  ▼
1. 明确评估目标与约束
  │   - 业务场景、规模、团队能力
  │   - 非功能性需求（性能、可用性、一致性）
  │
  ▼
2. 列出备选方案
  │   - 至少2-3个候选
  │   - 包含开源/商业/自研选项
  │
  ▼
3. 多维度对比
  │   - 按评估维度逐项打分
  │   - 标注权重
  │
  ▼
4. 权衡分析
  │   - 列出每个方案的trade-off
  │   - 明确推荐方案及理由
  │
  ▼
5. 输出评估报告
  │   - 结构化Markdown报告
  │   - 包含对比表、推荐方案、理由
  │
  ▼
6. 可选：生成ADR
    - 将选型结果记录为ADR
    - 保存到 docs/adr/ 目录
```
