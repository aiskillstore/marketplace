# 适老化设计规范 — 详细条款逐条原文

本文档将工信厅信管函〔2021〕67号文附件1（网站规范）和附件2（APP规范）中的技术要求条款逐条列出，附出处路径，方便 Skill 检测时精准引用。

---

## 一、互联网网站适老化通用设计规范（附件1）

### 可感知性

**条款 1.1.1 整体信息**
规范原文：应设置描述当前页面整体服务类型、信息状况和信息结构的语音阅读引导操作机制，并易于老年用户辨识理解和操作。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 1. 可感知性 → 1.1 标识与描述 → 1.1.1 整体信息

**条款 1.1.2 区域信息**
规范原文：网页各信息区域应有服务类型和信息内容的描述与介绍，并提供对应的语音阅读服务，便利老年用户在访问过程中随时获得信息。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 1. 可感知性 → 1.1 标识与描述 → 1.1.2 区域信息

**条款 1.1.3 关联性操作**
规范原文：具有上下文关系或其他关联性关系界面组件的计算机网站、网页，应设有显著的操作引导文字或图片说明，以及相应的语音阅读服务。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 1. 可感知性 → 1.1 标识与描述 → 1.1.3 关联性操作

**条款 1.2.1 页面布局**
规范原文：网页布局设计应依照扁平化原则进行，避免阴影、透视、纹理等复杂装饰设计，也可独立提供内容简约的适老化大版块网页样式。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 1. 可感知性 → 1.2 视觉呈现 → 1.2.1 页面布局

**条款 1.2.2 区域辨识**
规范原文：在展现服务信息的网页，对各信息服务区域以色彩差异进行区别，以方便老人用户辨识。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 1. 可感知性 → 1.2 视觉呈现 → 1.2.2 区域辨识

**条款 1.2.3 字体大小**
规范原文：在不依赖操作系统和浏览器的前提下，计算机适老化网页应提供网页的放大设置与大字屏幕服务，移动网页至少提供一种18dp/pt及以上的大字体。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 1. 可感知性 → 1.2 视觉呈现 → 1.2.3 字体大小

**条款 1.2.4 焦点状态**
规范原文：鼠标，或指点，或键盘操作，或以其他方式聚焦到页面各组件时，该组件应有明显的状态提示。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 1. 可感知性 → 1.2 视觉呈现 → 1.2.4 焦点状态

**条款 1.3.1 语音阅读**
规范原文：适老化页面各组件和文本信息均应提供在线的语音阅读的适老化服务，至少要在正文页面中实现。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 1. 可感知性 → 1.3 听觉感知 → 1.3.1 语音阅读

**条款 1.3.2 阅读控制**
规范原文：语音阅读服务应有开启和关闭阅读的设置，并可被辅助技术操作和控制，避免出现服务冲突。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 1. 可感知性 → 1.3 听觉感知 → 1.3.2 阅读控制

**条款 1.4.1 非文本链接**
规范原文：以非文本形式的链接，应提供语音阅读其链接的目的或链接用途的适老化服务。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 1. 可感知性 → 1.4 非文本处理 → 1.4.1 非文本链接

**条款 1.4.2 非文本控件**
规范原文：以非文本形式的控件或接受用户输入文本框，应提供语音阅读其目的或用途的适老化服务。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 1. 可感知性 → 1.4 非文本处理 → 1.4.2 非文本控件

**条款 1.4.3 验证码**
规范原文：
（1）验证码放大：如网页中存在非文本验证码，应提供相应的验证码放大服务，且验证码的放大倍数不低于2倍。包括字符、图形和各类拖拽形式的验证码。
（2）验证码替代：如网页中存在非文本验证码，至少提供一种视觉感官以外的验证码，如系统推送的语音验证码。
说明：以上两种形式需要同时存在。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 1. 可感知性 → 1.4 非文本处理 → 1.4.3 验证码

**条款 1.4.4 验证码时效**
规范原文：有时效限制且不超过3分钟时长的验证码，应为用户提供语音告知时效的服务，并提供延长时效设置。时效延长设置时长不低于原时效的2倍以上。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 1. 可感知性 → 1.4 非文本处理 → 1.4.4 验证码时效

### 可操作性

**条款 2.1 可操作性要求**
规范原文：在没有安全风险的条件下，适老化用户界面应开放组件访问接口，并可被语音控制或其他智能技术操作。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 2. 可操作性 → 2.1 可操作性要求

**条款 2.2.1 结构数据**
规范原文：适老化界面组件应是层次清晰、信息完整的关系结构。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 2. 可操作性 → 2.2 操作接口 → 2.2.1 结构数据

**条款 2.2.2 接口开放**
规范原文：无财务交易或用户信息完全风险的网页，应开放其内容的关系结构访问接口，支持语音控制等智能软件操作。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 2. 可操作性 → 2.2 操作接口 → 2.2.2 接口开放

**条款 2.3 多媒体控制**
规范原文：视频、音频等多媒体信息的播放控制，可通过键盘或智能手势完成。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 2. 可操作性 → 2.3 多媒体控制

**条款 2.4.1 禁止广告插件**
规范原文：提供适老化服务的网页或独立的适老化网站，网页中严禁出现广告内容及插件，也不能随机出现广告或临时性的广告弹窗。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 2. 可操作性 → 2.4 广告插件及诱导类按键限制 → 2.4.1 禁止广告插件

**条款 2.4.2 禁止诱导类按键**
规范原文：提供适老化服务的网页或独立的适老化网站中无诱导下载、诱导付款等诱导式按键。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 2. 可操作性 → 2.4 广告插件及诱导类按键限制 → 2.4.2 禁止诱导类按键

**条款 2.5.1 漂浮窗体时机**
规范原文：网页中如有漂浮窗体，尽可能在网页加载时与网页同步出现，并提供一个长期关闭的机制。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 2. 可操作性 → 2.5 漂浮窗体控制 → 2.5.1 漂浮窗体时机

**条款 2.5.2 临时漂浮窗体**
规范原文：如网页需要临时出现漂浮窗体，应有一种告知方式，并提供一个长期关闭的机制。
说明：本要求是针对宣传类且无指向链接的漂浮窗要求，对面向当前用户办理业务的告知类窗体不做限制。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 2. 可操作性 → 2.5 漂浮窗体控制 → 2.5.2 临时漂浮窗体

**条款 2.6.1 错误预防**
规范原文：对于会导致使用者发生法律承诺或财务交易的网页，提交动作是可逆的，且提交可在10分钟内予以撤销，或在10分钟内支持修改和再次提交。
说明：该细则不包括对于商家促销且影响其他用户公平等形式的财务交易（如秒杀活动）。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 2. 可操作性 → 2.6 信息输入处理 → 2.6.1 错误预防

**条款 2.6.2 区域辨识（可操作性）**
规范原文：网页中的各信息服务区域，任一表现形式（如纯文字、大版块等），应设有功能、目的和内容的语音告知服务，方便老年用户理解和进行下一步操作。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 2. 可操作性 → 2.6 信息输入处理 → 2.6.2 区域辨识

### 可理解性

**条款 3.1.1 专业词语与新词语**
规范原文：提供适老化服务的网站栏目或服务，避免采用专业词语或网络新词语作为访问目标和结果表达。如确有必要，应在用户操作前给予必要的提示。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 3. 可理解性 → 3.1 信息及操作表达 → 3.1.1 专业词语与新词语

**条款 3.1.2 交互的统一性**
规范原文：经适老化设计的网页界面，其组件的操作流程应与用户的常规操作流程认知保持一致。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 3. 可理解性 → 3.1 信息及操作表达 → 3.1.2 交互的统一性

**条款 3.1.3 识别的一致性**
规范原文：提供适老化服务的网站，避免修改公认的通用名称或功能标识，如确有必要，则应提供必要的说明机制。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 3. 可理解性 → 3.1 信息及操作表达 → 3.1.3 识别的一致性

**条款 3.1.4 位置告知和纠错**
规范原文：应提供告知当前状态、位置和组件关系的机制以指导用户操作，并设有撤销上一步操作的动作。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 3. 可理解性 → 3.1 信息及操作表达 → 3.1.4 位置告知和纠错

### 兼容性

**条款 4.1 兼容性要求**
规范原文：适老化版本应兼容各主流操作系统和各主流浏览器、盲用读屏等各种辅助软件，以及语音识别等智能技术的访问和操作。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 4. 兼容性 → 4.1 兼容性要求

**条款 4.2.1 组件样式**
规范原文：适老化页面的组件样式应支持主流浏览器和主流操作系统，不应因用户使用的浏览器或操作系统不同而发生变化。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 4. 兼容性 → 4.2 界面组件 → 4.2.1 组件样式

**条款 4.2.2 组件服务**
规范原文：适老化网页的组件服务数据内容，可以按照老年人生活实际需求情况进行提供。如在适老化网页上提供"社保查询、天气查询"等组件。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 4. 兼容性 → 4.2 界面组件 → 4.2.2 组件服务

### 特别性要求

**条款 5.1 口述网页结构服务**
规范原文：应对当前网页的信息结构、区域组成和服务功能的整体描述提供语音阅读服务。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 5. 特别性要求 → 5.1 口述网页结构服务

**条款 5.2 实时读屏服务**
规范原文：应提供用户操作一致的语音阅读服务，并提供开启和关闭切换设置，以避免与语音识别等智能软件冲突。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 5. 特别性要求 → 5.2 实时读屏服务

**条款 5.3 完整性服务**
规范原文：提供适老化服务的计算机网站和移动网站，应提供直接进入适老化服务的网站快捷通道或客户端。
出处：《互联网网站适老化通用设计规范》三、技术要求 → 5. 特别性要求 → 5.3 完整性服务

## 二、移动互联网应用（APP）适老化通用设计规范（附件2）

### 可感知性

**条款 1.1 字型大小调整**
规范原文：在移动应用中，建议使用无衬线字体，应可对字型大小进行调整（随系统设置调整，或移动应用内部具备字体大小设置选项），主要功能及主要界面的文字信息（不包含字幕、文本图像以及与移动应用功能效果相关的文本）最大字体不小于 30 dp/pt，适老版界面及单独的适老版 APP 中的主要文字信息不小于 18 dp/pt，同时兼顾移动应用适用场景和显示效果。
出处：《移动互联网应用（APP）适老化通用设计规范》二、技术要求 → 1. 可感知性 → 1.1 字型大小调整

**条款 1.2 行间距**
规范原文：段落内文字的行距至少为 1.3 倍，且段落间距至少比行距大 1.3 倍，同时兼顾移动应用适用场景和显示效果。
出处：《移动互联网应用（APP）适老化通用设计规范》二、技术要求 → 1. 可感知性 → 1.2 行间距

**条款 1.3 对比度**
规范原文：文本/文本图像呈现方式、图标等元素间的对比度至少为 4.5:1（字号大于 18 dp/pt 时文本及文本图像对比度至少为 3:1）。
出处：《移动互联网应用（APP）适老化通用设计规范》二、技术要求 → 1. 可感知性 → 1.3 对比度

**条款 1.4 颜色用途**
规范原文：文本颜色不是作为传达信息、表明动作、提示响应等区分视觉元素的唯一手段。例如，在用户输入密码错误的情景下，可使用文字或语音形式直接提示用户输入有误，避免仅使用颜色作为提示手段。
出处：《移动互联网应用（APP）适老化通用设计规范》二、技术要求 → 1. 可感知性 → 1.4 颜色用途

**条款 1.5 验证码**
规范原文：如果移动应用中存在非文本验证码（如拼图类、选图类验证方式）等老年人不易理解的验证方式，则应提供可被不同类型感官（视觉、听觉等）接受的替代表现形式，例如文字或语音形式，以适应老年人的使用需求。
出处：《移动互联网应用（APP）适老化通用设计规范》二、技术要求 → 1. 可感知性 → 1.5 验证码

### 可操作性

**条款 2.1 组件焦点大小**
规范原文：适老版界面中的主要组件可点击焦点区域尺寸不小于 60 × 60dp/pt，其他页面下的主要组件可点击焦点区域尺寸不小于 44 × 44dp/pt；单独的适老版 APP 中首页主要组件可点击焦点区域尺寸不小于 48 × 48dp/pt，其他页面下的主要组件可点击焦点区域尺寸不小于 44 × 44dp/pt。
出处：《移动互联网应用（APP）适老化通用设计规范》二、技术要求 → 2. 可操作性 → 2.1 组件焦点大小

**条款 2.2 手势操作**
规范原文：在移动应用中，应对用户进行手势导航或者操作的结果提供反馈提示；避免需 3 个或以上手指才能完成的复杂手势操作。
出处：《移动互联网应用（APP）适老化通用设计规范》二、技术要求 → 2. 可操作性 → 2.2 手势操作

**条款 2.3 充足操作时间**
规范原文：在移动应用中，如果限时不是活动的必要部分或关键要素，且不会导致用户发生法律承诺或财务交易，则应为用户的操作留下充足时间，在用户操作完毕前界面不发生变化。
出处：《移动互联网应用（APP）适老化通用设计规范》二、技术要求 → 2. 可操作性 → 2.3 充足操作时间

**条款 2.4 浮窗**
规范原文：在移动应用中，若内容产生新窗口（包含但不限于弹窗），应设置易于用户关闭窗口的按钮。关闭按钮只可在左上、右上、中央底部，且最小点击响应区域不能小于 44 × 44dp/pt。
出处：《移动互联网应用（APP）适老化通用设计规范》二、技术要求 → 2. 可操作性 → 2.4 浮窗

### 可理解性

**条款 3.1 提示机制**
规范原文：在用户安装移动应用时，应为适老化设置、老年人常用功能提供显著的引导提示。内嵌适老版界面的移动应用首页需具备显著入口，支持切换至适老版，或在首次进入时给予显著切换提示，且在"设置"中提供"长辈版"入口。具备搜索功能的移动应用应将"长辈版"作为标准功能名，用户可通过搜索功能直达，同时设置"亲情版"、"关爱版"、"关怀版"等别名作为搜索关键字。
出处：《移动互联网应用（APP）适老化通用设计规范》二、技术要求 → 3. 可理解性 → 3.1 提示机制

### 兼容性

**条款 4.1 辅助技术**
规范原文：移动应用程序不应禁止或限制终端厂商已适配好的辅助设备（如读屏软件等）的接入与使用。在辅助工具开启时，移动应用内容中所有功能性组件均能正常工作：按钮可正常访问；输入框能正常进行输入；多媒体能正常播放；在页面局部更新后，移动应用内容中新增的功能性组件也应能正常工作。
出处：《移动互联网应用（APP）适老化通用设计规范》二、技术要求 → 4. 兼容性 → 4.1 辅助技术

### 安全性

**条款 5.1.1 禁止广告插件**
规范原文：适老版界面、单独的适老版APP中严禁出现广告内容及插件，也不能随机出现广告或临时性的广告弹窗。
出处：《移动互联网应用（APP）适老化通用设计规范》二、技术要求 → 5. 安全性 → 5.1 广告插件及诱导类按键限制 → 5.1.1 禁止广告插件

**条款 5.1.2 禁止诱导类按键**
规范原文：移动应用程序中无诱导下载、诱导付款等诱导式按键。
出处：《移动互联网应用（APP）适老化通用设计规范》二、技术要求 → 5. 安全性 → 5.1 广告插件及诱导类按键限制 → 5.1.2 禁止诱导类按键

**条款 5.2 保障老年用户个人信息安全**
规范原文：移动应用程序进行个人信息处理时应遵循最小必要原则，即处理个人信息应当有明确、合理的目的，并应当限于实现处理目的的最小范围，不得进行与处理目的无关的个人信息处理，以保障老年用户个人信息安全。具体收集信息（如位置信息、图片信息等）行为，应符合《常见类型移动互联网应用程序必要个人信息范围规定》《APP收集使用个人信息最小必要评估规范》要求。
出处：《移动互联网应用（APP）适老化通用设计规范》二、技术要求 → 5. 安全性 → 5.2 保障老年用户个人信息安全
