## 第一部分 · 知识库

### 1.1 一句话定位

数据安全专家是**技术防线角色**。合规专家回答"该不该做"，安全专家回答"**怎么防住风险**"。

他的工作覆盖三个层面：
1. **数据本体安全**：分级管控、加密脱敏、权限控制
2. **系统安全**：等保、漏洞管理、日志审计
3. **运营安全**：监控预警、应急处置、持续审计

在数据资产化链条上，他的产出是：**安全保障措施说明**（产权登记必备材料，见专家 10）、**安全评估报告**（数据出境必备，见专家 37）、**风险清单**（融资尽调材料，见专家 28）。

### 1.3 核心模型一：数据分类分级（GB/T 43697-2024）

**三级分类：**

| 级别 | 定义 | 识别要点 | 管控要求 |
|---|---|---|---|
| **核心数据** | 关系国家安全、国民经济命脉、重要民生、重大公共利益 | 国家核心利益相关 | 最严格：专库、专人、审批 |
| **重要数据** | 特定领域、特定群体、特定区域，或达到一定精度和规模的数据，一旦泄露可能危害国家安全、经济运行、社会稳定、公共健康和安全 | 需按行业目录识别 | 严格：备案、评估、出境限制 |
| **一般数据** | 不属核心和重要的数据 | — | 按内部级别分 1~4 级 |

**一般数据的内部分级建议：**

| 级别 | 内容 | 措施 |
|---|---|---|
| 4 级 | 高敏感（如大额交易明细） | 加密存储 + 严格授权 |
| 3 级 | 敏感（如客户信息） | 加密 + 权限控制 |
| 2 级 | 内部（如内部报表） | 权限控制 |
| 1 级 | 公开（如公开产品信息） | 基本管理 |

**关键判断**：**重要数据的识别是数据安全工作中最重要也最容易遗漏的一环**。多数企业不知道自己的数据是否属重要数据，也未编制目录。

### 1.4 核心模型二：等保 2.0 五个级别

| 级别 | 适用对象 | 备案与测评 |
|---|---|---|
| 一级 | 一般系统 | 自主保护，不需备案测评 |
| 二级 | 一般企业系统 | 备案 + 测评（常见） |
| 三级 | 重要行业系统（金融、医疗、政务） | 备案 + 每年测评（**最常见要求**） |
| 四级 | 特别重要系统 | 备案 + 半年测评 |
| 五级 | 极端重要 | 最高管控 |

**实务要点**：
- 多数数据类系统需按**三级**备案测评
- 三级要求每年至少一次测评
- 测评由有资质的测评机构完成
- 测评通过后取得备案证明与测评报告（融资、登记、政府项目常需提供）

### 1.5 核心模型三：数据全生命周期安全

数据安全不是一次性工作，要覆盖全生命周期六个阶段：

| 阶段 | 安全措施 |
|---|---|
| **采集** | 来源合法性校验、最小必要、采集授权、传输加密 |
| **存储** | 分类分级存储、加密（静态加密）、备份、容灾、访问控制 |
| **使用** | 最小权限、动态授权、脱敏、水印、操作审计 |
| **共享** | 脱敏、加密传输、共享协议、审批流程、水印追踪 |
| **传输** | 传输加密（TLS/国密）、完整性校验 |
| **销毁** | 安全删除、介质销毁、销毁记录 |

**关键控制点**：
- **访问控制**：最小权限原则 + 职责分离 + 定期复核
- **脱敏**：静态脱敏（存储时）+ 动态脱敏（使用时）
- **审计**：全量日志 + 不可篡改 + 定期审计
- **加密**：传输加密 + 存储加密 + 密钥管理

### 1.6 核心模型四：数据安全能力成熟度（DSMM）

GB/T 37988-2019 定义了数据安全能力成熟度模型：

| 维度 | 内容 |
|---|---|
| **能力维度** | 数据采集安全、数据传输安全、数据存储安全、数据处理安全、数据交换安全、数据销毁安全 |
| **成熟度等级** | 1 非正式执行 → 2 计划跟踪 → 3 充分定义 → 4 量化控制 → 5 持续优化 |

**用途**：评估企业数据安全能力水平，作为改进路线图。与 DCMM 类似但聚焦安全。

### 1.7 常见问题与标准答复

**Q1：我们怎么知道有没有重要数据？**
A：查行业重要数据目录（各行业主管部门会发布），逐项比对。若无目录，按 GB/T 43697 的识别要点自查：影响范围（国家安全/经济运行/社会稳定/公共健康）+ 数据规模与精度。

**Q2：等保要做几级？**
A：多数企业系统做二级；涉及金融、医疗、政务、关键信息基础设施的做三级。判断标准是系统被破坏后的影响范围。

**Q3：等保要花多少钱？**
A：二级测评分几万到十几万；三级通常十几万到几十万（视系统复杂度）。整改成本另计。

**Q4：加密用什么算法？**
A：涉及国家安全的用国密算法（SM2/SM3/SM4）；一般商用场景可用国际标准算法（AES/RSA）。需符合《商用密码管理条例》。

**Q5：数据安全做完了怎么证明？**
A：三个材料——① 等保备案证明与测评报告；② 数据安全管理制度与执行记录；③ 安全评估报告（如涉重要数据/出境）。

### 2.2 标准作业流程 SOP

**S0 安全现状评估（2~3周）**
1. 梳理系统与数据资产
2. 了解现有安全措施
3. 访谈技术与管理人员
4. 输出《安全现状评估报告》

**S1 数据分类分级（2~4周）**
1. 按 GB/T 43697 识别三级：
   - 对照行业重要数据目录
   - 核心数据识别
   - 一般数据内部定级（1~4 级）
2. 输出《数据分类分级表》

**S2 重要数据识别与目录（2~3周，关键）**
1. 逐项比对行业目录
2. 无目录时按识别要点自查
3. 编制《重要数据目录》
4. 如需，向主管部门报送

**S3 安全风险评估（3~4周）**
1. 按风险 = 威胁 × 脆弱性 × 影响 评估
2. 逐项评估：
   - 数据泄露风险
   - 越权访问风险
   - 数据篡改风险
   - 数据丢失风险
   - 供应链风险
3. 输出《数据安全风险评估报告》

**S4 等保建设与测评（4~12周）**
1. 定级（判断几级）
2. 备案（公安网监）
3. 整改（按等保要求补措施）
4. 测评（委托测评机构）
5. 取得备案证明与测评报告
6. 输出等保材料

**S5 安全制度与技术措施（4~8周）**
1. 撰写安全管理制度
2. 设计技术措施：
   - 访问控制（RBAC + 最小权限）
   - 加密（传输 + 存储 + 密钥管理）
   - 脱敏（静态 + 动态）
   - 审计（日志 + 不可篡改 + 定期审计）
   - DLP（数据泄露防护）
3. 部署实施
4. 输出制度与技术方案

**S6 安全保障措施说明（1~2周）**
1. 编制用于产权登记/融资的《安全保障措施说明》
2. 涵盖：制度、组织、技术、审计、应急
3. 附证据（等保证明、测评报告、制度文件）
4. 输出安全保障说明

**S7 安全审计（每半年/年）**
1. 审计内容：权限合规性、日志完整性、措施有效性
2. 发现问题并整改
3. 输出《安全审计报告》

**S8 应急响应（事件发生时）**
1. 立即止损（断网/隔离）
2. 评估影响范围
3. 按预案处置
4. 取证与溯源
5. 依法报告
6. 输出处置报告

**S9 持续改进（持续）**
1. 跟踪新威胁与新标准
2. 定期评估与改进
3. 更新措施

### 2.6 关键话术

- "数据安全不是买几个软件，是覆盖采集到销毁的全生命周期。"
- "重要数据的识别是最容易漏也最危险的一环——漏了可能被认定违法。"
- "等保三级证明不只是合规材料，融资和登记的时候都得用。"

**风险提示**：
1. **重要数据未识别是最高风险**——可能面临行政处罚
2. 等保测评需每年一次（三级），过期失效会影响融资与登记
3. 加密密钥管理不当会让加密形同虚设
4. 日志不完整会导致事件无法溯源
5. 安全事故未依法报告会加重处罚
6. 涉及国密的必须用国密算法，不得用国际算法替代
