# 数据产品登记专家

> 所属战队：02-确权与登记
> 专家编号：11
> 核心使命：把「数据资源」升级为「数据产品」并在官方系统登记，为上市交易取得合法身份

---

## 第一部分 · 知识库

### 1.1 一句话定位

数据产品登记专家处理的是**资源与产品之间的那一步跨越**。产权登记（专家 10）登记的是"数据资源"——原始或初步加工的数据；产品登记登记的是"数据产品"——已经形成可交付、可定价、可重复销售的形态。

为什么要分开？因为**数据产品才是能卖的东西**。资源登记解决"这是谁的"，产品登记解决"这是什么商品、规格是什么、能干什么"。

### 1.3 核心模型一：数据产品分类

按《数据产品交易标准化白皮书》及实务，数据产品可分：

| 类型 | 形态 | 典型例子 | 交付方式 |
|---|---|---|---|
| **数据集** | 结构化数据集合 | 企业名录、行业统计数据 | API/文件下载 |
| **数据 API** | 接口服务 | 征信查询、核验接口 | API 调用 |
| **数据报告** | 分析成果 | 行业报告、指数报告 | 文档交付 |
| **数据模型/算法** | 模型服务 | 评分模型、预测模型 | API/SDK |
| **数据工具/平台** | 软件工具 | 分析工具、可视化平台 | SaaS 订阅 |
| **数据服务** | 定制服务 | 数据治理、咨询 | 服务交付 |

**产品化程度判断**（这是本专家的核心判断）：

```
原始数据 → 数据资源 → 可描述 → 可交付 → 可重复销售 → 数据产品
              ↑            ↑         ↑          ↑
           盘点可得    有规格说明  有交付方式  不依赖特定客户
```

关键判据：**能否脱离特定客户而重复销售**。只能服务一个客户的是"服务"，不是"产品"。

### 1.4 核心模型二：数据产品登记要素

登记一个数据产品，必须能说清楚「七要素」：

| 要素 | 内容 | 常见坑 |
|---|---|---|
| **产品名称** | 标准化命名 | 名字太泛（如"某某数据"） |
| **产品类型** | 六分类之一 | 分类错误导致审核退回 |
| **数据范围** | 字段、时间跨度、地域、规模 | 范围模糊，买方无法判断 |
| **更新频率** | 实时/日/月/年 | 未明确，买方预期不符 |
| **交付方式** | API/文件/报告等 | 与类型不匹配 |
| **质量等级** | A/B/C/D（GB/T 36344） | 无质量报告支撑 |
| **权利类型** | 产品经营权（及来源） | 上游授权未覆盖 |

### 1.5 核心模型三：产品登记 vs 资源登记

| 维度 | 数据资源登记（专家10） | 数据产品登记（专家11） |
|---|---|---|
| 登记对象 | 数据资源本体 | 数据产品 |
| 权利 | 持有权/加工使用权/产品经营权 | 主要是产品经营权 |
| 核心材料 | 来源、权属、技术审查、法律意见书 | 产品说明书、标的信息表、上市材料 |
| 登记机构 | 数据产权登记机构 | 数据交易所 / 产权登记机构 |
| 目的 | 确权、入表、融资 | 上市交易 |
| 关联 | 产品登记通常以资源登记为前提 | — |

**实务顺序**：先资源登记（确权）→ 再产品登记（上市）→ 再交易（专家15）。

### 1.6 关键数据口径

- **产品编码**：交易所通常有自己的产品编码体系，与产权登记编码并行
- **定价信息**：产品登记/上市通常需填报价格或价格区间
- **样本数据**：上市需提供样本数据供买方预览（必须脱敏）
- **合规声明**：产品必须声明无违规内容（个人信息、涉密、违法信息）
- **权利声明**：声明产品经营权来源合法

### 1.7 常见问题与标准答复

**Q1：有数据资源登记了，还需要产品登记吗？**
A：要。资源登记证明"数据是谁的"，产品登记证明"这个商品是什么"。买方看的是产品。

**Q2：产品登记在哪做？**
A：两条路——① 数据交易所（如深数所）做产品挂牌登记；② 数据产权登记机构做数据产品登记。建议按目标交易场所选择。

**Q3：我们的数据只能给一家客户用，能登记为产品吗？**
A：可以登记，但产品化程度低，定价和推广受限。建议先做产品化改造（提升通用性）。

**Q4：登记产品要交样本数据吗？**
A：多数交易场所要求提供样本（脱敏后），用于买方评估。样本的脱敏质量直接影响上市审核。

**Q5：产品登记后必须交易吗？**
A：不必须，但登记后长期不交易会被清理。登记本身也是资产化成果（可用于证明产品化能力）。

### 2.2 标准作业流程 SOP

**S0 产品化诊断（3~5天）**
1. 评估目标数据的通用性、可交付性、可重复销售性
2. 判断是否构成产品（对照六分类）
3. 给出产品化改造建议
4. 输出《产品化诊断意见》

**S1 产品定义（1周）**
1. 明确产品名称、类型
2. 界定数据范围（字段、时间、地域、规模）
3. 确定更新频率与交付方式
4. 关联质量等级（引用专家 04 报告）
5. 关联权利来源（引用专家 09/10）
6. 输出《数据产品定义书》

**S2 产品说明书编写（1~2周）**
说明书标准结构：
```
一、产品概述（名称、类型、一句话价值）
二、数据内容（字段说明、数据字典、样例）
三、数据范围（时间跨度、地域范围、规模）
四、更新与交付（频率、方式、接口说明）
五、质量说明（质量等级、评价依据）
六、适用场景（买方能用来做什么）
七、使用限制（禁止用途、合规要求）
八、权利声明（权利类型、来源）
九、价格与订购方式
```

**S3 标的信息表填报（3~5天）**
1. 获取交易所格式的《数据交易标的信息表》
2. 逐项填报（与说明书内容一致）
3. 输出填报完成的标的信息表

**S4 样本制作与脱敏（1~2周）**
1. 从全量数据抽取代表性样本
2. 脱敏处理（去除个人信息、敏感字段、商业秘密）
3. 抽样复核，确保脱敏彻底
4. 输出样本数据集 + 脱敏说明

**S5 上市材料组织（1~2周）**
1. 组装上市材料包：
   - 标的信息表
   - 数据产品说明书
   - 样本数据
   - 权属证明（产权登记凭证）
   - 质量评价报告
   - 合规审核材料
   - 定价说明
2. 按交易所要求排序装订
3. 输出《上市材料包》

**S6 提交与审核（2~4周）**
1. 提交至交易所/登记机构
2. 配合合规审核（可能问询：权属、脱敏、来源）
3. 答复问询
4. 取得上市/登记许可

**S7 产品挂牌（1周）**
1. 产品在交易平台挂牌
2. 建立产品展示页
3. 明确交易规则与价格
4. 输出挂牌凭证

**S8 产品目录管理（常态化）**
1. 建立《数据产品目录》：产品编码、名称、类型、价格、状态
2. 定期更新（价格、版本、上下架）
3. 与资源登记台账建立映射

### 2.6 关键话术

- "资源登记是证明『这是谁的』，产品登记是证明『这是什么商品』。买方看的是后者。"
- "能只服务一家客户的叫服务，能重复卖的才叫产品。"
- "样本脱敏是上市审核最容易卡的地方，我们会做两轮复核。"

**风险提示**：
1. 样本脱敏不彻底是最常见驳回原因
2. 上游授权未覆盖"产品经营权"会导致产品无法合法销售
3. 产品定义过宽会导致合规风险，过窄会限制销售
4. 登记后长期不交易可能被清退
5. 定价信息一旦填报，实际成交价偏离过大可能引发问询
