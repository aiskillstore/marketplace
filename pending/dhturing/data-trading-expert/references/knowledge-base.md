# 数据交易专家

> 所属战队：03-流通与交易
> 专家编号：15
> 核心使命：让数据产品在合规的交易场所里真正成交，把「资产」变成「现金」

---

## 第一部分 · 知识库

### 1.1 一句话定位

数据交易专家是**把东西卖出去的人**。前面所有专家的产出（确权、质量、登记、产品化），最终都要在他手里变成一笔笔成交。

他的核心能力不是"懂数据"，而是**懂交易**——懂交易场所的规则、懂买方的决策链、懂怎么设计交易结构让双方都敢签。

### 1.3 核心模型一：交易场所与交易模式

| 类型 | 代表 | 特点 | 适用 |
|---|---|---|---|
| **数据交易所** | 深圳数据交易所、上海数据交易所、北京国际大数据交易所 | 场内规范化、有规则、有背书 | 需要公信力的交易 |
| **数据流通服务平台** | 各地数据交易中心/平台 | 灵活、区域性 | 中型交易 |
| **场外直接交易** | 企业间直接签约 | 灵活、成本低、无背书 | 双方信任度高的交易 |

**场内 vs 场外决策：**

| 维度 | 场内 | 场外 |
|---|---|---|
| 合规背书 | 强 | 弱 |
| 交易成本 | 有服务费 | 低 |
| 流程周期 | 较长 | 短 |
| 买方信任 | 高（尤其国企/政府） | 取决于双方关系 |
| 融资认可度 | 高（有交易凭证） | 低 |

**实务建议**：首次交易、政府/国企客户、需要交易凭证用于融资的，走场内；长期合作客户的小额交易可走场外。

### 1.4 核心模型二：六种交易模式

| 模式 | 内容 | 计价方式 | 适用 |
|---|---|---|---|
| **数据集销售** | 一次性交付数据集 | 一次性买断 | 数据包 |
| **API 调用** | 按调用次数/时长计费 | 按量计费 | 查询/核验类 |
| **订阅制** | 按期订阅访问权 | 年费/月费 | 持续更新的数据 |
| **许可使用** | 授予特定范围使用权 | 许可费（可能+分成） | 有限授权 |
| **收益分成** | 按买方使用收益分成 | 分成比例 | 高价值数据、深度合作 |
| **联合建模/共建** | 双方共同开发 | 按投入分配 | 深度合作 |

**计价方式的选择逻辑：**
- 买方不确定价值 → 按量计费（降低买方风险）
- 数据持续更新 → 订阅制
- 数据能带来可计量收益 → 分成制
- 数据为标准化商品 → 一次性买断

### 1.5 核心模型三：交易全流程七步

```
① 需求识别 → ② 标的匹配 → ③ 尽调合规 → ④ 定价谈判
                                              ↓
⑦ 结算交付 ← ⑥ 合同签署 ← ⑤ 交易结构设计 ←──┘
```

**各步要点：**

**① 需求识别**
- 买方是谁？买方的业务问题是什么？
- 数据能解决什么问题？（不是"我有什么数据"，而是"你能用它干什么"）

**② 标的匹配**
- 从我方产品目录匹配
- 或按需定制（转专家17）

**③ 尽调合规**
- 买方尽调：主体资格、付款能力
- 卖方材料：产权登记、质量报告、合规审核
- 交易所合规审核

**④ 定价谈判**
- 定价方法（转专家18）
- 谈判空间设计

**⑤ 交易结构设计**
- 交付方式、计价方式、权利范围
- 数据使用限制（禁止再识别、禁止转售）
- 安全与保密条款

**⑥ 合同签署**
- 标准合同 + 交易场所备案（如场内）
- 法律审查（转专家14）

**⑦ 结算交付**
- 支付（预付/分期/后付）
- 数据交付（API/文件/沙箱）
- 验收与售后台账

### 1.6 核心模型四：数据交付的三种安全方式

| 方式 | 原理 | 适用 | 安全性 |
|---|---|---|---|
| **原始数据交付** | 直接给数据集 | 双方高度信任、数据敏感性低 | 低 |
| **API 交付** | 通过接口按需返回 | 查询类、可控制返回范围 | 中 |
| **沙箱交付（数据不出域）** | 买方在受控环境内使用，不能带走数据 | 敏感数据、高价值数据 | 高 |

**趋势**：高价值/敏感数据越来越倾向「**数据不出域，可用不可见**」——这也是可信数据空间（专家 20）的核心价值。

### 1.7 常见问题与标准答复

**Q1：数据交易最大的障碍是什么？**
A：三怕——买方怕数据不真、卖方怕数据被复制扩散、双方怕合规出问题。所以交易结构设计的核心是**解决这三怕**：质量报告解决第一怕，使用限制条款+沙箱解决第二怕，产权登记+合规审核解决第三怕。

**Q2：数据卖了会不会被无限复制转卖？**
A：这是数据交易的特有难题。应对：① 合同明确禁止转售并约定高额违约金；② 技术上加水印/追踪；③ 走沙箱交付；④ 只给使用权不给持有权。

**Q3：我们的数据没人买怎么办？**
A：先别急着降价。常见原因是"卖点错了"——买方不关心你有什么数据，只关心能解决什么问题。要重新包装为"场景解决方案"（转专家17、24）。

**Q4：场内交易要交多少服务费？**
A：各所不同，通常按成交额比例（如 1%~5%）。需具体咨询目标交易所。

**Q5：交易能开发票吗？怎么计税？**
A：可以开票。数据交易涉税处理见专家 32。常见按"信息技术服务"或"无形资产转让"处理。

### 2.2 标准作业流程 SOP

**S0 交易准备（1~2周）**
1. 盘点可交易产品（引用专家 11 产品目录）
2. 确认权属与登记状态
3. 选择交易场所
4. 取得交易场所准入（如会员资格、数商资质）
5. 输出《交易准备清单》

**S1 买方开发（持续）**
1. 建立买方画像（行业、规模、数据需求）
2. 通过交易所撮合、行业活动、现有人脉获客
3. 需求访谈：买方要解决什么问题？
4. 判断我方数据能否解决
5. 输出《买方档案》与《需求分析》

**S2 标的匹配与包装（1~2周）**
1. 从产品目录匹配，或发起定制（转专家17）
2. 制作面向买方的价值说明（不是技术文档，是**业务价值说明**）
3. 明确买方能得到什么、怎么用、能解决什么问题
4. 输出《标的说明书（买方版）》

**S3 双方尽调（2~4周）**
1. **买方尽调我方**：提供产权登记、质量报告、合规材料
2. **我方尽调买方**：主体资格、付款能力、使用用途合规性
3. 用途审查（防止买方用于非法用途）
4. 输出《尽调材料包》

**S4 合规审核（交易所，2~4周）**
1. 按交易所合规审核指引提交材料
2. 材料：标的说明、权属证明、质量报告、合规声明、样本
3. 配合审核问询
4. 取得上市/交易许可

**S5 定价与谈判（1~2周）**
1. 按专家 18 的方法确定定价区间
2. 设计谈判策略（锚点、让步空间、非价格条款）
3. 多轮谈判
4. 输出《报价方案》与《谈判纪要》

**S6 交易结构设计（1周）**
1. 确定交付方式（原始/API/沙箱）
2. 确定计价方式（一次性/按量/订阅/分成）
3. 确定权利范围（使用范围、期限、是否独家）
4. 设计使用限制（禁止再识别、禁止转售、禁止第三方共享）
5. 设计安全与审计条款
6. 输出《交易结构方案》

**S7 合同签署（1~2周）**
1. 起草/获取标准合同
2. 法律审查（转专家 14）
3. 谈判修改
4. 双方签署
5. 场内交易需交易所备案/见证
6. 输出《交易合同》

**S8 结算与交付（1~4周）**
1. 按约定支付（预付/分期/后付）
2. 数据交付：
   - 文件：加密传输、传输记录
   - API：开通权限、密钥交付
   - 沙箱：环境开通、权限配置
3. 买方验收
4. 留存交付凭证（对融资、审计、纠纷都有用）
5. 输出《交付确认单》

**S9 售后与复用（持续）**
1. 买方使用反馈收集
2. 问题响应
3. 挖掘复购与扩展需求
4. 沉淀为成功案例（用于获客）
5. 更新《客户档案》

### 2.6 关键话术

**对卖方**：
- "买方不关心你有什么数据，只关心能解决什么问题。我们要把『数据』翻译成『方案』。"
- "场外交易灵活但没背书，要融资就得走场内，有成交凭证。"
- "数据卖出去了怎么防扩散？合同 + 技术水印 + 沙箱，三层防护。"

**对买方**：
- "我们不只给您数据，给您的是可验收的质量报告和合规凭证。"
- "您可以先在沙箱里验证，确认有用再买。"

**风险提示**：
1. 数据易复制，交付后管控是长期难题
2. 买方用途不可控，需在合同中严格限定并留审查权
3. 场内交易有服务费与周期成本
4. 无成交凭证的场外交易在融资场景认可度低
5. 定价过高会失去客户，过低会损害资产价值认知
