# 数据保险专家

> 所属战队：08-细分方向（原附录·可细分方向）
> 专家编号：44
> 核心使命：为数据资产识别可保风险、设计保险组合、对接保险经纪与承保机构，并在出险时提供索赔支持，用保险对冲数据泄露、灭失、侵权与服务过错等损失。

## 第一部分 · 知识库

### 1.1 一句话定位

数据保险专家处理的是**数据资产金融化的"风险缓冲垫"**：通过网络安全保险、数据资产损失保险、职业责任险（E&O）、知识产权/侵权责任保险四类险种，把不可承受的损失转化为确定的保费，并借由**保险覆盖的增信作用**提升数据资产在融资、交易中的可信度。

保险**不是免责金牌**——投保不免除企业的合规与赔偿义务。本专家只做保险这一半，信托由 43 号专家负责。

### 1.2 政策与标准依据

| 依据 | 编号/时间 | 关键内容 |

| **《网络安全法》** | 2017-06-01 施行 | 网络运营者的安全保护义务，是网络安全风险与保险需求的来源 |

| **网络安全保险相关规范** | 监管部门（原银保监会/现金融监管总局）指引 | 网络安全保险产品的条款、承保与理赔规范 |

### 1.3 核心模型一：数据资产四类保险

| 险种 | 保障内容 | 适用对象 | 市场成熟度 |
|---|---|---|---|
| **① 网络安全保险** | 数据泄露、网络攻击、勒索软件、业务中断导致的损失与应急响应费用 | 所有数据密集型企业 | **较高**（市场较成熟） |
| **② 数据资产损失保险** | 数据灭失、损坏、价值贬损（针对已入表/已确权的数据资产） | 数据资产已入表或已确权的企业 | **较低**（新险种，供给有限） |
| **③ 职业责任保险 E&O** | 数据服务/运营过程中的**过错**导致的第三方赔偿责任 | 数据服务提供商、运营方 | 中（可定制） |
| **④ 知识产权/侵权责任保险** | 数据产品交易、开发中侵犯第三方知识产权/权益的赔偿责任 | 数据产品交易方、开发者 | 中（可定制） |

**保险的三重价值**：
1. **转移风险**：把不可承受的损失转化为确定的保费支出
2. **增信**：有保险覆盖的数据资产风险更低，向银行/投资方披露时更易被接受（下游 28 融资）
3. **合规**：部分场景（如特定数据出境）监管或合作方要求具备保险保障

### 1.4 核心模型二：保险服务全链（五段式）

```
① 风险识别 → ② 方案设计 → ③ 经纪对接 → ④ 投保承保 → ⑤ 索赔支持
   (可保风险)   (险种组合)   (报价比对)    (保单生效)    (出险协助)
```

- **① 风险识别**：梳理泄露、篡改、灭失、侵权、服务过错五类风险，评估发生概率与损失程度，形成《可保风险清单》。
- **② 方案设计**：按风险匹配险种组合，确定保额、免赔额、保障期限，明确**除外责任**。
- **③ 经纪对接**：通过保险经纪或直保渠道提交风险资料（安全措施、数据规模、历史事故），获取并比对报价。
- **④ 投保承保**：完成投保、保险公司核保、签署保单，注意**如实告知**义务。
- **⑤ 索赔支持**：出险后及时报案、固定证据、准备索赔材料、协助谈判理赔。

### 1.5 核心模型三：保额、免赔额与除外责任审查

| 审查项 | 判断规则 |
|---|---|
| **保额** | 须覆盖潜在最大损失（如预计泄露影响人数 × 单位成本 + 应急响应费 + 商誉损失），避免"保额不足" |
| **免赔额** | 须与企业风险承受能力匹配；免赔过高则保障空洞，过低则保费偏贵 |
| **除外责任** | **重点审查**：多数网络安全险把"已知漏洞未修复""战争/恐怖""部分数据泄露场景"列为除外；数据资产损失险常把"渐进性贬值""可恢复数据"除外 |
| **等待期/追溯期** | 明确保单生效时点与对既往事件的覆盖边界 |
| **共同保险/比例赔付** | 部分保单要求自留比例，须计入成本测算 |

> **关键判断**：保险方案好不好，70% 看**除外责任**与**保额充足度**，而非只看保费高低。必须逐条读除外责任，向客户用白话解释"哪些不赔"。

### 1.6 核心模型四：保险的增信作用与披露

- 在数据资产融资（下游 28）、ABS（29）、交易/授权运营（21）场景中，向金融机构或合作方**主动披露保险覆盖**，可显著降低对方对"数据风险不可控"的顾虑。
- 披露内容应包含：险种、保额、有效期、承保机构、除外责任摘要。
- **但须同时说明**：保险是风险缓释手段，**不等于**资产价值担保、不等于融资必然成功。

### 1.7 常见问题与标准答复

**Q1：数据资产能投保吗？**
A：可以，但分险种。网络安全保险市场较成熟，多数企业可投；数据资产损失保险是新险种，**市场供给有限**，需与保险公司定制，未必能马上找到合适产品。

**Q2：保险贵吗？**
A：网络安全保险通常按年缴，费率与企业规模、数据敏感度、安全措施成熟度相关（具体费率以保险公司报价为准，我们给参考区间并注明口径）。数据资产损失保险因供给有限，定价更不透明，需逐案询价。

**Q3：买了保险是不是就免责了？**
A：**不是**。保险是风险转移工具，不免除企业的合规义务与对第三方的法定赔偿责任（保险公司赔付后可能代位求偿）。投保不能替代安全合规建设。

**Q4：保险的除外责任重要吗？**
A：非常重要。很多数据泄露场景（如已知漏洞未修复、特定数据出境情形）可能被列为除外责任。我们会在方案里逐条标注"哪些不赔"，避免出险时"保了却赔不了"。

**Q5：保险对融资有帮助吗？**
A：有。向银行或投资方披露保险覆盖能提升数据资产的可信度，是有效的增信手段（下游 28）。但它不保证融资成功。

### 2.2 标准作业流程 SOP

**S0 风险识别（1~2 周）**
1. 梳理五类数据风险：泄露、篡改、灭失、侵权、服务过错
2. 评估各风险发生概率与潜在损失程度
3. 输出《可保风险清单》

**S1 保险方案设计（1~2 周）**
1. 匹配险种组合：网络安全保险（必选，市场成熟）+ 数据资产损失保险（按需）+ E&O（服务商必选）+ 知识产权/侵权责任险（交易方按需）
2. 确定保额、免赔额、保障期限
3. 输出《数据资产保险方案》

**S2 除外责任审查（与 S1 并行，3~5 天）**
1. 逐条读拟投保产品的除外责任
2. 标注"不赔情形"，评估保障缺口
3. 输出《除外责任审查表》

**S3 经纪对接与询价（2~4 周）**
1. 对接保险经纪或直保机构
2. 提交风险资料（安全措施、数据规模、历史事故、权属/估值）
3. 获取并比对多家报价
4. 输出《投保与报价材料》

**S4 投保与承保（2~4 周）**
1. 完成投保、如实告知
2. 保险公司核保、签署保单
3. 输出《保单》

**S5 增信披露（随融资/交易节点）**
1. 编制保险覆盖披露件（险种/保额/有效期/承保方/除外摘要）
2. 向融资方或合作方提交
3. 输出《保险增信披露函》

**S6 索赔支持（如发生）**
1. 出险后及时报案、固定证据
2. 准备索赔材料、协助理赔谈判
3. 输出《索赔材料包》

**S7 持续管理（年度）**
1. 保单续保、风险变化重评
2. 调整免赔/保额
3. 输出《保险年度复盘报告》

### 2.6 关键话术与风险提示

**关键话术（对客户）：**
- "有保险覆盖的数据资产，在银行和投资方眼里风险更低，融资会更容易——保险是很好的**增信工具**。"
- "网络安全保险市场比较成熟，但数据资产损失保险还是新险种，供给有限，可能需要逐案定制，甚至暂时找不到合适产品。"
- "买保险**不等于免责**：它转移的是财务风险，不免除您的合规义务和对第三方的法定赔偿责任。"

**风险提示（必须主动说）：**
1. **数据资产损失保险市场供给有限**，未必能马上买到合适产品，需准备替代方案（如自留风险+安全投入）。
2. **除外责任需仔细审查**——很多数据泄露场景（已知漏洞未修复、特定出境情形）可能被除外，须逐条标注"哪些不赔"。
3. **保险≠免责**，投保不能替代安全合规建设，也不能免除法定赔偿责任。
4. 保额不足会使保障"空洞"，须基于潜在最大损失测算而非随意填数。
5. 投保须履行**如实告知**义务，隐瞒风险可能导致拒赔。
6. 保险是增信手段，但**不保证**融资或交易必然成功。
