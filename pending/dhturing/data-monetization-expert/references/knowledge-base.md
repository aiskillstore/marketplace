## 第一部分 · 知识库

### 1.1 一句话定位

数据变现专家是**从价值到现金的操盘手**。前面所有专家都在做准备——盘点、治理、确权、评估、入表、产品化；变现专家负责**真正把钱收回来**。

他的核心工作有两件：
1. **选路径**：同一份数据有多条变现路径，选哪条最快、最稳、最值钱
2. **做闭环**：从接触买方到收款到复购，形成可持续的收入循环

本库的核心战略文档《图灵数盟-数据变现业务分析》正是围绕这一职能展开（DMaaS 运营商定位、"1+4+N"架构、七路径、DMS 评分、三大数据库、六收入模型）。

### 1.3 核心模型一：七路径模型

这是本库的核心变现框架（来自《图灵数盟-数据变现业务分析》）：

| 路径 | 内容 | 适用条件 | 变现速度 | 收入规模 |
|---|---|---|---|---|
| **路径1 · 数据产品直销** | 把数据做成产品直接销售 | 有标准化产品 | 快 | 中 |
| **路径2 · 数据服务收费** | 提供数据处理/分析服务 | 有专业能力 | 快 | 中 |
| **路径3 · 数据资产入表增信** | 入表后用于融资 | 有权属清晰数据 | 中 | 大 |
| **路径4 · 数据资产运营分成** | 与数据源方合作运营分成 | 有运营能力 | 中 | 持续 |
| **路径5 · 数据资本运作** | 作价出资、ABS、RWA | 有规模化资产 | 慢 | 很大 |
| **路径6 · 平台佣金** | 做撮合平台收佣金 | 有生态网络 | 中 | 持续 |
| **路径7 · 解决方案交付** | 场景化解决方案 | 有行业 Know-how | 快 | 大 |

**路径选择决策：**

```
有没有现成的可卖产品？
├─ 有 → 路径1（直销）
└─ 没有 → 能不能快速做出产品？
         ├─ 能 → 路径2（服务先行，边做产品）
         └─ 不能 → 数据权属清晰吗？
                  ├─ 清晰 → 路径3（入表增信 → 融资）
                  └─ 不清晰 → 先做确权（回到专家09/10）
```

**实务建议**：不要只走一条路。本库的战略是"**1+4+N**"——以入表为核心能力（1），向四类业务延伸（4），覆盖 N 个行业场景（N）。

### 1.4 核心模型二：DMS 数据变现评分模型

本库自有的评分模型，用于判断数据资源的变现潜力：

| 评分维度 | 权重 | 评分要点 |
|---|---|---|
| 数据规模与稀缺性 | 15% | 独特性越强分越高 |
| 数据质量 | 20% | 六维质量评分 |
| 权属清晰度 | 20% | 无瑕疵得分高 |
| 场景明确度 | 25% | 有明确付费场景得分高 |
| 合规风险 | 20% | 无个人信息/涉密（扣分项） |

**评分应用**：
- ≥75 分：立即变现，优先投入
- 60~74 分：培育后变现
- < 60 分：暂缓，先解决问题

### 1.5 核心模型三：三大数据库

本库战略中的核心资产（来自《数据变现业务分析》）：

| 数据库 | 内容 | 作用 |
|---|---|---|
| **数据资源库** | 掌握的可变现数据资源清单 | 供给侧（有什么可卖） |
| **需求数据库** | 买方需求清单 | 需求侧（谁要买） |
| **专家/服务机构库** | 可协作的专业服务方 | 交付侧（谁来干） |

**核心逻辑**：变现的本质是**供需匹配 + 交付能力**。三大数据库就是这三件事的载体。数据库越厚，变现效率越高——这是本库最重要的护城河思想。

### 1.6 核心模型四：六收入模型

本库商业模式中的收入结构：

| 收入类型 | 内容 | 特点 |
|---|---|---|
| **项目收入** | 入表、治理、评估等项目服务费 | 一次性、金额大 |
| **订阅收入** | 数据产品订阅、会员费 | 持续性、可预测 |
| **交易收入** | 数据产品交易佣金或差价 | 波动大 |
| **运营分成** | 数据运营收益分成 | 持续性 |
| **财务顾问收入** | 融资、ABS、RWA 顾问费 | 大额、低频 |
| **技术服务收入** | 平台、工具的技术服务费 | 持续性 |

**关键**：健康的商业模式应有**持续收入占比 > 50%**。纯项目制收入波动大，难以规模化。

### 1.7 核心模型五：六大首批市场

本库战略中锁定的首批市场方向：

| 市场 | 理由 | 变现方式 |
|---|---|---|
| 央企/国企 | 有数据、有入表需求、有预算 | 入表服务、资产运营 |
| 上市公司 | 有市值管理需求 | 入表增信、数据资产披露 |
| 地方政府 | 有公共数据授权运营需求 | 授权运营 |
| 金融机构 | 有数据风控需求 | 数据产品供应 |
| 医疗健康 | 数据价值高 | 数据资产化 |
| 农业/能源 | 数据资产化空白区 | 资产化服务 |

### 1.8 常见问题与标准答复

**Q1：变现最快的方式是什么？**
A：**服务收费**（路径2）。因为不需要先有产品，客户为专业能力付费。但要走出项目制，必须逐步产品化。

**Q2：为什么我们数据很多但赚不到钱？**
A：大概率是价值公式某一环断了。对照五因子：场景（没有明确买方）是最常见的断点。

**Q3：入表能直接变现吗？**
A：入表本身不产生现金，但它**解锁融资能力**（路径3）。所以要入表 + 融资组合做，形成闭环。

**Q4：三大数据库从哪开始建？**
A：从**需求数据库**开始。因为你有什么数据是固定的，但需求决定你该找什么数据。先有需求，再补资源。

**Q5：项目制和产品制怎么平衡？**
A：**用项目养产品**。第一个客户做项目（定制），第二个客户复用 70%，第三个客户标准化 → 产品成型。这是服务业的通用进化路径。

### 2.2 标准作业流程 SOP

**S0 变现潜力评估（1~2周）**
1. 从专家 22 获取价值分析报告
2. 用 DMS 模型打分
3. 确定优先级
4. 输出《变现潜力评分表》

**S1 路径选择（1周）**
1. 按七路径决策树比选
2. 评估每条路径的投入产出
3. 确定主路径 + 辅路径
4. 输出《变现路径方案》

**S2 数据库建设（持续）**
1. **需求数据库**（优先）：收集买方需求
   - 来源：交易所需求池、行业活动、客户拜访、政府渠道
   - 字段：买方、需求内容、用途、预算、时间
2. **数据资源库**：整理可供给的数据资源
3. **专家库**：整理可协作的服务方
4. 输出三大数据库

**S3 变现方案设计（2~3周）**
1. 针对优先变现对象，设计方案：
   - 卖给谁（目标买方）
   - 卖什么（产品/服务）
   - 怎么卖（路径、渠道）
   - 卖多少（定价，引用专家18）
   - 怎么交付（交付方式）
   - 收入怎么确认（引用专家32）
2. 输出《变现方案》

**S4 买方开发（持续，关键）**
1. 获客渠道：
   - 交易所撮合（引用专家19）
   - 行业活动、会议
   - 现有客户延伸
   - 政府/园区合作
   - 内容营销（公众号、白皮书）
2. 需求访谈：买方要解决什么问题？
3. 建立买方档案
4. 输出《买方档案》与《需求清单》

**S5 方案沟通与谈判（2~4周）**
1. 向买方呈现方案（价值导向）
2. 报价与谈判（引用专家18）
3. 处理异议（关注点：数据真实性、合规性、价格）
4. 输出报价与谈判记录

**S6 签约与交付（2~8周）**
1. 签署合同（引用专家14 审查）
2. 组织交付：
   - 自有能力交付
   - 或协调专家库中的服务方交付
3. 验收确认
4. 输出交付确认单

**S7 收款与收入确认（1~4周）**
1. 按约定收款
2. 收入确认（引用专家32 税务处理）
3. 输出收款凭证

**S8 复购与延伸（持续）**
1. 交付后回访，收集反馈
2. 挖掘延伸需求（一个客户往往有多种需求）
3. 建立长期合作关系
4. 输出复购记录

**S9 变现复盘（每季度）**
1. 分析：哪些路径成功、哪些失败
2. 更新 DMS 评分与数据库
3. 优化变现策略
4. 输出《变现复盘报告》

### 2.6 关键话术

**对内部（策略）**：
- "数据变现不是一件事，是七条路。选最短的那条先跑通。"
- "三大数据库是我们真正的护城河——资源、需求、专家。"
- "纯项目制做不大，必须用项目养产品，最终形成持续收入。"

**对客户**：
- "我们不是卖数据，我们是帮您把数据变成收入。"
- "您这次是入表，下一步可以基于入表做融资，再下一步可以做数据运营分成。"

**风险提示**：
1. 需求数据库比资源数据库更重要（先有需求再找资源）
2. 变现周期可能很长，需管理现金流
3. 单一客户依赖是风险（要客户多元化）
4. 收入确认时点影响利润，需与财务确认口径
5. 过度承诺交付能力会损害信誉
