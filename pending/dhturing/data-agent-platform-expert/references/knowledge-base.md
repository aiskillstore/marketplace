## 第一部分 · 知识库

### 1.1 一句话定位

数据智能体平台专家是**技术产品化的实现者**。前面 40 个专家代表的是"专业能力"，本专家负责把这些能力**装进系统**——变成可复用、可交付、可规模化的工具与平台。

他的核心对象是 **ACTN 平台**（Agent Collaboration & Trust Network，智能体任务分配网络）以及本库的其他系统：数据盘点工具、数据诊断工具、数据价值智能驾仓、数据变现大脑 DMB、数据资产管理系统（香农平台）、数据质量评价系统、DAM 等。

**战略意义**：专业服务难以规模化（靠人），平台可以规模化（靠系统）。这是从"项目制"走向"产品制/平台制"的关键（呼应专家 25 的五阶段进化）。

### 1.3 核心模型一：ACTN 平台（本库核心平台资产）

**ACTN = Agent Collaboration & Trust Network（智能体协作与信任网络）**

这是本库最有特色的技术资产——一个**AI 智能体任务发布/执行/审核/结算平台**。

| 模块 | 功能 |
|---|---|
| **任务发布** | 需求方发布任务（如写一份入表报告） |
| **智能体接单** | 注册的 AI 智能体（如小熊猫）接单 |
| **任务执行** | 智能体自主完成 |
| **审核验收** | 需求方或审核方验收 |
| **结算** | 按规则结算报酬 |
| **信任机制** | 通过存证、评价建立信任 |

**平台的价值逻辑**：
1. **把专业能力变成"可调用的服务"**——不需要养一堆人
2. **降低服务成本**——AI 智能体边际成本极低
3. **可规模化**——同时服务多个客户
4. **透明可信**——存证与评价机制

**与数据资产的结合点**：
- **skillAPI 存证证书**：智能体的技能调用被存证，可作为数据资产与知识产权证据（呼应专家 13）
- **ACTN 平台的数据安全风险评估报告**：平台自身也需要做安全评估（呼应专家 35）
- **平台数据本身是数据资产**：任务数据、评价数据、技能数据都可资产化

**产品化路径**：
```
知识（专家的知识与技能.md）
    ↓ 结构化
知识库/规则库（可查询、可调用）
    ↓ 工具化
工具（单一功能的软件）
    ↓ 平台化
平台（集成多工具、多用户）
    ↓ 智能化
智能体（自动调用工具完成任务）
```

**关键洞察**：我们刚刚产出的 42 份《知识与技能.md》，本身就是**平台的知识底座**——它们可以被结构化后作为 AI 智能体的知识库。这是本库完成专家体系后的自然延伸。

### 1.5 核心模型三：智能体能力设计

一个数据资产化领域的 AI 智能体应具备的能力（这是本专家的核心设计知识）：

| 能力层 | 内容 |
|---|---|
| **感知层** | 理解客户需求、解析文档、识别数据描述 |
| **知识层** | 调用专家知识库（42 个专家的知识） |
| **推理层** | 判断可行性、选择路径、生成方案 |
| **工具层** | 调用计算工具、文档生成、数据检测 |
| **输出层** | 生成报告、方案、台账、说明书 |
| **存证层** | 对关键动作存证（skillAPI） |

**能力边界设计（重要）**：
- 智能体可以：生成初稿、做初步诊断、执行标准化计算、生成标准文档
- 智能体不可以：替代持牌评估/法律资质、替代专业判断、替代客户决策

**实务原则**：**AI 提效，人做决策**。智能体输出的是"初稿/建议"，最终交付仍需专业人复核。

### 1.6 核心模型四：平台建设的四个技术要点

| 要点 | 内容 | 挑战 |
|---|---|---|
| **数据安全** | 平台处理客户数据，必须等保 + 加密 + 审计 | 安全是准入门槛 |
| **知识管理** | 专家知识的结构化与持续更新 | 知识会过时，需版本管理 |
| **智能体协作** | 多智能体任务分配、审核、结算 | 协议设计复杂 |
| **可审计性** | 关键动作留痕、可追溯 | 需要存证机制 |

### 1.7 常见问题与标准答复

**Q1：AI 智能体能替代数据资产化专家吗？**
A：不能完全替代，但能大幅提效。智能体擅长：标准化文档生成、数据检测、初步诊断、信息检索。不擅长：专业判断、客户沟通、责任承担（需资质）。

**Q2：ACTN 平台怎么赚钱？**
A：多种模式——① 任务撮合佣金；② 平台服务费（会员）；③ 智能体调用费；④ 增值服务（存证、审核）。本库的商业模式设计中有六收入模型的框架。

**Q3：平台要投多少钱？**
A：视规模。轻量工具集（几个模块）几十万；完整平台（ACTN 级别）数百万。建议**先做工具，再集成平台**。

**Q4：我们的专家知识怎么变成智能体能力？**
A：三步——① 把知识结构化（如我们刚写的 42 份知识与技能文档）；② 建立检索与调用机制（RAG 架构）；③ 设计任务流程（智能体按流程调用知识）。**我们刚完成的 42 份文档就是这个过程的第①步**。

**Q5：平台需要什么资质？**
A：视业务。涉及数据处理的需等保；涉及数据交易的可能需要数商资质（引用专家16）；涉个人信息需个保合规（引用专家36）。

### 2.2 标准作业流程 SOP

**S0 需求分析（2~3周）**
1. 识别可产品化的专业能力（对照六大模块）
2. 评估优先级（投入产出比）
3. 明确目标用户与场景
4. 输出《平台需求说明书》

**S1 知识结构化（2~4周，基础工作）**
1. 收集专家知识（如 42 份知识与技能文档）
2. 结构化：
   - 知识条目化（每条知识独立可检索）
   - 规则化（把判断逻辑写成规则）
   - 模板化（把交付物变成模板）
3. 建立知识库（支持检索与调用）
4. 输出知识库

**S2 智能体能力设计（2~3周）**
1. 设计能力清单（能做什么）
2. 设计能力边界（不能做什么）
3. 设计交互方式
4. 输出《智能体能力设计》

**S3 工作流设计（2~4周）**
1. 设计关键工作流（如"入表诊断"流程）
   - 输入：客户数据清单
   - 处理：调用知识 → 打分 → 判断
   - 输出：诊断报告初稿
2. 明确人工介入点（**关键**）
3. 输出《工作流设计》

**S4 工具开发（4~12周/个）**
1. 选择优先模块（建议从盘点诊断或质量检测入手）
2. 开发（技术栈参考：Node.js/React/Next.js 等）
3. 测试
4. 输出工具产品

**S5 平台集成（8~16周）**
1. 集成多个工具
2. 建立统一用户与权限
3. 建立数据流转
4. 输出平台系统

**S6 安全合规（4~8周，前置）**
1. 等保测评（引用专家 35）
2. 数据安全评估（尤其 ACTN 这类处理多方数据的平台）
3. 个保合规（如涉个人信息）
4. 输出安全评估报告与等保证明

**S7 存证机制（2~4周）**
1. 设计存证点（哪些动作需存证）
2. 实现存证（区块链/时间戳，参考 skillAPI 模式）
3. 输出存证方案与证书

**S8 平台上线与运营（持续）**
1. 灰度上线
2. 收集反馈迭代
3. 建立运营机制
4. 输出运营报告

**S9 效果评估（每季度）**
1. 评估提效指标（时间节省、成本降低、产能提升）
2. 评估质量（人工复核通过率）
3. 输出《效果评估报告》

### 2.6 关键话术

**对内部**：
- "专业服务靠人，做不大；平台靠系统，能规模化。ACTN 就是我们规模化的关键。"
- "我们刚产出的 42 份知识与技能文档，就是平台的知识底座——这是从'人的能力'变成'系统的能力'的第一步。"
- "AI 提效，人做决策。智能体出初稿，专业人复核交付。"

**对客户**：
- "我们不只是给您一份报告，我们给您一套工具，让您自己能持续管理数据资产。"
- "关键动作我们做链上存证，全程可追溯、可验证。"

**风险提示**：
1. **AI 输出不能直接作为交付物**——必须有专业人复核（责任承接）
2. 平台处理客户数据必须合规（等保 + 授权 + 审计）
3. 智能体能力边界要清晰，避免超出能力范围的承诺
4. 知识会过时，需建立更新机制（政策变化快）
5. 平台建设投入大，建议分阶段（先工具后平台）
6. 智能体涉及资质类工作（评估、法律意见）不能替代持牌机构
7. ACTN 这类多方平台需特别注意数据隔离与安全（本库已有风险评估报告 V3.0 可参考）
