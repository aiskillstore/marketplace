## 第一部分 · 知识库

### 1.1 一句话定位

数据供需匹配专家是**数据库的建设者与运营者**。他的核心资产不是数据，而是**知道谁有什么、谁要什么**的知识网络。

这个角色在本库战略中占据核心位置——《图灵数盟-数据变现业务分析》明确提出**三大数据库**（数据资源库、需求数据库、专家/服务机构库）是最重要的护城河。

他与专家 19（数据经纪人）的区别：
- **19 做单次撮合**（transaction）
- **27 建长期匹配体系**（infrastructure）

### 1.3 核心模型一：三大数据库

这是本专家的核心工作对象：

**数据库一 · 数据资源库（供给侧）**

| 字段 | 说明 |

| 案例 | 过往业绩 |

### 1.4 核心模型二：匹配效率公式

```
匹配效率 = 数据资源的覆盖度 × 需求信息的精准度 × 匹配算法的智能度
```

**三个变量：**
1. **覆盖度**：资源库里有多少可匹配的数据（广度）
2. **精准度**：需求信息是否完整准确（深度）
3. **智能度**：能否快速找到匹配（工具/算法）

**实务洞察**：多数人只关注覆盖度（收集更多数据），忽略了**需求精准度**。实际上，一个精准的需求信息比 100 条模糊的资源信息更有价值。

### 1.5 核心模型三：供需匹配的五种状态

匹配不是"有/无"二元，而是五种状态：

| 状态 | 含义 | 动作 |
|---|---|---|
| **A 直接匹配** | 现有资源直接满足需求 | 立即对接 |
| **B 加工匹配** | 资源经加工后可满足 | 组织加工 |
| **C 组合匹配** | 多个资源组合可满足 | 组织组合 |
| **D 外部匹配** | 需引入外部资源 | 寻找外部供给 |
| **E 待开发** | 当前无法满足 | 记录待开发，定期重看 |

**实务价值**：把 E 类需求记录下来，它指引了应该去获取什么数据。**需求数据库的最大价值不是匹配现有资源，而是指引资源获取方向**。

### 1.6 核心模型四：数据库建设三原则

| 原则 | 内容 | 原因 |
|---|---|---|
| **需求先行** | 优先建需求数据库 | 需求决定该找什么资源 |
| **持续更新** | 数据库是活的需要不断更新 | 数据会过期，客户会变化 |
| **可检索** | 结构化 + 标签化，支持快速检索 | 不能用 Excel 堆在一起 |

### 1.7 常见问题与标准答复

**Q1：三大数据库哪个最重要？**
A：需求数据库。因为你有多少数据是相对固定的，但需求决定了该找什么数据、往哪努力。**先有需求，再补资源**。

**Q2：需求从哪来？**
A：五个渠道——① 交易所需求池；② 行业活动、会议；③ 现有客户延伸需求；④ 政府/园区合作；⑤ 主动陌生拜访。其中**现有客户**质量最高。

**Q3：需求信息怎么保证准确？**
A：三个标准——① 有具体的人（不是"某公司可能想要"）；② 有明确的用途；③ 有预算或预算区间。三者齐全才算有效需求。

**Q4：要建系统吗？**
A：需求条目 < 100 条时 Excel 足够；超过 100 条建议上轻量 CRM 或自建系统。**不要一开始就开发系统**。

**Q5：匹配成功后怎么跟？**
A：转入交易流程（专家 15）或经纪流程（专家 19）。匹配专家的职责到"促成对接"为止，不承担成交责任。

### 2.2 标准作业流程 SOP

**S0 数据库设计（1~2周）**
1. 设计三库字段结构（参考 1.3 的字段表）
2. 设计标签体系（行业、数据类型、应用场景、地区）
3. 选择工具（Excel / CRM / 自建）
4. 输出《数据库设计说明书》

**S1 需求收集（持续，优先）**
1. 五个渠道并行：
   - 交易所需求池：定期浏览，摘录有效需求
   - 行业活动：参加活动，现场收集
   - 现有客户：回访时问"您还需要什么数据"
   - 政府/园区：合作对接时收集
   - 主动拜访：目标客户陌生拜访
2. 每条需求按五字段记录（需求方/内容/用途/预算/时间）
3. 校验有效性（三个标准）
4. 输出需求条目

**S2 资源收集（持续）**
1. 自有资源：从专家 05/11 获取
2. 合作资源：从生态伙伴获取
3. 外部资源：公开渠道收集
4. 按字段记录，标注权属与可交易性
5. 输出资源条目

**S3 专家库建设（持续）**
1. 收集服务机构：评估机构、律所、技术公司、咨询公司
2. 记录：领域、资质、案例、报价、评价
3. 优先收集本库已有合作方（世联评估、深算院、联兴、光大合作等）
4. 输出专家库条目

**S4 匹配执行（每次收到需求）**
1. 在资源库检索匹配
2. 判断匹配状态（A/B/C/D/E）
3. 执行对应动作：
   - A：直接对接双方
   - B/C：组织加工/组合
   - D：寻找外部资源
   - E：记录待开发
4. 输出《匹配方案》

**S5 匹配跟踪（持续）**
1. 跟踪对接进展
2. 记录结果（成功/失败及原因）
3. 成功案例沉淀（用于获客）
4. 失败分析（改进依据）
5. 输出匹配记录

**S6 数据库运营（每月）**
1. 更新需求状态（已匹配/已失效）
2. 更新资源状态（价格/可交易性变化）
3. 清理过期条目
4. 输出更新日志

**S7 数据分析（每季度）**
1. 分析：哪些行业需求多、哪些资源缺口大
2. 识别趋势（哪些场景在升温）
3. 指导资源获取方向
4. 输出《供需分析报告》

**S8 工具建设（按需）**
1. 条目 > 100 时考虑上系统
2. 建设匹配工具（标签检索、智能推荐）
3. 与数据变现大脑 DMB 集成
4. 输出匹配系统

### 2.6 关键话术

**对内部**：
- "我们真正的护城河不是数据，是三大数据库——谁知道有什么、谁知道要什么。"
- "需求数据库比资源数据库更重要。先知道客户要什么，再去找数据。"
- "匹配成功后要记录结果，成功案例是我们最好的获客工具。"

**对外**：
- "我们这里有 200 家买方需求在找数据，您的数据可能正好匹配。"
- "我们掌握 15 家数交所的资源网络，能帮您快速找到买方。"

**风险提示**：
1. 需求信息涉及客户商业机密，需严格保密
2. 数据库不更新会快速失效（客户会变、需求会变）
3. 匹配专家不承担成交责任（职责到对接为止）
4. 需求方可能绕过我们直接对接（需在协议中约定）
5. 资源方信息需核实真实性，避免虚假资源
