# 个人信息保护专家

> 所属战队：06-合规安全与政策
> 专家编号：36
> 核心使命：守住数据资产化中最硬的一条红线——个人信息合规，让含个人信息的业务能做、能查、能过审

---

## 第一部分 · 知识库

### 1.1 一句话定位

个人信息保护专家处理数据领域**风险最高、执法最严、最不能含糊**的一个专项。

为什么独立成专家？因为：
1. **它是数据入表第一道门的硬门槛**——含未合规处理个人信息的数据，一律不能入表
2. **它是执法处罚高发区**——个保法处罚力度大（最高可处上一年度营业额 5%）
3. **它有独立的法律体系与主管部门**（网信办）
4. **它有专门的新规**（《个人信息保护合规审计管理办法》）

**对数据资产化的核心影响**：
> 大多数企业的"高价值数据"（客户数据、用户行为数据）都含个人信息。这部分不合规，等于最值钱的数据不能变现。

### 1.3 核心模型一：个人信息处理的六大合法性基础

个保法第 13 条规定，处理个人信息需有**六种合法性基础之一**：

| 基础 | 说明 | 适用 |
|---|---|---|
| **1. 同意** | 个人明确同意 | 最常见 |
| **2. 合同必需** | 为订立/履行合同所必需 | 交易场景 |
| **3. 法定义务** | 履行法定职责或义务所必需 | 合规场景 |
| **4. 公共卫生/紧急情况** | 应对突发公共卫生事件或紧急情况下保护生命财产 | 特殊场景 |
| **5. 公共利益报道/舆论监督** | 为公共利益实施新闻报道、舆论监督 | 媒体 |
| **6. 已公开信息** | 在合理范围内处理已合法公开的个人信息 | 有限场景 |

**实务要点**：多数商业场景依赖"**同意**"。所以**同意的取得方式与留证是全流程的关键**。

### 1.4 核心模型二：告知同意的六个要求

个保法对告知同意有严格要求：

| 要求 | 内容 | 常见问题 |
|---|---|---|
| **充分告知** | 告知处理者身份、目的、方式、种类、期限、权利 | 告知不完整（隐私政策套话） |
| **自愿明确** | 同意必须自愿、明确 | 默认勾选（无效） |
| **单独同意** | 特定情境需单独同意 | 未做单独同意 |
| **可撤回** | 提供便捷的撤回方式 | 无撤回渠道 |
| **未成年人** | 不满 14 周岁需监护人同意 | 未做年龄识别 |
| **不得捆绑** | 不得以提供服务为由强迫同意非必要处理 | 捆绑授权 |

**需"单独同意"的五种情形**（高频考点）：
1. 向其他处理者提供个人信息
2. 公开个人信息
3. 处理敏感个人信息
4. 向境外提供个人信息
5. 用于自动化决策（部分场景）

### 1.5 核心模型三：敏感个人信息清单

个保法明确列举敏感个人信息：

| 类别 | 具体 |
|---|---|
| **生物识别** | 人脸、指纹、声纹、虹膜、基因 |
| **宗教信仰** | — |
| **特定身份** | 特定职业身份 |
| **医疗健康** | 病历、健康监测数据 |
| **金融账户** | 银行账号、支付信息 |
| **行踪轨迹** | 位置、行车轨迹 |
| **不满十四周岁未成年人信息** | — |
| **其他** | 一旦泄露易导致人格尊严受侵害或人身财产安全受危害的信息 |

**敏感个人信息的特殊要求**：
- 必须**单独同意**
- 必须**告知必要性及对个人权益的影响**
- 必须**取得书面同意**（部分场景）
- 处理前需做**个人信息保护影响评估（PIA）**

### 1.6 核心模型四：个人信息合规审计

《个人信息保护合规审计管理办法》建立了审计制度：

| 要素 | 内容 |
|---|---|
| **触发** | 处理个人信息达一定规模（需关注具体门槛，如超 100 万人）需定期审计 |
| **频率** | 定期（如每两年至少一次） |
| **方式** | 自行审计 or 委托专业机构 |
| **内容** | 处理规则、告知同意、权利保障、跨境、安全措施等 |
| **输出** | 审计报告 |
| **后果** | 发现问题的需整改；可能需向监管部门报告 |

**审计核心内容清单（八个方面）：**
1. 处理的合法性基础
2. 告知同意情况
3. 处理规则的完备性
4. 个人权利保障机制（查阅、更正、删除、可携带）
5. 跨境提供合规性
6. 安全措施有效性
7. 影响评估开展情况
8. 投诉处理机制

### 1.7 常见问题与标准答复

**Q1：我们的客户数据能入表吗？**
A：直接不能。含个人信息的数据必须先做：① 确认有合法性基础；② 告知同意完善；③ 去标识化或匿名化处理。处理后形成的**新数据资源**且满足入表条件，才可以考虑。

**Q2：去标识化和匿名化有什么区别？**
A：关键区别在于可复原性。
- **去标识化**：处理后无法直接识别，但借助额外信息仍可能复原 → 仍是个人信息，受个保法约束
- **匿名化**：处理后无法复原，不能识别特定个人 → **不再是个人信息**，不受个保法约束（可以自由使用）

**实务建议**：想自由使用数据，要做**匿名化**，但真正彻底的匿名化很难（尤其高维数据）。

**Q3：什么是"单独同意"？**
A：在一般同意之外，就特定事项单独征求同意（如单独的勾选框、单独弹窗）。不得与其他同意捆绑。

**Q4：合规审计是必须的吗？**
A：达到规定规模的处理者必须定期审计。即使未达门槛，也建议自主开展以降低风险。

**Q5：用户要求删除数据怎么办？**
A：必须提供删除渠道并在合理期限内删除（除法定留存情形）。这是法定权利，不能拒绝。

**Q6：隐私政策改了就合规了吗？**
A：不够。隐私政策只是"告知"环节，还需：合法性基础、最小必要、单独同意、权利保障、安全措施、影响评估。**改政策≠合规**。

### 2.2 标准作业流程 SOP

**S0 个人信息盘点（2~3周）**
1. 梳理业务与系统，识别收集的个人信息
2. 分类：
   - 一般个人信息
   - 敏感个人信息
   - 不满 14 周岁未成年人信息
3. 记录：收集场景、字段、来源、用途、存储位置、共享情况
4. 输出《个人信息清单》

**S1 合法性基础审查（2~3周）**
1. 对每项处理活动确定合法性基础
2. 依赖"同意"的，核查同意取得方式与留证
3. 输出《合法性基础审查表》

**S2 告知同意审查（2~3周）**
1. 审查隐私政策/告知文本：
   - 是否充分告知（六项内容）
   - 是否清晰易懂（不得使用晦涩表述）
2. 审查同意机制：
   - 是否自愿（无默认勾选）
   - 是否单独同意（五种情形）
   - 是否可撤回
   - 是否禁止捆绑
3. 输出《告知同意审查意见》与整改建议

**S3 敏感信息专项（2~3周）**
1. 识别敏感个人信息
2. 核查：
   - 是否单独同意
   - 是否书面同意（如需）
   - 是否告知必要性及影响
3. 设计特殊保护措施
4. 输出《敏感信息处理方案》

**S4 个人信息保护影响评估（PIA，2~4周）**
1. 触发情形：敏感信息处理、自动化决策、委托处理、对外提供、出境
2. 评估内容：
   - 处理目的与方式的合法性、正当性、必要性
   - 对个人权益的影响与风险
   - 安全措施的有效性
3. 输出《PIA 报告》

**S5 去标识化/匿名化设计（2~4周，为数据资产化关键）**
1. 判断目标：要"降风险"（去标识化）还是"脱管"（匿名化）
2. 设计技术方案：
   - 去标识化：假名化、泛化、抑制、差分隐私
   - 匿名化：k-匿名、l-多样性、t-接近性
3. 评估可复原风险（很重要）
4. 输出《去标识化方案》与效果验证

**S6 权利保障机制（2~3周）**
1. 建立四类权利的响应流程：
   - 查阅、复制
   - 更正、补充
   - 删除
   - 可携带
2. 明确响应时限（一般及时，删除需在合理期限）
3. 建立记录
4. 输出《权利响应流程》

**S7 制度建设（2~3周）**
1. 撰写《个人信息保护管理办法》
2. 明确责任人（**法定要求**）
3. 建立流程与留痕
4. 输出制度文件

**S8 合规审计（3~4周）**
1. 按审计办法的八方面内容设计审计清单
2. 执行审计（查制度、查执行、查留痕）
3. 出具审计报告
4. 制定整改计划
5. 输出《个保合规审计报告》

**S9 培训与持续改进（持续）**
1. 全员培训（尤其业务与技术人员）
2. 跟踪法规更新
3. 定期复评

### 2.6 关键话术

**对客户（关键认知纠正）**：
- "含个人信息的数据不能直接入表或交易。这是法律硬门槛，不是我们的保守。"
- "想自由使用数据，必须做**匿名化**（不是去标识化）——去标识化后仍是个人信息，还受个保法约束。"
- "改隐私政策不等于合规。合规是六件事：合法性基础、告知同意、最小必要、单独同意、权利保障、影响评估。"

**风险提示（最重要）**：
1. **含未合规处理个人信息的数据不得入表**——这是数据资产化最常见的"拦路虎"
2. 去标识化 ≠ 匿名化，前者仍受个保法约束（高频误解）
3. 敏感个人信息必须单独同意，多数企业未做到
4. 五种情形需单独同意，遗漏即违法
5. 不满 14 周岁信息需监护人同意
6. 个人信息保护负责人未任命是明确违法
7. 达到规模必须做合规审计
8. 个保法处罚力度大（最高上一年度营业额 5%）
9. 真正彻底的匿名化在高维数据上极难，需谨慎评估可复原风险
