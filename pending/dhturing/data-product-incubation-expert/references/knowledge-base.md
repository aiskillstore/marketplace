# 数据产品孵化专家

> 所属战队：03-流通与交易
> 专家编号：17
> 核心使命：把企业手里「说不出价值」的原始数据，孵化成「有场景、有规格、有价格、卖得动」的数据产品

---

## 第一部分 · 知识库

### 1.1 一句话定位

数据产品孵化专家是**产品经理角色**。他的工作是把"我们有很多数据"这句话，变成"这是我们的产品 X，它能帮你解决 Y 问题，价格 Z，这样交付"。

这在整条链路上是**从0到1的创造性环节**，也是最需要业务理解的环节——因为他要回答的不是"数据是什么"，而是"数据能变成什么商品"。

### 1.3 核心模型一：数据产品孵化四步法

```
① 场景发现 → ② 价值假设 → ③ 产品设计 → ④ 验证迭代
```

**① 场景发现**
找出数据能发挥价值的业务场景。三个来源：
- **内部场景**：企业自己业务的痛点（如库存预测、风控、营销）
- **行业场景**：同行业普遍痛点（可复制）
- **外部需求**：主动调研潜在买方的需求

**② 价值假设**
写出清晰的价值假设：
> "如果我把【数据A + 数据B】加工成【形态C】，提供给【客户类型D】，他们可以用它【解决E问题】，从而节省/赚取【F】。"

**要求**：F 必须可量化，否则无法定价也无法验证。

**③ 产品设计**
按七要素设计（见专家 11）：
- 产品名称、类型、数据范围、更新频率、交付方式、质量等级、权利类型

**④ 验证迭代**
- 找 1~3 个种子客户验证
- 收集反馈：有用吗？愿意付钱吗？愿意付多少？
- 迭代 → 定型 → 上架

### 1.4 核心模型二：产品化成熟度五级

| 级别 | 形态 | 特征 | 能做什么 |
|---|---|---|---|
| L1 | 原始数据 | 无加工、无说明 | 只能内部用 |
| L2 | 数据资源 | 有目录、有说明 | 可作为资产入表 |
| L3 | 数据产品雏形 | 有规格、有样本 | 可试点销售 |
| L4 | 标准化产品 | 有说明书、可重复交付、有定价 | 可上架交易 |
| L5 | 产品矩阵 | 多产品组合、有品牌 | 可规模化经营 |

**孵化目标**：把 L1/L2 推到 L4。多数企业的数据停在 L1~L2。

### 1.6 核心模型四：产品化改造五问

拿到一份原始数据，问五个问题就能判断能不能产品化：

| 问题 | 判断 |
|---|---|
| 1. 能说清楚它包含什么吗？（可描述性） | 字段、范围、规模是否明确 |
| 2. 能标准化交付吗？（可交付性） | 是否有稳定的交付方式 |
| 3. 能重复卖给不同客户吗？（可复制性） | 是否依赖特定客户 |
| 4. 买方知道怎么用吗？（可用性） | 是否需要大量指导 |
| 5. 质量稳定吗？（稳定性） | 是否每次交付都一样 |

五问全过 → 可以产品化。任一不过 → 需改造，改造方向对应该问题。

### 1.7 常见问题与标准答复

**Q1：我们有数据，但不知道能做什么产品，怎么办？**
A：反向思考——不要从数据出发，要从**买方痛点**出发。去找 5 个潜在客户，问他们最头疼什么，再看我们的数据能否解决。

**Q2：产品一定要卖给别人吗？**
A：不一定。内部使用（降本增效）也是产品化，且更容易验证。建议**先内部验证、再对外销售**。

**Q3：一个产品要多久孵化？**
A：从场景到可上架，通常 2~4 个月。其中验证环节最耗时且最容易失败。

**Q4：产品做出来了没人买怎么办？**
A：三个可能：① 场景选错（买方没这个痛点）；② 定价错（太贵或价值不清晰）；③ 包装错（技术语言而非业务语言）。逐一排查。

**Q5：产品化需要多少投入？**
A：取决于加工深度。轻加工（脱敏+标准化）几万元；深度加工（建模、持续更新）几十万。建议从小做起。

### 2.2 标准作业流程 SOP

**S0 资源盘点与筛选（1~2周）**
1. 从专家 05 的诊断报告获取数据资源清单
2. 按产品化五问初筛
3. 选出 3~5 个候选
4. 输出《产品化潜力评估》

**S1 场景发现（2~3周）**
1. 内部调研：访谈业务部门，找内部痛点
2. 外部调研：访谈潜在客户、行业专家
3. 对照"数据要素×"12 行业场景找匹配
4. 输出《场景机会清单》（含优先级）

**S2 价值假设设计（1周）**
1. 对优先场景撰写价值假设（按标准句式）
2. 量化价值（节省多少成本/带来多少收入）
3. 输出《价值假设说明书》

**S3 产品设计（1~2周）**
1. 按七要素设计产品
2. 定义数据范围、字段、更新频率
3. 设计交付方式
4. 输出《产品设计方案》

**S4 原型制作（2~4周）**
1. 制作最小可用产品（MVP）：
   - 提取、清洗、脱敏
   - 生成样本数据
   - 制作初步说明书
2. 输出产品原型与样本

**S5 种子客户验证（3~6周，关键）**
1. 找 1~3 个种子客户
2. 免费或低价试用
3. 收集反馈：
   - 数据有用吗？（价值验证）
   - 好用吗？（体验验证）
   - 愿意付多少钱？（定价验证）
4. 记录真实使用行为（不只是口头反馈）
5. 输出《验证报告》

**S6 产品定型（2~3周）**
1. 根据验证结果调整
2. 编写正式《数据产品说明书》
3. 确定质量等级（引用专家 04）
4. 确定权利来源（引用专家 09/10）
5. 输出定型产品

**S7 定价建议（1周）**
1. 转专家 18 做专业定价
2. 或按成本+价值+市场三法初定
3. 输出定价建议书

**S8 上架对接（2~4周）**
1. 转专家 11 做产品登记
2. 转专家 15 做交易准备
3. 输出上架材料

**S9 产品迭代（持续）**
1. 收集使用反馈
2. 定期更新数据与功能
3. 版本管理
4. 输出迭代记录

### 2.6 关键话术

- "不要问『我有什么数据能卖』，要问『客户有什么问题，我的数据能不能解决』。"
- "先做内部验证，再做种子客户验证。别一上来就开发完整产品。"
- "买方听不懂『非结构化多模态特征』，他听得懂『帮您把客户流失率降低 15%』。"

**风险提示**：
1. 产品化最大风险是"做完才发现没人要"——验证环节不能省
2. 深度加工投入大，建议分阶段投入
3. 产品定型过早会锁死迭代空间，过晚则无法推广
4. 内部使用产品对外销售时，需重新审查合规性
5. 产品说明书过度承诺会带来交付风险
