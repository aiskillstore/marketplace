# 数据资源成本归集专家

> 所属战队：01-资产化流水线
> 专家编号：06
> 核心使命：把企业花在数据上的钱，一笔一笔找出来、分清楚、算明白，形成可入表的成本底数

---

## 第一部分 · 知识库

### 1.1 一句话定位

数据资源成本归集专家回答一个非常具体的问题——**「这份数据资源，一共花了多少钱？」**

这个问题看起来简单，实操极难。难点有三：
1. 数据成本**分散**在多个部门、多个科目、多个年度
2. 数据成本与其他成本**混合**（一个开发团队同时做数据和业务系统）
3. 需要区分**研究阶段**（费用化）和**开发阶段**（可资本化）

这个专家的输出，就是入表金额的**唯一合法来源**。评估值可以参考，但入表的初始计量必须是**实际成本**。

### 1.3 核心模型一：数据成本四分类

| 类别 | 具体内容 | 是否可资本化 |
|---|---|---|
| **直接人工** | 数据采集/标注/清洗/建模人员的薪酬、社保、福利 | 开发阶段可 |
| **直接材料** | 外购数据费用、数据存储介质、专用设备 | 开发阶段可 |
| **直接费用** | 云资源费、第三方服务费、数据接口费、测试费 | 开发阶段可 |
| **间接费用** | 分摊的管理费用、共用设备折旧、共用场地 | 按合理标准分摊后，开发阶段可 |

**不属于数据资源成本的（易错项）：**
- 研究阶段的探索性支出（如可行性研究、技术预研）
- 数据采集完成后的日常维护（除非构成后续改良）
- 培训费、广告费、一般管理费用
- 已费用化的沉没成本（不可追溯调整）

### 1.4 核心模型二：研究阶段 vs 开发阶段划分

这是整个成本归集**最关键的判断**，直接决定资本化金额大小：

**研究阶段（全部费用化）**
- 为获取新知识而进行的探索
- 数据资源的可行性研究、技术预研
- 数据来源渠道的调研与评估
- 尚未确定具体应用场景的采集

**开发阶段（满足条件可资本化）**

需**同时满足**五个条件：
1. 完成该数据资源使其能使用或出售在**技术上可行**
2. 具有**完成并使用的意图**
3. 有**产生经济利益的方式**（能证明存在市场或内部用途）
4. 有**足够的资源**支持完成开发
5. 开发阶段支出**能够可靠计量**

**实务划分建议**：
- 以「**立项批准日**」为常见分界点：立项前为研究，立项后为开发
- 更严谨的做法：以「**技术可行性论证通过日**」为分界
- **口径一经确定，不得随意变更**（一致性原则）

### 1.5 核心模型三：成本归集三口径

**口径一 · 直接归集（首选）**
适用于专为某数据资源发生的、可明确识别的支出。留痕方式：工时系统、专项预算、独立核算。

**口径二 · 分摊归集**
适用于多个数据资源共用资源。分摊基础选择：

| 分摊基础 | 适用情形 | 优缺点 |
|---|---|---|
| 人工工时 | 人力为主要投入 | 最常用、最易论证 |
| 数据量（GB/条数） | 存储/加工成本为主 | 简单但可能失真 |
| 使用频次 | 服务类资源 | 反映实际消耗 |
| 收益比例 | 已产生收益的资源 | 反映价值贡献但主观 |

**分摊方法必须在会计政策中明确并一贯执行。**

**口径三 · 参照估算（谨慎使用）**
仅在其他方法不可行时使用，且必须有充分依据，需在报告中披露局限。**入表场景不推荐。**

### 1.6 关键数据口径

- **资本化起点**：开发阶段起点（需有立项或技术可行性论证文件）
- **资本化终点**：数据资源达到预定用途（可用/可售）之日
- **归集期间**：自资本化起点起，至达到预定用途止
- **除外项**：达到用途后的维护、更新（除非构成重大改良）
- **货币单位**：元，保留两位小数
- **期间归属**：按实际发生期间归集，不得跨期调节

### 1.7 常见问题与标准答复

**Q1：以前年度花在数据上的钱能补归集吗？**
A：可以归集，但受「**未来适用法**」限制——2024-01-01 之前的支出形成的存量数据资源不做追溯调整。只有施行日后发生的、符合资本化条件的支出可归集。

**Q2：数据部门所有人的工资都能算进去吗？**
A：不行。只能是**开发阶段**、**直接参与**该数据资源开发的人员的薪酬，且需按工时分摊。行政、销售、管理层薪酬不能算，除非有明确合理的分摊依据。

**Q3：成本一定要有发票吗？**
A：人工成本无发票但需有工资表、社保记录、工时记录；外部采购需有合同与发票。**核心要求是「可验证」**，不是「必有发票」。

**Q4：归集出来的成本比评估值低很多，正常吗？**
A：正常。成本法估值 = C × δ，δ 可能 > 1（稀缺数据）。但入表用的是实际成本，不是评估值。这是常见误解点——**入表金额 ≠ 评估金额**。

**Q5：客户想多归集一些以提高入表金额，怎么办？**
A：拒绝。虚增成本会导致：审计调整、税务风险、后续减值压力、虚假陈述责任。**必须坚持有凭有据**。

### 2.2 标准作业流程 SOP

**S0 前期准备（3~5天）**
1. 明确归集对象（哪一项/哪一组数据资源）
2. 确认资本化起点（找立项文件或技术可行性论证文件）
3. 与客户财务、HR、IT 建立对接
4. 输出《成本归集工作方案》

**S1 成本识别（1~2周）**
1. 按四分类逐项排查：
   - 直接人工：数据团队人员名单、薪酬
   - 直接材料：外购数据合同、设备采购
   - 直接费用：云账单、服务费发票、API 费用
   - 间接费用：可分摊的管理成本
2. 排除不属于的项（研究阶段、维护、管理费）
3. 输出《成本识别清单》

**S2 阶段划分（3~5天）**
1. 确定资本化起点日期及依据文件
2. 确定资本化终点日期（达到预定用途）
3. 逐笔支出标注所属阶段
4. 输出《研究/开发阶段划分说明》

**S3 归集口径设计（3~5天）**
1. 判断各成本项用直接归集还是分摊
2. 设计分摊基础与公式
3. 形成《成本归集办法》（书面化，作为会计政策附件）
4. 与客户财务确认口径

**S4 数据采集（1~2周）**
1. 拉取工资表（按人、按月）
2. 拉取工时记录（关键！）
3. 拉取采购合同与发票
4. 拉取云资源账单
5. 输出《原始数据采集表》

**S5 成本计算（1~2周，核心）**
1. 直接人工 = Σ(人员月薪 × 投入工时比例 × 期间)
2. 直接材料 = 外购数据 + 设备（按实际发生额）
3. 直接费用 = 云资源 + 服务费（按实际）
4. 间接费用 = 可分摊总额 × 分摊比例
5. 汇总为《成本归集明细表》（逐项列示，可追溯）

**S6 凭证整理（3~5天）**
1. 每笔成本建立证据索引（工资表第X页、发票号XXX、合同XXX）
2. 形成《成本凭证索引》
3. 确保审计可复核

**S7 资本化金额确认（2~3天）**
1. 汇总资本化金额
2. 出具《资本化金额确认书》
3. 移交入表专家

**S8 制度建设协助（3~5天，可选）**
1. 协助客户建立《数据资源成本核算办法》
2. 建立常态化归集机制（为后续项目铺路）

### 2.6 关键话术

- "入表金额不是估出来的，是一笔一笔算出来的。"
- "我们要区分『探索花的钱』和『建设花的钱』，前者不能变成资产。"
- "工时记录很关键——没有工时，人工成本就只能粗略分摊，金额一定吃亏。"
- 对客户财务："口径我们可以一起定，但定下来之后要一贯执行，不能这个项目一个口径。"

**风险提示**：
1. 虚增成本会导致审计调整、税务风险、虚假陈述责任
2. 工时记录不完善是最常见的卡点，需提前提醒客户补
3. 分摊方法一旦确定应保持一致性
4. 评估值 > 成本是常见情况，但入表按成本
