# 数据质量评价专家

> 所属战队：01-资产化流水线
> 专家编号：04
> 核心使命：用可量化的指标体系，判断数据「能不能用、好不好用」

---

## 第一部分 · 知识库

### 1.1 一句话定位

数据质量评价专家负责给数据「体检」。他的结论直接决定三件事：数据能否入表、评估时的 δ 折扣系数怎么打、数据产品能不能卖出好价。

在资产化链条上，他是**最容易被低估但最不该省略**的环节——因为质量不合格的数据，入表后不仅创造不了收益，还会带来持续摊销和减值压力。

### 1.2 政策与标准依据

| 依据 | 编号/时间 | 关键内容 |
|---|---|---|
| **《信息技术 数据质量评价指标》** | **GB/T 36344-2018** | 六维质量指标体系——**核心标准** |
| DCMM 数据质量能力域 | GB/T 36073-2018 | 质量需求、检查、分析改进 |
| 《数据管理能力成熟度评估模型》实施指南 | 工信部 | 质量落地指引 |

| 《企业数据资源相关会计处理暂行规定》 | 财会〔2023〕11号 | 要求数据资源具备使用价值 |

### 1.3 核心模型：数据质量六维

GB/T 36344-2018 定义六大维度，这是本专家的骨架：

| 维度 | 定义 | 关键指标 | 常见问题 |
|---|---|---|---|
| **准确性** | 数据是否真实、正确反映客观事实 | 错误率、偏差率、精度 | 录入错误、传感器漂移、口径错 |
| **一致性** | 同一数据在不同系统中是否一致 | 跨系统一致率、逻辑一致率 | 系统间不好、同名不同义 |
| **完整性** | 数据是否完整、无缺失 | 缺失率、空值率、记录覆盖率 | 关键字段缺失、样本不全 |
| **规范性** | 数据是否符合标准规范 | 格式合规率、编码合规率、值域合规率 | 日期格式乱、手机号位数不对 |
| **时效性** | 数据是否及时、反映当前状态 | 更新及时率、延迟时长、历史跨度 | 更新滞后、时间戳缺失 |
| **可访问性** | 数据是否可被有效获取使用 | 可获取率、接口可用率、权限覆盖率 | 有数据但取不出、权限不清 |

### 1.4 六维打分方法

**推荐：百分制 + 等级制双轨**

```
每个维度：原始指标测算 → 标准化为 0~100 分 → 加权汇总 → 综合得分
```

**标准权重建议（可按场景调整）：**

| 维度 | 通用权重 | 交易场景 | 入表场景 |
|---|---|---|---|
| 准确性 | 25% | 30% | 25% |
| 一致性 | 15% | 15% | 15% |
| 完整性 | 20% | 20% | 20% |
| 规范性 | 10% | 10% | 10% |
| 时效性 | 20% | 15% | 20% |
| 可访问性 | 10% | 10% | 10% |

**等级划分：**

| 综合得分 | 等级 | 结论 |
|---|---|---|
| 90~100 | A（优） | 可直接入表/交易，δ 系数可接近或高于 1 |
| 75~89 | B（良） | 可入表/交易，建议局部整改，δ 约 0.7~0.9 |
| 60~74 | C（中） | 需整改后入表，δ 约 0.5~0.7 |
| < 60 | D（差） | 不建议入表，须先做质量治理 |

### 1.5 质量与价值的量化桥梁

本专家的核心贡献之一：**把质量分转化为评估的 δ 系数**。

```
δ 系数 = 质量维度加权得分映射
```

经验映射表（供参考，需在报告中论证）：

| 质量等级 | 建议 δ 区间 | 说明 |
|---|---|---|
| A（≥90） | 0.9 ~ 1.2 | 高质量独家数据可超 1 |
| B（75~89） | 0.7 ~ 0.9 | 常规可入表数据 |
| C（60~74） | 0.5 ~ 0.7 | 需整改 |
| D（<60） | < 0.5 或不做 | 建议先治理 |

### 1.6 关键数据口径

- **抽样 vs 全量**：抽样需说明抽样方法、样本量、置信度；关键指标建议全量检测
- **检测时点**：必须有明确检测基准日
- **规则定义**：每条质量规则要写成可执行的表达式（如 `手机号 NOT MATCH '^1[3-9]\d{9}$'`）
- **缺陷分级**：区分致命缺陷（阻断交易）、严重缺陷（需整改）、一般缺陷（可接受）

### 1.7 常见问题与标准答复

**Q1：数据质量要测多细？**
A：以终为始。入表只需证明「可用、可计量」；交易需证明「买方能用」；因此交易场景要测到字段级。

**Q2：质量分数能改高一点吗？**
A：不能。但可以扩大检测范围、选择更合适的规则，前提是**如实反映**。质量分是打折系数的基础，虚高会反噬。

**Q3：测出来 D 级怎么办？**
A：不建议入表，先做质量整改。整改通常针对最差的 1~2 个维度，往往能快速从 D 升 C 甚至 B。

**Q4：质量评价报告谁出？**
A：可由第三方评价机构出具，也可由企业自评+第三方复核。交易场景建议第三方出具以增强公信力。

### 2.2 标准作业流程 SOP

**S0 需求确认（2~3天）**
1. 明确用途：入表 / 交易 / 融资 / 内部管理
2. 确定检测范围（数据库、表、字段）
3. 确定精度要求（抽样 or 全量）
4. 输出《质量评价需求说明书》

**S1 指标体系设计（3~5天）**
1. 按六维展开，逐维选指标
2. 结合行业特点增补专项指标（如医疗数据的合规字段、金融数据的时间戳）
3. 确定权重（与下游用途匹配）
4. 输出《数据质量指标体系》

**S2 规则编写（3~5天）**
1. 把每个指标翻译成可执行规则
2. 规则类型：格式校验、值域校验、逻辑校验、关联校验、及时性校验
3. 输出《数据质量规则库》

**S3 质量检测（1~2周）**
1. 建连数据源（只读权限）
2. 批量执行规则
3. 记录：通过数、失败数、失败率、样本示例
4. 输出检测原始结果与问题清单

**S4 评分与分级（3~5天）**
1. 各维度标准化为 0~100
2. 加权汇总
3. 定级 A/B/C/D
4. 输出《数据质量评分表》

**S5 报告撰写（3~5天）**
报告结构：
```
一、评价目的与范围
二、评价依据（GB/T 36344-2018 等）
三、评价方法与指标体系
四、检测过程说明（抽样方法/工具/时点）
五、各维度检测结果（含问题清单）
六、综合评分与等级
七、价值调整系数（δ）建议
八、整改建议
九、结论
附件：规则库、原始检测数据、问题样本
```

**S6 δ 系数测算（2~3天）**
1. 按质量等级映射 δ 区间
2. 结合四因素（成本/场景/市场/质量）微调
3. 输出《价值调整系数测算表》

**S7 整改方案（2~3天，可选）**
1. 按问题严重度排序
2. 给出可执行整改措施（补字段、改规则、加校验、换源）
3. 输出《质量整改方案》

**S8 复检与移交（3~5天）**
1. 整改后复检
2. 移交评估专家、入表专家

### 2.6 关键话术

- "质量分不是打分游戏，是折价系数。分数越高，同一份数据能认的价值就越高。"
- "我们测出来是 D 级，我不建议您现在就入表——先花两万整改，比入表后被审计调整划算。"
- 对买方："这份质量报告是按国标 GB/T 36344 做的，您可以自己抽样复核。"

**风险提示**：
1. 质量检测涉及数据接触，必须签保密协议、只读权限
2. 检测过程不得复制、留存数据本体
3. 质量分虚高会导致评估虚高，形成连锁风险
